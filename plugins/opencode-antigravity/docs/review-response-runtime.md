Every fix has a test that fails without it; each was checked by reverting the fix and running the test.

## Changes needed in other owners' files

- **`src/proxy.ts` (proxy owner), N-7:** in the `checkOutcome` hook, call `this.bridge.reportSignInRequired(SIGNED_OUT_MESSAGE)` when the returned failure has kind `auth_required`, like `mapError` does. Until then a 401 error step answers 401 but the provider card does not switch to "Sign in again".
- **`src/proxy.ts` (proxy owner), O-6:** in `setupNotes`, while `this.manager.state === "draining"`, send a note such as `Antigravity was updated. Waiting for running tool calls on the old version (up to 30 s).`. `this.manager.drainDeadline` gives the time the old child stops.
- **`src/proxy.ts` (proxy owner), O-4:** the comment on `runRoot` still says `<os.tmpdir()>/opencode-antigravity`; the default is now `defaultRunRoot()` from `tmp-sweeper.ts`.
- `test/fixtures/fake-bridge.ts`: `changeAuth` delivers `onAuthChanged` in a microtask, like the real `AuthEpoch` for external changes, and returns `delivered` to await; `simulateLogout` awaits it before the runtime stop, the order `AuthManager.logoutLocked` has. `test/contracts.test.ts` checks the delayed delivery.
- `src/constants.ts` (no owner this pass) got `RuntimeTimings.drainWaitMs` (default 30 000); `test/fixtures/mock-agy.ts` got the `error-mcp-url` scenario and a second, injected permission request in `builtin-permission`.
