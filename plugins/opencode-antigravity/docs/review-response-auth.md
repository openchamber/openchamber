## Cross-owner notes

- O-1: the runtime owner's fix is the whole fix. `stop()` in `starting` must not await a start that is still inside `beforeSpawn()`, and the start must check `cancelledStart` after `beforeSpawn` returns or rejects. The auth side guarantees `beforeSpawn` settles once logout ends, with `SignInRequiredError` unless another process signed in meanwhile.
- O-2: with the notification deferred, the proxy's `onAuthChanged` listener no longer runs inside `handleMain`'s `bridge.authEpoch()` call, but it can still run at the next await inside the session mutex. The proxy owner's hardening (skip entries a mutex holder uses, or re-fetch the entry) is still needed.
- `test/fixtures/fake-bridge.ts` (runtime owner): to cover O-2 in the e2e tests, the fake bridge's `authEpoch()` could notify listeners in a microtask after a `changeAuth`, the way `AuthEpoch` now does.
