# Diagnostic timeline

The local file classifier recognizes one updater failure from the current desktop log: `Cannot find latest-mac.yml in the latest release artifacts` with HTTP 404. It drops the release URL. Other updater errors retain their category without a raw message.

For known `/api/event` `fetch failed`, `terminated`, and `OpenCode service unavailable` pairs, the local file classifier identifies the message-stream WS bridge and `PushWatcher` separately and groups repeated warnings by reporter. The renderer accepts only these fixed reporter names, the event-stream action and bounded count/span details. It rejects unknown routes, appended error text and private data at the transport boundary.

The server now records completed 4xx/5xx HTTP responses as they happen without continuous polling or relying on verbose access logs. The journal exports method, fixed route template, `stage=downstream_response`, and observed status; adjacent matching responses are grouped for up to ten minutes. A 404 does not establish an upstream cause. Unknown warnings/errors from local files, managed stderr, and the local SSH buffer are counted under `Sources` with warning/error totals rather than shown as unexplained `unclassified output` events. Neither unknown text nor query strings, paths, IDs, and response bodies enter the export.

The standard web/desktop `App` records a bounded in-memory history for the local instance when it mounts. Store subscriptions capture changes to connection, event-stream, session-selection and directory-selection state. A selection snapshot and every transition use numbered session and directory labels, including changes between two nonempty selections. Recent turn and send failures use the same session/directory labels, with a separate message label for rejected sends. The label map retains the original IDs and directory paths only in memory; the log contains neither those values nor session titles. The map is capped at 5,000 identifiers and reset with the event buffer on a runtime switch. Tagged console calls and untagged warnings/errors record a fixed severity and optional allowlisted error type. Renderer exceptions and unhandled rejections may carry an exact known browser message or a fixed template such as `Cannot read properties of undefined (reading [property])`. The original property name is discarded. Uncaught exceptions record their allowlisted error type and line/column in a same-origin built JS asset when available. If the browser gives no type or no verifiable asset location, the event says so instead of implying that the export dropped those fields. It never includes a raw message, filename, URL or stack. While a remote runtime is active, no events are captured and export returns an explicit skipped result. VS Code and the dedicated mobile app do not mount this capture or expose this dialog.

Server health is sampled at startup and export, not polled continuously. Export includes one current health summary (or explicit unavailable state) plus a timed health event, instead of repeating each status field as its own event. A health response without running/ready fields is invalid, not a successful empty snapshot. OpenCode API probes record their fixed API path, `probeOpenCode` function, HTTP status, response content class and elapsed time; they distinguish timeout from transport failure without copying response bodies. The server keeps a process-local, bounded journal of managed OpenCode lifecycle and health transitions as they occur. The managed child prints its own logs to stderr; the server admits exact known startup, watcher and subprocess messages as fixed categories from spawn. Adjacent watcher subscriptions/starts and subprocess spawns are grouped into ten-second bursts with counts and a span. Unequal watcher counts show the burst's activity; they do not prove that a particular subscription failed to start. Command arguments and directory names never enter the group. Unknown lines of every severity are counted under `Sources`, not turned into unexplained events. It never retains the raw line in the export or the process health snapshot. Export sorts these observations with the journal, UI error buffers and available local file events by timestamp. A missing, filtered or truncated source is reported under `Sources`, never treated as an empty success.

`packages/web/server/lib/diagnostics/local-files.js` owns file reading and fixed-vocabulary classification, including the desktop SSH manager's local in-memory buffer. Web requests to `/api/diagnostics/local-files` require loopback socket access and UI auth; desktop reads via local-page-gated IPC. The SSH manager hands raw lines to the native main process only, which sends classified events to the renderer without host names, command output or credentials. Known file-log messages receive fixed categories, including relay signing/encryption key generation, SSH server reuse failures and OpenCode API proxy failures. New proxy failures carry a fixed method, allowlisted API route template, actual error-handler function, bounded transport class and a vetted message and cause. For example, `fetch failed` may carry `connect ECONNREFUSED [address]`; unknown messages are marked `unavailable`. Unknown routes become `/api/other`; dynamic IDs and query parameters are never included. Historical proxy logs without a reliable route or handler are counted as filtered, not presented as unexplained proxy failures. Failed HTTP access records use the method, allowlisted API route or `/other`, and HTTP status. Identical records from one file are grouped in ten-minute bursts with a count and span, so a stream of 404s does not bury other failures; request IDs, paths outside the allowlist, query parameters and individual response times are dropped. Unknown lines, including warnings/errors, are excluded and counted separately from lines lost to truncation. Classification matches the start of a log message, never a phrase inside its private data. Export validates IPC/HTTP records against that fixed vocabulary again, retains valid entries if another record is malformed, and reports the omitted count. SSH export keeps the latest 8,000 local manager events; older records and excess connections are marked as truncated. File content, filesystem paths, URLs, session IDs, prompts, and raw error messages are not exported. Remote SSH-host and container logs remain outside this local export.

OpenCode's on-disk log directory is shared by processes in the same local user profile and is not read. The managed child's stderr is process-owned; external OpenCode stderr is not, and its log source is explicitly skipped. Both server and managed-child histories retain at most 4,000 combined records or 24 hours, with omitted records marked as truncated. The capture is event-driven, not an additional API poller.
