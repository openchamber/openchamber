# SSH-хосты и проксирование

Используйте **Настройки → Удалённые экземпляры** в десктопном приложении, чтобы импортировать сохранённые SSH-хосты, подключаться к удалённой машине и открывать дополнительные порты через то же SSH-соединение.

> SSH-хосты и SSH-проксирование — это функции **только для десктопа**. Они используют SSH-клиент на вашем компьютере.

## Импортируйте SSH-хост

OpenChamber может читать хосты из вашего локального конфига SSH — того же места, которое используют команды вроде `ssh work-server`.

1. Откройте **Настройки → Удалённые экземпляры**.
2. Выберите хост из раздела **Сохранённые SSH-хосты**.
3. Если хост — это шаблон, введите реальное назначение, например `deploy@app.example.com`.
4. Сохраните и подключитесь.

OpenChamber создаёт удалённый экземпляр с помощью этой команды SSH. Когда он достигнет состояния **готов**, удалённый интерфейс OpenChamber откроется в десктопном приложении.

## Добавьте дополнительные перенаправления портов

У каждого удалённого экземпляра есть раздел **Перенаправления портов**. Используйте его, когда чему-то на одной стороне SSH-соединения нужно добраться до порта на другой стороне.

OpenChamber поддерживает три типа перенаправления:

- **Локальное (-L)** — открывает порт на вашем компьютере, который подключается к чему-то на удалённой машине.
- **Удалённое (-R)** — открывает порт на удалённой машине, который подключается обратно к вашему компьютеру.
- **Динамическое (-D)** — открывает локальный прокси SOCKS через SSH-соединение.

Для большинства предпросмотров приложений и дашбордов, работающих на удалённой машине, используйте **Локальное (-L)**.

## Используйте прокси SOCKS

Выберите **Динамическое (-D)**, когда хотите, чтобы другие инструменты на вашем компьютере выходили в сеть через удалённую машину. OpenChamber открывает локальный порт прокси SOCKS для этого SSH-соединения.

Когда соединение готово, скопируйте или используйте локальный адрес прокси из строки перенаправления. Настройте браузер или инструмент на использование его как прокси SOCKS5.

## Держите доступ приватным

Используйте `127.0.0.1` или `localhost` в качестве локального хоста привязки, если только вы намеренно не хотите, чтобы другие устройства в вашей сети могли добраться до перенаправленного порта.
