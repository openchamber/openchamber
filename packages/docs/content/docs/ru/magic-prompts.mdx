# Волшебные промпты

OpenChamber использует встроенные промпты за кулисами всякий раз, когда что-то делает автоматически — пишет сообщение коммита, готовит черновик PR, разбирает issue, разрешает конфликт, подводит итог сессии. Волшебные промпты — это место, где вы читаете и переписываете эти промпты. Откройте его в **Настройки → Волшебные промпты**.

Для обычной работы эта страница не нужна. Обращайтесь к ней, когда хотите, чтобы какой-то процесс вёл себя иначе — скажем, сообщения коммитов в определённом стиле.

## Редактирование промпта

1. Откройте **Настройки → Волшебные промпты**.
2. Выберите промпт из групп в боковой панели — Git, GitHub, Planning и Session.
3. Отредактируйте текст и сохраните.

У некоторых промптов есть видимая часть (сообщение, которое вы увидите) и часть с инструкциями (скрытые указания для агента). Промпты могут содержать `{{placeholders}}`, которые OpenChamber подставляет, — например, дифф или заголовок issue. Оставляйте их на месте.

## Сброс

Передумали? У каждого промпта есть **reset to default**, а ещё есть **reset all**, если хотите начать заново везде.

## Где используется каждый промпт

Для каждого промпта ниже указано, где он выполняется и какой триггер его запускает. Проверьте триггер перед редактированием, чтобы понимать, какой процесс вы меняете.

### Git

| Промпт | Где выполняется | Когда срабатывает |
| --- | --- | --- |
| Генерация коммита | Кнопка генерации в поле коммита в представлении git и на мобильном экране Changes | Вы генерируете сообщение коммита. Подставляются выбранные файлы и темы недавних коммитов ветки, чтобы тема соответствовала уже принятому в вашем репозитории стилю. |
| Генерация PR | Форма создания pull request на вкладке PR в представлении git | Вы генерируете заголовок и описание PR. Подставляются базовая ветка и ветка с изменениями, коммиты и изменённые файлы между ними, ваш дополнительный контекст и шаблон PR репозитория, если он есть. |
| Разрешение конфликтов слияния/rebase | Диалог конфликтов в представлении git, когда слияние или rebase останавливается на конфликтах | Вы выбираете «Resolve in current session» или «Resolve in new session». Агент читает конфликтующие файлы, предлагает стратегию разрешения для каждого файла и ждёт вашего подтверждения, прежде чем редактировать, индексировать или продолжать операцию. |
| Разрешение конфликтов cherry-pick | Раздел «Re-integrate commits» для сессии в worktree | Перенос коммитов сессии в целевую ветку упирается в конфликт, и вы передаёте его агенту. Агент разрешает конфликт во временном worktree, индексирует разрешённые файлы и продолжает cherry-pick. |

### GitHub

| Промпт | Где выполняется | Когда срабатывает |
| --- | --- | --- |
| Разбор PR | Выбор «Link GitHub PR» в меню вложений в поле ввода и диалог нового worktree | Два триггера. Когда вы прикрепляете PR как контекст, формируются инструкции, которые уходят вместе с вашим следующим сообщением. Когда вы начинаете сессию в worktree из PR, промпт становится первым сообщением этой сессии, а полный контекст PR прикрепляется к нему. |
| Разбор issue | Диалог нового worktree, когда вы создаёте worktree из issue | Первое сообщение новой сессии разбирает issue, а его текст и комментарии прикрепляются как контекст. |
| Неудачные проверки PR / комментарии PR / отдельный комментарий PR | — | Сегодня их не отправляет ни один процесс. Раньше представление PR запускало их действиями разбора в один клик; теперь неудачные проверки и комментарии закрепляются как черновики контекста чата. Они остаются редактируемыми, чтобы уже сделанные изменения продолжали работать. |

### Planning

| Промпт | Где выполняется | Когда срабатывает |
| --- | --- | --- |
| Планирование задачи | Панель задач в боковой панели проекта | Вы отправляете задачу в сессию или в новую сессию в worktree. Текст задачи становится видимым сообщением; инструкции превращают его в диалог планирования, который начинается с вопросов, а не бросается сразу к реализации. |
| Улучшение плана | Действие «Improve» для сохранённого плана в представлении Plans | Вы отправляете сохранённый план в процесс улучшения. Сначала агент читает файл плана, затем предлагает изменения, опираясь на текущее состояние репозитория, и предлагает отредактировать тот же файл. |
| Реализация плана | Действие «Implement» для сохранённого плана | Вы отправляете сохранённый план в процесс реализации. Агент читает файл плана и реализует его от начала до конца, не расширяя объём, а если сам план оказывается неверным, сохраняет правки плана обратно в файл. |

### Session

Большинство из них стоят за слэш-командами, которые вы вводите в поле ввода. Большинство также появляются как стартовые чипы в черновике новой сессии.

| Промпт | Где выполняется | Когда срабатывает |
| --- | --- | --- |
| Тур по кодовой базе | `/explore` | Вы просите общий обзор кодовой базы. |
| Итог сессии | `/summary`, необязательно `/summary <тема>` | Вы подводите итог разговора на текущий момент — полезно, чтобы передать его в новую сессию. Нужна уже существующая сессия. |
| Разбор рабочей области | `/workspace-review` | Вы просите агента разобрать текущий дифф рабочей области на предмет замысла, корректности и безопасности. |
| Планирование функции | `/plan-feature` | Вы превращаете черновую идею функции в план реализации через управляемый диалог вопросов и ответов. |
| Формулирование Goal | `/craft-goal`, необязательно `/craft-goal <идея>` | Вы превращаете идею в проверяемую цель Goal для диалога Goal. |
| Catch up | `/catch-up` | Вы возвращаетесь к проекту и спрашиваете, на чём всё остановилось и за что взяться дальше. |
| Отладка | `/debug` | Вы исследуете баг: агент строит гипотезы, подтверждает корневую причину по коду и только потом предлагает исправление. |
| Взвешивание вариантов | `/weigh` | Вы знаете, что хотите сделать, но не как. Агент сравнивает два-три подхода и рекомендует один. |
| Fusion | Действие «Run fusion» для группы multi-run | Вы объединяете результаты нескольких запусков в один ответ. Результаты запусков добавляются после инструкций. |

### Промпты без страницы в Настройках

Несколько промптов срабатывают автоматически и не имеют редактируемой страницы в Настройках:

| Промпт | Когда срабатывает |
| --- | --- |
| Запланированная задача | `/schedule-task`, необязательно с начальной идеей. Ведёт диалог, который определяет запланированную задачу. |
| Передача на разбор | `/handoff-review` или кнопка Review в представлении диффа с включённой передачей. Формирует передачу в рабочей сессии. |
| Стартовое сообщение сессии разбора | Первое сообщение созданной сессии разбора — с передачей, если она была сформирована, и без неё в остальных случаях. |
| Отзыв о разборе / ответ исполнителя | Переносят сообщения между двумя сессиями: отзыв проверяющего возвращается в сессию-исполнителя, а ответ исполнителя — обратно в сессию разбора. |
