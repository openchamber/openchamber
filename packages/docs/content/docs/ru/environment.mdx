# Переменные окружения

OpenChamber читает эти переменные окружения при запуске. Для служб автозапуска `openchamber startup enable` по умолчанию сохраняет снимок текущего окружения, поэтому запустите её заново после изменения переменных, которые должна использовать служба.

## Сервер OpenChamber

### `OPENCHAMBER_HOST`

Адрес привязки для веб-сервера OpenChamber. Используйте `0.0.0.0`, чтобы разрешить доступ с других машин.

### `OPENCHAMBER_UI_PASSWORD`

Пароль для интерфейса в браузере. Используйте его при привязке вне localhost, работе через туннели или за обратным прокси.

### `OPENCHAMBER_API_ONLY`

Запускает OpenChamber в headless-режиме, если задано `true` или `1`. Маршруты API остаются доступными для десктопных и мобильных клиентов, но интерфейс в браузере не отдаётся.

### `OPENCHAMBER_DATA_DIR`

Переопределяет папку данных OpenChamber. По умолчанию — `~/.config/openchamber`.

Всё, что хранит OpenChamber, лежит в этой папке: настройки, аутентификация, конфигурации проектов, темы, планы и модели распознавания речи. Экземпляр, который использовал собственную папку до версии 1.23, при первом запуске получает свои папки `projects`, `themes` и `speech-models`, скопированные из `~/.config/openchamber`; оригиналы остаются на месте, и ничего не объединяется.

### `OPENCHAMBER_CHATS_DIR`

Перемещает управляемые папки чатов, которые OpenChamber создаёт для чатов без проекта. По умолчанию — `~/.config/openchamber/chats`. Укажите папку, которую может читать сервер OpenCode, когда OpenChamber и OpenCode работают под разными пользователями. Существующие чаты не перемещаются.

### `OPENCHAMBER_COMPRESS_API`

Управляет сжатием ответов API. Используйте `true` или `1`, чтобы принудительно включить его, `false` или `0` — чтобы принудительно отключить.

### `OPENCHAMBER_SKIP_API_COMPRESSION`

Отключает сжатие ответов API, если задано `true` или `1`. Имеет приоритет над `OPENCHAMBER_COMPRESS_API`.

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

Включает подробные логи HTTP-запросов, если задано `true` или `1`.

### `OPENCHAMBER_UPDATE_API_URL`

Переопределяет конечную точку API для проверки обновлений. Большинству пользователей её задавать не нужно.

### `OPENCHAMBER_PACKAGE_MANAGER`

Принудительно задаёт менеджер пакетов, используемый операциями обновления, когда автоопределение ошибается.

## Сервер OpenCode

### `OPENCODE_HOST`

Подключает OpenChamber к уже запущенному серверу OpenCode. Значение должно быть origin `http` или `https` с явным портом и без пути, строки запроса или фрагмента. `OPENCODE_HOST` имеет приоритет над `OPENCODE_PORT`.

### `OPENCODE_PORT`

Задаёт порт сервера OpenCode. С управляемым OpenCode это запрашиваемый управляемый порт; при `OPENCODE_SKIP_START=true` он подключается к внешнему серверу на этом порту.

### `OPENCODE_SKIP_START`

Не даёт OpenChamber запускать собственный сервер OpenCode, если задано `true`.

### `OPENCHAMBER_OPENCODE_HOSTNAME`

Имя хоста для привязки сервера OpenCode, управляемого OpenChamber. По умолчанию — `127.0.0.1`.

### `OPENCODE_BINARY`

Путь к исполняемому файлу `opencode`, который должен запускать OpenChamber.

### `OPENCODE_CONFIG`

Путь к конкретному файлу конфигурации OpenCode.

### `OPENCODE_CONFIG_DIR`

Путь к конкретной папке конфигурации OpenCode для агентов, навыков, сниппетов и поиска конфигурации.

### `OPENCODE_DATA_DIR`

Собственная папка данных для управляемого сервера OpenCode.

### `OPENCODE_WSL_DISTRO`

Выбирает дистрибутив WSL, используемый для интеграции OpenCode в Windows.

### `OPENCHAMBER_OPENCODE_WSL_DISTRO`

Псевдоним, специфичный для OpenChamber, для выбора дистрибутива WSL. Когда заданы обе переменные, приоритет у `OPENCODE_WSL_DISTRO`.

### `OPENCODE_JWT_SECRET`

Секрет, используемый для подписи токенов аутентификации интерфейса. Для постоянно работающих служб используйте длинное случайное значение.

## Терминал и Git

### `OPENCHAMBER_TERMINAL_SHELL`

Исполняемый файл оболочки, используемый для сессий терминала OpenChamber.

### `OPENCHAMBER_GIT_BINARY`

Исполняемый файл Git, используемый функциями Git в OpenChamber.

### `GIT_BINARY`

Альтернативное переопределение исполняемого файла Git. Для конфигурации, специфичной для OpenChamber, предпочитайте `OPENCHAMBER_GIT_BINARY`.

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

Время жизни (TTL) в миллисекундах для кэшированного чтения файлов из Git. Задайте `0`, чтобы отключить этот кэш при отладке.

## Голос и туннели

### `OPENAI_API_KEY`

API-ключ, используемый голосовыми функциями OpenChamber, которые обращаются к сервисам, совместимым с OpenAI.

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Разрешает удалённые базовые URL, совместимые с OpenAI, для голосовых функций, если задано `true` или `1`.

### `NGROK_AUTHTOKEN`

Токен аутентификации ngrok, используемый командами туннеля OpenChamber. Также можно настроить ngrok с помощью `ngrok config add-authtoken <token>`.

## Вспомогательные компоненты среды выполнения

### `BUN_BINARY`

Исполняемый файл Bun, который OpenChamber должна использовать при запуске процессов-демонов.

### `BUN_INSTALL`

Корень установки Bun. OpenChamber использует его, чтобы найти `bin/bun` для запуска демона и обновлений.

### `VITE_OPENCODE_URL`

Базовый URL API на этапе сборки для веб-приложения, собранного Vite. Большинству пользователей не нужно задавать его при обычном использовании CLI или десктопа.
