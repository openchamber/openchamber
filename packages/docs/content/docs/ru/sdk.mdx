# Создание расширения

Используйте `@openchamber/sdk`, чтобы добавить свою панель в OpenChamber. Расширение — это небольшая веб-страница, которую OpenChamber показывает на правой рейке. С приложением она общается через `connectHost()`: может читать текущий проект и сессию, показывать всплывающие уведомления, вставлять текст в поле чата, прикреплять задачу к сессии, а с одобрения пользователя — запускать сессии и отправлять промпты.

Расширения работают в OpenChamber для веба и десктопа. VS Code и мобильное приложение пока их не загружают.

## Что такое расширение

Папка с тремя файлами:

- `package.json` с блоком `openchamber` (манифест)
- `panel/index.html` — страница, которую показывает OpenChamber
- `panel/main.js` — ваш скрипт, собранный в один классический файл (IIFE, а не ES-модуль, потому что страница загружается в изолированном iframe)

OpenChamber никогда не компилирует ваш код. Поставляйте уже собранный файл `.js`. В SDK есть команда сборки; подойдёт и любой другой сборщик, который выдаёт IIFE.

```bash
npm install @openchamber/sdk
bunx openchamber-guest-bundle panel/main.ts panel/main.js
```

Команда сборки работает на Bun. Без Bun используйте esbuild или другой сборщик с `--format=iife --platform=browser`.

Полностью рабочее расширение, все три файла, есть на странице [Пример](/ru/sdk/example/). Скопируйте его и измените API и список.

Подключите `main.js` в `index.html` обычным `<script src="main.js"></script>`.

## Установите расширение во время работы

1. Запустите OpenChamber в вебе или на десктопе.
2. Откройте Настройки → Расширения.
3. Вставьте абсолютный путь к своей папке и нажмите Добавить.

OpenChamber читает манифест и показывает диалог со списком того, что запрашивает расширение (см. [возможности](#возможности)). Одобрите его, и ваш значок появится на рейке. Нажмите на него, и ваша страница загрузится.

Можно также добавить локальный `.zip` или https-ссылку на git-репозиторий либо zip-файл. Обновляться умеет только установка из git: поднимите `version` в `package.json` и запушьте, и OpenChamber предложит обновление, когда пользователь в следующий раз откроет Настройки → Расширения. `#tag` или `#branch` в URL закрепляет, за чем именно оно следит. Их копируют в папку данных OpenChamber и запускают из этой копии, поэтому поставляйте собранные файлы, а не `node_modules` или исходники TypeScript. Удаление расширения удаляет копию. Установка из папки работает прямо из вашей папки, так что можно редактировать, пересобирать и перезагружать.

## Манифест

```json
{
  "name": "@acme/hello",
  "version": "1.0.0",
  "openchamber": {
    "apiVersion": 1,
    "engines": { "openchamber": ">=1.24.0" },
    "contributes": {
      "panel": {
        "id": "acme-hello",
        "name": "Hello",
        "icon": "window",
        "entry": "panel/index.html"
      },
      "attach": "dialog",
      "page": true,
      "capabilities": ["prompt", "sessions"],
      "integration": {
        "name": "Acme",
        "description": "Tasks from Acme",
        "token": {
          "apiOrigin": "https://api.acme.example",
          "account": { "path": "/me", "name": "login" },
          "scheme": "bearer"
        },
        "settings": [{ "id": "list-id", "label": "List ID" }]
      }
    }
  }
}
```

`version` обязательна и должна быть в формате semver. Настройки → Расширения показывает её на карточке.

`apiVersion` равен `1`. Любое другое значение OpenChamber отклоняет.

`engines.openchamber` необязателен. Укажите самую старую версию OpenChamber, с которой работает ваше расширение, например `1.24.0` или `>=1.24.0`. Более старые сборки откажутся его устанавливать, вместо того чтобы сломаться позже.

`contributes.panel` описывает пункт на рейке. `id` пишется в kebab-case и должен быть уникальным среди установленных расширений. `icon` — это имя иконки Remixicon (`RiWindowLine` превращается в `window`) или SVG-файл в вашей папке, например `icon.svg`. `entry` — HTML-файл в вашей папке; пропустите его для расширения, которое объявляет только `tools` (см. [Ваши инструменты в чате](#ваши-инструменты-в-чате)).

`contributes.attach` необязателен. Он добавляет ваше расширение в меню + рядом с полем чата, чтобы пользователь мог выбрать задачу и прикрепить её к сессии.

- `"dialog"` открывает вашу страницу в окне
- `true` или `"panel"` вместо этого открывает панель на рейке
- `{ "mode": "dialog", "entry": "panel/attach.html" }` открывает в окне отдельную вашу страницу, так что выбору не нужно делить код с панелью на рейке
- если не указывать его, расширение не появится в этом меню

Ваша страница может узнать, где она находится, из `ctx.surface`: `panel`, `dialog`, `page` или `status`. Когда пользователь нажимает на прикреплённый элемент, его `data` возвращаются в `ctx.item`. При открытии с рейки, из меню + или из меню полноэкранных страниц запуск происходит без элемента.

`contributes.page: true` делает вашу панель доступной на весь экран из меню «Страницы расширения» над списком сессий. Используйте `{ "entry": "panel/page.html", "title": "Board" }` для отдельного HTML и необязательного заголовка. Поставляйте этот HTML и его собранные скрипты. Странице нужен `panel.entry`, она использует ту же песочницу и разрешения и открывается только когда пользователь её выбирает. Перезагрузка, пауза, удаление или переключение сервера закрывают её.

Для доски используйте `host.storage` для постоянного JSON и методы проектов, worktree и сессий для общих данных приложения. `startSession` может работать с другим проектом или worktree, не закрывая доску. О подписках, живых состояниях и частичных результатах создания см. [Host API](/ru/sdk/host/).

`contributes.integration` необязателен. Он добавляет карточку в Настройки → Интеграции, где пользователь подключает аккаунт. См. [Аккаунты и сеть](#аккаунты-и-сеть).

`contributes.service` необязателен. Он объявляет локальный процесс, который OpenChamber запускает рядом с расширением, для того, до чего веб-страница не дотянется, например сокета Docker. Этот процесс работает с полным доступом пользователя и без песочницы, поэтому диалог одобрения предупреждает о нём; объявляйте его только тогда, когда страница не справляется с задачей. См. файл пакета `GUEST_SERVICES.md`. Сервис с `provides: ["browser"]` может также заменить браузер агента: он отвечает на действия `browser.*` на сервере, так что агенты работают в вебе без открытого десктопного приложения, а пользователь выбирает его в разделе Настройки → OpenChamber Tools. Такому сервису панель не нужна.

## Возможности

Чтобы нарисовать панель и прочитать текущую сессию, разрешение не нужно. Оно нужно для всего, что действует от имени пользователя. Перечислите их в `contributes.capabilities`:

| Возможность | Что она позволяет |
| --- | --- |
| `prompt` | отправлять сообщения в сессию пользователя (`prompt({ send: true })`, `startSession` с `text`) |
| `sessions` | просматривать проекты, worktree и состояния сессий; создавать и открывать сессии во всех зарегистрированных проектах |
| `files` | читать и записывать файлы внутри открытого проекта (`readFile`, `writeFile`, `listDir`, `stat` с относительным путём) |
| `model` | разовая генерация текста с помощью малой модели пользователя (`generate`), вне любой сессии |

Ещё четыре добавляются автоматически: `network`, когда вы объявляете `integration`, `service`, когда объявляете `service`, `filesystem`, когда объявляете шаблоны `filesystem`, и `conversation`, когда действие сессии запрашивает сообщения (см. [Действия, команды и счётчик](#действия-команды-и-счётчик)).

Пользователь видит полный список один раз, при установке расширения, и либо одобряет его, либо удаляет расширение. Если новая версия просит больше, диалог появляется снова. Вызов, которому нужна не одобренная пользователем возможность, завершается ошибкой `NOT_GRANTED`.

## Генерация текста

С возможностью `model` `host.generate` просит малую модель пользователя дать разовый ответ: резюме, заголовок, черновик. Ничего не попадает в сессию, история не сохраняется, и расширение никогда не выбирает провайдера. OpenChamber использует ту же модель, что и для своей фоновой работы, выбранную в разделе Настройки → Сессии → Малая модель или подобранную автоматически среди провайдеров, в которые вошёл пользователь.

```ts
const { text } = await host.generate({
  prompt: task.description,
  system: "Write a one-line summary. Return only the summary.",
  maxOutputTokens: 200,
});
```

Когда модель недоступна, вызов завершается ошибкой `NO_MODEL`; модель, которая вернула ошибку, — `MODEL_FAILED`. Промпты ограничены 64 000 символов, а вызов ждёт до 90 секунд. Пользователь видит это разрешение как «Использовать вашу малую модель», и оно расходует его токены, поэтому держите промпты короткими и вызывайте его по клику, а не при каждом нажатии клавиши.

## Аккаунты и сеть

Ваша страница работает в песочнице и не может обращаться в интернет напрямую. Объявите `integration`, и OpenChamber будет делать запросы за вас через `host.request`, прикрепляя токен пользователя. Токен никогда не попадает на вашу страницу.

- `token`: пользователь вставляет API-токен на карточке в разделе Настройки → Интеграции. `apiOrigin` — единственный источник, который может вызывать `request`. `account` необязателен: GET-путь и имя поля, чтобы карточка могла показать, кто подключён. `scheme` указывает, как отправляется токен; см. таблицу ниже. Проверьте в документации API провайдера, какой заголовок он ожидает.
- `oauth`: пользователь вставляет client id, и OpenChamber проводит авторизацию. Нужны `authorizeUrl`, `tokenUrl` и `apiOrigin`.
- `host: { "provider": "linear" }`: использовать аккаунт Linear, уже подключённый в OpenChamber. Client id не нужен.

Что отправляет каждый `scheme`:

| `scheme` | Заголовок, который отправляет OpenChamber | Когда его использовать |
| --- | --- | --- |
| не указан | `Authorization: <token>` | API документирует токен без префикса в заголовке |
| `"bearer"` | `Authorization: Bearer <token>` | API документирует bearer или personal access token |
| `"basic"` | `Authorization: Basic base64(username:token)` | API документирует HTTP Basic auth с именем пользователя (часто это email) и API-токеном; карточка запрашивает оба, а `usernameLabel` задаёт подпись первого поля |

`settings` добавляет на карточку простые текстовые поля. Их значения приходят в `ctx.settings`.

## Файлы

Ваша страница не может трогать диск сама. OpenChamber читает и пишет за неё, в пределах, которые одобрил пользователь.

- Относительный путь (`README.md`, `src/index.ts`, `.`) означает открытый проект. Нужна возможность `files`. Если открытого проекта нет — `NO_DIRECTORY`.
- Путь, начинающийся с `/` или `~/`, означает любое другое место. Он должен совпадать с одним из шаблонов, которые вы объявляете в `contributes.filesystem`, и пользователь видит эти самые шаблоны в диалоге одобрения:

```json
"filesystem": ["~/.config/opencode/opencode.json", "~/notes/**"]
```

В шаблонах `*` означает один сегмент пути, а `**` — любую глубину. Всё, что вне них, — `BAD_PATH`, даже после одобрения. `..` не допускается никогда.

```ts
const config = await host.readFile("~/.config/opencode/opencode.json");
await host.writeFile("~/.config/opencode/opencode.json", nextJson);
const { entries } = await host.listDir(".");
```

Запись атомарна: OpenChamber пишет временный файл и переименовывает его, так что читатель никогда не увидит наполовину записанный файл. Файлы читаются и записываются как текст UTF-8, размером до 2 МБ.

## Раздел в панели «Статус работы»

`contributes.statusSection` добавляет ваш собственный раздел в панель «Статус работы» рядом с чатом. Пользователи включают и отключают его и перемещают в списке разделов этой панели, как и встроенные разделы.

```json
"statusSection": { "entry": "status/index.html", "title": "Recent commits", "height": 160 }
```

- `true` использует `panel.entry`.
- `entry` — отдельная HTML-страница в вашей папке. С ней `panel.entry` не нужен, так что расширение может состоять только из этого раздела, без значка на рейке.
- `title` заменяет название панели в заголовке раздела, до 60 символов.
- `height` — начальная высота в пикселях, от 24 до 320 (по умолчанию 120). Вызывайте [`host.setHeight()`](/ru/sdk/host/), когда размер содержимого меняется.

Ваша страница видит `ctx.surface` как `status`. OpenChamber загружает её только пока панель «Статус работы» видна и ваш раздел развёрнут, и выгружает, когда пользователь сворачивает раздел, поэтому не держите там ничего, что не сможете восстановить. Расширение только с разделом может использовать возможности, сервис, интеграцию и файлы, но не `page`, `attach`, `actions` или `commands`. Только веб и десктоп. Пример `git-graph-status` — это готовый раздел.

## Редактор для вашего типа файлов

`contributes.fileEditors` открывает файлы на вашей странице вместо текстового редактора. Когда пользователь открывает подходящий файл в разделе «Файлы», OpenChamber показывает там ваш редактор — с тем же переключателем исходного кода, кнопкой полноэкранного режима и кнопкой сохранения, что и у встроенных просмотрщиков.

```json
"fileEditors": [
  { "id": "canvas", "title": "Excalidraw", "match": ["*.excalidraw", "*.excalidraw.md"], "entry": "editor/index.html" }
]
```

- `match` сравнивает только имена файлов, без учёта регистра. `*` совпадает с любой последовательностью символов, а `?` — с одним. Шаблон не может содержать `/` и не может состоять только из подстановочных символов.
- `entry` — HTML-страница в вашей папке. `panel.entry` не нужен, так что расширение может состоять только из редактора, без значка на рейке.
- `content` — это `"text"` (по умолчанию) или `"binary"`, см. ниже.
- До 8 редакторов на расширение, до 16 шаблонов в каждом.

Файлом управляет OpenChamber. Ваша страница никогда не читает и не записывает его и не нуждается для этого в возможности. OpenChamber передаёт вам текст, запрашивает изменённый текст при сохранении и сам обрабатывает Cmd/Ctrl+S, автосохранение, запрос о несохранённых изменениях, окончания строк и изменения, сделанные на диске:

```ts
import { connectHost, createFileSaveTracker } from "@openchamber/sdk";

const host = connectHost();
let tracker = createFileSaveTracker(null);

host.onFileOpen((file) => {
  if (file.encoding !== "text") return; // a text editor always gets text
  load(file.content); // file.path, file.name, file.readOnly too
  tracker = createFileSaveTracker(versionOf(currentText()));
});

// Call this after every edit. `edited` holds autosave back until the user stops.
const changed = () => host.reportFileChange(tracker.observe(versionOf(currentText())));

host.onFileSnapshot(() => ({ content: currentText(), version: versionOf(currentText()) }));

// Edits made while OpenChamber was writing keep the file unsaved.
host.onFileSaved((version) => host.reportFileChange({ dirty: tracker.markSaved(version), edited: false }));
```

`version` — любая короткая строка, которая меняется вместе с документом, например хеш. Если файл не из тех, что может открыть ваш редактор, вызовите `host.reportFileUnsupported()`, и OpenChamber покажет его исходный код с уведомлением. Файлы больше 20 МБ остаются в режиме исходного кода.

### Бинарные файлы

Укажите `"content": "binary"`, чтобы открывать файлы, которые не являются текстом, например таблицы, документы или изображения. Ваш редактор получает байты файла и возвращает байты; всё остальное работает так же.

```ts
host.onFileOpen((file) => {
  if (file.encoding !== "binary") return;
  open(file.bytes); // a Uint8Array, exactly as on disk
});

host.onFileSnapshot(() => ({ bytes: currentBytes(), version: versionOf(currentBytes()) }));
```

Бинарный редактор может взять любой файл, совпадающий с его шаблонами, включая те, которые OpenChamber показывает сам, например изображения и PDF. У него нет режима исходного кода, а когда пользователь переводит его в полноэкранный режим или выходит из него с несохранёнными изменениями, OpenChamber сначала сохраняет их. Читать и записывать формат должен ваш редактор: OpenChamber записывает ровно те байты, которые вы вернули.

Ваша страница видит `ctx.surface` как `file`. OpenChamber перезагружает её, снова передавая файл, когда файл меняется на диске, пользователь отменяет изменения или редактор переходит в полноэкранный режим либо выходит из него. Побеждает первое включённое расширение, чей шаблон совпал, — раньше собственных просмотрщиков OpenChamber. Расширение только с редактором может использовать возможности, сервис, интеграцию и файлы, но не `page`, `attach`, `actions` или `commands`. Только веб и десктоп. Пример `checklist-editor` — это готовый редактор.

## Действия, команды и счётчик

Кроме рейки и меню +, расширение может появляться ещё в трёх местах. Все они передают расширению `item` так же, как это делает нажатие на плашку.

**Действия для сообщений и сессий.** Объявите пункты меню, и OpenChamber покажет их рядом со встроенными:

```json
"actions": [
  { "id": "create-task", "label": "Create task", "icon": "add-line", "where": "message", "roles": ["assistant"] },
  { "id": "summarize", "label": "Summarize session", "where": "session", "payload": ["messages"] }
]
```

Действие для сообщения открывает ваше расширение с `ctx.item` вида `kind: "message"`: id и название сессии, папка проекта, id сообщения, его роль и текст. Действие для сессии открывает его с `kind: "session"` и id, названием и папкой сессии. Добавьте `"payload": ["messages"]`, и элемент также несёт всю переписку, от самого старого сообщения, — тот же текст, что даёт экспорт в Markdown. Для этого нужна возможность `conversation`, которую пользователь видит отдельной строкой в диалоге одобрения. `item.action` подсказывает, по какому пункту нажали.

**Слэш-команды, которые прикрепляют.** Объявите команду и обработайте её на странице:

```json
"commands": [{ "name": "task", "description": "Attach a task by id" }]
```

```ts
host.onResolve(async ({ command, args }) => {
  const task = await findTask(args.trim());
  return task ? { providerId: "acme-tasks", id: task.id, title: task.title, url: task.url } : null;
});
```

Когда пользователь вводит `/task ABC-12` в поле чата, OpenChamber просит ваше расширение разобрать её и прикрепляет то, что вы вернули, как плашку, ничего не открывая. Верните `null`, если ничего не найдено. Если ваша панель закрыта, OpenChamber загружает её в фоне для этого вызова. Имя, которое уже использует OpenChamber или OpenCode, игнорируется.

**Счётчик на значке в рейке.** `host.setBadge(3)` показывает число на вашем значке, например количество открытых задач; `host.setBadge(null)` убирает его. Открытие панели тоже его убирает.

## Ваши инструменты в чате

Когда ваш плагин OpenCode или MCP-сервер добавляет инструмент, чат показывает его вызовы с типовой иконкой и сырым выводом. Вместо этого опишите, как они должны выглядеть, без единой строки кода:

```json
"tools": [
  {
    "match": "mcp.jira.*",
    "name": "Jira",
    "icon": "task-line",
    "title": "{input.key}",
    "subtitle": "{output.status}",
    "output": "table",
    "columns": ["key", "summary", "status"]
  }
]
```

`match` — это имя инструмента так, как его сообщает OpenCode; `*` в конце совпадает с префиксом. `icon` — имя иконки Remixicon или `.svg`-файл в вашем пакете, как и `panel.icon`. `title` и `subtitle` — шаблоны над `input`, `output` и `metadata` вызова. `output` определяет, как отрисовывается тело: `text`, `json` (дерево), `markdown`, `code` с `language`, `table` с `columns` (строки берутся из массива вывода или из `output.items`) или `auto` для значения по умолчанию. Точный `match` побеждает шаблон с `*`, а при равенстве выигрывает первое установленное расширение. Разрешение не нужно: это меняет только то, как отрисовываются данные, уже находящиеся в чате.

Расширению, которое только оформляет инструменты, страница вообще не нужна: пропустите `panel.entry`, и у него не будет значка на рейке, только карточка в разделе Настройки → Расширения. Без страницы оно может объявлять `tools` и больше ничего. Другое исключение — раздел «Статус работы» или редактор файлов с собственным `entry`, см. выше.

## Первые строки в панели

```ts
import { connectHost } from "@openchamber/sdk";

const host = connectHost();

host.onReady((ctx) => {
  document.body.dataset.theme = ctx.theme.mode;
  document.body.dataset.surface = ctx.surface;
});
```

`connectHost` работает только внутри OpenChamber. Если открыть страницу как обычный файл, каждый вызов отклоняется с `HOST_UNAVAILABLE`.

Сначала собирайте панель из готовых блоков `@openchamber/sdk/ui`: кнопки, поля, выпадающие списки, вкладки, списки и многое другое, оформленные цветами и шрифтами приложения, чтобы панель ощущалась частью OpenChamber. Собственный HTML и CSS пишите только для того, чего в наборе нет. См. [UI-набор](/ru/sdk/ui/).
