# Разрешения и предохранитель

Каждое действие агента (запуск команды, редактирование файла, вызов инструмента MCP, загрузка страницы) сначала проходит через правила разрешений агента. Режимы разрешений OpenChamber решают, что происходит, когда правило говорит «ask».

## Allow, ask и deny

Правила разрешений живут в OpenCode. Каждое правило даёт действию один из трёх результатов:

- **allow:** агент действует дальше
- **deny:** действие заблокировано
- **ask:** агент останавливается и ждёт ответа

По умолчанию большинство действий разрешено. OpenCode спрашивает только перед тем, как агент затронет папки вне проекта или прочитает файлы `.env`. Добавьте свои правила, чтобы, например, спрашивать перед любой командой оболочки. Формат правил описан в [документации OpenCode о разрешениях](https://opencode.ai/v2/docs/permissions/), а посмотреть разрешения агента в OpenChamber можно в **Настройки → Агенты**.

Режимы разрешений меняют только то, кто отвечает на «ask». Они никогда не снимают «deny», а «allow» вообще не спрашивает.

## Три режима

| Режим | Кто отвечает на «ask» |
| --- | --- |
| **Спрашивать каждый раз** | Вы. Каждый запрос ждёт вашего ответа. |
| **Предохранитель** | Jev пропускает обычные действия, а рискованные оставляет вам. |
| **Принимать всё** | OpenChamber, всегда «да». Каждый запрос разрешается сразу, без проверок. |

**Принимать всё** не требует ничего дополнительного: этот режим просто считает каждое «ask» разрешённым. Включайте его, когда доверяете задаче и не хотите, чтобы вас прерывали.

## Как переключать режимы

- **Для одной сессии:** нажмите кнопку со щитом в поле ввода. Каждое нажатие переключает на следующий режим.
- **Для новых сессий:** выберите режим по умолчанию в **Настройки → Сессии → Разрешения**. Существующие сессии сохраняют свой режим.

Субагенты наследуют режим сессии, которая их запустила.

## Предохранитель

В этом режиме OpenChamber спрашивает [Jev](/ru/classification-providers/) о каждом запросе: это обычное действие или решать должны вы? Чтение, сборка, запуск тестов, редактирование файлов проекта и обычные коммиты проходят. Переписывание истории git, удаление данных, изменение системы, развёртывание, публикация где-либо или отправка файлов наружу ждут вас, как и всё неясное.

Придержанный запрос показывает обычную карточку разрешения с одной дополнительной строкой — **Предохранитель придержал это действие, чтобы вы решили сами** — и указанием типа действия. Если Jev не ответит за четыре секунды, действие тоже ждёт вас. Предохранитель никогда не разрешает действие только потому, что проверка не удалась.

Предохранителю нужен [провайдер классификации](/ru/classification-providers/). Без него кнопка со щитом этот режим пропускает, а в настройках он отключён.

## Работает, даже когда вас нет

Режим живёт на сервере OpenChamber, поэтому он продолжает отвечать на запросы после того, как вы закрыли вкладку или заблокировали телефон, и переживает перезапуски.

> В VS Code предохранителя нет. Расширение предлагает только «Спрашивать каждый раз» и «Принимать всё» и отвечает на запросы только пока открыта панель OpenChamber.
