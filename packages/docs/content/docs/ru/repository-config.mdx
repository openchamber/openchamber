# Конфигурация репозитория

Действия проекта, команды настройки worktree и стартеры черновиков по умолчанию живут в ваших собственных настройках OpenChamber. Больше никто их не видит. Если вы хотите, чтобы коллега, который клонирует репозиторий, получил то же действие для dev-сервера и тот же `bun install` в каждом новом worktree, перенесите эти элементы в репозиторий.

OpenChamber хранит их в `.openchamber/project.json` в корне репозитория. Файл появляется только тогда, когда вы переносите туда первый элемент, и исчезает, когда вы переносите последний обратно. Коммитьте его как любой другой файл.

## Что где лежит

| Остаётся в ваших настройках | Можно перенести в репозиторий |
|---|---|
| Заметки и задачи | Действия проекта |
| Запланированные задачи | Команды настройки worktree |
| Какие действия из репозитория скрыты для вас | Стартеры черновиков (закреплённые команды и навыки) |
| Ваш ответ о доверии к командам из репозитория | Планы |

Заметки, задачи и запланированные задачи принадлежат вам. Они никогда не попадают в репозиторий.

## Перенос элемента

Откройте **Настройки → Проекты** и выберите проект. У каждого действия и команды настройки есть кнопка **Переместить в репозиторий**, а у каждого элемента из репозитория — **Переместить в мои настройки**. Стартеры на экране новой сессии показывают ту же пару при наведении. У планов она есть в каждой строке вкладки «Планы».

Перенос — это именно перенос. Элемент покидает одно место и оказывается в другом, так что ничего не дублируется.

Элементы из репозитория показывают метку **В репозитории**. Действия из репозитория также можно скрыть из своего меню кнопкой **Скрыть для меня**. Это меняет только ваше меню, а не файл.

## Файл

```json
{
  "version": 1,
  "setupWorktree": [
    "bun install"
  ],
  "setupWorktreeWait": true,
  "projectActions": [
    {
      "id": "dev",
      "name": "Dev server",
      "command": "bun run dev",
      "icon": "rocket",
      "autoOpenUrl": true,
      "platforms": ["macos", "linux"]
    },
    {
      "id": "test",
      "name": "Tests",
      "command": "bun test"
    }
  ],
  "draftStarters": [
    { "type": "skill", "name": "triage-prs" }
  ],
  "plansDir": "docs/plans"
}
```

Обязателен только `version`. Все остальные ключи необязательны, и OpenChamber записывает только те ключи, которые что-то содержат.

`setupWorktree` — это список shell-команд, которые OpenChamber выполняет внутри нового worktree сразу после его создания, по порядку. Используйте `$ROOT_PROJECT_PATH` для пути к основному checkout. `setupWorktreeWait: true` заставляет OpenChamber дождаться этих команд, прежде чем запускать сессию в worktree.

`projectActions` — это список действий в меню заголовка. `id`, `name` и `command` обязательны. `icon` необязательна и по умолчанию берёт значок play; OpenChamber знает такие имена: `play`, `build`, `lint`, `terminal`, `tools`, `bug`, `flask`, `rocket`, `code`, `server`, `branch`, `search`, `settings`, `brain`, `stack`, `robot`, `command` и `file`. `autoOpenUrl: true` открывает адрес, который выводит команда, см. [Preview и dev-серверы](/ru/preview/). `platforms` ограничивает действие значениями `macos`, `linux` или `windows`. `runIn: "parent"` выполняет действие в основном checkout, а не в текущем worktree.

`draftStarters` закрепляет команды и навыки на экране новой сессии. Каждая запись имеет вид `{ "type": "command" | "skill", "name": "..." }`, а сама команда или навык должны существовать в конфиге OpenCode этого репозитория.

`plansDir` — где лежат планы репозитория. Пропустите его, чтобы использовать `.openchamber/plans`. См. ниже.

Вы можете писать этот файл вручную. Ключ неправильной формы делает весь файл недействительным, и страница «Проекты» говорит, почему, вместо того чтобы молча его игнорировать.

## Как сочетаются элементы из репозитория и личные

Команды настройки из репозитория выполняются первыми, затем ваши. Отметьте **Использовать только мои команды настройки** в разделе Worktree, чтобы вообще пропустить команды из репозитория.

Действия объединяются по `id`. Действие в ваших настройках с тем же id, что и действие из репозитория, заменяет его. Стартеры объединяются по имени.

Флаг ожидания берётся из ваших настроек, если вы его задали, иначе из репозитория.

## Доверие

Команды настройки и действия из репозитория выполняются на вашей машине, и `git pull` может их изменить. Поэтому в первый раз, когда одно из них вот-вот выполнится, OpenChamber показывает точные команды и спрашивает. **Доверять и запустить** запоминает ваш ответ на этом экземпляре. **Не в этот раз** выполняет только ваши собственные команды.

Ответ привязан к самим командам. Когда pull меняет команду из репозитория, вопрос возвращается для нового текста. Забыть ответ можно с помощью **сбросить доверие** в разделе Worktree в настройках проекта.

Перенос своей команды в репозиторий считается доверием к ней, ведь вы только что её видели.

## Планы в репозитории

Планы на вкладке «Планы» тоже могут жить в репозитории, в виде файлов Markdown. По умолчанию это папка `.openchamber/plans`. Задайте **Папка планов** в настройках проекта, чтобы использовать другую папку внутри репозитория, например `docs/plans`, если ваша команда уже хранит планы там. Своя папка полностью заменяет папку по умолчанию: OpenChamber читает и пишет только в неё, поэтому при её изменении перенесите существующие файлы сами.

Каждый файл `.md` в этой папке появляется на вкладке «Планы», включая файлы, написанные другими инструментами. Редактирование в OpenChamber сохраняет файл так, как вы его набрали. План, перенесённый в репозиторий, сохраняет свою идентичность, поэтому сессии, к которым он был прикреплён, по-прежнему его находят.
