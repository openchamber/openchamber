# Запланированные задачи

Запланированная задача запускает промпт за вас по расписанию — например, ежедневное «подведи итог вчерашних изменений» или еженедельную уборку. Когда она срабатывает, OpenChamber создаёт новую сессию и отправляет промпт самостоятельно. Откройте планировщик кнопкой вверху боковой панели сессий.

## Создание задачи

1. Откройте диалог запланированных задач из боковой панели сессий.
2. Добавьте задачу и дайте ей имя.
3. Выберите, когда она запускается:
   - **daily** — в одно или несколько времён каждый день
   - **weekly** — в выбранные дни недели и время
   - **once** — одна дата и время
   - **cron** — произвольное cron-выражение
4. Задайте, что она делает: промпт для отправки, а также провайдера, модель и агента. Промпт может быть слэш-командой, например `/review`.
5. Сохраните и убедитесь, что задача включена.

Любую задачу можно запустить сразу кнопкой **Запустить сейчас**, чтобы проверить, что она делает то, что вы ожидаете.

Отметьте **Выполнить как цель**, чтобы запуск доводил свой промпт до завершения, а не останавливался после одного ответа — см. [Цели сессии](/ru/session-goals/).

## Циклы: запланированные задачи как markdown-файлы

**Цикл** — это запланированная задача, определённая как переносимый markdown-файл, который можно закоммитить в свой репозиторий. Положите файл в `.agents/loops/` и откройте список запланированных задач, чтобы синхронизировать его — перезапуск сервера не нужен:

```markdown
---
name: daily-digest
schedule: "0 9 * * *"
enabled: true
model: anthropic/claude-sonnet-4-5
agent: plan
timezone: Europe/Kyiv
---
Summarize repository changes since yesterday and post the digest.
```

### Где живут файлы

- **Область проекта** — `.agents/loops/*.md` в папке проекта или в любой родительской папке вплоть до корня git worktree.
- **Область пользователя** — `~/.agents/loops/*.md` применяется ко всем проектам, которые вы открываете.

Если цикл проекта и цикл пользователя носят одно имя, побеждает цикл проекта.

### Поля

| Поле | Значение |
|---|---|
| `name` | Имя задачи (обязательно, максимум 80 символов). |
| `schedule` | Cron-выражение (обязательно) — файлы циклов поддерживают только cron. |
| `enabled` | Установите `true`, чтобы запускать. Циклы **по умолчанию выключены**, поэтому коммит файла сам по себе никогда не запускает задачу. |
| `model` | `provider/model` (обязательно), например `anthropic/claude-sonnet-4-5`. |
| `agent` | Агент для использования (необязательно). |
| `timezone` | Часовой пояс IANA (необязательно, по умолчанию — зона сервера). |
| body | Промпт для выполнения (обязательно). Может быть слэш-командой, например `/review src/`. |

### Как ведут себя циклы

- Пока **файл существует, он главный**. **Редактировать** открывает его во встроенном редакторе файлов, переключатель включения обновляет его frontmatter, а удаление задачи удаляет markdown-файл после подтверждения. **Запустить сейчас** остаётся доступным.
- Состояние во время работы (последний запуск, следующий запуск, статус) хранится в конфигурации проекта и никогда не записывается обратно в markdown-файл.
- Переименование поля `name` переименовывает задачу на месте. Если файл цикла временно не разбирается (во время редактирования, при конфликте слияния), его задача сохраняется с последним корректным определением, пока файл не исправят.
- Расписания `daily`/`weekly`/`once` и настройки цели остаются только в интерфейсе; файлы циклов всегда используют cron.

## Как выглядит успех

После запуска задача показывает, когда она выполнялась в последний раз, успешно ли, и ссылку на созданную сессию. Если запуск не удался, ошибка тоже показывается там.

## Имейте в виду

Задачи срабатывают только пока запущен сервер OpenChamber. Если вы его закроете, запланированные запуски приостанавливаются, пока он не вернётся.
