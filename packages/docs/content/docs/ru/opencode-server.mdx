# Сервер OpenCode

OpenChamber работает поверх сервера OpenCode. По умолчанию он запускает его для вас, так что вам ничего делать не нужно. Эта страница нужна только если вы хотите направить OpenChamber на сервер, который уже запущен, или управлять тем, который он запускает.

## Как OpenChamber находит сервер

Когда OpenChamber запускается, он ищет сервер в таком порядке:

1. повторно использует сервер, который уже запустил
2. подключается к внешнему, если вы так указали (см. ниже)
3. автоматически находит сервер на порту по умолчанию (`4096`)
4. иначе запускает и обслуживает собственный

Если ничего не настроено, шаг 4 происходит автоматически, и всё работает.

## Подключение к серверу, который вы уже запускаете

Задайте это перед запуском OpenChamber:

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true openchamber
```

- `OPENCODE_HOST` — полный адрес вашего сервера OpenCode, включая порт (значение вида `http://localhost:4096`). В конце не должно быть пути.
- `OPENCODE_SKIP_START=true` — говорит OpenChamber не запускать собственный сервер.

Если вам нужно изменить только порт, задайте `OPENCODE_PORT` вместо `OPENCODE_HOST`.

Если в `OPENCODE_HOST` нет порта или есть путь, OpenChamber игнорирует его и возвращается к запуску собственного сервера. Следите за журналами запуска — там будет предупреждение `[config]`, если ожидаемое подключение не произошло.

## Управление сервером из CLI

```bash
openchamber status
openchamber logs
openchamber restart
openchamber stop
```

`openchamber` сам по себе запускает сервер в фоне. Добавьте `--foreground`, чтобы оставить его привязанным к вашему терминалу.

## Запуск OpenChamber при входе в систему

Используйте `startup enable`, чтобы установить нативный пользовательский сервис. OpenChamber использует `launchd` на macOS, `systemd --user` на Linux и Task Scheduler на Windows.

```bash
openchamber startup enable
openchamber startup status
openchamber startup disable
```

Чтобы защитить UI, задайте пароль при включении сервиса:

```bash
OPENCHAMBER_UI_PASSWORD='secret' openchamber startup enable
```

Для headless-сервера, который стартует при входе и предназначен для десктопных или мобильных клиентов, добавьте `--api-only` и доступный хост:

```bash
openchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` сохраняет снимок текущего окружения в сервисе, поэтому он ведёт себя ближе к запуску `openchamber` из той же оболочки. Так сохраняются токены провайдеров, `PATH`, настройки SSH-агента и другие CLI-переменные авторизации и конфигурации. Используйте `--no-env-snapshot`, если хотите минимальное окружение сервиса.

Сервис запуска также запоминает `--port`, `--host`, `--ui-password` и `--api-only`. Перезапуск из CLI и перезапуск при обновлении повторно используют эти сохранённые настройки.

Чтобы создать ссылку подключения для другого приложения OpenChamber, используйте:

```bash
openchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

Запустите `openchamber connect-url --help`, чтобы увидеть все параметры ссылки, включая `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` и `--qr`.

Туннелями для этого запущенного сервиса по-прежнему можно управлять отдельно:

```bash
openchamber tunnel start --port 3000
openchamber tunnel stop --port 3000
```

Остановка туннеля не перезапускает сервис или приложение.

## «OpenCode перезапускается»

Пока сервер запускается или перезапускается, OpenChamber показывает состояние «OpenCode перезапускается» и приостанавливает запросы, пока он не будет готов. Это нормально сразу после запуска или перезапуска. Если это состояние не проходит, см. [Подключение к OpenCode](/ru/troubleshooting/opencode-connection/).
