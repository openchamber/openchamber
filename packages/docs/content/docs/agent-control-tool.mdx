# Agent Control Tool

Use the `openchamber` agent tool to manage work in the app directly from chat, and `openchamber_schedule` for scheduled tasks. Both are enabled by default when OpenChamber runs its own local OpenCode server; there is nothing to install or shell command to run.

## What you can ask

Ask the agent in plain language. For example:

- "Create a new OpenChamber session in this project, use the `openai/gpt-5.6-sol` model, and send it this prompt: review the authentication flow."
- "Create a new OpenChamber session for this task in a separate worktree, and ask it to add tests for the login flow."
- "Use OpenChamber to list my 10 most recent sessions and include their current status."
- "Create an OpenChamber scheduled task named Weekday review that sends this prompt at 09:00 every weekday: review changes since the last run."
- "Run the OpenChamber scheduled task named Weekday review now."
- "Check the OpenChamber session named Authentication review and show me its latest assistant response."

The control tool can list projects and model preferences, search the model catalog, create and follow up on sessions, fork a session, archive a session (and restore it later), and create isolated worktree sessions. The schedule tool creates, changes, runs, pauses and deletes scheduled tasks. Sessions started this way appear in OpenChamber like any other session, so you can open them and continue the work yourself.

## Keep in mind

- New session prompts return immediately by default. Follow the session in OpenChamber, or ask the agent to check it later.
- A new session in a Git project runs in a new worktree unless you ask for it to work in the folder itself; a folder that isn't a Git repository is used as it is, and a forked session stays in the folder of the session it came from. Uncommitted changes from your current worktree are not copied into a new worktree. A session for a pull request always gets a worktree of its own.
- When the checkout looks busy, for example another session works on the same branch, the agent may offer to move its own session into a new worktree. It moves after you agree, and takes along only the files it changed.
- The tools cannot delete sessions or worktrees, run arbitrary shell commands, or call arbitrary URLs. They can add a folder as a project and remove a project from the list, which leaves its files alone. Archiving is the agent's way to clear a session away; permanent deletion stays with you, through the CLI (`openchamber session delete`).

## Turn the tools on or off

Open **Settings → General → OpenChamber Tools** and change **Agent control tool** or **Agent schedule tool**; each switches on its own. If you had turned the control tool off before scheduling became its own tool, the schedule tool starts off too. The change reaches running sessions on their next turn, without a restart. If your own environment already sets `OPENCODE_CONFIG`, it applies once the managed OpenCode server restarts.

The tools are not available when OpenChamber connects to an external OpenCode server through `OPENCODE_HOST` or skip-start, or inside the VS Code extension. Desktop and web installations that use OpenChamber's managed OpenCode server support it automatically.
