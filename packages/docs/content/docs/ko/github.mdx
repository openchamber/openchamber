# Git 호스트: 이슈와 풀 리퀘스트

프로젝트가 있는 호스트의 계정을 연결하면 OpenChamber가 그 이슈와 풀 리퀘스트를 나열하고, 그중 하나에서 세션을 시작하고, 풀 리퀘스트를 열고 리뷰하고 병합해 줍니다. 기본 제공 호스트는 다섯 가지입니다. GitHub(GitHub Enterprise 포함), GitLab(자체 관리형 GitLab 포함), Gitea, Forgejo(Codeberg 포함), Gerrit입니다. [확장](/ko/extensions/#git-호스트-역할을-하는-확장)으로 다른 호스트를 추가할 수도 있습니다.

OpenChamber가 어느 호스트와 통신할지는 프로젝트의 원격 저장소가 정합니다. `origin`이 gitlab.com에 있는 프로젝트는 보드, 브랜치의 풀 리퀘스트 배지, Git 패널에 GitLab 계정을 사용합니다. `github.com-work`처럼 `~/.ssh/config`의 호스트 별칭에 있는 원격 저장소는 어떤 호스트와도 연결되지 않습니다.

용어는 호스트를 따릅니다. GitLab에서는 머지 리퀘스트, Gerrit에서는 변경이라고 부릅니다.

## 호스트 연결하기

1. **Settings → Integrations**를 엽니다. 호스트마다 카드가 있습니다.
2. 프로젝트 호스트의 카드를 펼치고 로그인합니다.
   - **GitHub**: **Connect GitHub**를 선택하고, 표시된 링크를 열어 짧은 코드를 입력한 뒤 승인합니다. GitHub Enterprise에서는 **다른 인스턴스** 아래의 **인스턴스 추가**를 선택하고, 서버 주소를 입력한 다음 개인 액세스 토큰을 붙여 넣습니다.
   - **GitLab**: gitlab.com에서는 짧은 코드, 개인 액세스 토큰 또는 `glab` 로그인으로 로그인합니다. 자체 관리형 GitLab에서는 주소를 추가하고 개인 액세스 토큰을 붙여 넣습니다.
   - **Gitea**: 서버 주소를 추가하고 개인 액세스 토큰을 붙여 넣습니다.
   - **Forgejo**: Codeberg는 개인 액세스 토큰을 붙여 넣습니다. 다른 서버는 먼저 주소를 추가합니다.
   - **Gerrit**: 서버 주소를 추가한 다음 Gerrit 사용자 이름과 HTTP 비밀번호를 입력합니다.

연결되면 카드에 계정이 표시됩니다. 한 호스트에 계정을 여러 개 연결해 전환할 수 있으며, 언제든 연결을 해제할 수 있습니다. 같은 컴퓨터에서 `gh` CLI에 로그인되어 있으면 OpenChamber가 GitHub에도 이를 사용할 수 있습니다. 토큰마다 필요한 범위와 호스트마다 필요한 버전은 [통합 기능](/ko/integrations/#gitlab-gitea-forgejo-gerrit)에 있습니다.

연결한 계정은 프로젝트의 [Git 아이덴티티](/ko/git-identities/)로도 쓸 수 있습니다. 그러면 커밋에 그 계정의 이름이 들어가고, HTTPS 푸시에는 그 계정의 토큰이 쓰입니다.

## 이슈나 풀 리퀘스트에서 작업 시작하기

[worktree 세션](/ko/worktrees/)을 만들 때 프로젝트 호스트의 이슈나 풀 리퀘스트에서 시작할 수 있습니다.

- **issue**를 선택하면 OpenChamber가 그 이슈에 따라 브랜치 이름을 짓습니다
- **pull request**를 선택하면 풀 리퀘스트의 브랜치를 체크아웃합니다. diff를 포함하면 에이전트가 전체 변경 사항을 갖게 됩니다
- **Gerrit 변경**을 선택하면 최신 패치셋을 `change-<number>`라는 브랜치에 체크아웃합니다

새 세션은 항목이 메시지 입력창에 이미 첨부된 상태로 열립니다. 자동으로 전송되는 것은 없습니다. 모델과 에이전트를 고르고, 원하는 작업을 적어서 보내세요.

[이슈 및 PR](/ko/issues-and-prs/) 보드에도 같은 항목이 필터, 미리보기, 댓글, 리뷰와 함께 나오며, 거기서도 세션을 시작할 수 있습니다.

## 풀 리퀘스트 열기 및 관리

[Git 패널](/ko/git/)의 **PR** 탭에서 풀 리퀘스트를 만들고, 업데이트하고, 초안을 준비 완료로 표시하거나 병합할 수 있습니다. OpenChamber는 변경 사항에서 제목과 설명을 작성할 수 있습니다.

- **GitLab**: 같은 탭에서 머지 리퀘스트를 엽니다. 병합할 때 merge와 squash를 고를 수 있습니다.
- **Gitea**와 **Forgejo**: GitHub와 같습니다.
- **Gerrit**: 리뷰로 푸시하면 변경이 만들어지고, 이후 푸시할 때마다 새 패치셋이 업로드됩니다. [Gerrit에서 리뷰로 푸시하기](/ko/git/#gerrit에서-리뷰로-푸시하기)를 참고하세요. 병합은 **제출**이며, 변경이 제출 요건을 충족할 때까지 기다립니다. 리뷰는 Code-Review, Verified 같은 프로젝트 라벨에 대한 투표입니다.

## 이슈나 풀 리퀘스트를 메시지에 연결하기

채팅 작성창에서 **+** 메뉴를 열고 호스트에 맞는 연결 항목을 선택합니다. 예를 들어 **GitHub 이슈 또는 PR 연결**, **GitLab 이슈 또는 MR 연결**, **Gerrit 변경 연결**입니다. 항목을 하나 이상 고르세요. 각 항목은 다음 메시지에 컨텍스트로 함께 전송되고, 풀 리퀘스트는 diff를 가져올 수 있으며, 세션의 작업 상태 패널에 링크가 남습니다. 첨부는 컨텍스트만 더할 뿐이고, 무엇을 할지는 메시지에 적습니다.

Gerrit에는 이슈가 없으므로 변경만 표시됩니다.
