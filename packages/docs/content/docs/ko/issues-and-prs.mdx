# 이슈 및 PR

**Issues and PRs** 보드는 프로젝트의 GitHub 또는 GitLab 이슈와 풀 리퀘스트(GitLab에서는 머지 리퀘스트), 또는 Linear 이슈를 나열하는 전체 페이지입니다. 항목을 고르면 목록 옆에 미리보기가 열립니다. 여기서 다른 프로젝트를 봐도 앱의 나머지 부분이 보고 있는 프로젝트는 바뀌지 않습니다.

## 보드 열기

- 사이드바 헤더에서 예약 작업과 보관함 옆에 있는 풀 리퀘스트 아이콘을 클릭합니다.
- 명령 팔레트에서 **Issues and PRs**를 선택합니다.
- <kbd>⌘K</kbd>를 누른 다음 <kbd>B</kbd>를 누릅니다(Windows와 Linux에서는 <kbd>Ctrl+K</kbd> 다음 <kbd>B</kbd>). 같은 키로 닫습니다.

휴대전화에서는 세션 메뉴 하단의 풀 리퀘스트 버튼을 탭합니다. VS Code 확장에는 보드가 없습니다.

보드는 마지막으로 떠날 때의 프로젝트, 탭, 팀으로 다시 열립니다.

## 항목 찾기

모든 것이 도구 모음 한 줄에 있습니다. 왼쪽에는 프로젝트 아이콘과 검색이 있는 프로젝트 선택기가 있습니다. 그 옆에서 **Issues**, **Pull requests**, **Linear** 사이를 전환합니다. 이슈와 풀 리퀘스트는 프로젝트 자체의 호스트인 GitHub 또는 GitLab에서 가져옵니다. 이런 원격 저장소가 없는 프로젝트에는 **Linear**만 표시됩니다.

**Linear**에서는 프로젝트 선택기가 팀 선택기로 바뀝니다. **All teams** 또는 한 팀을 고르세요. Linear 워크스페이스를 둘 이상 연결했다면 같은 메뉴에서 워크스페이스를 전환합니다. Linear 연결 방법은 [통합 기능](/ko/integrations/)에 있습니다.

검색에는 제목, 번호 또는 붙여 넣은 링크를 쓸 수 있습니다. 필터 메뉴는 고르는 동안 열려 있으므로 필터를 함께 걸 수 있습니다.

GitHub와 GitLab:

- 상태: **Open**, **Closed**, **All**, 풀 리퀘스트에는 **Merged**도
- 사람: **Anyone**, **Assigned to me**, **Created by me**, 풀 리퀘스트에는 **Review requested**도

Linear:

- 상태: **Open**, **All**, **Backlog**, **To Do**, **In Progress**, **In Review**, **Done**, **Canceled**, **Duplicate**
- 사람: **Anyone**, **Assigned to me**, **Created by me**
- 우선순위: **All priorities**, **Urgent**, **High**, **Medium**, **Low**, **No priority**

## 항목 읽기

미리보기에는 설명, 라벨, 댓글이 표시됩니다. Linear 이슈에서는 상태 배지를 클릭해 팀의 다른 상태로 옮길 수 있습니다.

**Labels** 행에는 연필 버튼이 있어, 저장소의 라벨을 검색할 수 있는 목록을 엽니다. 라벨을 체크하거나 해제하세요. 변경 사항은 목록을 닫을 때 저장되므로 여러 번 클릭해도 한 번의 변경으로 처리됩니다. 열린 풀 리퀘스트(GitLab에서는 머지 리퀘스트)에는 같은 방식으로 동작하는 **Reviewers** 행도 있으며, 저장소에서 리뷰할 수 있는 사람들이 나옵니다. GitHub에서는 풀 리퀘스트 작성자가 목록에 나오지 않습니다. Linear 이슈에는 두 행 모두 없습니다.

## 댓글과 리뷰

이슈나 풀 리퀘스트의 활동 아래에는 댓글 입력창이 있습니다. **Comment**는 작성한 내용을 GitHub 또는 GitLab에 게시하며, <kbd>⌘</kbd>+<kbd>Enter</kbd>(Windows와 Linux에서는 <kbd>Ctrl</kbd>+<kbd>Enter</kbd>)도 같은 일을 합니다. 텍스트는 게시될 때까지 입력창에 남아 있으므로 게시에 실패해도 잃는 것이 없습니다. 다른 항목으로 전환하면 입력창이 비워집니다. Linear 이슈에는 댓글 입력창이 없습니다.

열린 풀 리퀘스트(GitLab에서는 머지 리퀘스트)에는 **Approve**와 **Request changes**도 있으며, 입력창의 내용이 리뷰와 함께 전송됩니다. **Request changes**에는 무엇을 바꿔야 하는지 적은 텍스트가 필요합니다. 리뷰는 미리보기에 표시된 커밋에 대한 것입니다. 그 뒤에 누군가 푸시했다면 리뷰가 거부되고 미리보기가 새로 고쳐지므로 다시 확인할 수 있습니다. GitLab에서는 머지 리퀘스트의 리뷰어일 때 **Request changes**를 쓸 수 있으며, 리뷰 텍스트는 별도 댓글로 게시됩니다. 그 댓글만 실패하면 리뷰는 그대로 반영되고 텍스트는 입력창에 남습니다.

## 작업 시작하기

작업 버튼은 미리보기 하단에 있습니다.

- **New session**은 항목을 메시지 입력창에 첨부한 채로 프로젝트에 새 세션을 엽니다. 첫 메시지는 직접 작성합니다.
- 이슈의 **Start in worktree…** 또는 풀 리퀘스트의 **Check out in worktree…**는 항목이 이미 선택된 상태로 New Worktree 대화상자를 엽니다. 풀 리퀘스트는 자체 브랜치를 체크아웃합니다. [Worktree 세션](/ko/worktrees/)을 참고하세요.

Linear 이슈에서는 **Start in**에 세션이 시작될 프로젝트가 표시됩니다. [통합 기능](/ko/integrations/)의 Linear 카드에서 이슈의 팀에 매핑한 프로젝트입니다. 팀 매핑이 없으면 기본 프로젝트이고, 그것도 없으면 보드가 마지막으로 표시한 프로젝트입니다. 거기서 이 이슈에만 다른 프로젝트를 고를 수 있습니다.

## 풀 리퀘스트

풀 리퀘스트의 미리보기에는 브랜치, 크기(추가·삭제된 줄과 변경된 파일 수), 체크, 리뷰도 표시됩니다. **Activity** 피드는 댓글, 리뷰 판정, 최신 커밋을 일어난 순서대로 보여 줍니다. 연이어 들어온 커밋은 묶어서 보여 주므로 리뷰가 어떤 커밋에 대한 것인지 알 수 있습니다.

크기 옆에는 버튼이 두 개 있습니다. **Changes**는 풀 리퀘스트의 diff를 사이드 패널에 열고, **Walkthrough**는 [변경 워크스루](/ko/walkthrough/)를 엽니다. 앱이 다른 프로젝트에 있으면 먼저 PR의 프로젝트로 전환합니다. 두 버튼 모두 데스크톱과 웹에서만 쓸 수 있습니다.

하단의 **Merge**는 병합 전에 확인을 묻고 평소 쓰는 병합 방식을 사용합니다. 초안에는 **Ready for review**도 있습니다.

열린 이슈나 풀 리퀘스트의 하단에는 **Close issue** 또는 **Close pull request**(GitLab에서는 **Close merge request**)도 있고, 닫힌 항목에는 **Reopen issue** 또는 **Reopen pull request**(**Reopen merge request**)가 있습니다. 되돌릴 수 있는 작업이라 확인을 묻지 않습니다. 병합된 풀 리퀘스트는 닫거나 다시 열 수 없습니다. GitHub에서는 이슈가 완료 상태로 닫힙니다.
