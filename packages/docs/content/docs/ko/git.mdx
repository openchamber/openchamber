# Git 워크플로

OpenChamber에는 내장 git 보기가 있어 터미널로 전환하지 않고도 변경 사항을 검토하고, 커밋하고, 브랜치를 관리할 수 있습니다. 오른쪽 사이드바의 **Git** 탭에서 엽니다.

## 검토 및 커밋

git 보기는 변경 사항을 **staged**와 **unstaged**로 나눕니다.

- 파일의 **+**를 클릭해 스테이징하거나 **−**를 클릭해 스테이징을 해제합니다
- 그룹의 모든 항목을 한 번에 스테이징하거나 해제합니다
- 파일을 클릭해 diff를 봅니다

그런 다음 커밋 메시지를 작성하고 커밋합니다. OpenChamber가 스테이징된 변경 사항에서 **커밋 메시지를 생성**하게 할 수 있습니다. 현재 세션의 모델을 사용하므로 세션이 열려 있어야 합니다.

## 브랜치와 히스토리

git 보기는 일상적인 나머지 git 작업도 다룹니다.

- 브랜치 생성, 전환, 이름 변경, 삭제
- push, pull, fetch
- 히스토리와 커밋별 diff 탐색
- 변경 사항 stash 및 복원

## 풀 리퀘스트

프로젝트 호스트에 계정을 연결하면 **PR** 탭에서 풀 리퀘스트를 열고, 업데이트하고, 준비 완료로 표시하거나 병합할 수 있습니다. OpenChamber는 커밋 메시지와 같은 방식으로 제목과 설명을 작성할 수 있습니다. GitHub, Gitea, Forgejo, GitLab에서 동작하며, GitLab에서는 이 탭이 머지 리퀘스트를 엽니다. Gerrit에는 **리뷰로 푸시**라는 별도 양식이 있습니다. 호스트 연결 방법은 [Git 호스트](/ko/github/)에 있습니다.

## Gerrit에서 리뷰로 푸시하기

Gerrit 프로젝트에서는 풀 리퀘스트 양식이 **리뷰로 푸시**로 바뀝니다. 커밋을 `refs/for/<branch>`로 푸시해 변경을 만들거나, 이미 푸시한 변경의 새 패치셋을 만듭니다. 커밋 메시지가 변경의 설명이 되므로 양식에는 제목과 본문 대신 최신 커밋의 제목이 표시됩니다. 대상 브랜치를 고르고, 원하면 토픽, 해시태그, **작업 중**, **비공개**를 지정합니다. 대상 브랜치 자체에서도 동작하며, 이것이 Gerrit에서 일하는 일반적인 방식입니다.

Gerrit는 commit-msg 훅이 각 메시지에 추가하는 `Change-Id` 줄로 커밋과 변경을 연결합니다. 최신 커밋에만 Change-Id가 없으면 **Change-Id 추가**가 확인을 받은 뒤 그 커밋을 amend합니다. 푸시하기 전까지는 아무것도 전송되지 않습니다. 그보다 앞선 커밋에 Change-Id가 없으면, 훅을 설치하고 각 커밋에 Change-Id를 붙일 때까지 푸시가 기다립니다.

첫 푸시 후에는 로컬 커밋이 아직 변경에 올라가지 않았을 때마다 패널에 **패치셋 업로드**가 표시됩니다. 변경 체인에 속한 변경은 배지 옆에 체인 안의 위치(예: **3개 중 2**)를 보여 줍니다.

## 충돌 가져오기

병합, 리베이스, 통합이 충돌하면 OpenChamber가 무엇이 막혔는지 보여주고 해결하게 해줍니다. 에이전트에게 넘기는 것도 포함됩니다.
