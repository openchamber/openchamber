# 워크플로

워크플로는 큰 작업을 작은 조각 여러 개로 나누고 조각마다 에이전트를 하나씩 맡깁니다. 세션의 에이전트가 어떤 에이전트를 시작하고 각각에게 무엇을 물을지 적은 짧은 스크립트를 작성합니다. OpenChamber는 이 스크립트를 백그라운드에서 실행하므로 에이전트들이 일하는 동안에도 세션을 계속 쓸 수 있습니다. 실행이 끝나면 보고서가 세션으로 돌아옵니다.

워크플로는 서로 비슷하고 독립적인 조각이 많은 작업에 알맞습니다. 변경된 파일마다 하는 리뷰, API 경로마다 하는 점검, 여러 파일에 걸친 마이그레이션, 출처마다 따로 확인하는 조사 같은 작업입니다. 기능 하나나 몇 단계짜리 작업은 세션 하나에서 하는 편이 더 빠릅니다.

## 켜기

워크플로 도구는 기본으로 꺼져 있습니다. **설정 → 일반 → OpenChamber 도구**를 열고 **워크플로 도구**를 켜세요. 실행 중인 세션에는 다음 턴부터 적용됩니다. 다시 끄면 모든 세션에서 도구와 관련 안내가 사라지고 워크플로 패널도 숨겨집니다. 다시 켜면 기존 실행이 다시 나타납니다.

워크플로는 OpenChamber의 관리형 OpenCode 서버가 있어야 합니다. OpenChamber가 `OPENCODE_HOST`나 skip-start로 외부 OpenCode 서버에 연결된 경우와 VS Code 확장 안에서는 쓸 수 없습니다.

## 워크플로 실행하기

1. 평소 말투로 요청합니다. 예: "이 브랜치에서 변경된 파일을 모두 리뷰하고 찾은 버그를 정리하는 워크플로를 실행해 줘."
2. 에이전트가 계획과 단계별 모델을 제안합니다. 실행이 시작되기 전에 모델을 합의하세요. [모델과 비용](#모델과-비용)을 참고하세요.
3. 계획이 담긴 카드가 채팅에 나타납니다. **워크플로 실행**을 선택하면 시작되고, **실행하지 않기**를 선택하면 취소됩니다. 선택하기 전에는 아무것도 실행되지 않습니다.
4. 실행 중에는 카드에 각 단계와 에이전트가 표시됩니다. 사이드바의 세션 행에는 **워크플로 실행 중**이 표시되고, 작업 상태 패널의 **워크플로** 섹션에 실행이 나열됩니다. 일찍 끝내려면 **중지**를 선택합니다.
5. 실행이 끝나면 보고서가 메시지로 세션에 도착합니다. 완료되거나 실패한 실행은 에이전트를 깨워 결과에 따라 이어서 작업하게 합니다. 직접 중지하거나 실행하지 않기로 한 실행은 에이전트를 깨우지 않습니다.

중지되거나 실패한 실행은 **재개**로 이어 갈 수 있습니다. 이미 답한 에이전트는 답을 그대로 유지하고, 나머지만 다시 실행됩니다.

실행 중인 워크플로의 에이전트는 자기 워크플로를 따로 시작할 수 없습니다.

## 모델과 비용

스크립트에서 다른 모델을 지정하지 않으면 워크플로의 모든 에이전트는 세션의 모델로 실행됩니다. 최상위 모델에서 에이전트 수십 개를 돌리면 같은 작업을 작은 모델로 할 때보다 비용이 몇 배나 듭니다. 그래서 에이전트는 단계마다 모델을 제안합니다. 읽기나 정해진 목록과 대조하는 확인에는 저렴한 모델을, 판단이 필요하거나 프로젝트에 반영될 내용을 작성하는 단계에는 더 강한 모델을 고릅니다. 마음에 들지 않으면 실행을 승인하기 전에 바꾸세요.

동시에 작업하는 에이전트는 최대 8개이며, 실행 하나는 모든 시도를 합쳐 최대 200개의 에이전트를 시작합니다.

## 워크플로 패널

오른쪽 레일의 **워크플로** 패널에는 프로젝트의 실행이 표시됩니다. 에이전트, 로그, 결과, 스크립트와 함께 에이전트별 모델과 토큰 사용량을 볼 수 있습니다. 이 패널이나 채팅 카드에서 에이전트의 세션을 열어 전체 대화를 읽을 수 있습니다. 아이콘은 프로젝트에 실행이나 저장된 워크플로가 생기면 나타납니다.

실행 하나가 에이전트를 백 개씩 시작할 수 있으므로 워크플로 에이전트는 세션 사이드바에 나타나지 않습니다. 대신 실행 카드와 워크플로 패널에서 언제든 열 수 있습니다.

**실행 삭제**는 끝난 실행을 패널에서 지웁니다. 에이전트의 세션은 남습니다.

## 저장된 워크플로

다시 실행하고 싶은 워크플로는 에이전트에게 저장해 달라고 요청하세요. 프로젝트 안에 `.openchamber/workflows/<name>.js`로 저장되므로 저장소의 다른 파일과 함께 커밋할 수 있습니다.

저장된 워크플로는 패널의 실행 선택기에 있는 **저장된 워크플로**에서 실행합니다. 열려 있는 세션이나 새 세션에서 바로 시작되며, 보고서는 그 세션으로 돌아옵니다. 에이전트에게 이름으로 실행해 달라고 요청할 수도 있습니다.
