# 에이전트 제어 도구

`openchamber` 에이전트 도구는 채팅에서 바로 앱의 작업을 관리하고, `openchamber_schedule`은 예약 작업을 맡습니다. OpenChamber가 자체 로컬 OpenCode 서버를 실행하면 두 도구 모두 기본으로 켜져 있으며, 따로 설치하거나 shell 명령을 실행할 필요가 없습니다.

## 요청할 수 있는 것

에이전트에게 평소 말투로 요청하세요. 예를 들면:

- "이 프로젝트에 새 OpenChamber 세션을 만들고 `openai/gpt-5.6-sol` 모델을 사용해서 이 프롬프트를 보내 줘: 인증 흐름을 검토해."
- "이 작업을 위해 별도 worktree에 새 OpenChamber 세션을 만들고 로그인 흐름 테스트를 추가해 달라고 해 줘."
- "OpenChamber로 최근 세션 10개를 현재 상태와 함께 보여 줘."
- "평일 리뷰라는 OpenChamber 예약 작업을 만들어서 평일마다 09:00에 이 프롬프트를 보내게 해 줘: 지난 실행 이후의 변경 사항을 검토해."
- "평일 리뷰라는 OpenChamber 예약 작업을 지금 실행해 줘."
- "인증 리뷰라는 OpenChamber 세션을 확인하고 어시스턴트의 최신 응답을 보여 줘."

제어 도구는 프로젝트와 모델 기본 설정을 나열하고, 모델 카탈로그를 검색하며, 세션을 만들고 이어 가며, 세션을 포크하고, 격리된 worktree 세션을 만듭니다. 예약 도구는 예약 작업을 만들고, 바꾸고, 실행하고, 일시 중지하고, 삭제합니다. 이렇게 시작한 세션은 다른 세션처럼 OpenChamber에 나타나므로 열어서 직접 작업을 이어 갈 수 있습니다.

## 알아 둘 점

- 새 세션에 보낸 프롬프트는 기본적으로 바로 반환됩니다. OpenChamber에서 세션을 지켜보거나 나중에 확인해 달라고 에이전트에게 요청하세요.
- 별도 worktree는 요청할 때만 만들어집니다. 현재 worktree의 커밋하지 않은 변경 사항은 그곳으로 복사되지 않습니다.
- 다른 세션이 같은 브랜치에서 작업하는 등 체크아웃이 사용 중으로 보이면, 에이전트가 자기 세션을 새 worktree로 옮기자고 제안할 수 있습니다. 동의한 뒤에 옮기며, 자신이 변경한 파일만 가져갑니다.
- 이 도구들은 세션이나 worktree를 삭제하거나, 프로젝트 경로를 등록하거나, 임의의 shell 명령을 실행하거나, 임의의 URL을 호출할 수 없습니다.

## 도구 켜고 끄기

**설정 → 일반 → OpenChamber 도구**를 열고 **에이전트 제어 도구** 또는 **에이전트 예약 도구**를 바꾸세요. 각각 따로 켜고 끌 수 있습니다. 예약이 별도 도구가 되기 전에 제어 도구를 꺼 두었다면 예약 도구도 꺼진 상태로 시작합니다. 변경 사항은 실행 중인 세션의 다음 턴에 재시작 없이 반영됩니다. 사용 중인 환경에서 이미 `OPENCODE_CONFIG`를 설정했다면 관리형 OpenCode 서버가 다시 시작될 때 적용됩니다.

OpenChamber가 `OPENCODE_HOST`나 skip-start로 외부 OpenCode 서버에 연결된 경우와 VS Code 확장 안에서는 이 도구들을 쓸 수 없습니다. OpenChamber의 관리형 OpenCode 서버를 쓰는 데스크톱과 웹 설치에서는 자동으로 지원됩니다.
