# 통합 기능

**설정 → 통합 기능**에서 OpenChamber가 함께 사용하는 서비스에 로그인합니다. 로그인 정보는 OpenChamber 서버에 저장되므로 웹, 데스크톱, 페어링된 휴대전화가 이를 공유합니다.

## 통합 기능 카탈로그

통합 기능 카탈로그에는 클릭 한 번으로 에이전트에게 연결할 수 있는 150개가 넘는 서비스가 있습니다. Linear, Notion, Sentry, Supabase, Figma, 관측 도구, CRM, 회의록 도구 등이 포함됩니다. 설치하면 보통 서비스의 MCP 서버가 추가되며, 에이전트는 이 연결로 해당 서비스의 내용을 읽고 바꿉니다. 함께 제공되는 스킬이나 플러그인이 추가되기도 합니다. 설치는 사용자 단위이므로 모든 프로젝트에서 사용할 수 있습니다.

1. 사이드바 헤더의 스토어 아이콘을 선택합니다.
2. 서비스를 찾습니다. 이름으로 검색하거나 **코드**, **품질과 운영** 같은 카테고리로 목록을 좁힙니다. **OpenChamber**에는 OpenChamber의 자체 확장 기능과 플러그인이 있습니다.
3. 해당 행의 **+**를 선택하거나, 서비스를 열고 **설치**를 선택합니다.
4. 서비스가 요구하는 방식으로 로그인합니다.
   - **OAuth**: 브라우저에서 서비스의 로그인 페이지가 열립니다. 거기서 접근을 승인합니다.
   - **토큰**: **API 토큰**에 API 토큰을 붙여 넣습니다. **토큰 발급**을 누르면 서비스에서 토큰을 발급하는 페이지가 열립니다.
   - **로그인 불필요**: 따로 할 일이 없습니다.

설치가 끝나면 서비스에 체크 표시가 나타나고 왼쪽의 **설치됨** 아래에 표시되며, 다음 메시지부터 그 도구를 쓸 수 있습니다. 노란 점이나 **로그인 필요**가 보이면 로그인이 끝나지 않은 것입니다. 서비스를 열고 다시 로그인하세요.

일부 항목은 로그인 외에 더 필요한 것이 있습니다.

- **로컬 서버**는 OpenCode가 실행되는 컴퓨터에서 실행되며 Node.js, uv가 있는 Python, 또는 Docker가 필요할 수 있습니다. 처음 시작할 때 시간이 걸릴 수 있습니다.
- **플러그인**은 OpenCode 안에서 실행되는 코드이므로, 카탈로그가 먼저 플러그인의 라이선스를 보여 주고 확인을 요청합니다.
- 서비스와 함께 제공되는 **스킬**은 서비스와 함께 설치됩니다. 빠진 스킬이 있으면 서비스 페이지에 해당 스킬의 **설치** 버튼이 나타납니다.

서비스를 제거하려면 서비스를 열고 **추가 작업**(**⋯**)을 선택한 다음 **제거**를 선택합니다. 카탈로그가 추가한 것만 제거되며, 서비스의 계정은 그대로 남습니다. MCP 서버, 플러그인, 스킬은 지금처럼 설정에서도 관리할 수 있습니다.

카탈로그는 웹 앱과 데스크톱 앱에 있습니다. [엔터프라이즈 모드](/ko/security/#엔터프라이즈-모드)에서는 숨겨집니다.

## GitHub

**GitHub** 카드를 펼치고 **Connect GitHub**를 선택해 짧은 기기 코드로 로그인합니다. 연결되면 OpenChamber가 이슈와 풀 리퀘스트에서 세션을 시작하고, 메시지에 첨부하고, PR을 열거나 업데이트할 수 있습니다. Git 호스트로 할 수 있는 모든 것은 [Git 호스트](/ko/github/)에 있습니다.

## GitLab, Gitea, Forgejo, Gerrit

GitLab, Gitea, Forgejo, Gerrit는 GitHub 옆에 각자의 카드가 있습니다. 연결하면 그 이슈와 풀 리퀘스트(GitLab에서는 머지 리퀘스트, Gerrit에서는 변경)가 GitHub처럼 [이슈 및 PR](/ko/issues-and-prs/) 보드와 채팅의 **+** 메뉴에 표시됩니다.

- **GitLab**: gitlab.com에서는 짧은 기기 코드, 개인 액세스 토큰 또는 서버의 `glab` 로그인으로 로그인합니다. 자체 관리형 GitLab에서는 주소를 추가하고 `api` 범위가 있는 개인 액세스 토큰을 붙여 넣습니다. 그곳에서 기기 코드 로그인은 서버가 `OPENCHAMBER_GITLAB_CLIENT_ID`를 그 인스턴스에 등록한 애플리케이션으로 설정한 경우에만 동작합니다.
- **Gitea**: `https://gitea.example.com` 같은 인스턴스 주소를 추가하고 `write:repository`, `write:issue`, `read:user` 범위가 있는 개인 액세스 토큰을 붙여 넣습니다. 카드에는 인스턴스에서 토큰을 만드는 페이지로 가는 링크가 있습니다. Gitea에는 기기 코드나 CLI 로그인이 없습니다. Gitea 1.21 이상이 필요하며, 주소의 루트에서 제공되어야 합니다.
- **Forgejo**: Codeberg는 이미 카드에 있으므로 `write:repository`, `write:issue`, `read:user` 범위가 있는 개인 액세스 토큰만 있으면 연결할 수 있습니다. 카드에는 Codeberg에서 토큰을 만드는 페이지로 가는 링크가 있습니다. 다른 Forgejo 서버는 `https://forgejo.example.com` 같은 주소를 추가하고 같은 범위가 있는 토큰을 붙여 넣습니다. Forgejo 7.0 이상이 필요하며, 주소의 루트에서 제공되어야 합니다. Forgejo 서버는 이 카드에서, Gitea 서버는 Gitea 카드에서 연결합니다.
- **Gerrit**: `https://gerrit.example.com` 같은 인스턴스 주소를 추가한 다음 Gerrit 사용자 이름과 HTTP 비밀번호를 입력합니다. 비밀번호는 Gerrit의 **Settings → HTTP Credentials**에서 생성하며, 카드에 그곳으로 가는 링크가 있습니다. 로그인 비밀번호는 쓸 수 없고, 사용자 이름이 없는 계정은 연결할 수 없습니다. Gerrit 3.8 이상이 필요하며, 주소의 루트에서 제공되어야 합니다. googlesource.com과 `.gitcookies`처럼 리뷰 주소와 Git 주소가 다른 사이트는 지원하지 않습니다.

Gerrit에서는 변경을 리뷰합니다. 변경을 업로드할 때마다 패치셋이 생기며, 변경의 미리보기에서 이전 패치셋을 골라 읽을 수 있습니다. 리뷰는 Code-Review, Verified 같은 프로젝트 라벨에 투표하는 방식이며, 제출 요건을 충족한 변경은 **제출**로 반영합니다. Gerrit에는 이슈가 없으므로 변경만 표시됩니다. 변경을 만들거나 변경에 새 패치셋을 업로드하려면 Git 패널의 **리뷰로 푸시**를 사용하세요. [Git](/ko/git/#gerrit에서-리뷰로-푸시하기)을 참고하세요.

OpenChamber가 어느 카드의 계정을 쓸지는 프로젝트의 원격 저장소가 정하며, 이 카드들의 계정은 모두 프로젝트의 [Git 아이덴티티](/ko/git-identities/)가 될 수 있습니다. [확장](/ko/extensions/#git-호스트-역할을-하는-확장)은 자체 카드가 있는 다른 호스트를 추가할 수 있습니다.

## Linear

### 워크스페이스 연결하기

1. **Linear** 카드를 펼치고 **Connect**를 선택합니다.
2. 열리는 브라우저 탭에서 접근을 승인합니다. 승인 전까지 카드에는 **Waiting for Linear**가 표시됩니다.

다른 Linear 조직은 **Add workspace**로 연결합니다. 현재 워크스페이스는 한 번에 하나이며, **Switch to**로 전환하고 **Disconnect**는 현재 워크스페이스만 제거합니다. 프로젝트 매핑은 유지됩니다.

### 이슈 찾아보기

Linear 이슈는 **Issues and PRs** 보드에 있습니다. 사이드바 헤더의 풀 리퀘스트 아이콘으로 열거나 <kbd>⌘K</kbd>를 누른 다음 <kbd>B</kbd>를 누르고(Windows와 Linux에서는 <kbd>Ctrl+K</kbd> 다음 <kbd>B</kbd>), 상단에서 **Linear**를 선택합니다. 보드는 현재 워크스페이스의 이슈를 나열하며 다음을 할 수 있습니다.

- 한 팀 또는 **All teams** 표시
- 워크스페이스가 여러 개 연결된 경우 현재 워크스페이스 전환
- 상태, 담당(**Assigned to me** 또는 **Created by me**), 우선순위를 함께 걸어 필터링하고 제목이나 식별자로 검색
- 목록 옆에서 이슈의 설명, 댓글, 라벨, 우선순위 확인
- **Status** 변경

### 이슈에서 세션 시작하기

- 보드에서 이슈를 고른 뒤 새 브랜치가 필요하면 **Start in worktree…**를, 프로젝트를 그대로 쓰려면 **New session**을 선택합니다.
- **New Worktree** 대화상자에서 Linear 이슈를 선택합니다.

어느 쪽이든 세션은 이슈가 메시지 입력창에 첨부된 상태로 열리고, 첫 메시지는 직접 작성합니다. 보드는 이슈의 팀에 매핑된 프로젝트에서 세션을 시작하며, 이 프로젝트는 **Start in** 옆에 표시됩니다. 필요하면 거기서 다른 프로젝트를 고를 수 있습니다. 팀 매핑은 Linear 카드에서 합니다. **Default project**는 모든 팀에 적용되고 **Team projects**는 팀별로 이를 덮어씁니다. 매핑이 없으면 보드는 마지막으로 표시한 프로젝트를 사용합니다.

### 이슈를 메시지에 연결하기

채팅 작성창에서 **+** 메뉴를 열고 **Linear**를 선택합니다. 이슈가 다음 메시지에 컨텍스트로 함께 전송되고, 세션의 작업 상태 패널에 링크가 남습니다.

### 세션 댓글

Linear 카드에서 **Session comments**를 켜면 이슈에서 시작했거나 첫 메시지에 그 이슈가 첨부된 세션이 시작, 완료, 실패 시 해당 이슈에 댓글을 남기며, 각 댓글에는 세션을 여는 링크가 포함됩니다. 댓글은 이 OpenChamber 서버에 공개 주소가 있을 때만 게시되어 이슈의 모든 사람이 링크를 열 수 있습니다. 로컬이나 사설 주소에서는 아무것도 게시되지 않습니다.

## 통합 기능 설치

1. **Settings → Integrations**를 엽니다.
2. 통합 기능을 찾아 **Install**을 선택합니다.
3. 요청되면 OpenCode를 다시 시작합니다 — 재시작 후 공급자가 나타납니다.
4. **Set up**를 선택하고 로그인합니다. 그러면 채팅의 모델 선택기에 모델이 나타납니다.

통합 기능은 사용자 단위로 설치되므로 모든 프로젝트에서 작동합니다. 같은 카드에서 언제든 업데이트하거나 제거할 수 있습니다.

## 확장 알림 채널

[확장](/ko/extensions/)은 Slack, Matrix 또는 자체 서버로 알림을 전달할 수 있습니다. **설정 → 확장**에서 허용하면 이 페이지의 **확장 계정** 아래에 카드가 생깁니다. 거기에 계정의 토큰을 입력하고, 카드가 요청하면 서버 주소도 입력한 뒤 연결합니다. 그 뒤로 확장은 [알림 설정](/ko/notifications/)에 따라 휴대폰이 받을 것과 같은 알림을 받습니다. 토큰은 OpenChamber에 남습니다. 확장의 서비스는 OpenChamber를 통해 보내며 토큰을 결코 보지 못합니다.

나중에 서버가 토큰을 거부하면 카드에 **계정 확인 필요**가 표시됩니다. 새 토큰으로 다시 연결하세요. 확장을 제거하지 않고 전달을 멈추려면 **연결 해제**하거나 확장을 일시 중지합니다. 확장을 제거하면 계정을 잊습니다.

## Claude Code

Claude Code는 컴퓨터에 설치된 Claude Code CLI를 통해 Claude Pro 또는 Max 플랜을 사용합니다 — API 키는 필요 없습니다.

1. 통합 기능을 설치합니다(위 참고).
2. **Set up**를 선택하고 로그인합니다. Claude Code CLI가 아직 없으면 설정에서 먼저 설치를 제안한 뒤 로그인을 진행합니다.

**Claude 계정이 안전하게 유지되는 방식:** 이 통합 기능은 Anthropic의 공식 Claude Agent SDK와 설치된 Claude Code CLI를 사용합니다. OAuth 탈취, 브라우저 토큰 추출·재사용, 지원되지 않는 클라이언트로의 위장, Anthropic 인증 우회를 하지 않습니다. Anthropic이 지원하는 정상 경로를 사용하므로 토큰 탈취나 비인가 인증 우회에 따른 계정 정지 위험이 없습니다.

## 업데이트 및 제거

- **Update**는 플러그인의 최신 공개 버전을 설치합니다.
- **Remove**는 OpenCode 설정에서 플러그인을 삭제합니다. OpenCode가 다시 로드되면 공급자는 더 이상 로드되지 않습니다.

카드에 항목을 수동으로 관리해야 한다고 표시되면 **Manage plugins**를 선택해 중복 항목을 정리하세요.

## Excalidraw

Excalidraw를 사용하면 `.excalidraw` 파일과 Obsidian `.excalidraw.md` 그림을 Files에서 바로 그릴 수 있습니다. OpenChamber 확장 기능이며 같은 페이지의 **OpenChamber extensions** 아래에 표시됩니다.

1. **Settings → Integrations**를 열고 Excalidraw 카드에서 **Install**을 선택합니다. Files에서 그림을 열고 그 위에 표시되는 알림에서 **Install**을 선택해도 됩니다.
2. 그림을 다시 엽니다. 파일의 텍스트 대신 캔버스가 표시되며, Cmd/Ctrl+S, 자동 저장, 소스 보기 전환, 전체 화면은 다른 파일과 똑같이 작동합니다.

카드에서 새 버전이 나오면 확장 기능을 업데이트하고, 일시 중지했다면 다시 켜고, 제거할 수 있습니다. 제거해도 그림은 그대로 남으며 텍스트로 열릴 뿐입니다. 웹과 데스크톱에서만 사용할 수 있습니다.

## Resource Monitor

Resource Monitor는 컴퓨터가 사용하는 CPU와 메모리, 그리고 그중 OpenChamber, OpenCode, 이들이 시작한 모든 프로세스, 그 아래에서 실행되는 개발 서버가 차지하는 양을 보여 줍니다. OpenChamber 확장 프로그램이며 같은 페이지의 **OpenChamber extensions**에 표시됩니다.

1. **Settings → Integrations**를 열고 Resource Monitor 카드에서 **Install**을 선택합니다.
2. **Settings → Extensions**에서 로컬 서비스를 승인합니다. 수치는 OpenChamber가 패널 옆에서 시작하는 작은 프로세스에서 옵니다. 이 프로세스는 패널이나 **Resources** 섹션이 화면에 있을 때만 측정합니다.
3. 오른쪽 레일에서 **Resource Monitor**를 엽니다. Work Status 패널의 **Resources**에도 짧은 요약이 표시됩니다.

개발 서버나 작업의 Stop은 그 명령과 그것이 시작한 모든 프로세스를 종료하므로, watcher가 서버를 다시 띄우지 못합니다. Terminal 그룹의 **Stop all**은 터미널과 project actions에서 실행 중인 모든 것을 종료하고 터미널 탭은 열어 둡니다. OpenChamber 자체와 OpenCode 서버에는 Stop이 없습니다.

개발 서버는 내장 터미널에서, 또는 OpenChamber가 직접 OpenCode를 시작한 경우 에이전트가 시작해 OpenChamber 아래에서 실행될 때 표시됩니다. 부모 프로세스에서 분리되는 서버나 `docker compose up -d`로 시작한 컨테이너는 목록에 나오지 않습니다. 원격 OpenChamber에 연결되어 있으면 모니터는 그 컴퓨터를 보여 줍니다. 웹과 데스크톱에서만 지원됩니다.
