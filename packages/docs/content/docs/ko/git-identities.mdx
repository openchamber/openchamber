# Git 아이덴티티

git 신원은 커밋에 들어가는 이름과 이메일이자, 저장소가 원격에 로그인하는 방식입니다. 개인 저장소와 업무 저장소를 오가며 작업한다면 신원을 저장해 두고 저장소마다 알맞은 것을 적용할 수 있습니다. **Settings → Git**에서 관리합니다.

## 신원 추가하기

1. **Settings → Git**를 열고 **New**를 선택합니다.
2. 커밋에 사용할 **사용자 이름**과 **이메일 주소**를 입력합니다.
3. 푸시와 풀 방식인 **인증 방식**을 선택합니다.
   - **이 컴퓨터**: 이 컴퓨터의 Git이 이미 쓰고 있는 방식. SSH 키, 자격 증명 관리자, `gh` CLI 등
   - **계정**: 선택한 **소스 제어 계정**. [통합 기능](/ko/integrations/)의 호스트 카드에서 연결한 계정이면 무엇이든 됩니다(GitHub, GitLab, Gitea, Forgejo, Gerrit 등). 푸시는 그 계정의 토큰으로 HTTPS를 통해 이루어집니다
   - **SSH**: OpenChamber가 이 신원용으로 보관하는 키
   - **익명**: 로그인 없이 HTTPS로 공개 저장소를 읽으며, 푸시는 할 수 없습니다
4. 필요하다면 알아보기 쉽도록 색상과 아이콘을 지정합니다.

시스템의 전역 신원도 읽기 전용으로 표시됩니다.

Gerrit에서는 계정 신원이 Gerrit 사용자 이름과 연결한 HTTP 비밀번호로 Git에 로그인합니다. GitHub Enterprise 계정은 이슈와 풀 리퀘스트에 쓰이지만, 거기서 클론하고 푸시할 때는 **이 컴퓨터** 또는 **SSH**를 사용합니다.

## 저장소에 신원 적용하기

[Git 패널](/ko/git/) 상단의 신원 버튼을 선택하고 하나를 고릅니다. 추가 화면과 클론 화면에서도 같은 선택을 할 수 있습니다. 저장소에 닿을 수 없는 신원은 목록에 꺼진 상태로 남고 이유가 함께 표시됩니다. 다른 호스트의 계정, SSH 원격에 대한 계정이나 **익명**, HTTPS 원격에 대한 SSH 키가 그런 경우입니다.

신원을 적용하면 해당 저장소의 **local** git 설정에 기록되므로 그 저장소에만 영향을 주고 전역 설정은 그대로 남습니다. 터미널의 Git과 에이전트의 셸도 이 신원을 사용합니다. **시스템 아이덴티티**를 고르면 OpenChamber가 기록한 내용이 지워지고, 원래의 Git 설정이 다시 적용됩니다.

## SSH 키 암호

암호화된 SSH 키는 `~/.ssh`에서 찾기 전에 선택 사항인 암호를 입력한 다음, 지문을 확인하고 추가하세요. OpenChamber는 키를 암호화된 상태로 유지하고 암호를 OpenCode의 자격 증명 저장소에 저장합니다. 저장된 암호는 앱 내 Git 작업에만 사용됩니다. 터미널이나 에이전트가 실행하는 Git 명령은 이 암호를 가져오지 않으므로 암호화된 관리형 키는 해당 경로에서 인증할 수 없습니다.
