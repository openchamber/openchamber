# 분류 제공자 (Jev)

OpenChamber의 일부 기능은 동작하기 전에 빠른 판단이 필요합니다. 이 명령은 위험한가, 이 프롬프트는 어떤 종류의 작업인가, 사용자가 방금 실제 작업을 시작했는가. 이런 질문에 답하는 것이 TypeSafe의 작은 판단 모델 Jev입니다. 이 페이지에서는 OpenChamber가 Jev를 쓸 수 있게 하는 방법을 설명합니다.

Jev는 코드를 쓰지도, 채팅에 답하지도 않습니다. 판정만 돌려주고, OpenChamber가 그에 따라 움직입니다. OpenChamber는 답을 최대 4초까지 기다립니다.

## Jev를 쓰는 기능

| 기능 | Jev가 답하는 질문 |
| --- | --- |
| [권한과 안전망](/ko/permissions/) | 에이전트가 이 작업을 실행하기 전에 사용자에게 물어야 하는가? |
| [자동 모델 라우팅](/ko/auto-model-routing/) | 이 프롬프트는 어느 카테고리에 속하는가? |
| [작업 중인 세션](/ko/sessions-in-work/) | 방금 실제 작업을 요청했는가? 이번 턴으로 작업이 끝나는 것 같은가? |
| [요약과 다음 메시지 제안](/ko/sessions-in-work/) | 이번 턴 뒤에 요약이나 제안을 만들 가치가 있는가? |

제공자가 없으면 안전망과 Auto는 숨겨지고, 세션은 직접 옮길 때만 작업 중이 됩니다. 요약과 제안은 필터 없이 그대로 동작합니다.

## 설정하기

**설정 → 프로바이더 → 분류 제공자**를 열고 Jev 요청을 어디로 보낼지 고릅니다. 선택지는 다섯 가지입니다.

### OpenCode Zen 프로모션

기간 한정 무료이며 키가 필요 없습니다. 프로모션 기간 동안 OpenCode는 OpenChamber가 OpenCode Zen을 통해 Jev를 무료로 쓰도록 허용합니다. 이 페이지를 한 번도 건드리지 않았다면 이미 이 방식을 쓰고 있습니다.

프로모션이 끝나면 이 선택지는 사라지고, 아래 키 중 하나가 있으면 OpenChamber가 그 키로 전환합니다.

### OpenCode Zen 키

OpenCode에 저장된 Zen API 키를 사용하며, 요금은 Zen 잔액에서 나갑니다.

1. **설정 → 프로바이더**를 열고 **OpenCode Zen** 프로바이더에 API 키를 추가합니다([공급자, 모델, 에이전트](/ko/providers/) 참고).
2. **분류 제공자**로 돌아와 **OpenCode Zen 키**를 고릅니다.

OpenCode 계정으로 로그인하는 것만으로는 부족합니다. Zen은 Jev에 대해 API 키만 받습니다.

### OpenRouter 키

OpenCode에 저장된 OpenRouter API 키를 사용하며, 요금은 OpenRouter 계정으로 청구됩니다. OpenCode에서 이미 OpenRouter 모델을 쓰고 있다면 따로 설정할 것이 없습니다. 환경 변수 `OPENROUTER_API_KEY`에 있는 키도 쓸 수 있습니다. 둘 다 있으면 OpenCode에 저장된 키가 우선합니다.

1. **설정 → 프로바이더**를 열고 **OpenRouter** 프로바이더에 API 키를 추가합니다.
2. **분류 제공자**로 돌아와 **OpenRouter 키**를 고릅니다.

### Vercel AI Gateway 키

OpenCode에 저장된 AI Gateway API 키를 사용하며, 요금은 Vercel 계정으로 청구됩니다. 환경 변수 `AI_GATEWAY_API_KEY`에 있는 키도 쓸 수 있습니다. 둘 다 있으면 OpenCode에 저장된 키가 우선합니다.

1. **설정 → 프로바이더**를 열고 **Vercel AI Gateway** 프로바이더에 API 키를 추가합니다.
2. **분류 제공자**로 돌아와 **Vercel AI Gateway 키**를 고릅니다.

### TypeSafe API 키

직접 발급받은 TypeSafe 키와 할당량을 씁니다.

1. [TypeSafe](https://docs.typesafe.ai)에서 API 키를 발급받습니다.
2. **TypeSafe API 키** 칸에 붙여 넣고 **저장**을 누릅니다.

키를 저장하면 그 키가 바로 선택됩니다. 키는 OpenChamber 서버의 전용 파일에 보관되며 브라우저로 전송되지 않습니다.

제공자가 동작하면 **설정 → 프로바이더**의 카드에 **준비됨**이 표시됩니다.

## 선택한 제공자가 동작하지 않을 때

선택한 제공자를 쓸 수 없으면(프로모션 종료, 키 삭제) OpenChamber는 동작하는 첫 번째 제공자로 넘어갑니다. 직접 등록한 키가 먼저이며, TypeSafe 키, OpenRouter, Vercel AI Gateway, Zen 키, 프로모션 순입니다. 지금 어떤 것을 쓰는지는 페이지에 표시됩니다.

Jev가 한 번의 요청에서 느리거나 실패해도 망가지는 것은 없습니다. 기능마다 이런 경우를 위한 안전한 동작이 있습니다.

- 안전망은 작업을 사용자의 결정을 기다리는 상태로 둡니다.
- Auto는 프롬프트를 대체 모델로 보냅니다.
- 작업 중인 세션은 그대로 유지됩니다.
- 요약과 제안은 Jev가 없을 때처럼 생성됩니다.

## Jev가 보는 것

Jev는 대화의 짧은 발췌만 받습니다. 가장 최근 메시지와, 맥락을 위한 직전 최대 세 턴이며, 각각 앞부분 수백 자로 잘립니다. 안전망의 경우 확인 중인 작업도 OpenCode가 설명한 그대로 받습니다. 에이전트가 실행하려는 명령, 편집이라면 파일과 변경 내용입니다. 파일 전체나 이미지는 받지 않습니다.

요청은 선택에 따라 OpenChamber 서버에서 OpenCode Zen, OpenRouter, Vercel AI Gateway 또는 TypeSafe로 바로 갑니다.

## 사용할 수 있는 곳

Jev는 OpenChamber 서버에서 동작하므로 데스크톱 앱, 웹 앱, 그리고 둘 중 하나에 연결된 휴대폰에서 쓸 수 있습니다. VS Code 확장은 OpenCode와 직접 통신하므로 Jev가 없습니다. 안전망도 Auto도 없고, 세션은 수동으로만 작업 중이 됩니다.
