# Worktree 세션

worktree 세션은 자체 브랜치 위에서 체크아웃된 저장소 사본으로 실행됩니다(git worktree). 그래서 병렬 세션이 서로의 파일을 건드리지 않으며, 한 세션이 리팩터링하는 동안 다른 세션이 버그를 고칠 수 있고 오갈 필요가 없습니다.

## 만들기

1. 새 worktree 대화 상자를 엽니다. 새 세션을 시작할 때 입력창 위의 브랜치 메뉴에서 **새 worktree…** 를 고르거나, 사이드바의 프로젝트 행에 있는 worktree 버튼을 사용합니다.
2. **Start from**에서 하나를 고릅니다.
   - **new branch** — 브랜치 이름을 지정합니다
   - **existing branch** — 이미 가지고 있는 브랜치를 체크아웃합니다
   - **PR or issue** — GitHub, GitLab, Gitea, Forgejo, Gerrit, Linear 또는 확장 기능에서 하나를 고릅니다. 브랜치 이름은 그 항목을 따라 정해지고(PR은 자체 브랜치를, Gerrit 변경은 최신 패치셋을 `change-<number>`에 체크아웃합니다), 항목은 첫 메시지에 첨부됩니다
3. **Based on**(새 브랜치가 시작될 브랜치, 기본값은 원격 저장소의 기본 브랜치, 예: `origin/main`)과 **Folder name**을 확인하고, 필요할 때만 바꿉니다.
4. 만듭니다. 프로젝트에 설정 명령이 있으면 생성 직후 실행됩니다.

OpenChamber가 브랜치를 만들고 폴더를 설정한 뒤 그곳에서 새 세션을 엽니다. 바로 첫 메시지를 쓸 수 있습니다. [할 일](/ko/notes-todos-plans/)이나 [이슈 또는 풀 리퀘스트](/ko/github/)에서 바로 시작할 수도 있습니다.

질문 없이 만들려면 같은 브랜치 메뉴에서 **빠른 worktree** 를 고르세요. OpenChamber가 브랜치 이름을 정하고 새 세션을 그곳으로 연결합니다.

## 사이드바에서

worktree는 사이드바에서 한 행이고, 그 아래에 안의 모든 세션이 있습니다. 행에는 에이전트가 이름을 붙이면 작업 이름(그 전까지는 그곳에서 마지막으로 작업한 세션의 제목), 연결된 풀 리퀘스트나 이슈를 나타내는 색깔 표시, 그리고 그 안의 세션이 실행 중인지 또는 새 소식이 있는지가 표시됩니다. 풀 리퀘스트나 이슈를 위해 만든 worktree는 에이전트가 더 짧은 이름을 정할 때까지 그 항목의 제목으로 시작합니다. 행에 마우스를 올리면 브랜치가 보입니다. 클릭하면 그곳에서 마지막으로 작업한 세션이 열리고, 왼쪽의 브랜치 아이콘에 마우스를 올린 뒤 그 자리에 나타나는 화살표를 누르면 목록이 펼쳐집니다. 메뉴에서는 작업 이름을 바꾸거나, worktree를 프로젝트의 폴더로 옮기거나, 삭제할 수 있습니다. 작업이 작업 중 영역에 들어오고 나가는 방식은 [작업 중인 세션](/ko/sessions-in-work/)을 참고하세요.

## 저장소 안의 폴더에서 연 프로젝트

`repo/ai`처럼 저장소 안의 폴더에서 프로젝트를 열었다면, 새 worktree도 같은 위치에서 열립니다. 새 worktree의 세션은 체크아웃 안의 같은 폴더에서 시작하므로 OpenCode가 그 안에 있는 설정을 찾습니다. 저장소 루트에서 연 프로젝트는 이전처럼 worktree 루트에서 시작합니다. 브랜치에 해당 폴더가 없으면 세션은 worktree 루트에서 시작하고 OpenChamber가 알려 줍니다.

## 작업 되돌려 가져오기

작업이 만족스러우면 Git 보기에서 **Integrate**를 사용해 worktree의 커밋을 다른 브랜치(예: `main`)로 가져옵니다. 변경 사항이 충돌하면 충돌을 에이전트에게 넘겨 해결하게 할 수 있습니다.

## 정리하기

작업이 끝나면 worktree 행을 완료로 표시하세요. 잃을 것이 없으면 세션은 보관되고 worktree와 로컬 브랜치는 삭제됩니다. 잃을 것이 있으면 OpenChamber가 무엇을 잃게 되는지 보여 주고 결정을 맡깁니다. 메뉴에서 worktree를 삭제하거나, 세션을 삭제 또는 보관해도 됩니다. 로컬 브랜치와, 있다면 원격 브랜치까지 함께 삭제할지 선택합니다.

## 무언가 잘못된 것처럼 보이면

worktree는 폴더가 사라졌거나, 브랜치가 detached 상태이거나, 병합 또는 리베이스가 절반만 끝난 경우 주의가 필요할 수 있습니다. OpenChamber가 이를 표시하여 고칠 수 있게 합니다. [Worktrees & Git](/ko/troubleshooting/worktrees-git/)을 참고하세요.
