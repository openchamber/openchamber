# Sessions en cours

Le bloc **En cours**, en haut de la barre latérale, garde les sessions sur lesquelles vous travaillez jusqu’à ce que vous les marquiez comme terminées, peu importe depuis quand vous ne les avez pas ouvertes. Vos projets gardent toutes vos sessions ; En cours ne contient que ce que vous n’avez pas encore terminé.

## Où le trouver

Le bloc **En cours** se trouve dans la barre latérale, sous les discussions et au-dessus de vos projets ou de la chronologie. Sur le téléphone, il est au même endroit dans la liste des sessions.

Une session en cours reste aussi dans son projet et dans son dossier, et sous son projet dans la chronologie : vous la voyez donc à deux endroits. Ses sous-sessions la suivent. La recherche ne l’affiche qu’une fois, dans le bloc En cours.

Dans la vue en arbre, chaque session du bloc tient sur une ligne : titre, état et heure, avec une marque colorée quand elle a une pull request ou une issue. Survolez une ligne pour voir son projet, sa branche et ses liens, ou activez **Lignes détaillées** dans le menu d’affichage de la barre latérale pour les afficher sous le titre. La vue en liste utilise toujours deux lignes.

Pour regrouper les sessions épinglées dans leur propre bloc **Épinglées** au-dessus d’En cours, activez **Afficher la section épinglées** dans le même menu. Une session épinglée en cours n’apparaît alors que dans Épinglées.

## Comment les sessions y entrent

Suivez une session à la main, comme décrit plus bas, ou laissez les sessions y entrer seules avec **Quand une session passe en cours** dans **Paramètres → Sessions → Sessions en cours** :

- **Désactivé**, par défaut : seules les sessions que vous suivez y entrent.
- **Chaque message :** envoyez un message dans une session et elle y entre. Une session marquée comme terminée revient dès que vous y envoyez un nouveau message.
- **Jev décide :** avec un [fournisseur de classification](/fr/classification-providers/) configuré, Jev lit chaque message que vous envoyez et fait passer la session en cours quand vous demandez une modification, signalez un bug ou discutez d’une modification concrète que vous allez faire. Les questions, les explications et les recherches ne comptent pas. Jev regarde à nouveau quand l’agent termine un tour, ce qui repère le travail qui n’apparaît que dans la réponse. Une session marquée comme terminée ne revient que si Jev voit du nouveau travail dans un message envoyé après. Sans fournisseur de classification, Jev décide fonctionne comme Désactivé.

Cela vaut pour toute session de projet, y compris les sessions dans un worktree.

Si vous aviez activé vous-même **Afficher les sessions en cours** avant l’arrivée de ce réglage, il démarre sur **Chaque message**, c’est ainsi que les sessions y entraient jusque-là. Sinon, il démarre sur Désactivé.

Les discussions, les sessions archivées, les sessions de revue et les exécutions de [tâches planifiées](/fr/scheduled-tasks/) n’y entrent jamais ; si vous forkez une exécution pour continuer à travailler dessus, le fork y entre. Les sous-sessions n’y entrent pas seules ; elles suivent leur session parente.

## Suivre et terminer une session à la main

- **Suivre :** survolez une session et cliquez sur l’œil, ou choisissez **Suivre comme en cours** dans le menu de la session.
- **Terminer :** survolez une session du bloc et cliquez sur la coche, ou choisissez **Marquer comme terminé** dans le menu.

Sur le téléphone, faites glisser la ligne d’une session pour atteindre la même action, ou utilisez le menu de la session.

Les discussions n’ont pas d’œil : ce sont de simples conversations.

### « Ce travail semble terminé. »

Avec un [fournisseur de classification](/fr/classification-providers/) configuré, Jev examine chaque tour d’une session en cours. Quand un tour ressemble à la fin du travail (vous avez dit merci, demandé un commit, confirmé que ça marche), Jev ne ferme rien et laisse une indication :

- une coche grise sur la ligne de la session dans la barre latérale
- un bandeau au-dessus du champ de saisie : **Ce travail semble terminé.** avec un bouton **Marquer comme terminé**

Cliquez sur **Marquer comme terminé** si Jev a raison. Sinon, continuez simplement : l’indication disparaît avec votre prochain message. Sans fournisseur de classification, il n’y a pas d’indication et vous marquez les sessions comme terminées vous-même.

## Récapitulatif et suggestion du prochain message

Quand l’agent a fini et que la session reste calme pendant une minute, OpenChamber peut écrire deux choses avec votre petit modèle (voir [Fournisseurs, modèles et agents](/fr/providers/)) :

- **Récapitulatif :** un court rappel de ce qui a été fait et de l’état actuel, affiché sous la dernière réponse et dans l’infobulle de la session dans la barre latérale
- **Suggestion :** le message que vous enverriez probablement ensuite, sous forme de ligne en haut du champ de saisie ; un clic place le texte dans le champ, il ne part jamais tout seul

Quand Jev est disponible, OpenChamber lui demande d’abord si le tour en a besoin. Un simple « merci, c’est tout » après un vrai travail reçoit quand même un récapitulatif, mais la suggestion est sautée quand il ne reste rien à faire, et le petit modèle n’est pas appelé du tout quand aucun des deux n’est utile. Sans Jev, les deux sont générés après chaque tour, comme avant.

Activez-les ou désactivez-les dans **Paramètres → Chat → Assistance de session**.

## Paramètres

Ouvrez **Paramètres → Sessions → Sessions en cours** :

- **Afficher les sessions en cours**, activé par défaut : désactivé, il coupe toute la fonction, sans bloc et sans session qui y entre seule.
- **Quand une session passe en cours** : Désactivé, Chaque message ou Jev décide, comme décrit plus haut.

Pour masquer seulement le bloc, utilisez **Afficher la section en cours** dans le menu d’affichage de la barre latérale.

## Où ça fonctionne

Le bloc et le suivi manuel fonctionnent partout, VS Code compris. L’entrée automatique des sessions, l’indication « semble terminé » et le filtre Jev pour les récapitulatifs ont besoin du serveur OpenChamber : ils fonctionnent donc dans l’application desktop, dans l’application web et sur le téléphone, mais pas dans VS Code. Dans VS Code, vous suivez les sessions à la main.
