# Integrations

**Settings → Integrations** is where you sign in to the services OpenChamber works with. The sign-in is stored on the OpenChamber server, so web, desktop, and a paired phone share it.

## Integrations catalog

The integrations catalog lists over 150 services you can give the agent in one click: Linear, Notion, Sentry, Supabase, Figma, observability tools, CRMs, meeting notes and more. Installing one usually adds the service's MCP server (the connection the agent uses to read and change things there), and sometimes skills or a plugin that come with it. It installs for your user, so every project gets it.

1. Choose the store icon in the sidebar header.
2. Find a service: search by name, or narrow the list with a category such as **Code** or **Quality and ops**. **OpenChamber** lists our own extensions and plugins.
3. Choose **+** on its row, or open it and choose **Install**.
4. Sign in the way the service asks:
   - **OAuth**: the service's sign-in page opens in your browser. Approve access there.
   - **Token**: paste an API token into **API token**. **Get a token** opens the page where the service hands one out.
   - **No sign-in**: nothing to do.

When it's done, the service shows a check mark and appears under **Installed** on the left, and its tools are available in your next message. A yellow dot or **Sign-in required** means the sign-in didn't finish; open the service and sign in again.

Some entries need more than a sign-in:

- **Local servers** run on the machine OpenCode runs on and may need Node.js, Python with uv, or Docker. The first start can take a while.
- **Plugins** are code that runs inside OpenCode, so the catalog asks you to confirm and shows the plugin's license first.
- **Skills** that come with a service install with it. If one is missing, its own **Install** appears on the service's page.

To remove a service, open it, choose **More actions** (**⋯**), then **Uninstall**. This removes only what the catalog added; your account on the service stays as it is. You can also manage MCP servers, plugins and skills in Settings as usual.

The catalog is in the web app and desktop app. It's hidden in [enterprise mode](/security/#enterprise-mode).

## GitHub

Expand the **GitHub** card and choose **Connect GitHub** to sign in with a short device code. Once connected, OpenChamber can start sessions from issues and pull requests, attach them to messages, and open or update PRs. Everything GitHub can do is on [GitHub Issues & PRs](/github/).

## GitLab, Gitea and Gerrit

GitLab, Gitea and Gerrit each have their own card next to GitHub. Once connected, their issues and pull requests (merge requests on GitLab, changes on Gerrit) show on the [Issues and PRs](/issues-and-prs/) board and in the chat's **+** menu, like GitHub's.

- **GitLab**: on gitlab.com, sign in with a short device code, a personal access token, or the `glab` login on the server. For a self-managed GitLab, add its address and paste a personal access token with the `api` scope. Device-code sign-in works there only when the server sets `OPENCHAMBER_GITLAB_CLIENT_ID` to an application registered on that instance.
- **Gitea**: add your instance's address, such as `https://gitea.example.com`, and paste a personal access token with the `write:repository`, `write:issue` and `read:user` scopes. The card links to the page on your instance that creates one. Gitea has no device-code or CLI sign-in. It needs Gitea 1.21 or newer, served from the root of its address. Forgejo uses the same API and should work, but hasn't been tested.
- **Gerrit**: add your instance's address, such as `https://gerrit.example.com`, then your Gerrit username and an HTTP password. Generate the password in Gerrit under **Settings → HTTP Credentials**; the card links there. Your sign-in password won't work, and an account without a username can't connect. It needs Gerrit 3.8 or newer, served from the root of its address. Sites whose review address differs from the Git address, such as googlesource.com with `.gitcookies`, aren't supported.

On Gerrit you review changes. Each upload of a change is a patchset, and the change's preview lets you pick an earlier one to read. You review by voting on the project's labels, such as Code-Review and Verified, and land a change with **Submit** once its submit requirements are met. Gerrit has no issues, so only changes show. To create a change, or upload a new patchset to one, use **Push for review** in the Git panel; see [Git](/git/#push-for-review-on-gerrit).

## Linear

### Connect a workspace

1. Expand the **Linear** card and choose **Connect**.
2. Approve access in the browser tab that opens. The card shows **Waiting for Linear** until you do.

Connect another Linear organization with **Add workspace**. One workspace is current at a time: switch with **Switch to**, and **Disconnect** removes only the current one. Your project mapping stays.

### Browse issues

Linear issues live on the **Issues and PRs** board. Open it with the pull-request icon in the sidebar header, or press <kbd>⌘K</kbd> then <kbd>B</kbd> (<kbd>Ctrl+K</kbd> then <kbd>B</kbd> on Windows and Linux), and choose **Linear** at the top. The board lists the current workspace's issues and lets you:

- show one team or **All teams**
- switch the current workspace, when more than one is connected
- filter by status, by whose issues they are (**Assigned to me** or **Created by me**), and by priority, all at once, and search by title or identifier
- read an issue's description, comments, labels, and priority beside the list
- change its **Status**

### Start a session from an issue

- On the board, pick an issue and choose **Start in worktree…** for a fresh branch, or **New session** to work in the project as it is.
- In the **New Worktree** dialog, pick a Linear issue.

Either way the session opens with the issue attached to the message box, and you write the first message yourself. The board starts it in the project mapped to the issue's team, shown next to **Start in**; pick another project there if you need to. Map teams in the Linear card: **Default project** covers every team, and **Team projects** override it per team. Without a mapping, the board uses the project it showed last.

### Link an issue to a message

In the chat composer, open the **+** menu and choose **Linear**. The issue rides along with your next message as context, and the session's work status panel keeps a link back to it.

### Session comments

Turn on **Session comments** in the Linear card and a session started from an issue, or whose first message has the issue attached, posts a comment on that issue when it starts, finishes, or fails, each with a link that opens the session. Comments are only posted when this OpenChamber server has a public address, so the link works for everyone on the issue; on a local or private address nothing is posted.

## Install an integration

1. Open **Settings → Integrations**.
2. Find the integration and choose **Install**.
3. Restart OpenCode when asked — the provider appears after the restart.
4. Choose **Set up** and sign in. The models then appear in the chat model picker.

Integrations install for your user, so they work in every project. You can update or remove them from the same card at any time.

## Claude Code

Claude Code uses your Claude Pro or Max plan through the Claude Code CLI on your machine — no API keys.

1. Install the integration (above).
2. Choose **Set up** and sign in. If you don't have the Claude Code CLI yet, setup offers to install it first and then sign you in.

**How your Claude account stays safe:** this integration uses Anthropic's official Claude Agent SDK and your installed Claude Code CLI. It does not hijack OAuth, extract or replay browser tokens, impersonate an unsupported client, or bypass Anthropic's authentication flow. It stays on Anthropic's supported access path, so it does not carry the account-ban risk of token hijacking or unauthorized authentication workarounds.

## Update or remove

- **Update** installs the latest published version of the plugin.
- **Remove** deletes the plugin from your OpenCode config. The provider stops loading after OpenCode refreshes.

If a card says the entries need manual management, choose **Manage plugins** and clean up the duplicates there.

## Excalidraw

Excalidraw lets you draw in `.excalidraw` files and Obsidian `.excalidraw.md` drawings right in Files. It's an OpenChamber extension, listed under **OpenChamber extensions** on the same page.

1. Open **Settings → Integrations** and choose **Install** on the Excalidraw card. You can also open a drawing in Files and choose **Install** in the notice above it.
2. Open the drawing again. The canvas replaces the file's text, and Cmd/Ctrl+S, autosave, the source toggle, and fullscreen work as for any file.

The card updates the extension when a new version is out, turns it back on if you paused it, and removes it. Your drawings stay as they are when you remove it; they just open as text. Web and desktop only.

## Resource Monitor

Resource Monitor shows how much CPU and memory your machine uses and how much of it goes to OpenChamber, OpenCode, everything they started, and the dev servers running under them. It's an OpenChamber extension, listed under **OpenChamber extensions** on the same page.

1. Open **Settings → Integrations** and choose **Install** on the Resource Monitor card.
2. Approve its local service in **Settings → Extensions**. The numbers come from a small process OpenChamber starts next to the panel. It measures only while the panel or the **Resources** section is on screen.
3. Open **Resource Monitor** from the right-hand rail. A short readout also appears under **Resources** in the Work Status panel.

Stop on a dev server or a job ends that command with everything it started, so a watcher can't bring the server back. **Stop all** in the Terminal group ends everything running in the terminal and project actions and leaves the terminal tabs open. OpenChamber itself and the OpenCode server have no Stop.

Dev servers show up when they run under OpenChamber: started in the built-in terminal, or by an agent when OpenChamber started OpenCode itself. A server that detaches from its parent, or a container started with `docker compose up -d`, isn't listed. When you're connected to a remote OpenChamber, the monitor shows that machine. Web and desktop only.
