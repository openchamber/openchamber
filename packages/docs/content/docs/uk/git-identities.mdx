# Git-ідентичності

Git-ідентичність — це ім'я та email, які мають ваші коміти, і спосіб, яким репозиторій входить на свій remote. Якщо ви працюєте і з особистими, і з робочими репозиторіями, ви можете зберегти ідентичності й застосовувати правильну для кожного репозиторію. Керуйте ними в **Settings → Git**.

## Додавання ідентичності

1. Відкрийте **Settings → Git** і виберіть **New**.
2. Заповніть поля **Ім'я користувача** та **Адреса електронної пошти**, із якими комітити.
3. У полі **Автентифікація** виберіть, як ідентичність робить push і pull:
   - **Цей комп'ютер**: те, що вже використовує Git на цьому комп'ютері, наприклад SSH-ключі, менеджер облікових даних або `gh` CLI
   - **Обліковий запис**: вибраний вами **Обліковий запис керування кодом**, будь-який обліковий запис, підключений на картці хоста в [Інтеграціях](/uk/integrations/), наприклад GitHub, GitLab, Gitea, Forgejo чи Gerrit; push іде через HTTPS із токеном цього облікового запису
   - **SSH**: ключ, який OpenChamber зберігає для цієї ідентичності
   - **Анонімно**: читає публічні репозиторії через HTTPS без входу й не може робити push
4. За бажанням дайте їй колір та іконку, щоб її було легко впізнати.

Глобальна ідентичність вашої системи теж показується, лише для читання.

На Gerrit ідентичність з обліковим записом входить у Git з вашим ім'ям користувача Gerrit і HTTP-паролем, який ви підключили. Обліковий запис GitHub Enterprise обслуговує issues і pull requests, але клонування й push там ідуть через **Цей комп'ютер** або **SSH**.

## Застосування ідентичності до репозиторію

Натисніть кнопку ідентичності вгорі [панелі Git](/uk/git/) і виберіть потрібну. Екрани додавання й клонування пропонують той самий вибір. Ідентичність, яка не може дістатися до репозиторію, лишається в списку, але вимкнена, з поясненням причини: обліковий запис на іншому хості, обліковий запис або **Анонімно** на SSH-remote чи SSH-ключ на HTTPS-remote.

Застосування ідентичності записує її в **локальний** git-конфіг цього репозиторію, тож вона впливає лише на цей репозиторій, а ваше глобальне налаштування лишається як є. Git у терміналі й shell агента теж її використовують. **Системна ідентичність** прибирає те, що записав OpenChamber, і знову діє ваша власна конфігурація Git.
