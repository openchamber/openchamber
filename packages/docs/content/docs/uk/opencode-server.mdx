# OpenCode Server

OpenChamber працює поверх сервера OpenCode. За замовчуванням він сам запускає такий сервер, тож вам нічого робити не доводиться. Ця сторінка потрібна лише тоді, коли ви хочете спрямувати OpenChamber на сервер, який ви вже запускаєте, або керувати тим, що він запускає.

## Як OpenChamber знаходить сервер

Коли OpenChamber стартує, він шукає сервер у такому порядку:

1. повторно використовує сервер, який уже запустив
2. підключається до зовнішнього сервера, якщо ви його налаштували
3. інакше запускає власний сервер і керує ним

За замовчуванням OpenChamber керує власним сервером на виділеному порту. Порт може змінитися після перезапуску. OpenChamber не підключається автоматично до іншого сервера OpenCode на порту `4096`.

## Підключення до сервера, який ви вже запускаєте

Задайте це перед запуском OpenChamber:

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true openchamber
```

- `OPENCODE_HOST` — повна адреса вашого сервера OpenCode, разом із портом (значення на кшталт `http://localhost:4096`). У кінці не повинно бути шляху.
- `OPENCODE_SKIP_START=true` — каже OpenChamber не запускати власний сервер.

Якщо вам потрібно лише змінити порт, задайте `OPENCODE_PORT` замість `OPENCODE_HOST`.

Якщо в `OPENCODE_HOST` бракує порту або є шлях, OpenChamber ігнорує його й повертається до запуску власного сервера. Слідкуйте за журналами запуску на предмет попередження `[config]`, якщо очікуване підключення не відбулося.

## Один сервер для Desktop і VS Code

Застосунок для комп'ютера і розширення VS Code зазвичай запускають окремі сервери OpenCode. На Windows деякі плагіни, зокрема `opencode-mem`, не можуть відкрити ту саму базу даних у двох процесах. Щоб уникнути цього конфлікту, підключіть обидва застосунки до одного сервера.

Спільному серверу потрібен OpenCode 2.2.4 або новіший. Зі старішою версією обидва застосунки зупиняться на екрані «оновіть OpenCode».

1. Закрийте OpenChamber Desktop і VS Code, щоб їхні керовані сервери зупинилися. Зупиніть також будь-який інший сервер OpenCode, який використовує ті самі дані плагінів, наприклад запущений у терміналі. TUI OpenCode теж запускає фоновий сервер, який працює й після того, як ви її закрили. Перевірте його командою `opencode service status` і зупиніть командою `opencode service stop`.
2. Запустіть один сервер OpenCode і залиште його працювати:

   ```bash
   opencode serve --port 4096
   ```

   OpenCode друкує адресу, на якій слухає, у рядку `server listening on`. Використовуйте цю адресу всюди, де в кроках нижче написано `http://localhost:4096`.

   Якщо не задано ні `OPENCODE_PASSWORD`, ні `OPENCODE_SERVER_PASSWORD`, OpenCode також друкує згенерований `server password`. Якщо одну з них задано, пароль не друкується, і сервер використовує той, що ви задали. Тримайте пароль у таємниці й використайте його в наступних кроках.

3. Запустіть OpenChamber Desktop із `OPENCODE_HOST=http://localhost:4096`, `OPENCODE_SKIP_START=true` і `OPENCODE_PASSWORD`, у якому пароль сервера. На Windows запустіть його з вікна PowerShell:

   ```powershell
   $env:OPENCODE_HOST = 'http://localhost:4096'
   $env:OPENCODE_SKIP_START = 'true'
   $password = Read-Host 'OpenCode server password' -AsSecureString
   $env:OPENCODE_PASSWORD = [System.Net.NetworkCredential]::new('', $password).Password
   & "$env:LOCALAPPDATA\Programs\@openchamberelectron\OpenChamber.exe"
   ```

   Якщо ви встановили Desktop в інше місце, вкажіть шлях до свого `OpenChamber.exe`.

4. Запустіть VS Code з того самого вікна PowerShell командою `code`. У налаштуваннях VS Code задайте `openchamber.apiUrl` значення `http://localhost:4096`, потім виконайте **Developer: Reload Window**.

Тепер обидва застосунки працюють із сервером за цією адресою. Не зупиняйте його, поки користуєтеся будь-яким із них. Щоразу запускайте обидва застосунки з PowerShell, як у кроках 3 і 4: відкритий з меню «Пуск» Desktop знову запускає власний сервер, а VS Code не має пароля до спільного. Якщо ви перезапустите сервер без заданого пароля, він надрукує новий; використовуйте його. Стара назва `OPENCODE_SERVER_PASSWORD` теж працює, якщо `OPENCODE_PASSWORD` не задано. Не відкривайте сервер для ненадійної мережі. Цей спосіб не працює з сервером, який Desktop запускає сам: у нього змінюються порт і пароль.

Зовнішній сервер не отримує керованих плагінів OpenChamber. Якщо котрийсь застосунок не може підключитися, див. [Підключення до OpenCode](/uk/troubleshooting/opencode-connection/).

## Керування сервером із CLI

```bash
openchamber status
openchamber logs
openchamber restart
openchamber stop
```

`openchamber` сам по собі запускає сервер у фоні. Додайте `--foreground`, щоб лишити його прив'язаним до вашого терміналу.

## Запуск OpenChamber при вході в систему

Скористайтеся `startup enable`, щоб встановити нативний користувацький сервіс. OpenChamber використовує `launchd` на macOS, `systemd --user` на Linux і Task Scheduler на Windows.

```bash
openchamber startup enable
openchamber startup status
openchamber startup disable
```

Щоб захистити UI, задайте пароль під час увімкнення сервісу:

```bash
OPENCHAMBER_UI_PASSWORD='secret' openchamber startup enable
```

Для headless-сервера, який стартує під час входу та використовується desktop або mobile застосунками, додайте `--api-only` і доступний host:

```bash
openchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` зберігає знімок поточного середовища в сервісі, щоб запуск був ближчим до ручного запуску `openchamber` з тієї самої shell-сесії. Так зберігаються токени провайдерів, `PATH`, налаштування SSH agent та інші CLI-змінні для auth/config. Використайте `--no-env-snapshot`, якщо потрібне мінімальне середовище сервісу.

Startup-сервіс пам'ятає `--port`, `--host`, `--ui-password` і `--api-only`. CLI restart і restart під час оновлення повторно використовують ці збережені налаштування.

Щоб створити link підключення для іншого застосунку OpenChamber, використайте:

```bash
openchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

Запустіть `openchamber connect-url --help`, щоб побачити всі опції link, зокрема `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` і `--qr`.

Тунелями для такого запущеного сервісу можна керувати окремо:

```bash
openchamber tunnel start --port 3000
openchamber tunnel stop --port 3000
```

Зупинка тунелю не перезапускає сервіс або застосунок.

## «OpenCode перезапускається»

Поки сервер запускається або перезапускається, OpenChamber показує стан «OpenCode перезапускається» і призупиняє запити, доки той не буде готовий. Це нормально одразу після запуску чи перезапуску. Якщо стан так і не зникає, див. [Підключення до OpenCode](/uk/troubleshooting/opencode-connection/).
