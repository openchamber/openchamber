# Зробити розширення

Використовуйте `@openchamber/sdk`, щоб додати власну панель в OpenChamber. Розширення - це невелика вебсторінка, яку OpenChamber показує на правій рейці. Із застосунком вона спілкується через `connectHost()`: може читати поточний проєкт і сесію, показувати тости, вставляти текст у поле чату, прикріплювати задачу до сесії, а зі згоди користувача ще й створювати сесії та надсилати повідомлення.

Розширення працюють в OpenChamber у вебі, на десктопі й у мобільному застосунку. На телефоні ваші панель і сторінка показуються лише тоді, коли ви вкажете, що вони підходять для телефона; див. [На телефоні](#на-телефоні). VS Code не завантажує розширень.

## Що таке розширення

Тека з трьома файлами:

- `package.json` з блоком `openchamber` (маніфест)
- `panel/index.html`, сторінка, яку показує OpenChamber
- `panel/main.js`, ваш скрипт, зібраний в один класичний файл (IIFE, не ES-модуль, бо сторінка завантажується в ізольованому iframe)

OpenChamber ніколи не компілює ваш код. Віддавайте вже зібраний `.js`. У SDK є команда збірки; підійде й будь-який інший бандлер, який видає IIFE.

```bash
npm install @openchamber/sdk
bunx openchamber-guest-bundle panel/main.ts panel/main.js
```

Команда збірки працює на Bun. Без Bun беріть esbuild або будь-який інший бандлер з `--format=iife --platform=browser`.

Повне робоче розширення, усі три файли, є на сторінці [Приклад](/sdk/example/). Скопіюйте його і замініть API та список.

Підключіть `main.js` в `index.html` звичайним `<script src="main.js"></script>`.

## Встановити під час роботи

1. Запустіть OpenChamber у вебі або на десктопі.
2. Відкрийте Налаштування → Розширення.
3. Вставте абсолютний шлях до своєї теки і натисніть Додати.

OpenChamber читає маніфест і показує діалог зі списком того, що просить розширення (див. [Дозволи](#дозволи)). Підтвердьте, і ваша іконка з'явиться на рейці. Натисніть її, і сторінка завантажиться.

Можна також додати локальний `.zip` або https-посилання на git-репозиторій чи zip-файл. Оновлюватися вміє лише встановлення з git: підніміть `version` у `package.json` і запуште, і OpenChamber перевірить це невдовзі після відкриття та кожні кілька годин, один раз повідомить користувача й запропонує оновлення в Налаштування → Розширення. Посилання на `openchamber://extensions/install?url=<encoded repository URL>` на будь-якій сторінці відкриває десктопний застосунок із цим репозиторієм у діалозі додавання, тож можна запропонувати кнопку встановлення. `#tag` чи `#branch` в URL закріплює, за чим саме воно стежить. Їх OpenChamber копіює у свою теку даних і запускає з тієї копії, тому віддавайте зібрані файли, а не `node_modules` чи TypeScript-джерела. Видалення розширення видаляє копію. Розширення з теки працює прямо з вашої теки, тож можна редагувати, перезбирати й перезавантажувати.

## Маніфест

```json
{
  "name": "@acme/hello",
  "version": "1.0.0",
  "openchamber": {
    "apiVersion": 1,
    "engines": { "openchamber": ">=1.24.0" },
    "id": "acme-hello",
    "name": "Hello",
    "icon": "window",
    "contributes": {
      "panel": { "entry": "panel/index.html" },
      "attach": "dialog",
      "page": true,
      "capabilities": ["prompt", "sessions"],
      "integration": {
        "name": "Acme",
        "description": "Tasks from Acme",
        "token": {
          "apiOrigin": "https://api.acme.example",
          "account": { "path": "/me", "name": "login" },
          "scheme": "bearer"
        },
        "settings": [{ "id": "list-id", "label": "List ID" }]
      }
    }
  }
}
```

`version` обов'язкова і має бути semver. Налаштування → Розширення показує її на картці.

`apiVersion` дорівнює `1`. Будь-яке інше значення OpenChamber відхиляє.

`engines.openchamber` необов'язкове. Вкажіть найстарішу версію OpenChamber, з якою працює ваше розширення, як `1.24.0` або `>=1.24.0`. Старіші збірки відмовляться його встановлювати замість того, щоб ламатися пізніше.

`id`, `name` і `icon` називають розширення. `id` пишеться в kebab-case і має бути унікальним серед встановлених розширень. `icon` - це назва іконки Remixicon (`RiWindowLine` стає `window`) або SVG-файл у вашій теці, наприклад `icon.svg`. `contributes.panel` - це панель розширення на рейці: її `entry` - HTML-файл у вашій теці. Розширення без панелі на рейці пропускає `panel`. Старіші пакети тримають `id`, `name` і `icon` всередині `panel`, і це далі працює.

`contributes.attach` необов'язкове. Воно додає ваше розширення в меню + біля поля чату, щоб користувач міг вибрати задачу і прикріпити її до сесії.

- `"dialog"` відкриває вашу сторінку у вікні
- `true` або `"panel"` замість цього відкриває панель на рейці
- `{ "mode": "dialog", "entry": "panel/attach.html" }` відкриває у вікні окрему вашу сторінку, тож вибір не мусить ділити код із панеллю на рейці
- без цього поля розширення в тому меню не з'являється

`ctx.surface` має значення `panel`, `dialog`, `page`, `status` або `block`. Натискання прикріпленого елемента передає його дані в `ctx.item`; в інших випадках це `null`.

`contributes.page: true` додає повноекранну версію панелі в меню Сторінки розширень над списком сесій. `{ "entry": "panel/page.html", "title": "Board" }` задає окремий HTML і необов'язковий заголовок. `true` бере `panel.entry`; сторінці з власним `entry` панель на рейці не потрібна, тож розширення може складатися лише з повноекранної сторінки. Ізоляція та дозволи ті самі, що й у панелі. Сторінку відкриває лише користувач. Перезавантаження, пауза, видалення чи зміна сервера закривають її.

Для дошки є `host.storage` та списки проєктів, worktree і сесій із живими станами. `startSession` може працювати в іншому проєкті, не закриваючи дошку. Деталі в [Host API](/sdk/host/).

`contributes.integration` необов'язкове. Воно додає картку в Налаштування → Інтеграції, де користувач підключає обліковий запис. Див. [Облікові записи і мережа](#облікові-записи-і-мережа).

`contributes.service` необов'язкове. Воно оголошує локальний сервіс (процес, який OpenChamber запускає поруч із розширенням) для речей, до яких вебсторінка не дотягнеться, наприклад сокета Docker. Цей процес працює з повним доступом користувача і без пісочниці, тому діалог підтвердження попереджає про нього; оголошуйте його лише тоді, коли сторінка не може впоратися із завданням. Див. файл пакета `GUEST_SERVICES.md`. Сервіс із `provides: ["browser"]` може також замінити браузер агента: він відповідає на дії `browser.*` на сервері, тож агенти працюють з вебом без відкритого десктопного застосунку, а користувач обирає його в Налаштування → Інструменти OpenChamber. Такому сервісу панель не потрібна. Сервіс також може дізнаватися, що відбувається в сесіях користувача: оголосіть поруч із ним `contributes.sessionEvents`, і OpenChamber надсилатиме сервісу кожен хід, який завершився або зазнав збою, і кожен дозвіл чи питання, яке ставить агент, з усіх проєктів і без відкритого вікна. Див. [Події сесій](/sdk/host/#події-сесій). А сервіс із `provides: ["notifications"]` доставляє сповіщення користувача поруч із десктопом і телефоном: у Slack, Matrix або на власний сервер; користувач підключає обліковий запис у Налаштування → Інтеграції, а токен лишається в OpenChamber. Див. [Канали сповіщень](/sdk/host/#канали-сповіщень). Сервіс із `provides: ["tracker"]` — трекер робочих елементів поруч із Linear, з карткою облікового запису в розділі Облікові записи розширень; див. [Трекери](/sdk/host/#трекери). А сервіс із `provides: ["quota"]` звітує про використання поруч із вбудованими провайдерами, читаючи облікові дані, які OpenCode зберігає для провайдерів, перелічених у маніфесті; див. [Провайдери використання](/sdk/host/#провайдери-використання). Сервіс також може ставити маленькі значки на рядки бічної панелі через `contributes.marks`; див. [Позначки на рядках бічної панелі](/sdk/host/#позначки-на-рядках-бічної-панелі).

## Дозволи

Щоб намалювати панель і прочитати поточну сесію, дозвіл не потрібен. Він потрібен для всього, що діє від імені користувача. Перелічіть такі речі в `contributes.capabilities`:

| Дозвіл | Що дозволяє |
| --- | --- |
| `prompt` | надсилати повідомлення в сесію користувача (`prompt({ send: true })`, `startSession` з `text`) |
| `sessions` | переглядати проєкти, worktree та стани сесій; створювати й відкривати сесії в доданих проєктах |
| `files` | читати й писати файли всередині відкритого проєкту (`readFile`, `writeFile`, `listDir`, `stat` з відносним шляхом) |
| `model` | одноразова генерація тексту через Small Model користувача (`generate`), поза будь-якою сесією |

Ще тринадцять додаються автоматично: `network`, коли ви оголошуєте `integration`, `service`, коли оголошуєте `service`, `filesystem`, коли оголошуєте шаблони `filesystem`, `origins`, коли оголошуєте `origins`, `conversation`, коли дія сесії просить повідомлення (див. [Дії, команди та бейдж](#дії-команди-та-бейдж)), `transcript`, коли `sessionEvents` або `sessionControl` просить `content` (див. [Події сесій](/sdk/host/#події-сесій)), `sessionControl`, коли ваш сервіс діє над сесіями (див. [Виклик OpenChamber](/sdk/host/#виклик-openchamber-із-вашого-сервісу)), `sessionAnswers`, коли він відповідає за користувача на запити дозволів і форми агента (`sessionControl: { answers: true }`), `instructions`, коли він доповнює те, що читають агенти, `skills`, коли ви оголошуєте `contributes.skills`, теку пакета зі скілами, які доходять до кожного агента, поки розширення увімкнене, `opencodePlugin`, коли ви оголошуєте `contributes.opencodePlugin` (див. нижче), і `links`, коли ви оголошуєте `contributes.links` (див. [Посилання в повідомленнях чату](#посилання-в-повідомленнях-чату)). `marks` додається, коли ви оголошуєте `contributes.marks` (див. [Позначки на рядках бічної панелі](/sdk/host/#позначки-на-рядках-бічної-панелі)).

Користувач бачить повний список один раз, під час встановлення розширення, і або підтверджує його, або видаляє розширення. Якщо нова версія просить більше, діалог з'являється знову. Виклик, якому потрібен непідтверджений дозвіл, завершується помилкою `NOT_GRANTED`.

## Плагін OpenCode у вашому пакеті

Розширення може постачати плагін OpenCode, щоб люди встановлювали одну річ замість двох. Оголосіть `"opencodePlugin": "plugin"`, теку всередині пакета з `index.js` або `server.js` у корені. OpenCode не читає `main`, тож для файлу входу в іншому місці додайте `name` і `exports` у `package.json` цієї теки. Файл входу експортує за замовчуванням `{ id, setup }`, форму, яку завантажує OpenCode; він нічого не імпортує, бо OpenCode завантажує його простим `import()` з вашої теки, де нічого не встановлено. `input` інструмента є звичайною JSON Schema, а його `execute` відповідає `{ content }`.

```json
{
  "contributes": {
    "panel": { "id": "teapot-tools", "name": "Teapot Tools", "icon": "cup" },
    "opencodePlugin": "plugin"
  }
}
```

Діалог схвалення отримує ще один рядок, **Додати плагін до OpenCode**, який прямо каже, що код плагіна виконується всередині OpenCode з усіма правами користувача. Після дозволу OpenChamber вписує вашу теку в конфігурацію OpenCode, якою він керує, той самий файл, що несе `contributes.skills`; OpenCode, який він запускає, стежить за цим файлом і завантажує плагін за кілька секунд. Вимкнення або видалення розширення прибирає його тим самим шляхом. У власний `opencode.json` користувача нічого не пишеться: цей файл належить користувачу, а плагін у ньому пережив би ваше розширення і працював би в кожному OpenCode на машині.

Там, де цей файл не доходить до OpenCode, екран розширення каже про це і пропонує **Додати до глобальної конфігурації**, що записує вашу теку в глобальну конфігурацію OpenCode користувача як запис, який відтоді належить йому. Так буває, коли OpenChamber не запускав OpenCode, з яким спілкується, або коли середовище сервера задає власний `OPENCODE_CONFIG` (тоді плагін завантажиться під час наступного запуску OpenCode). OpenCode на іншій машині не може завантажити теку з цієї; екран каже про це й нічого не пропонує. Про плагін, який не завантажується, OpenCode повідомляє в Налаштуваннях → Плагіни, коли там є запис; ваше розширення працює далі в будь-якому разі. Встановлення відхиляє пакет, у якого немає теки плагіна або чий `package.json` не вказує файл входу.

VS Code не завантажує розширень, тож плагін не доходить до OpenCode, який він запускає. Телефон підключається до сервера OpenChamber, і плагін працює в OpenCode цього сервера. Сесія в ізольованому просторі запускає власний OpenCode, який ніколи не читає конфігурацію хоста. Корпоративний режим трактує плагін як локальний сервіс: він встановлюється лише з репозиторію, який вказав адміністратор. У SDK є робочий приклад, `examples/opencode-plugin`.

## Посилання в повідомленнях чату

Розширення може зробити свої ідентифікатори й посилання клікабельними в повідомленнях чату, тож `DEMO-12` у відповіді агента відкриває цю задачу у вашому розширенні, а не у вкладці браузера. Оголосіть, що розпізнавати і що робить натискання:

```json
"links": {
  "action": "open",
  "identifier": { "keys": ["DEMO"] },
  "urls": { "origin": "https://tasks.example.com", "identifier": "key-number", "item": ["/tasks/{id}"] }
}
```

- `identifier.keys` містить до 8 сталих ключів великими літерами. `DEMO` розпізнає `DEMO-12` лише як окреме слово; код, посилання, шляхи, слова на кшталт `XDEMO-1` і версії на кшталт `DEMO-1.5` лишаються текстом.
- `urls` розпізнає посилання на одному https-джерелі, яке має збігатися точно. `item` містить шаблони посилань того ж формату, що й у `contributes.tracker`: `{id}` один раз, у шляху або як `?name={id}`, і `{segment}` чи `{segments+}` для змінних частин. `identifier` задає, як виглядає `{id}`: `key-number`, `number` або `short-code`. Регулярних виразів писати не треба; шаблони компілює OpenChamber.
- `action: "open"` відкриває ваше розширення і передає в `ready.item` (або `onItem`) значення `{ kind: "link", identifier, url? }`: у вашому діалозі, коли `attach` має значення `"dialog"`, інакше в панелі на рейці. Звузьте тип через `isGuestLinkItem`. Для цього потрібен `panel.entry`. `url` містить натиснуте посилання без фрагмента і без query-параметрів, яких немає в самому шаблоні; для ідентифікатора в тексті це посилання, яке складає ваш перший шаблон без `{segment}`, якщо такий шаблон є й ідентифікатор має форму, яку оголошує `urls.identifier` (`DEMO-12` ніколи не підставляється в `number`).
- `action: "attach"` натомість додає в поле чату чип з ідентифікатором. Для цього потрібен шаблон без `{segment}` і `{segments+}`, щоб чип міг вказати своє посилання; з `identifier.keys` значення `urls.identifier` не може бути `number`.

Розпізнавання працює у відповідях агента і у власних повідомленнях користувача, але не в міркуваннях, виводі інструментів чи перегляді Files, а скопійоване повідомлення зберігає текст таким, яким його написали. Посилання, які OpenChamber читає сам, тобто задачі трекера, issue чи pull request репозиторію і коміти, відкриваються як завжди, а натискання з клавішею-модифікатором робить те, що зазвичай робить браузер. Оголошення `links` додає дозвіл `links`: діалог схвалення показує ваші ключі й джерело та каже, що робить натискання, а версія, яка змінює щось із цього, просить схвалення знову. `examples/tasks-demo` розпізнає `DEMO-2` і `https://example.com/tasks/DEMO-2`.

## Генерація тексту

З дозволом `model` `host.generate` просить Small Model користувача дати одноразову відповідь: резюме, заголовок, чернетку. Нічого не потрапляє в сесію, історія не зберігається, і розширення ніколи не обирає провайдера. OpenChamber використовує ту саму модель, яку використовує для власної фонової роботи, обрану в Налаштування → Сесії → Small Model, або малу модель провайдера, з яким працює користувач, або модель за замовчуванням з його конфігурації OpenCode.

```ts
const { text } = await host.generate({
  prompt: task.description,
  system: "Write a one-line summary. Return only the summary.",
  maxOutputTokens: 200,
});
```

Коли жодна модель недоступна, виклик завершується помилкою `NO_MODEL`; модель, що повернула помилку, — `MODEL_FAILED`. Промпти обмежені 64 000 символів, а виклик чекає до 90 секунд. Користувач бачить цей дозвіл як «Використовувати ваш Small Model», і це коштує йому токенів, тож тримайте промпти короткими й викликайте це по кліку, а не на кожне натискання клавіші.

## Облікові записи і мережа

Ваша сторінка працює в пісочниці і не може сама виходити в мережу: скрипти, стилі, зображення, шрифти й медіа завантажуються лише з вашого пакета, а `fetch` дістає лише файли вашого пакета. Кладіть шрифти й зображення в пакет, а не завантажуйте їх із CDN.

Щоб звертатися до зовнішнього сервісу, оголосіть `integration`, і OpenChamber робитиме запити за вас через `host.request`, додаючи токен користувача. Токен ніколи не потрапляє на вашу сторінку.

Для всього іншого, що вашій сторінці потрібно напряму, наприклад шрифтів чи зображень із CDN або публічного API, перелічіть до 8 https-джерел:

```json
"origins": ["https://fonts.example.com"]
```

Користувач бачить їх у діалозі підтвердження як адреси, на які ваше розширення може надсилати дані й з яких може їх отримувати, і підтверджує їх знову, якщо оновлення додає нове. Підтверджені джерела відкриті для `fetch`, зображень, шрифтів, стилів і медіа, але ніколи для скриптів: код має постачатися у вашому пакеті. Джерело сторінки — `null`, тож щоб прочитати відповідь `fetch`, сервер має дозволити CORS для цього джерела.

У [корпоративному режимі](/security/) розширення з `origins`, `integration` або `service` встановлюється лише з Git-репозиторію, який адміністратор додав до списку. Якщо ваше розширення може працювати без них, такі команди й далі зможуть його встановити. Щоб розробляти розширення на такій машині, попросіть адміністратора про `allowLocalExtensions`: тоді ви зможете встановити його прямо з папки.

- `token`: користувач вставляє API-токен на картці в Налаштування → Інтеграції. `apiOrigin` - єдине джерело, яке може викликати `request`. `account` необов'язкове: GET-шлях і назва поля, щоб картка могла показати, хто підключений. `scheme` каже, як надсилати токен; див. таблицю нижче. Перевірте в документації API провайдера, який заголовок він очікує.
- `oauth`: користувач вставляє client id, а OpenChamber проводить авторизацію. Потрібні `authorizeUrl`, `tokenUrl` і `apiOrigin`.
- `host: { "provider": "linear" }`: використати обліковий запис Linear, який уже підключено в OpenChamber. Client id не потрібен.

Що надсилає кожен `scheme`:

| `scheme` | Заголовок, який надсилає OpenChamber | Коли використовувати |
| --- | --- | --- |
| не вказано | `Authorization: <token>` | API документує голий токен у заголовку |
| `"bearer"` | `Authorization: Bearer <token>` | API документує bearer або personal access token |
| `"basic"` | `Authorization: Basic base64(username:token)` | API документує HTTP Basic auth з іменем користувача (часто це email) і API-токеном; картка запитує обидва, а `usernameLabel` задає підпис першого поля |

`settings` додає на картку прості текстові поля. Їхні значення приходять у `ctx.settings`. Поле з `"secret": true` замасковане на картці й ніколи не потрапляє на сторінку; ваш сервіс читає його через `readSettings()`.

## Файли

Ваша сторінка не може торкатися диска сама. OpenChamber читає і пише за неї, у межах, які підтвердив користувач.

- Відносний шлях (`README.md`, `src/index.ts`, `.`) означає відкритий проєкт. Потрібен дозвіл `files`. Немає відкритого проєкту - `NO_DIRECTORY`.
- Шлях, що починається з `/` або `~/`, означає будь-яке інше місце. Він має збігатися з одним із шаблонів, які ви оголошуєте в `contributes.filesystem`, і користувач бачить саме ці шаблони в діалозі підтвердження:

```json
"filesystem": ["~/.config/opencode/opencode.json", "~/notes/**"]
```

У шаблонах `*` означає один сегмент шляху, а `**` - будь-яку глибину. Усе поза ними - `BAD_PATH`, навіть після підтвердження. `..` не дозволяється ніколи.

```ts
const config = await host.readFile("~/.config/opencode/opencode.json");
await host.writeFile("~/.config/opencode/opencode.json", nextJson);
const { entries } = await host.listDir(".");
```

Запис атомарний: OpenChamber пише тимчасовий файл і перейменовує його, тож читач ніколи не побачить напівзаписаний файл. Файли читаються і пишуться як текст UTF-8, до 2 МБ.

## Секція в Work Status

`contributes.statusSection` додає вашу власну секцію в панель Work Status поруч із чатом. Користувачі вмикають і вимикають її та пересувають у списку секцій цієї панелі, як і вбудовані.

```json
"statusSection": { "entry": "status/index.html", "title": "Recent commits", "height": 160 }
```

- `true` бере `panel.entry`.
- `entry` є окремою HTML-сторінкою у вашій теці. З нею `panel.entry` не потрібен, тож розширення може складатися лише з цієї секції, без іконки на рейці.
- `title` замінює назву панелі в заголовку секції, до 60 символів.
- `height` задає початкову висоту в пікселях, від 24 до 480 (за замовчуванням 120). Викликайте [`host.setHeight()`](/sdk/host/), коли розмір вмісту змінюється.

Ваша сторінка бачить `ctx.surface` як `status`. OpenChamber завантажує її, лише поки панель Work Status видно, а ваша секція розгорнута, і вивантажує, коли користувач згортає секцію, тож не тримайте там нічого, що не зможете відновити. Розширення лише із секцією може використовувати дозволи, сервіс, інтеграцію, файли та сторінку з власним `entry`, але не `page: true`, `attach`, `actions` чи `commands`. Секція показується у вебі, на десктопі та у вкладці Стан роботи на телефоні, де їй не потрібне ввімкнення і вона отримує ширину телефона. Приклад `git-graph-status` є готовою секцією.

## Редактор для вашого типу файлів

`contributes.fileEditors` відкриває файли у вашій сторінці замість текстового редактора. Коли користувач відкриває відповідний файл у Files, OpenChamber показує там ваш редактор із тим самим перемикачем вихідного коду, кнопкою повноекранного режиму та кнопкою збереження, що й у вбудованих переглядачів.

```json
"fileEditors": [
  { "id": "canvas", "title": "Excalidraw", "match": ["*.excalidraw", "*.excalidraw.md"], "entry": "editor/index.html" }
]
```

- `match` порівнює лише імена файлів, без урахування регістру. `*` відповідає будь-якій послідовності символів, а `?` одному символу. Шаблон не може містити `/` і не може складатися лише із символів підстановки.
- `entry` є HTML-сторінкою у вашій теці. `panel.entry` не потрібен, тож розширення може складатися лише з редактора, без іконки на рейці.
- `content` має значення `"text"` (типово) або `"binary"`, див. нижче.
- До 8 редакторів на розширення, до 16 шаблонів у кожному.

Файлом керує OpenChamber. Ваша сторінка ніколи не читає і не записує його та не потребує для цього жодного дозволу. OpenChamber передає вам текст, просить змінений текст під час збереження і сам обробляє Cmd/Ctrl+S, автозбереження, запит про незбережені зміни, закінчення рядків і зміни на диску:

```ts
import { connectHost, createFileSaveTracker } from "@openchamber/sdk";

const host = connectHost();
let tracker = createFileSaveTracker(null);

host.onFileOpen((file) => {
  if (file.encoding !== "text") return; // текстовий редактор завжди отримує текст
  load(file.content); // а також file.path, file.name, file.readOnly
  tracker = createFileSaveTracker(versionOf(currentText()));
});

// Викликайте це після кожної зміни. `edited` притримує автозбереження, доки користувач не зупиниться.
const changed = () => host.reportFileChange(tracker.observe(versionOf(currentText())));

host.onFileSnapshot(() => ({ content: currentText(), version: versionOf(currentText()) }));

// Зміни, зроблені, поки OpenChamber записував файл, залишають його незбереженим.
host.onFileSaved((version) => host.reportFileChange({ dirty: tracker.markSaved(version), edited: false }));
```

`version` є будь-яким коротким рядком, що змінюється разом із документом, наприклад хешем. Якщо ваш редактор не вміє відкрити файл, викличте `host.reportFileUnsupported()`, і OpenChamber покаже його вихідний код із повідомленням. Файли понад 20 MB залишаються в перегляді вихідного коду.

### Бінарні файли

Вкажіть `"content": "binary"`, щоб відкривати файли, які не є текстом, наприклад таблиці, документи чи зображення. Ваш редактор отримує байти файлу і повертає байти; усе інше працює так само.

```ts
host.onFileOpen((file) => {
  if (file.encoding !== "binary") return;
  open(file.bytes); // Uint8Array, точно такий, як на диску
});

host.onFileSnapshot(() => ({ bytes: currentBytes(), version: versionOf(currentBytes()) }));
```

Бінарний редактор може взяти будь-який файл, що відповідає його шаблонам, зокрема ті, які OpenChamber сам показує в перегляді, як-от зображення та PDF. Перегляду вихідного коду він не має, а коли користувач переводить його в повноекранний режим чи виводить із нього з незбереженими змінами, OpenChamber спершу зберігає їх. Читати й записувати формат має ваш редактор: OpenChamber записує рівно ті байти, які ви повертаєте.

Ваша сторінка бачить `ctx.surface` як `file`. OpenChamber перезавантажує її і знову передає файл, коли файл змінюється на диску, користувач скасовує зміни або редактор переходить у повноекранний режим чи виходить із нього. Перемагає перше увімкнене розширення, чий шаблон збігся, і воно має пріоритет над власними переглядачами OpenChamber. Розширення лише з редактором може використовувати дозволи, сервіс, інтеграцію, файли та сторінку з власним `entry`, але не `page: true`, `attach`, `actions` чи `commands`. Редактор відкривається у вебі, на десктопі та у вкладці Файли на телефоні, де він займає весь екран і не потребує ввімкнення. Приклад `checklist-editor` є готовим редактором.

## Дії, команди та бейдж

Крім рейки і меню +, розширення може з'являтися ще в трьох місцях. Усі вони передають розширенню `item` так само, як клік по чипу.

**Дії на повідомленнях і сесіях.** Оголосіть пункти меню, і OpenChamber покаже їх поруч із вбудованими:

```json
"actions": [
  { "id": "create-task", "label": "Create task", "icon": "add-line", "where": "message", "roles": ["assistant"] },
  { "id": "summarize", "label": "Summarize session", "where": "session", "payload": ["messages"] }
]
```

`where` також приймає `selection` (виділений текст у повідомленні), `file` (рядок у Files) і `diff` (виділені рядки файлу чи diff). Їхні елементи мають `kind` з такою самою назвою: `selection` містить текст, `file` шлях, `diff` шлях і діапазон рядків. На виділенні `display` визначає, як показується дія: `label` (типово), `icon` з підписом у підказці або `both`.

Дія на повідомленні відкриває ваше розширення з `ctx.item` виду `kind: "message"`: id і назва сесії, тека проєкту, id повідомлення, його роль і текст. Дія на сесії відкриває його з `kind: "session"` та id, назвою і текою сесії. Додайте `"payload": ["messages"]`, і елемент також несе всю розмову, від найстарішого повідомлення, той самий текст, який дає експорт у Markdown. Для цього потрібен дозвіл `conversation`, який користувач бачить окремим рядком у діалозі схвалення. `item.action` каже, який пункт натиснули.

**Слеш-команди, які прикріплюють.** Оголосіть команду і обробіть її на сторінці:

```json
"commands": [{ "name": "task", "description": "Attach a task by id" }]
```

```ts
host.onResolve(async ({ command, args }) => {
  const task = await findTask(args.trim());
  return task ? { providerId: "acme-tasks", id: task.id, title: task.title, url: task.url } : null;
});
```

Коли користувач вводить `/task ABC-12` у полі чату, OpenChamber просить ваше розширення розв'язати її і прикріплює те, що ви повернули, як чип, нічого не відкриваючи. Поверніть `null`, якщо нічого не знайдено. Якщо ваша панель закрита, OpenChamber завантажує її у фоні для цього виклику. Ім'я, яке вже використовує OpenChamber або OpenCode, ігнорується.

Дії сесії та слеш-команди також з'являються в палітрі команд (⌘P або Ctrl+P), коли користувач шукає їхню назву, команду або назву вашого розширення. Дія сесії там виконується на відкритій сесії. Команда стає на початок поля чату, а вже введений текст стає її аргументом; вона виконується, коли користувач надсилає повідомлення. Дії для повідомлень, виділення, файлів і diff залишаються у своїх меню.

**Бейдж на іконці в рейці.** `host.setBadge(3)` ставить крапку на вашій іконці, а число показує в її підказці, наприклад кількість відкритих задач; `host.setBadge(null)` прибирає його. Відкриття панелі теж його прибирає.

## Ваші інструменти в чаті

Коли ваш плагін OpenCode або MCP-сервер додає інструмент, чат показує його виклики з типовою іконкою і сирим виводом. Натомість опишіть, як вони мають виглядати, без жодного коду:

```json
"tools": [
  {
    "match": "jira_*",
    "name": "Jira",
    "icon": "task-line",
    "title": "{input.key}",
    "subtitle": "{output.status}",
    "output": "table",
    "columns": ["key", "summary", "status"]
  }
]
```

`match` це ім'я інструмента так, як його повідомляє OpenCode; `*` наприкінці збігається з префіксом. `icon` - це назва іконки Remixicon або `.svg`-файл у вашому пакеті, як і `panel.icon`. `title` і `subtitle` це шаблони над `input`, `output` і `metadata` виклику. `output` визначає, як малюється тіло: `text`, `json` (дерево), `markdown`, `code` з `language`, `table` з `columns` (рядки беруться з масиву виводу або з `output.items`), `card` з `card` (один елемент як картка, див. нижче) або `auto` для типового вигляду. Точний `match` перемагає шаблон із зірочкою, а за нічиєї виграє перше встановлене розширення. Дозвіл не потрібен: це змінює лише те, як малюються дані, що вже є в чаті.

Коли в OpenCode увімкнено Code Mode, агент викликає інструменти з короткого скрипту, а не по одному. Скрипт з одним викликом показується як рядок цього інструмента, а `output` це те, що повернув скрипт. У `match` пишіть `_` там, де у скрипті крапка: `tools.github.list_issues` у скрипті це `github_list_issues`. Скрипт із кількома викликами зберігає власний рядок.

Розширенню, яке лише оформлює інструменти, сторінка взагалі не потрібна: пропустіть `panel.entry`, і воно не матиме іконки на рейці, лише картку в Налаштування → Розширення. Без сторінки воно може оголошувати `tools` і `providerLogos` і більше нічого. Інший виняток становить секція Work Status, редактор файлів або повноекранна сторінка з власним `entry`, див. вище.

### Картка для одного елемента

Коли інструмент відповідає одним об'єктом, наприклад задачею, `output: "card"` малює його як картку замість сирого JSON. `card` каже, яка частина виводу куди потрапляє:

```json
"tools": [
  {
    "match": "jira_get_issue",
    "name": "Jira issue",
    "title": "{input.key}",
    "output": "card",
    "card": {
      "label": "{output.key} · {output.fields.issuetype.name}",
      "title": "{output.fields.summary}",
      "status": {
        "value": "{output.fields.status.name}",
        "tones": { "In Progress": "info", "Blocked": "error", "Done": "success" }
      },
      "fields": [
        { "label": "Assignee", "value": "{output.fields.assignee.displayName}" },
        { "label": "Priority", "value": "{output.fields.priority.name}" }
      ],
      "link": { "label": "Open in Jira", "url": "{output.url}" }
    }
  }
]
```

`label` - це малий рядок угорі, `title` - заголовок, `status` - бейдж, `fields` - до восьми значень із підписами, а `link` - посилання внизу. Оголосіть принаймні одне з перших чотирьох. Кожне значення є шаблоном, який читає `output` інструмента. `tones` фарбує бейдж за його точним текстом, як `info`, `success`, `warning`, `error` або `neutral`. Статус, якого ви не перелічили, буде нейтральним.

Коли вивід є масивом або має масив `items`, той самий `card` малює компактний список: один рядок на елемент з його підписом, заголовком, першим полем і статусом, а `{output.…}` читає цей елемент. Показуються перші 200 елементів, і рядки не мають посилання.

Частина, значення якої немає у виводі, пропускається. Якщо у виводі немає нічого з того, що ви назвали, або вивід не є JSON, чат показує вивід так, як показав би без правила.

Посилання відкриває лише адресу `https`. `"{output.url}"` бере адресу з виводу як є. Ви також можете написати адресу самі навколо значень, наприклад `"https://tracker.example.com/browse/{output.key}"`. Тоді кожне значення проходить відсоткове кодування, тож воно не може змінити хост чи шлях, які ви написали. Розширення з `settings` інтеграції (див. Облікові записи і мережа вище) може також прочитати налаштування, яке не є секретним: `"https://{settings.site}/browse/{output.key}"`, де користувач зберіг ім'я хоста на кшталт `acme.atlassian.net` як `site`. Налаштування, яке містить повну адресу, порт або шлях, не дає посилання, як і значення, якого немає.

`card` потребує версії OpenChamber, новішої за 2.7.0. Старіша відхиляє розширення як недійсне, і `engines.openchamber` цього не змінює.

## Логотип вашого провайдера

Коли ваш плагін OpenCode реєструє провайдера моделей, вибір моделі та Налаштування зазвичай показують загальний значок. Додайте логотип у пакет і вкажіть провайдера, без коду:

```json
"providerLogos": {
  "acme-cloud": "assets/acme-cloud.svg"
}
```

Ключ це ID провайдера, як його повідомляє OpenCode. Значення це файл `.svg` або `.png` у вашому пакеті, до 1 МБ. Якщо файлу немає, він порожній або більший, встановлення не вдається. Пакет вказує до 256 провайдерів, і два ID можуть вказувати на той самий файл. Логотип зберігає власні кольори, а `currentColor` у SVG слідує за світлою або темною темою. Він замінює логотип, який застосунок містить для цього ID. Те, що користувач задав для цього провайдера, має перевагу, а за рівних умов перемагає розширення, встановлене першим. Дозвіл не потрібен. Телефон теж показує ці логотипи; VS Code не завантажує розширень, тому там їх немає.

## На телефоні

Мобільний застосунок і OpenChamber, відкритий у браузері телефона, завантажують розширення, встановлені на сервері, до якого вони підключені. Те, що OpenChamber малює з вашого маніфесту, працює там без змін: посилання в повідомленнях чату, розкладка ваших інструментів, логотипи провайдерів, рядки в меню `@`, позначки на рядках бічної панелі та картки облікових записів. Дотик до позначки відкриває вашу вкладку робочої панелі в сесії цього рядка, якщо ви задали `panel.mobile`, так само як клік на десктопі відкриває вашу панель; без цього дотик показує текст позначки й відкриває її `url`, якщо він є.

Вузькі фрейми показуються на телефоні без жодних додаткових дій з вашого боку, на ширину телефона:

- блоки в чаті
- ваша секція Work Status, у вкладці Стан роботи робочої панелі
- ваш редактор файлів, що займає вкладку Файли
- поповери, в аркуші знизу екрана (нижче)

Слеш-команди там працюють, як і дії з `"mode": "background"`. Фонові дії з'являються у власних меню телефона: в аркуші Більше дій повідомлення, в аркуші виділеного тексту, у меню рядка сесії після довгого натискання, після довгого натискання на рядок у Файлах і як кнопки з підписом під полем коментаря виділених рядків диффу.

Вашим панелі й сторінці потрібне ввімкнення, бо сторінка, зроблена для панелі на десктопі, зазвичай ламається на 390px:

```json
"contributes": {
  "panel": { "entry": "panel/index.html", "mobile": true },
  "page": { "entry": "panel/page.html", "mobile": true }
}
```

- `panel.mobile: true` робить вашу панель вкладкою робочої панелі телефона, з вашим бейджем. Воно також охоплює живу картинку, пристиковану до панелі, ваш пункт у меню + (`attach: "dialog"` відкривається там на весь екран), дії без `"mode": "background"`, посилання з `action: "open"`, дотики до чипів і `openSurface("plugin:<id>")`.
- `page: true` використовує HTML панелі, тож іде за `panel.mobile`. Об'єкт сторінки з власним `entry` іде лише за власним `mobile: true`: `panel.mobile` його не вмикає, і йому не потрібна панель для телефона, тож пакет може бути лише сторінкою для телефона. Сторінка з'являється в Більше у списку сесій телефона й відкривається на весь екран зі стрілкою назад.

Без ввімкнення нічого з цього не відкривається на телефоні: меню пропускають ваші дії, що відкрили б панель, дотик до чипа повідомляє, що ваше розширення не відкривається на телефоні, посилання працює як завжди, а `openSurface` відхиляється з `UNSUPPORTED`.

Робіть увімкнену сторінку приблизно на 360px завширшки й під дотик. `ready.device` каже, де фрейм:

| Поле | Що це |
| --- | --- |
| `formFactor` | `phone`, `tablet` або `desktop` |
| `pointer` | `coarse` для пальця, `fine` для миші |
| `insets` | `{ top, right, bottom, left }` у px: безпечна зона, на яку застосунок відсуває власний екран на телефоні з вирізом, деінде нулі |
| `keyboard` | px екрана, які закриває екранна клавіатура, `0`, поки вона схована |

OpenChamber надсилає новий `ready`, коли змінюється одне з цих значень, наприклад під час повороту або коли з'являється клавіатура, тож читайте його в `onReady` разом із темою.

[UI kit](/sdk/ui/) збільшує свої елементи керування до сенсорних розмірів при `pointer: coarse`: рядки списків і варіанти вибору щонайменше 44px заввишки, кнопки й поля 40px, малі кнопки, тригери та вкладки 36px. Поля зберігають щонайменше 16px тексту, бо iOS збільшує менше поле у фокусі. Розміри масштабуються з розміром інтерфейсу користувача й доходять до вашого розширення, щойно ви перезберете його з поточним SDK.

На телефоні поповер відкривається в нижньому аркуші застосунку, на ширину аркуша й на запитану вами висоту, до межі аркуша. Він лишається, поки користувач його не закриє, і ви отримуєте це як `outside`. `mountPopoverAnchor` відкриває його дотиком пальця чи стилуса, і цей дотик замінює власний клік елемента: ваш обробник кліку для нього не спрацьовує. Покладіть у поповер те, що робив клік, якщо це потрібно користувачеві сенсорного екрана. Клік мишею чи з клавіатури не змінюється. `API.md` у пакеті SDK описує виклики поповерів.

Старіші версії OpenChamber ігнорують `mobile` і встановлюють пакет як раніше, а також не передають `device` у `ready`, тож вважайте відсутній `device` десктопом із мишею.

## Перші рядки в панелі

```ts
import { connectHost } from "@openchamber/sdk";

const host = connectHost();

host.onReady((ctx) => {
  document.body.dataset.theme = ctx.theme.mode;
  document.body.dataset.surface = ctx.surface;
});
```

`connectHost` працює лише всередині OpenChamber. Якщо відкрити сторінку як звичайний файл, кожен виклик відхиляється з `HOST_UNAVAILABLE`.

Спершу збирайте панель з готових елементів `@openchamber/sdk/ui`: кнопки, поля, випадні списки, вкладки, списки тощо, оформлені кольорами і шрифтами застосунку, щоб панель відчувалася частиною OpenChamber. Власний HTML і CSS пишіть лише для того, чого в наборі немає. Див. [UI-набір](/sdk/ui/).
