# Робочі процеси Git

OpenChamber має вбудований вигляд git, тож ви можете переглядати зміни, комітити та керувати гілками, не перемикаючись на термінал. Відкрийте його на вкладці **Git** у правій бічній панелі.

## Перегляд і коміт

Вигляд git розділяє ваші зміни на **staged** та **unstaged**:

- клікніть **+** біля файлу, щоб додати його до staging, або **−**, щоб прибрати
- додайте до staging або приберіть усе в групі за раз
- клікніть файл, щоб побачити його diff

Потім напишіть повідомлення коміту й закомітьте. Ви можете доручити OpenChamber **згенерувати повідомлення коміту** з ваших staged-змін — він використовує модель поточної сесії, тож вам потрібна відкрита сесія.

## Гілки та історія

Вигляд git також охоплює щоденну рутину git:

- створення, перемикання, перейменування та видалення гілок
- push, pull і fetch
- перегляд історії та diff для кожного коміту
- stash і відновлення змін

## Pull request'и

Коли на хості проєкту підключено обліковий запис, вкладка **PR** дає змогу відкрити pull request, оновити його, позначити готовим чи злити. OpenChamber може написати його заголовок та опис так само, як повідомлення комітів. Це працює на GitHub, Gitea і GitLab, де вкладка відкриває merge requests. Gerrit має власну форму, **Запушити на рев’ю**. Як підключити хост, описано в [Git-хостах](/uk/github/).

## Push на рев'ю в Gerrit

У проєкті на Gerrit форма pull request стає формою **Запушити на рев’ю**. Вона пушить ваші коміти в `refs/for/<branch>`, і це створює зміну (change) або новий патчсет зміни, яку ви вже запушили. Опис зміни береться з повідомлення коміту, тому замість заголовка й тексту форма показує тему останнього коміту. Виберіть цільову гілку і, якщо треба, topic, hashtags, **У роботі** та **Приватна**. Форма працює й тоді, коли ви на самій цільовій гілці, бо з Gerrit зазвичай працюють саме так.

Gerrit зіставляє коміти зі змінами за рядком `Change-Id`, який його хук commit-msg додає до кожного повідомлення. Якщо такого рядка бракує лише в останньому коміті, **Додати Change-Id** після підтвердження змінює (amend) цей коміт; нічого не пушиться, доки ви не зробите push. Якщо його бракує в старіших комітах, push чекатиме, доки ви встановите хук і дасте кожному з них Change-Id.

Після першого push панель пропонує **Завантажити патчсет**, коли на зміні ще немає ваших локальних комітів. Зміна з ланцюжка змін показує своє місце в ньому, наприклад **2 з 3**, поруч зі своєю позначкою.

## Внесення конфліктів

Якщо злиття, rebase чи integrate натрапляє на конфлікт, OpenChamber показує, що застрягло, і дає змогу розв'язати його — зокрема передати агентові.
