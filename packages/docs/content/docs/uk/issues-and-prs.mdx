# Issues і PR

Дошка **Issues and PRs** — це окрема сторінка зі списком issues і pull requests проєкту з GitHub або GitLab (на GitLab це merge requests) або ваших issues з Linear. Виберіть елемент, і його попередній перегляд відкриється поруч зі списком. Якщо ви дивитеся тут інший проєкт, решта застосунку лишається на своєму.

## Відкрити дошку

- Натисніть іконку pull request у заголовку бічної панелі, поруч із запланованими завданнями та архівом.
- Виберіть **Issues and PRs** у палітрі команд.
- Натисніть <kbd>⌘K</kbd>, а потім <kbd>B</kbd> (<kbd>Ctrl+K</kbd>, а потім <kbd>B</kbd> у Windows і Linux). Ті самі клавіші закривають її.

На телефоні торкніться кнопки pull request унизу меню сесій. У розширенні VS Code дошки немає.

Дошка відкривається на тому проєкті, вкладці й команді, де ви її залишили.

## Пошук

Усе вміщено в один рядок панелі інструментів. Ліворуч вибір проєкту з іконками проєктів і пошуком. Поруч перемикач **Issues**, **Pull requests** і **Linear**. Issues і pull requests беруться з хостингу самого проєкту, GitHub або GitLab. Якщо в проєкту немає такого remote, видно лише **Linear**.

На **Linear** вибір проєкту стає вибором команди: виберіть **All teams** або одну команду. Якщо підключено кілька робочих просторів Linear, перемикайте їх у тому ж меню. Як підключити Linear, описано в [Інтеграціях](/uk/integrations/).

Пошук приймає назву, номер або вставлене посилання. Меню фільтрів не закривається, поки ви вибираєте, тож фільтри можна поєднувати.

Для GitHub і GitLab:

- Статус: **Open**, **Closed**, **All**, а для pull requests ще **Merged**
- Люди: **Anyone**, **Assigned to me**, **Created by me**, а для pull requests ще **Review requested**

Для Linear:

- Статус: **Open**, **All**, **Backlog**, **To Do**, **In Progress**, **In Review**, **Done**, **Canceled**, **Duplicate**
- Люди: **Anyone**, **Assigned to me**, **Created by me**
- Пріоритет: **All priorities**, **Urgent**, **High**, **Medium**, **Low**, **No priority**

## Перегляд елемента

У попередньому перегляді видно опис, мітки й коментарі. В issue з Linear натисніть на позначку статусу, щоб перевести її в інший стан команди.

У рядку **Labels** є кнопка з олівцем: вона відкриває список міток репозиторію з пошуком. Позначте потрібні або зніміть позначки. Зміна зберігається, коли ви закриваєте список, тож кілька натискань стають однією зміною. Відкритий pull request (на GitLab це merge request) має ще рядок **Reviewers**, який працює так само: у ньому люди, що можуть робити рев'ю в цьому репозиторії. На GitHub автора pull request у списку немає. В issues з Linear жодного з цих рядків немає.

## Коментарі та рев'ю

Під активністю issue чи pull request є поле коментаря. **Comment** публікує ваш текст на GitHub або GitLab, так само як <kbd>⌘</kbd>+<kbd>Enter</kbd> (<kbd>Ctrl</kbd>+<kbd>Enter</kbd> у Windows і Linux). Текст лишається в полі, доки його не опубліковано, тож у разі невдачі нічого не втрачається. Якщо перейти до іншого елемента, поле очиститься. В issues з Linear такого поля немає.

Відкритий pull request (на GitLab це merge request) має ще **Approve** і **Request changes**, і текст із поля йде разом із рев'ю. Для **Request changes** потрібен текст: напишіть, що змінити. Рев'ю стосується комітів, які показано в попередньому перегляді. Якщо відтоді хтось зробив push, рев'ю відхиляється, а попередній перегляд оновлюється, щоб ви могли подивитися ще раз. На GitLab **Request changes** працює, коли ви рев'юер цього merge request, а текст рев'ю публікується окремим коментарем. Якщо не вдалося опублікувати лише цей коментар, рев'ю все одно зараховано, а ваш текст лишається в полі.

## Початок роботи

Дії розташовано внизу попереднього перегляду.

- **New session** відкриває нову сесію в проєкті з елементом, прикріпленим до поля повідомлення. Перше повідомлення ви пишете самі.
- **Start in worktree…** для issue або **Check out in worktree…** для pull request відкриває діалог New Worktree з уже вибраним елементом. Pull request викачує власну гілку. Див. [Сесії worktree](/uk/worktrees/).

Для issue з Linear **Start in** показує проєкт, у якому почнеться сесія. Це проєкт, зіставлений з командою issue в картці Linear в [Інтеграціях](/uk/integrations/). Якщо команду не зіставлено, це проєкт за замовчуванням, а якщо немає і його, то проєкт, який дошка показувала останнім. Там же можна вибрати інший проєкт для цієї issue.

## Pull requests

Попередній перегляд pull request також показує його гілку, розмір (додані й видалені рядки та змінені файли), перевірки й рев'ю. Стрічка **Activity** розставляє коментарі, вердикти рев'ю й найновіші коміти в тому порядку, як усе відбувалося. Коміти, що йшли поспіль, згруповано, тож видно, на які коміти відповідало рев'ю.

Поруч із розміром є дві кнопки. **Changes** відкриває diff pull request у бічній панелі, а **Walkthrough** відкриває його [розбір змін](/uk/walkthrough/). Якщо застосунок зараз на іншому проєкті, спершу він перемкнеться на проєкт цього PR. Обидві кнопки є лише на десктопі та у вебі.

Унизу **Merge** спершу перепитує, а тоді зливає вашим звичним способом. Для чернетки є ще **Ready for review**.

Відкриті issue чи pull request мають унизу ще **Close issue** або **Close pull request** (на GitLab **Close merge request**), а закриті — **Reopen issue** або **Reopen pull request** (**Reopen merge request**). Підтвердження не потрібне, бо дію можна скасувати. Злитий pull request не можна ні закрити, ні відкрити знову. На GitHub issue закривається як виконана.
