# MCP Servers

An MCP server gives your agents extra tools — things like searching a database, calling an API, or reading a service you use. Add them in **Settings → MCP**.

## Add a server

1. Open **Settings → MCP**.
2. Add a server and choose its type:
   - **local** — OpenChamber runs a command on your machine. You give it the command to run and, if needed, environment variables.
   - **remote** — OpenChamber connects to a URL someone else hosts. You give it the URL and any headers it needs (for example an auth token).
3. Save. The server is on by default; you can turn it off without deleting it.

## Where it applies

Pick the scope when you add a server:

- **personal** — available in every project
- **project** — available only in the current project, and saved alongside the project's other settings

Server names use lowercase letters, numbers, hyphens, and underscores.

## Example: Build Remote Agent

Pair a phone running [Build Remote Agent](https://grokbuildremote.com/) as a **spectator** for this OpenChamber / OpenCode session. Protocol `gbr/1`. Independent product; not affiliated with xAI or SpaceX.

This does **not** replace OpenChamber’s own [device pairing](/connect-devices/) or [Private Relay](/private-relay/). Use it when you want a second phone on the free MIT `gbr-agent` Bot API.

1. Install and pair:

```bash
curl -fsSL https://grokbuildremote.com/install.sh | bash
gbr-agent version    # need v0.6.0+
gbr-agent pair && gbr-agent run
```

2. In **Settings → MCP**, add a **local** server named `gbr`. Command (after cloning [GrokBuildRemote-Agents](https://github.com/LinespottingOrg/GrokBuildRemote-Agents) and `npm install` in `mcp/gbr-mcp`):

```text
node /path/to/GrokBuildRemote-Agents/mcp/gbr-mcp/bin/gbr-mcp.js
```

Bot API is `http://127.0.0.1:8788` after `gbr-agent run`. Phone is spectator + veto, not orchestrator. Never put mailbox keys in OpenChamber settings notes or git.
