# Host-API

Gebruik deze pagina voor de precieze `connectHost`-methoden, limieten en foutcodes. Begin voor de mapindeling, het manifest en installatie bij [Een extensie bouwen](/nl/sdk/).

```ts
import { connectHost, HostRequestError } from "@openchamber/sdk";

const host = connectHost();
```

`connectHost` werpt `HOST_UNAVAILABLE` als er geen `window` is. Buiten OpenChamber geeft het een client terug waarvan elke aanroep met `HOST_UNAVAILABLE` wordt geweigerd. Roep `dispose()` aan wanneer u de pagina opruimt. Nog lopende aanroepen worden dan met dezelfde code afgewezen.

## Wat OpenChamber doorgeeft

`onReady` wordt aangeroepen met de eerste momentopname en telkens wanneer OpenChamber deze ververst.

Het is geen eenmalige callback voor het opbouwen van de interface. Bouw uw UI en registreer abonnementen één keer. Gebruik latere momentopnamen om thema en context bij te werken zonder invoervelden of concepten te vervangen. Het voorbeeld bij [UI-kit](/nl/sdk/ui/) laat zien hoe u voorkomt dat de interface opnieuw wordt opgebouwd. Veldlisteners zoals `onConnection` geven hun huidige waarde meteen door en kunnen dezelfde waarde opnieuw ontvangen bij een verversing. Vergelijk de velden waarvan uw gegevens afhangen voordat u een nieuw verzoek start en negeer antwoorden van inmiddels achterhaalde verzoeken.

| Veld | Betekenis |
| --- | --- |
| `theme.mode` | `light` of `dark` |
| `theme.tokens` | appkleuren voor achtergronden, tekst, interactiestatussen, primary en success/warning/error/info, plus `font`, `mono` en `radius`; geef deze vóór het opbouwen van de UI aan `applyHostReady` door |
| `locale` | taalcode van de app |
| `directory` | huidige projectmap, of `null` |
| `session` | `{ id, title, busy }` of `null`; zonder titel wordt de sessie-ID gebruikt. `busy` is de livestatus. `model` en `agent`, de OpenCode-agent, zijn aanwezig wanneer de sessie die heeft. |
| `surface` | `panel` in de balk, `dialog` in het bijlagevenster, `page` schermvullend, `status` in Werkstatus, `file` als editor in Bestanden, `block` in een UI-blok in de chat |
| `item` | waarvoor de weergave werd geopend, of `null`: het aangeklikte gekoppelde item met dezelfde velden als bij `attach`, inclusief `data`, een bericht met `kind: "message"` of een sessie met `kind: "session"` uit een opgegeven actie. Zie [Acties](/nl/sdk/#acties-opdrachten-en-de-badge). |
| `connection` | `{ connected, account }` voor uw integratie |
| `settings` | waarden van de velden uit `integration.settings` |

Toegangstokens verschijnen hier nooit, ook niet in een `request`-resultaat.

`onDirectory`, `onSession`, `onSessionLifecycle`, `onConnection`, `onSettings` en `onItem` geven bij een late aanmelding eerst de recentste waarde door en blijven daarna wijzigingen melden.

`theme.tokens` bevat `primaryText`, `successText`, `warningText`, `errorText` en `infoText`. Deze verplichte velden bevatten door de host berekende tekstkleuren voor neutrale achtergronden en lichtgekleurde UI-kitonderdelen, niet voor volle kleurvlakken. `applyHostReady` past ze bij elke momentopname toe. Zie [UI-kit](/nl/sdk/ui/) voor de CSS-variabelen.

## attach, startSession en sessionLink

Deze drie methoden accepteren dezelfde itemvelden:

```ts
await host.attach({
  providerId: "acme-hello",
  id: "TICKET-1",
  title: "Login is broken",
  url: "https://example.com/TICKET-1",
});

await host.attach({
  providerId: "acme-hello",
  id: "!12",
  title: "Fix login",
  url: "https://example.com/merge_requests/12",
  kind: "pull",
  author: "ada",
  branches: { head: "feature", base: "main" },
  text: "Optional notes for the model",
});

await host.startSession({
  providerId: "acme-hello",
  id: "!12",
  title: "Fix login",
  url: "https://example.com/merge_requests/12",
  kind: "pull",
  worktree: true,
  text: "Optional first message",
});
```

`providerId` is uw paneel-ID. OpenChamber overschrijft deze hoe dan ook met uw ID. `id` is uw eigen item-ID. `kind` is standaard `issue`, of `pull`. `text` is optionele modelcontext van 1 tot 16000 tekens na trimmen. `data` is eigen optionele JSON, bijvoorbeeld status of reacties, maximaal 16000 tekens na serialisatie. OpenChamber bewaart die bij het gekoppelde item en geeft haar ongewijzigd terug in `ctx.item` als de gebruiker erop klikt. Ze gaat nooit naar het model.

`startSession` accepteert `projectId` zonder het huidige project te wisselen. Laat `worktree` weg voor de doelmap, gebruik `true` voor een gegenereerde worktree, `{ kind: "existing", directory }` voor een bekende worktree of `{ kind: "new", name?, baseBranch? }` voor een benoemde nieuwe worktree. De naam bepaalt zowel de branch als de worktree. `navigation` is standaard `"preserve"`; gebruik `"open"` om de nieuwe chat te selecteren. Model, agent en variant voor het eerste bericht worden vastgelegd bij het begin van het aanmaken.

Het resultaat bevat `sessionId`, `directory`, `sent`, `linked` en eventueel `worktree`. `sent` is `sent`, `no-model`, `skipped` of `failed`. `linked: false` betekent dat het item niet op de aangemaakte sessie is opgeslagen. Blijft na een mislukte inrichting of sessieaanmaak een worktree achter, dan krijgt u `sessionId: null`, `failure: "bootstrap-failed" | "session-create-failed"` en de map/worktree terug. Controleer dit voordat u opnieuw probeert. De aanroep wacht maximaal 180 seconden. Een time-out betekent niet dat het aanmaken is teruggedraaid.

`sessionLink` koppelt het item aan de nu geopende sessie. Zonder project of sessie geeft dit `NO_SESSION`.

Limieten die de client vóór het versturen toepast:

| Veld | Maximum aantal tekens |
| --- | --- |
| `id` | 128 |
| `title` | 200 |
| `url` | 2000 |
| `text` | 16000 |
| `data` na serialisatie | 16000 |
| `author` | 80 |
| elke branchnaam | 200 |

## prompt en de sessielevenscyclus

```ts
await host.prompt({ text: "Fix the login" });
await host.prompt({ text: "Fix the login", send: true });

host.onSessionLifecycle((event) => {
  document.body.dataset.phase = event.phase;
});
```

Zonder `send` vervangt `prompt` de tekst in het chatveld. Met `send: true` wordt het bericht verstuurd met het model en de agent die de gebruiker heeft gekozen. De extensie kiest die nooit. Zonder geopende sessie volgt `NO_SESSION`. Versturen naar een bezige sessie geeft `SESSION_BUSY`; tekst in het veld plaatsen mag wel. Het resultaat is `{ sent }` met dezelfde waarden als `startSession`.

`onSessionLifecycle` meldt wat de sessie doet. `phase` is `started` terwijl het model werkt, `completed` als het inactief wordt en `failure` bij een onverwachte status. Een later geregistreerde listener krijgt direct de huidige fase.

## Projecten, worktrees en livesessies

Deze methoden gebruiken het bestaande recht `sessions` en de gedeelde appstores. Ze voeren niet voor elk verzoek een Git-scan uit en geven geen gespreksinhoud vrij.

```ts
const projects = await host.listProjects();
const projectId = projects.projects[0]?.id;
if (projectId) {
  const worktrees = await host.listWorktrees(projectId);
  const sessions = await host.listSessions(projectId);
  const stop = await host.onSessions(projectId, (snapshot) => {
    renderSessions(snapshot.sessions, snapshot.state);
  });
  // Call stop() when this view closes.
}
```

`onProjects(listener)` en `onWorktrees(projectId, listener)` werken op dezelfde manier. Wacht met `await` op de registratie om toestemmingsfouten af te handelen. Het resultaat is een functie om het abonnement op te zeggen. Eerst komt een momentopname, daarna volgen wijzigingen. `dispose()` beëindigt alle abonnementen. De host staat maximaal 32 per frame toe en ruimt ze op bij sluiten, pauzeren, verwijderen of serverwisseling.

Momentopnamen hebben `state: "loading" | "ready" | "error"`. Tijdens laden of bij fouten kunnen eerdere gegevens bewaard blijven. Alleen `ready` bevestigt dat een leeg resultaat volledig en geldig is. Sessiemomentopnamen bevatten `coverage` per map en bekende gearchiveerde sessies. Projecten geven ID, naam en map; worktrees geven map, naam, branch en beschikbaarheid. Sessies bevatten hun project, map en worktree, tijdstempels, bovenliggende ID en de gekoppelde item-ID's en gegevens van deze extensie.

`activity` is `unknown`, `idle`, `running`, `retrying`, `waiting-permission` of `waiting-question`. `outcome` is een waargenomen beurt met `completed` of `failed`, of `null`. Dit wordt niet uit de geschiedenis afgeleid en blijft voor maximaal 2.000 waargenomen sessies in het geheugen. Inactief worden na een fout behoudt de mislukte uitkomst totdat een nieuwe run begint. Noch `idle` noch `completed` markeert uw taak als klaar. Gebruik `host.openSession(sessionId)` om vanuit een kaart bewust naar de chat te gaan.

## Blijvende extensiegegevens

```ts
await host.storage.set("board", { columns: ["Todo", "Review"] });
const board = await host.storage.get("board");
const keys = await host.storage.keys();
await host.storage.delete("board");
```

Extra toestemming is niet nodig. De opslag hoort bij deze extensie op de verbonden server, blijft na herladen bestaan en wordt bij verwijderen gewist. `get` geeft `undefined` voor een ontbrekende sleutel; opgeslagen JSON-null blijft null. Sleutels bevatten 1 tot 128 tekens. Elke geserialiseerde JSON-waarde is maximaal 64 KiB UTF-8. De hele naamruimte is maximaal 2 MiB of 2.000 sleutels. Neem voor projectgebonden gegevens een project-ID op in de sleutel. Schrijfbewerkingen worden na elkaar uitgevoerd en zijn atomair. Bij fouten blijven bestaande gegevens behouden.

## request

```ts
const user = await host.request({ method: "GET", path: "/api/v2/user" });
```

`path` begint met `/` en bevat geen protocol of host. OpenChamber voegt het toe aan `apiOrigin` uit uw manifest en voegt de `Authorization`-header toe. Tokenintegraties versturen het geplakte token ongewijzigd, als `Bearer <token>` bij `token.scheme: "bearer"`, of als `Basic base64(username:token)` bij `"basic"`. OAuth- en Linear-integraties gebruiken altijd `Bearer`. Het resultaat is `{ status, body }`. De body is tekst; JSON verwerkt u zelf.

Een Linear-integratie mag ook `GET /api/linear/issues/get` gebruiken. OpenChamber beantwoordt dat via de eigen Linear-route.

Geen antwoord binnen 20 seconden geeft `HOST_TIMEOUT`.

```ts
try {
  await host.request({ method: "GET", path: "/api/v2/user" });
} catch (error) {
  if (error instanceof HostRequestError && error.code === "DISCONNECTED") {
    await host.oauthStart();
  }
}
```

## serviceRequest

Als het manifest `contributes.service` opgeeft, start OpenChamber dat proces. Uw pagina spreekt ermee via een vergelijkbare aanroep en opent nooit zelf de socket.

```ts
const status = await host.serviceStatus();
const result = await host.serviceRequest({ method: "GET", path: "/containers" });
```

Voor `path` gelden dezelfde regels als bij `request`. Een service declareren voegt `service` toe aan de bij installatie goed te keuren rechten. Tot goedkeuring geeft elke `serviceRequest` `NO_SERVICE`. Het volledige contract staat in `GUEST_SERVICES.md` in het pakket.

## Sessiegebeurtenissen

Uw pagina weet alleen van een sessie zolang die open is. Uw service kan meer weten: geef `contributes.sessionEvents` op naast `contributes.service`, en OpenChamber stuurt de gebeurtenissen die u opgeeft naar de service, uit elk project, of er nu een venster open is of niet.

```json
"service": { "entry": "service/main.js", "runtime": "host" },
"sessionEvents": { "events": ["turn-finished", "question-asked"], "content": true }
```

De gebeurtenissen zijn `turn-started`, `session-created`, `session-archived`, `session-deleted`, `turn-finished` (de agent is klaar en wacht op niets: geen lopende subagent, geen openstaande toestemming of vraag, geen doelstap), `turn-failed`, `permission-asked` en `question-asked`. Een beurt die de gebruiker heeft gestopt, stuurt niets. De goedkeuring van de extensie is het abonnement; het toestemmingsvenster toont de gebeurtenissen onder de regel van de service. Zonder `content` krijgt de service alleen identificatiegegevens: de sessie, de projectmap en de items die de gebruiker eraan heeft gekoppeld. Met `"content": true` vraagt het manifest ook om een recht dat de gebruiker als eigen regel ziet, **Lezen wat de agent op de achtergrond zegt**, en draagt elke gebeurtenis het eindantwoord van de agent, de velden van de vraag of de details van de toestemming.

Elke gebeurtenis komt aan als één `POST /session-events` met de bearer van de service. Lees hem met `readSessionEventRequest` en antwoord met `{ "ok": true }`:

```ts
import { SESSION_EVENTS_PATH, readSessionEventRequest } from "@openchamber/sdk";

// inside your service's request handler, after the bearer check
if (url.pathname === SESSION_EVENTS_PATH) {
  const request = readSessionEventRequest(body);
  if (!request) return json(res, 400, { ok: false, error: "not a session event" });
  const { event, content } = request;
  if (event.type === "turn-finished" && event.project.directory === myProject) {
    await postComment(event.linked, content?.type === "turn-finished" ? content.reply : "");
  }
  return json(res, 200, { ok: true });
}
```

De gebeurtenissen van elk project worden verstuurd. Vergelijk `event.project.directory` met uw eigen instellingen en antwoord voor de rest met `{ "ok": true }`. Bezorging gebeurt hoogstens één keer en in volgorde, één verzoek tegelijk. Een mislukt antwoord laat uw gebeurtenissen 30 seconden vallen, en niets wordt opnieuw verstuurd nadat OpenChamber of uw service niet bereikbaar was. De service heeft hiervoor geen paneel nodig. Het voorbeeld `session-events-log` schrijft elke gebeurtenis naar een bestand.

## OpenChamber aanroepen vanuit uw service

Een service kan handelen zonder dat er een venster open is. `createServiceHost` is de weg terug naar OpenChamber:

```ts
import { createServiceHost } from '@openchamber/sdk';

const host = createServiceHost({ env: process.env });

const { sessionId } = await host.sessions.start({ prompt: 'Summarize the failed deploy', directory });
await host.sessions.send(sessionId, 'Now write the incident note');
await host.setInstructions(directory, 'Deploys run through the release branch.');
await host.emit('deploy-finished', { id: 42 });
```

`sessions.start`, `sessions.send`, `sessions.retry` en `sessions.status` hebben `contributes.sessionControl` nodig, dat de gebruiker als eigen regel goedkeurt. `sessions.lastReply` heeft `sessionControl: { content: true }` nodig. `setInstructions` heeft `contributes.instructions` nodig en vult aan wat agents lezen, in één map of, met `null`, overal.

`emit` bereikt uw open frames via `host.onServiceEvent`, zodat een paneel niet meer hoeft te pollen. Niets wordt opnieuw verstuurd, dus een frame dat later opent, leest eerst de huidige status. `readSettings` geeft de service de instellingen van de integratie, inclusief `secret`-velden, en `needsConfiguration` toont een bericht op de kaart van de extensie.

## Draaien zonder dat iemand erom vraagt

Een service start bij het eerste verzoek, en de service van een rol stopt bij inactiviteit. `service.keepRunning: true` start hem samen met OpenChamber en brengt hem terug als hij stopt. `service.schedule` wekt hem volgens een schema:

```json
"service": {
  "entry": "service/main.js",
  "runtime": "host",
  "keepRunning": true,
  "schedule": [{ "id": "nightly", "cron": "0 3 * * *", "timezone": "Europe/Kyiv" }]
}
```

Een run is één `POST /schedule`. Lees hem met `readServiceScheduleRequest` en antwoord met 200. Een run die is gemist terwijl OpenChamber niet draaide, vervalt. Een service die externe gebeurtenissen nodig heeft, houdt een eigen verbinding open of pollt.

## Rijen in het @-menu

`contributes.mentions: { label }` voegt een sectie toe aan het `@`-menu van het chatveld. Uw service beantwoordt `POST /mentions/search` binnen 2 seconden met `{ items: [{ id, title, subtitle?, url? }] }` en `POST /mentions/resolve` met `{ text }` voor de rij die de gebruiker kiest. De tekst gaat met het bericht naar de agent, en de gebruiker ziet een chip. Een trage service voegt geen rijen toe en houdt de bestanden nooit op; een rij die niet gelezen kan worden, laat geen chip achter en meldt dat.

## Blokken in de chat

`contributes.blocks` voegt componenten toe die agents in een UI-blok kunnen schrijven. Uw eigen pagina tekent elk daarvan, in dezelfde sandbox en met dezelfde rechten als uw paneel.

```json
"blocks": [{ "name": "JiraIssue", "description": "A Jira ticket", "args": ["key"], "entry": "blocks/issue.html" }]
```

De agent schrijft `JiraIssue("OPE-1")`, en uw pagina leest de aanroep:

```ts
host.onBlock(({ args }) => draw(args.key));
```

Roep `host.setHeight(px)` aan wanneer de inhoud van grootte verandert. Maximaal 4 componenten per extensie, omdat elke handtekening tekst is die elke sessie leest.

Een blok kan de agent antwoorden, zoals een knop in een blok dat doet. Roep `host.answerBlock(text)` aan vanuit een klik: de agent krijgt de tekst en start zijn volgende beurt. Eén antwoord per blok, en `block.answered` bewaart het na herladen, dus teken het blok dan als beantwoord.

```ts
host.onBlock(({ args, answered }) => draw(args.key, answered));
button.onclick = () => host.answerBlock('Close this ticket');
```

De argumenten worden door een model geschreven, dus tekst van een webpagina of ticket kan ze sturen. Behandel ze als onbetrouwbaar en doe niets met neveneffecten totdat de gebruiker klikt.

## Meldingskanalen

Een service kan de meldingen van de gebruiker bezorgen, naast de desktop en de telefoon: geef `provides: ["notifications"]` op en beschrijf het kanaal in `contributes.notifications`.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["notifications"] },
"notifications": {
  "label": "Slack",
  "instances": { "kind": "fixed", "origin": "https://slack.com" },
  "token": { "header": "authorization", "scheme": "bearer", "scopes": ["chat:write"] }
}
```

OpenChamber maakt uit die beschrijving een accountkaart voor het kanaal bij Instellingen → Integraties en bewaart het account. De gebruiker verbindt het daar, het token blijft in OpenChamber en uw service ziet het nooit. Zodra een account is verbonden, gaat elke melding die OpenChamber naar de telefoon zou sturen ook naar uw service, volgens de meldingsinstellingen van de gebruiker en alleen zolang er geen venster zichtbaar is, tenzij de gebruiker heeft gekozen om altijd een melding te krijgen. De extensie pauzeren stopt het.

OpenChamber stuurt drie aanroepen door naar `POST /notifications`: `auth.probe` (is dit een server waaraan u bezorgt), `auth.verify` (van wie is dit token) en `notify` (één melding). Lees elke aanroep met `readNotificationsProviderRequest` en bereik de server van het kanaal alleen via de outbound-helper, die uw verzoek met de handle van de aanroep naar OpenChamber stuurt. OpenChamber voegt het token toe en houdt het verzoek op de server van het account.

```ts
import { NOTIFICATIONS_PROVIDER_PATH, createNotificationsOutbound, readNotificationsProviderRequest } from "@openchamber/sdk";

const outbound = createNotificationsOutbound({ env: process.env });

// inside your service's request handler, after the bearer check
if (url.pathname === NOTIFICATIONS_PROVIDER_PATH) {
  const request = readNotificationsProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a notifications call" } });
  if (request.method === "notify") {
    const { notification } = request.input as { notification: GuestNotification };
    const answer = await outbound.request(request.session.handle, {
      method: "POST", path: "/api/chat.postMessage",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ channel: "#agents", text: `${notification.title}: ${notification.body}` }),
    });
    return json(res, 200, answer.status === 200 ? { ok: true, data: { delivered: true } } : { ok: false, error: { message: `Slack answered ${answer.status}`, status: answer.status } });
  }
  // auth.probe → { ok: true, data: { supported: true } }; auth.verify → { ok: true, data: { account: { id, login } } }
}
```

Naar welke ruimte of welk kanaal een project gaat, bepaalt uw extensie zelf: de melding draagt `directory` en `sessionName`. In de enterprise-modus draagt ze alleen de algemene titel, net als de telefoon. Het voorbeeld `notification-webhook` is een compleet kanaal met een ontvanger om het tegen te testen.

## Trackers

Een service kan een tracker voor werkitems zijn naast Linear: geef `provides: ["tracker"]` op en beschrijf de tracker in `contributes.tracker`. OpenChamber zet hem dan naast Linear overal waar trackers verschijnen, alleen op basis van het manifest, nog voordat de service ooit draait.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["tracker"] },
"tracker": {
  "wire": 1,
  "label": "YouTrack",
  "instances": { "kind": "user", "label": "Server address", "placeholder": "https://youtrack.example.com" },
  "auth": { "token": { "header": "authorization", "scheme": "bearer", "createPath": "/users/me?tab=account-security" } },
  "capabilities": { "stateUpdate": true, "labels": true, "priority": true, "projectMapping": true, "sessionComments": true },
  "stateFilters": ["open", "all", "todo", "in-progress", "done"],
  "identifier": "key-number",
  "urls": { "item": ["/issue/{id}", "/{segments+}/issue/{id}"] }
}
```

De gebruiker verbindt accounts op de kaart van de tracker onder Extensieaccounts: een token, of inloggen in de browser wanneer u `auth.oauth` opgeeft (OpenChamber voert het inloggen uit met de client-ID die de gebruiker invoert en bewaart de tokens). Uw service ziet nooit inloggegevens. `urls.item` zijn sjablonen voor het adres van een item, met `{id}` voor de identificatie (ook als `?name={id}` wanneer die in de query meereist); OpenChamber compileert ze zodat geplakte links gekoppelde items worden. `identifier` zegt hoe de sleutel eruitziet: `key-number` (`PROJ-42`), `number` of `short-code`.

OpenChamber stuurt negen aanroepen door naar `POST /tracker`: `auth.probe` en `auth.verify`, de leesaanroepen `items.list`, `items.get`, `items.liveSummaries`, `states.list` en `containers.list`, en de schrijfaanroepen `items.updateState` en `comments.create`. Lees elke aanroep met `readTrackerProviderRequest`, antwoord in de neutrale itemvormen en bereik de server van de tracker alleen via de outbound-helper, die uw verzoek met de handle van de aanroep naar OpenChamber stuurt; OpenChamber voegt de inloggegevens toe en houdt het verzoek op de server van het account. De handle van een leesaanroep verstuurt alleen `GET`.

```ts
import { TRACKER_PROVIDER_PATH, createTrackerOutbound, readTrackerProviderRequest } from "@openchamber/sdk";

const outbound = createTrackerOutbound({ env: process.env });

// inside your service's request handler, after the bearer check
if (url.pathname === TRACKER_PROVIDER_PATH) {
  const request = readTrackerProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a tracker call" } });
  if (request.method === "items.get") {
    const answer = await outbound.request(request.session.handle, { method: "GET", path: `/api/issues/${encodeURIComponent(String(request.input.id))}` });
    if (answer.status === 404) return json(res, 200, { ok: true, data: { item: null } });
    if (answer.status !== 200) return json(res, 200, { ok: false, error: { message: `YouTrack answered ${answer.status}`, status: answer.status } });
    return json(res, 200, { ok: true, data: { item: toTrackerItem(JSON.parse(answer.body)) } });
  }
}
```

Wanneer de gebruiker sessiereacties inschakelt, roept OpenChamber `comments.create` aan met "session started", "completed" of "failed" en een link naar de sessie, elk één keer; de reactie draagt verder niets. Het voorbeeld `tracker-provider` is een complete tracker met een nepserver om het tegen te testen.

## Verbruiksproviders

Een service kan het verbruik naast de ingebouwde providers rapporteren: geef `provides: ["quota"]` op en noem in `contributes.quota.providers` de OpenCode-providers waarvan hij de aanmeldgegevens nodig heeft. OpenChamber noemt de provider `ext-<panel.id>`, tekent zijn kaart met de naam en het pictogram van de extensie en bevraagt hem zoals een ingebouwde provider.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["quota"] },
"quota": { "providers": ["openrouter"] }
```

De goedkeuringsdialoog noemt die providers, en een versie die de lijst wijzigt, vraagt opnieuw. Bij elke vernieuwing stuurt OpenChamber één aanroep, `usage.read`, naar `POST /quota`, met in `input.credentials` de aanmeldgegevens die OpenCode bewaart voor elke genoemde provider waarvoor het die heeft (een API-sleutel of de tokens van een browseraanmelding) en verder niets uit de opslag. Een genoemde provider waarvoor OpenCode geen aanmeldgegevens heeft, wordt als niet ingesteld getoond en de service wordt niet aangeroepen; een lege lijst is toegestaan, voor een provider waarvan de sleutel in de eigen instellingen van de extensie staat.

Lees de body met `readQuotaProviderRequest` en antwoord `{ ok: true, data }` met het resultaat dat een ingebouwde provider berekent: `ok`, `configured`, `error`, `planLabel` en `usage.windows` per vensternaam, elk met `usedPercent`, `windowSeconds`, `resetAt` (epoch in milliseconden) en een optionele `valueLabel` of `value`, plus `usage.models` voor vensters per model. OpenChamber leidt het resterende deel, de aftelling tot de reset en de opgemaakte tekst af, zodat de kaart overeenkomt met die van een ingebouwde provider.

```ts
import { QUOTA_PROVIDER_PATH, readQuotaProviderRequest } from "@openchamber/sdk";

// inside your service's request handler, after the bearer check
if (url.pathname === QUOTA_PROVIDER_PATH) {
  const request = readQuotaProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a usage call" } });
  const credential = request.input.credentials.openrouter;
  const bearer = credential.type === "api" ? credential.key : credential.access;
  const answer = await fetch("https://openrouter.ai/api/v1/key", { headers: { authorization: `Bearer ${bearer}` } });
  if (answer.status === 401) return json(res, 200, { ok: true, data: { ok: false, configured: true, error: "OpenRouter refused the key.", usage: null } });
  return json(res, 200, { ok: true, data: toUsage(await answer.json()) });
}
```

De service antwoordt binnen 20 s en stopt na tien minuten zonder aanroep; de verbruikspagina vernieuwt elke drie minuten zolang zij open is. Het voorbeeld `quota-provider` is een complete provider met een nep-verbruiks-API om hem tegen te testen.

## Bestanden

Een relatief pad ligt binnen het geopende project en vereist `files`. Een pad met `/` of `~/` moet passen bij een opgegeven `contributes.filesystem`-patroon en vereist `filesystem`. Zie [Een extensie bouwen](/nl/sdk/#bestanden) voor de regels.

```ts
const { content } = await host.readFile("package.json");
await host.writeFile("notes/today.md", "# Today\n");
const { entries } = await host.listDir("src");
const info = await host.stat("~/.config/opencode/opencode.json");
```

Limieten: paden tot 1024 tekens, inhoud tot 2.000.000 tekens en mappenlijsten tot 2000 vermeldingen. Te grote inhoud geeft `FILE_TOO_LARGE`.

## generate

```ts
const { text } = await host.generate({ prompt: notes, system: "Summarize in one sentence." });
```

`prompt` bevat na trimmen 1 tot 64.000 tekens, `system` maximaal 8.000 en `maxOutputTokens` ligt tussen 1 en 4.000. Niets gaat een sessie in en er wordt geen geschiedenis bewaard. De extensie kiest nooit het model. De aanroep wacht maximaal 90 seconden. Zonder bruikbaar Small Model volgt `NO_MODEL`; een modelfout geeft `MODEL_FAILED`. Zie [Tekst genereren](/nl/sdk/#tekst-genereren).

## Foutcodes

Mislukte aanroepen werpen `HostRequestError`. `code` is een van de onderstaande waarden; `message` geeft meer informatie.

| Code | Wanneer |
| --- | --- |
| `HOST_UNAVAILABLE` | geen window, niet binnen OpenChamber of `dispose()` is uitgevoerd |
| `HOST_TIMEOUT` | geen antwoord binnen 20 seconden |
| `HOST_REJECTED` | OpenChamber weigert of antwoordt met een code die deze SDK niet kent |
| `DISCONNECTED` | geen token of Linear-verbinding voor de integratie |
| `BAD_PATH` | ongeldig pad of poging buiten de toegestane origin te gaan |
| `NO_INTEGRATION` | het manifest bevat geen `integration` |
| `NO_SESSION` | `prompt` of `sessionLink` zonder geopende sessie |
| `SESSION_BUSY` | `prompt({ send: true })` terwijl de sessie bezig is |
| `DISABLED` | de gebruiker heeft de extensie gepauzeerd bij Instellingen → Extensies |
| `NO_SERVICE` | geen service opgegeven, goedgekeurd of actief |
| `NOT_GRANTED` | het benodigde recht is niet goedgekeurd |
| `SERVICE_FAILED` | de service is vastgelopen of werd nooit gereed |
| `NO_DIRECTORY` | relatief bestandspad of `openCommit` zonder geopend project |
| `NOT_FOUND` | `readFile` voor een ontbrekend bestand of `openCommit` voor een commit buiten het project |
| `FILE_TOO_LARGE` | bestandsinhoud boven de lees- of schrijflimiet |
| `DENIED` | het besturingssysteem weigert de bestandsbewerking |
| `NO_MODEL` | `generate` zonder beschikbaar Small Model |
| `MODEL_FAILED` | het Small Model gaf een fout |
| `UNSUPPORTED` | deze OpenChamber kan de aanroep niet uitvoeren, bijvoorbeeld `openCommit` zonder diffweergave |
