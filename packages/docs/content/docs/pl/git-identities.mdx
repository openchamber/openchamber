# Tożsamości Git

Tożsamość git to imię i adres e-mail, które noszą Twoje commity, oraz sposób, w jaki repozytorium loguje się do swojego remote'a. Jeśli pracujesz z repozytoriami osobistymi i służbowymi, możesz zapisać tożsamości i zastosować właściwą dla każdego repozytorium. Zarządzaj nimi w **Settings → Git**.

## Dodaj tożsamość

1. Otwórz **Settings → Git** i wybierz **New**.
2. Wypełnij pola **Nazwa użytkownika** i **Adres e-mail**, którymi chcesz commitować.
3. W polu **Uwierzytelnianie** wybierz, jak tożsamość wypycha i pobiera:
   - **Ten komputer**: to, czego Git na tym komputerze już używa, na przykład klucze SSH, menedżer poświadczeń albo CLI `gh`
   - **Konto**: wybrane przez Ciebie **Konto kontroli źródeł**, dowolne konto połączone na karcie hosta w [Integracjach](/pl/integrations/), na przykład GitHub, GitLab, Gitea, Forgejo albo Gerrit; wypychanie idzie przez HTTPS z tokenem tego konta
   - **SSH**: klucz, który OpenChamber przechowuje dla tej tożsamości
   - **Anonimowo**: czyta publiczne repozytoria przez HTTPS bez logowania i nie może wypychać
4. Opcjonalnie nadaj jej kolor i ikonę, by łatwo było ją rozpoznać.

Globalna tożsamość Twojego systemu również jest pokazana, tylko do odczytu.

Na Gerrit tożsamość z kontem loguje się do Git Twoją nazwą użytkownika Gerrit i hasłem HTTP, które połączyłeś. Konto GitHub Enterprise obsługuje issues i pull requesty, ale klonowanie i wypychanie idą tam przez **Ten komputer** albo **SSH**.

## Zastosuj tożsamość do repozytorium

Kliknij przycisk tożsamości u góry [panelu Git](/pl/git/) i wybierz jedną. Ekrany dodawania i klonowania oferują ten sam wybór. Tożsamość, która nie może dotrzeć do repozytorium, zostaje na liście jako wyłączona, z podanym powodem: konto na innym hoście, konto albo **Anonimowo** przy remote SSH, albo klucz SSH przy remote HTTPS.

Zastosowanie tożsamości zapisuje ją do **lokalnej** konfiguracji git tego repozytorium, więc wpływa tylko na to repozytorium, a Twoje ustawienie globalne zostaje bez zmian. Git w terminalu i powłoka agenta też jej używają. **Tożsamość systemowa** usuwa to, co zapisał OpenChamber, więc znów obowiązuje Twoja własna konfiguracja Git.

## Hasła kluczy SSH

W przypadku zaszyfrowanego klucza SSH wpisz opcjonalne hasło przed wyszukiwaniem w `~/.ssh`, a następnie potwierdź odcisk i dodaj klucz. OpenChamber zachowuje zaszyfrowany klucz i zapisuje hasło w magazynie poświadczeń OpenCode. Zapisane hasła działają tylko dla operacji Git w aplikacji. Polecenia Git w terminalu lub uruchamiane przez agentów nie pobierają ich, więc zaszyfrowany zarządzany klucz nie może uwierzytelnić się w ten sposób.
