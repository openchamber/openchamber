# OpenCode Server

OpenChamber działa na bazie serwera OpenCode. Domyślnie uruchamia go za Ciebie, więc nie musisz robić nic dodatkowego. Ta strona jest potrzebna tylko wtedy, gdy chcesz wskazać OpenChamber serwer, który już uruchamiasz, albo zarządzać tym, który sam startuje.

## Jak OpenChamber znajduje serwer

Gdy OpenChamber się uruchamia, szuka serwera w tej kolejności:

1. ponownie używa serwera, który już uruchomił
2. łączy się z zewnętrznym serwerem, jeśli go skonfigurujesz
3. w przeciwnym razie uruchamia i obsługuje własny serwer

Domyślnie OpenChamber zarządza własnym serwerem na przydzielonym porcie. Port może się zmienić po ponownym uruchomieniu. OpenChamber nie łączy się automatycznie z innym serwerem OpenCode na porcie `4096`.

## Połącz się z serwerem, który już uruchamiasz

Ustaw te wartości przed uruchomieniem OpenChamber:

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true openchamber
```

- `OPENCODE_HOST` — pełny adres Twojego serwera OpenCode, wraz z portem (wartość taka jak `http://localhost:4096`). Nie może zawierać ścieżki na końcu.
- `OPENCODE_SKIP_START=true` — informuje OpenChamber, aby nie uruchamiał własnego serwera.

Jeśli chcesz zmienić tylko port, ustaw `OPENCODE_PORT` zamiast `OPENCODE_HOST`.

Jeśli w `OPENCODE_HOST` brakuje portu lub zawiera ścieżkę, OpenChamber go zignoruje i wróci do uruchamiania własnego serwera. Obserwuj logi startowe pod kątem ostrzeżenia `[config]`, jeśli oczekiwane połączenie nie nastąpiło.

## Jeden serwer wspólny z VS Code

Aplikacja na komputer i rozszerzenie VS Code zwykle uruchamiają osobne serwery OpenCode. W systemie Windows niektóre wtyczki, w tym `opencode-mem`, nie mogą otworzyć tej samej bazy danych w dwóch procesach. Aby uniknąć tego konfliktu, połącz obie aplikacje z jednym serwerem.

Wspólny serwer wymaga OpenCode 2.2.4 lub nowszego. Przy starszej wersji obie aplikacje zatrzymają się na ekranie „zaktualizuj OpenCode”.

1. Zamknij OpenChamber Desktop i VS Code, aby ich zarządzane serwery się zatrzymały. Zatrzymaj też każdy inny serwer OpenCode, który używa tych samych danych wtyczek, na przykład uruchomiony w terminalu. TUI OpenCode też uruchamia serwer w tle, który działa dalej po jego zamknięciu. Sprawdź go poleceniem `opencode service status` i zatrzymaj poleceniem `opencode service stop`.
2. Uruchom jeden serwer OpenCode i zostaw go włączonego:

   ```bash
   opencode serve --port 4096
   ```

   OpenCode wypisuje adres, na którym nasłuchuje, w wierszu `server listening on`. Używaj tego adresu wszędzie tam, gdzie w kolejnych krokach jest `http://localhost:4096`.

   Jeśli nie ustawiono ani `OPENCODE_PASSWORD`, ani `OPENCODE_SERVER_PASSWORD`, OpenCode wypisuje też wygenerowane `server password`. Jeśli jedna z nich jest ustawiona, hasło nie jest wypisywane, a serwer używa tego, które ustawiono. Zachowaj hasło dla siebie i użyj go w kolejnych krokach.

3. Uruchom OpenChamber Desktop z `OPENCODE_HOST=http://localhost:4096`, `OPENCODE_SKIP_START=true` i `OPENCODE_PASSWORD` zawierającym hasło serwera. W systemie Windows uruchom go z okna PowerShell:

   ```powershell
   $env:OPENCODE_HOST = 'http://localhost:4096'
   $env:OPENCODE_SKIP_START = 'true'
   $password = Read-Host 'OpenCode server password' -AsSecureString
   $env:OPENCODE_PASSWORD = [System.Net.NetworkCredential]::new('', $password).Password
   & "$env:LOCALAPPDATA\Programs\@openchamberelectron\OpenChamber.exe"
   ```

   Jeśli Desktop jest zainstalowany w innym miejscu, podaj ścieżkę do swojego `OpenChamber.exe`.

4. Uruchom VS Code z tego samego okna PowerShell poleceniem `code`. W ustawieniach VS Code ustaw `openchamber.apiUrl` na `http://localhost:4096`, a potem uruchom **Developer: Reload Window**.

Obie aplikacje korzystają teraz z serwera pod tym adresem. Nie wyłączaj go, dopóki używasz którejkolwiek z nich. Za każdym razem uruchamiaj obie aplikacje z PowerShell tak jak w krokach 3 i 4: otwarty z menu Start Desktop znowu uruchamia własny serwer, a VS Code nie ma hasła do wspólnego serwera. Jeśli uruchomisz serwer ponownie bez ustawionego hasła, wypisze nowe; użyj go. Starsza nazwa `OPENCODE_SERVER_PASSWORD` też działa, gdy `OPENCODE_PASSWORD` nie jest ustawione. Nie udostępniaj serwera w niezaufanej sieci. Ten sposób nie działa z serwerem, którym Desktop zarządza automatycznie, bo jego port i hasło się zmieniają.

Serwer zewnętrzny nie dostaje wtyczek zarządzanych przez OpenChamber. Jeśli któraś aplikacja nie może się połączyć, zobacz [Połączenie z OpenCode](/pl/troubleshooting/opencode-connection/).

## Zarządzaj serwerem z poziomu CLI

```bash
openchamber status
openchamber logs
openchamber restart
openchamber stop
```

Samo `openchamber` uruchamia serwer w tle. Dodaj `--foreground`, aby pozostał dołączony do Twojego terminala.

## Uruchamianie OpenChamber po zalogowaniu

Użyj `startup enable`, aby zainstalować natywną usługę użytkownika. OpenChamber używa `launchd` na macOS, `systemd --user` na Linuksie i Harmonogramu zadań w Windows.

```bash
openchamber startup enable
openchamber startup status
openchamber startup disable
```

Aby zabezpieczyć UI, ustaw hasło podczas włączania usługi:

```bash
OPENCHAMBER_UI_PASSWORD='secret' openchamber startup enable
```

Dla serwera headless uruchamianego przy logowaniu i używanego przez aplikacje desktopowe lub mobilne dodaj `--api-only` oraz osiągalny host:

```bash
openchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` zapisuje migawkę bieżącego środowiska w usłudze, aby uruchomienie było bliższe ręcznemu startowi `openchamber` z tej samej powłoki. Zachowuje to tokeny dostawców, `PATH`, ustawienia agenta SSH i inne zmienne CLI auth/config. Użyj `--no-env-snapshot`, jeśli chcesz minimalne środowisko usługi.

Usługa startowa pamięta `--port`, `--host`, `--ui-password` i `--api-only`. Restart z CLI oraz restart podczas aktualizacji używają tych zapisanych ustawień.

Aby utworzyć link połączenia dla innej aplikacji OpenChamber, użyj:

```bash
openchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

Uruchom `openchamber connect-url --help`, aby zobaczyć wszystkie opcje linku, w tym `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` i `--qr`.

Tunelami dla tej działającej usługi możesz zarządzać niezależnie:

```bash
openchamber tunnel start --port 3000
openchamber tunnel stop --port 3000
```

Zatrzymanie tunelu nie restartuje usługi ani aplikacji.

## „OpenCode uruchamia się ponownie”

Gdy serwer startuje lub uruchamia się ponownie, OpenChamber pokazuje stan „OpenCode uruchamia się ponownie” i wstrzymuje żądania, aż będzie gotowy. To normalne tuż po uruchomieniu lub restarcie. Jeśli ten stan nigdy nie znika, zobacz [Połączenie z OpenCode](/pl/troubleshooting/opencode-connection/).
