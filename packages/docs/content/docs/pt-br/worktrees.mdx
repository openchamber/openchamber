# Sessões de Worktree

Uma sessão de worktree roda em sua própria cópia do seu repositório, em seu próprio branch (um worktree do git). Isso impede que sessões paralelas atrapalhem os arquivos umas das outras — uma pode refatorar enquanto outra corrige um bug, sem ficar alternando entre elas.

## Criar uma

1. Abra a caixa de diálogo de novo worktree: escolha **Novo worktree…** no menu de branches acima do campo de mensagem ao começar uma nova sessão, ou use o botão de worktree na linha de um projeto na barra lateral.
2. Em **Start from**, escolha uma opção:
   - **novo branch** — nomeie o branch
   - **branch existente** — faça checkout de um branch que você já tem
   - **PR or issue** — escolha um do GitHub, GitLab, Gitea, Forgejo, Gerrit, Linear ou de uma extensão; o branch recebe o nome dele (um PR faz checkout do próprio branch, e uma alteração do Gerrit, do seu último patchset em `change-<number>`) e o item é anexado à sua primeira mensagem
3. Confira **Based on** (o branch de onde um novo parte; por padrão, o branch padrão do remoto, como `origin/main`) e **Folder name**; mude só se precisar.
4. Crie-a. Se o projeto tiver comandos de setup, eles rodam logo em seguida.

O OpenChamber cria o branch, configura a pasta e abre uma nova sessão ali, pronta para sua primeira mensagem. Você também pode iniciar uma direto de uma [tarefa](/pt-br/notes-todos-plans/) ou de uma [issue ou pull request](/pt-br/github/).

Para pular as perguntas, escolha **Worktree rápido** no mesmo menu de branches: o OpenChamber dá nome ao branch e aponta a nova sessão para ele.

## Na barra lateral

Um worktree é uma linha na barra lateral, com todas as sessões dele embaixo. A linha mostra o nome da tarefa assim que o agente o define (até lá, o título da sessão em que você trabalhou por último ali), o pull request ou issue que ele acompanha como uma marca colorida, e se alguma sessão ali está rodando ou tem novidades para você. Um worktree criado para um pull request ou uma issue começa com o título desse item até o agente escolher um nome mais curto. Passe o cursor sobre ela para ver o branch. Clique para abrir a sessão em que você trabalhou por último ali; para abrir a lista, passe o cursor sobre o ícone de branch à esquerda e clique na seta que aparece no lugar dele. O menu dele renomeia a tarefa, move o worktree para uma pasta do projeto ou o exclui. Veja [Sessões em andamento](/pt-br/sessions-in-work/) para saber como os trabalhos entram e saem do bloco Em andamento.

## Projetos abertos em uma pasta do repositório

Se você abre um projeto em uma pasta dentro de um repositório, como `repo/ai`, os novos worktrees também abrem ali. Uma sessão em um novo worktree começa na mesma pasta do checkout, e assim o OpenCode encontra a configuração que está nela. Um projeto aberto na raiz do repositório começa na raiz do worktree, como antes. Se uma branch não tiver essa pasta, a sessão começa na raiz do worktree e o OpenChamber avisa você.

## Trazer o trabalho de volta

Quando o trabalho estiver bom, use **Integrate** na visão de Git para trazer os commits do worktree para outro branch (como `main`). Se uma mudança conflitar, você pode entregar o conflito ao agente para resolver.

## Limpeza

Marque a linha do worktree como concluída quando a tarefa terminar: se nada se perder, as sessões dele são arquivadas e o worktree e o branch local são removidos; caso contrário, o OpenChamber mostra o que seria perdido e deixa você decidir. Excluir o worktree pelo menu dele, ou excluir ou arquivar a sessão, também funciona. Você escolhe se também deve excluir o branch — local, e remoto se houver um.

## Se algo parecer errado

Um worktree pode precisar de atenção se sua pasta sumiu, se seu branch está em estado detached ou se um merge ou rebase ficou pela metade. O OpenChamber sinaliza esses casos para você corrigi-los — veja [Worktrees e Git](/pt-br/troubleshooting/worktrees-git/).
