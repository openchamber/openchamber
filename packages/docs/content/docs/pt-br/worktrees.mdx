# Sessões de Worktree

Uma sessão de worktree roda em sua própria cópia do seu repositório, em seu próprio branch (um worktree do git). Isso impede que sessões paralelas atrapalhem os arquivos umas das outras — uma pode refatorar enquanto outra corrige um bug, sem ficar alternando entre elas.

## Criar uma

1. Abra a caixa de diálogo de novo worktree: escolha **Novo worktree…** no menu de branches acima do campo de mensagem ao começar uma nova sessão, ou use o botão de worktree na linha de um projeto na barra lateral.
2. Em **Start from**, escolha uma opção:
   - **novo branch** — nomeie o branch
   - **branch existente** — faça checkout de um branch que você já tem
   - **PR or issue** — escolha um do GitHub, GitLab, Gitea, Forgejo, Gerrit, Linear ou de uma extensão; o branch recebe o nome dele (um PR faz checkout do próprio branch, e uma alteração do Gerrit, do seu último patchset em `change-<number>`) e o item é anexado à sua primeira mensagem
3. Confira **Based on** (o branch de onde um novo parte; por padrão, o branch padrão do remoto, como `origin/main`) e **Folder name**; mude só se precisar.
4. Crie-a. Se o projeto tiver comandos de setup, eles rodam logo em seguida.

O OpenChamber cria o branch, configura a pasta e abre uma nova sessão ali, pronta para sua primeira mensagem. Você também pode iniciar uma direto de uma [tarefa](/pt-br/notes-todos-plans/) ou de uma [issue ou pull request](/pt-br/github/).

Para pular as perguntas, escolha **Worktree rápido** no mesmo menu de branches: o OpenChamber dá ao branch um nome provisório e aponta a nova sessão para ele. Quando o agente dá um nome à tarefa, ele também renomeia o branch de acordo com ela, como `fix/login-timeout`, desde que o branch ainda não tenha sido enviado com push.

## Criar worktrees com sua própria ferramenta

Todo worktree novo é um checkout do zero, então um projeto grande pode passar minutos instalando dependências antes de qualquer coisa rodar. Uma ferramenta copy-on-write cria o worktree como um clone de um checkout que você já tem: `node_modules`, `.venv` e os artefatos de build vêm junto e não ocupam espaço extra em disco até mudarem.

Para usar uma, abra as configurações do projeto, vá em **Worktrees** e digite o comando da sua ferramenta em **Criação de worktrees**. O OpenChamber cria o branch primeiro e depois roda o comando na raiz do projeto com duas variáveis de ambiente:

- `$WORKTREE_PATH` é a pasta onde criar o worktree. Ela ainda não existe.
- `$WORKTREE_BRANCH` é o branch para fazer checkout ali. Ele já existe.

Este comando faz o que o OpenChamber faz quando não há nenhum; coloque o comando da sua ferramenta no lugar de `git worktree add`:

```bash
git worktree add "$WORKTREE_PATH" "$WORKTREE_BRANCH"
```

Depois o worktree aparece na barra lateral como qualquer outro, e os comandos de setup do projeto rodam nele. Se a ferramenta guarda o checkout em outro lugar e deixa um link em `$WORKTREE_PATH`, o OpenChamber trabalha na pasta real. Se o comando falhar, o OpenChamber mostra a saída dele e exclui o branch que criou. Excluir o worktree depois funciona mesmo quando a ferramenta o bloqueou.

O comando é só seu: ele não fica salvo no repositório, então colegas sem a ferramenta continuam com a criação de sempre. Deixe o campo vazio para voltar ao git. Worktrees de um pull request vindo do fork de outra pessoa sempre usam git.

## Na barra lateral

Um worktree é uma linha na barra lateral, com todas as sessões dele embaixo. Dentro do projeto, ele aparece entre as outras sessões do projeto pela atividade mais recente, então um worktree em que você acabou de trabalhar fica perto do topo. A linha mostra o nome da tarefa assim que o agente o define (até lá, o título da sessão em que você trabalhou por último ali), o pull request ou issue que ele acompanha como uma marca colorida, e se alguma sessão ali está rodando ou tem novidades para você. Um worktree criado para um pull request ou uma issue começa com o título desse item até o agente escolher um nome mais curto. Passe o cursor sobre ela para ver o branch. Clique para abrir a sessão em que você trabalhou por último ali; para abrir a lista, passe o cursor sobre o ícone de branch à esquerda e clique na seta que aparece no lugar dele. O menu dele renomeia a tarefa, move o worktree para uma pasta do projeto, o arquiva ou o exclui. No celular, toque na seta da linha para abrir a lista e deslize a linha para o lado para marcá-la como concluída, renomear a tarefa, arquivar o worktree ou excluí-lo. Veja [Sessões em andamento](/pt-br/sessions-in-work/) para saber como os trabalhos entram e saem do bloco Em andamento.

## Projetos abertos em uma pasta do repositório

Se você abre um projeto em uma pasta dentro de um repositório, como `repo/ai`, os novos worktrees também abrem ali. Uma sessão em um novo worktree começa na mesma pasta do checkout, e assim o OpenCode encontra a configuração que está nela. Um projeto aberto na raiz do repositório começa na raiz do worktree, como antes. Se uma branch não tiver essa pasta, a sessão começa na raiz do worktree e o OpenChamber avisa você.

## Trazer o trabalho de volta

Quando o trabalho estiver bom, use **Integrate** na visão de Git para trazer os commits do worktree para outro branch (como `main`). Se uma mudança conflitar, você pode entregar o conflito ao agente para resolver.

## Limpeza

Quando a tarefa terminar, escolha **Arquivar o worktree** no menu da linha, ou segure Shift e clique no botão de arquivar que aparece na linha no lugar do botão de nova sessão. O OpenChamber arquiva o worktree: a pasta some, e as sessões, as mudanças sem commit e o branch dele ficam esperando na página Arquivo. Se uma sessão ainda estiver rodando ali, o worktree fica.

Marcar a linha como concluída só a tira de Em andamento. Para arquivar um worktree sempre que você o marcar como concluído, ou quando o PR dele for mesclado, ative isso em **Configurações → Sessões → Worktrees concluídos**.

Na página Arquivo, os worktrees arquivados aparecem sob o projeto deles. **Restaurar** traz um de volta com o branch, roda os comandos de setup do projeto e devolve as mudanças e as sessões dele; restaurar uma das sessões dele faz o mesmo. Arquivos que o git ignora, como `node_modules` ou `.env`, não são guardados, então são os comandos de setup que os trazem de volta. A página Worktrees do projeto também lista os worktrees arquivados.

Para se livrar de um worktree de vez, exclua-o pelo menu dele, ou exclua um arquivado na página Arquivo. Ao excluir pelo menu, você escolhe se também deve excluir o branch — local, e remoto se houver um.

## Se algo parecer errado

Um worktree pode precisar de atenção se sua pasta sumiu, se seu branch está em estado detached ou se um merge ou rebase ficou pela metade. O OpenChamber sinaliza esses casos para você corrigi-los — veja [Worktrees e Git](/pt-br/troubleshooting/worktrees-git/).
