# Fluxos de Git

O OpenChamber tem uma visão de git integrada para você revisar mudanças, fazer commit e gerenciar branches sem mudar para um terminal. Abra-a pela aba **Git** na barra lateral direita.

## Revisar e fazer commit

A visão de git divide suas mudanças em **staged** e **unstaged**:

- clique no **+** de um arquivo para fazer stage dele, ou **−** para remover do stage
- faça stage ou unstage de tudo de um grupo de uma vez
- clique em um arquivo para ver seu diff

Então escreva uma mensagem de commit e faça o commit. Você pode fazer o OpenChamber **gerar uma mensagem de commit** a partir das suas mudanças em stage — ele usa o modelo da sessão atual, então você precisa de uma sessão aberta.

## Branches e histórico

A visão de git também cobre o resto do dia a dia do git:

- criar, trocar, renomear e excluir branches
- push, pull e fetch
- navegar pelo histórico e diffs por commit
- guardar (stash) e restaurar mudanças

## Pull requests

Com uma conta conectada no host do projeto, a aba **PR** permite abrir um pull request, atualizá-lo, marcá-lo como pronto ou fazer merge. O OpenChamber pode escrever o título e a descrição da mesma forma que as mensagens de commit. Isso funciona no GitHub, no Gitea e no GitLab, onde a aba abre merge requests. O Gerrit tem seu próprio formulário, **Enviar para revisão**. Como conectar um host está em [Hosts Git](/pt-br/github/).

## Enviar para revisão no Gerrit

Num projeto no Gerrit, o formulário de pull request vira **Enviar para revisão**. Ele faz push dos seus commits para `refs/for/<branch>`, o que cria uma alteração (change) ou um novo patchset de uma alteração que você já enviou. A mensagem do commit é a descrição da alteração, então o formulário mostra o assunto do último commit em vez de título e corpo. Escolha o branch de destino e, se quiser, um topic, hashtags, **Em andamento** e **Privada**. Funciona também no próprio branch de destino, que é o jeito comum de trabalhar com o Gerrit.

O Gerrit associa commits a alterações pela linha `Change-Id` que o hook commit-msg dele adiciona a cada mensagem. Se só o último commit não tiver essa linha, **Adicionar Change-Id** faz amend nesse commit depois de perguntar; nada é enviado até você fazer push. Se commits mais antigos não tiverem, o push espera até você instalar o hook e dar um Change-Id a cada um deles.

Depois do primeiro push, o painel oferece **Enviar patchset** sempre que seus commits locais ainda não estiverem na alteração. Uma alteração numa cadeia de alterações mostra sua posição na cadeia, como **2 de 3**, ao lado do seu selo.

## Trazendo conflitos

Se um merge, rebase ou integração encontra um conflito, o OpenChamber mostra o que está travado e permite resolvê-lo — incluindo entregá-lo ao agente.
