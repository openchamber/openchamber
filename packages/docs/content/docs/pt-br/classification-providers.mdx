# Provedores de classificação (Jev)

Algumas funções do OpenChamber precisam de uma decisão rápida antes de agir: este comando é arriscado? Que tipo de tarefa é este prompt? Este trabalho parece concluído? Quem responde a essas perguntas é o Jev, um pequeno modelo de decisão da TypeSafe. Esta página mostra como dar ao OpenChamber acesso ao Jev.

O Jev nunca escreve código nem responde no seu chat. Ele só devolve um veredito, e o OpenChamber age de acordo. O OpenChamber espera a resposta por no máximo quatro segundos antes de enviar uma mensagem ou executar uma ação, e por até quinze segundos nas verificações depois de um turno, das quais nada depende.

## O que usa o Jev

| Função | A pergunta que o Jev responde |
| --- | --- |
| [Permissões e rede de segurança](/pt-br/permissions/) | O agente deve perguntar a você antes de executar esta ação? |
| [Roteamento automático de modelos](/pt-br/auto-model-routing/) | A qual das suas categorias este prompt pertence? |
| [Sessões em andamento](/pt-br/sessions-in-work/) | Este turno parece o fim do trabalho? |
| [Resumo e sugestão da próxima mensagem](/pt-br/sessions-in-work/) | Vale a pena gerar um resumo ou uma sugestão depois deste turno? |

Sem provedor, a rede de segurança e o Auto ficam ocultos, e as sessões em andamento não recebem a dica "parece concluído". As sessões continuam indo para em andamento quando você envia uma mensagem. Resumos e sugestões continuam funcionando, só que sem o filtro.

## Configuração

A classificação começa desativada. Abra **Configurações → Provedores → Provedores de classificação** e escolha para onde enviar as solicitações de classificação. Se deixar em **Desativado**, nada será enviado.

### Promoção do OpenCode Zen

Grátis por tempo limitado, sem chave. Enquanto a promoção durar, o OpenCode deixa o OpenChamber usar o Jev pelo OpenCode Zen sem custo.

Quando a promoção acabar, a opção some e o OpenChamber passa para uma das chaves abaixo, se você tiver alguma.

### Chave do OpenCode Zen

Usa a chave de API do Zen salva no OpenCode, paga com o seu saldo do Zen.

1. Abra **Configurações → Provedores** e adicione uma chave de API ao provedor **OpenCode Zen** (veja [Provedores, modelos e agentes](/pt-br/providers/)).
2. Volte a **Provedores de classificação** e escolha **Chave do OpenCode Zen**.

Entrar com uma conta do OpenCode não basta. Para o Jev, o Zen só aceita uma chave de API.

### Chave do OpenRouter

Usa a chave de API do OpenRouter salva no OpenCode, cobrada da sua conta OpenRouter. Se você já usa modelos do OpenRouter no OpenCode, não há nada para configurar. Uma chave na variável de ambiente `OPENROUTER_API_KEY` também funciona. Se houver as duas, vale a chave salva no OpenCode.

1. Abra **Configurações → Provedores** e adicione uma chave de API ao provedor **OpenRouter**.
2. Volte para **Provedores de classificação** e escolha **Chave do OpenRouter**.

### Chave do Vercel AI Gateway

Usa a chave de API do AI Gateway salva no OpenCode, cobrada da sua conta Vercel. Uma chave na variável de ambiente `AI_GATEWAY_API_KEY` também funciona. Se houver as duas, vale a chave salva no OpenCode.

1. Abra **Configurações → Provedores** e adicione uma chave de API ao provedor **Vercel AI Gateway**.
2. Volte para **Provedores de classificação** e escolha **Chave do Vercel AI Gateway**.

### Google Gemini

Usa o Gemini Decision 1, o modelo de decisão do próprio Google, pela Decisions API do Google, cobrado da sua conta Google. O OpenChamber faz a ele as mesmas perguntas que faz ao Jev. No nível gratuito do Google, o Google pode usar o que recebe para melhorar seus produtos ([termos da API do Gemini](https://ai.google.dev/gemini-api/terms#data-use-unpaid)).

1. Obtenha uma chave de API no [Google AI Studio](https://aistudio.google.com/apikey).
2. Cole-a no campo **Chave de API do Gemini** e clique em **Salvar**.

Salvar uma chave também a seleciona. A chave fica no servidor do OpenChamber, em um arquivo próprio, e nunca é enviada ao navegador.

Se o provedor **Google** no OpenCode já tiver uma chave de API, você pode pular o campo e escolher **Google Gemini**. Uma chave em `GOOGLE_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY` ou `GEMINI_API_KEY` também funciona. Uma chave salva no OpenChamber vale mais que as duas. Mantenha a chave no OpenChamber se quiser o Gemini só para decisões: uma chave no provedor Google do OpenCode também libera lá todos os modelos de chat do Gemini, e uma chave de API do Gemini não pode ser limitada a um só modelo.

### OpenAI Decisions

Envia solicitações de classificação diretamente à OpenAI. Em [O que o Jev vê](#o-que-o-jev-vê) estão os dados de conversa que um classificador pode receber. Com OpenAI Decisions, a rede de segurança só envia solicitações de leitura elegíveis com caminhos relativos ao projeto. As demais permissões continuam manuais.

1. Configure `OPENAI_API_KEY` no ambiente do servidor do OpenChamber. Entrar no ChatGPT não fornece uma chave de API.
2. Selecione **OpenAI Decisions** e clique em **Testar**. Confira se o resultado mostra **OpenAI Decisions**. O teste usa o provedor que está respondendo, que pode ser diferente da opção salva.

Se uma solicitação à OpenAI falhar, o OpenChamber não a reenvia a outro provedor de classificação.
Se o OpenAI Decisions estiver selecionado, mas indisponível, a rede de segurança deixa os pedidos de permissão para você decidir, em vez de usar outro provedor.

### Chave de API da TypeSafe

Sua própria chave e sua própria cota da TypeSafe.

1. Obtenha uma chave de API na [TypeSafe](https://docs.typesafe.ai).
2. Cole-a no campo **Chave de API da TypeSafe** e clique em **Salvar**.

Salvar uma chave também a seleciona. A chave fica no servidor do OpenChamber, em um arquivo próprio, e nunca é enviada ao navegador.

### Endpoint personalizado

Qualquer serviço que fale a API System One da TypeSafe: um gateway auto-hospedado, um proxy da empresa ou um provedor que não aparece aqui.

1. Em **Endpoint personalizado**, preencha a **URL do endpoint** e o **Modelo** (por exemplo, `jev-latest`).
2. Adicione uma **Chave de API** se o serviço precisar. Ela é enviada como token `Bearer`.
3. Clique em **Salvar**.

Cole o endereço completo em que o serviço responde, como `https://api.typesafe.ai/v1/systemone` ou `https://proxy.company.internal/v1/decision` num proxy da empresa. O OpenChamber chama exatamente o que você colou e não acrescenta nada ao caminho. Só `http` e `https` funcionam, e a chave vai no campo próprio dela, nunca na URL.

Salvar também seleciona o endpoint. Assim como a chave da TypeSafe, o endpoint e a chave dele ficam no servidor do OpenChamber, em um arquivo próprio, e a chave nunca é enviada ao navegador.

Um servidor também pode receber o endpoint pelo ambiente, o que ajuda quando você configura o OpenChamber para uma equipe:

```bash
OPENCHAMBER_JEV_URL=https://jev.example.com/v1/systemone
OPENCHAMBER_JEV_MODEL=jev-latest        # opcional, este é o padrão
OPENCHAMBER_JEV_API_KEY=...             # opcional
```

Nos notebooks que você gerencia, coloque o mesmo endpoint em `jev` no [arquivo de política](/pt-br/security/) da máquina. Ele tem prioridade sobre o ambiente.

De qualquer forma, esse endpoint substitui o endpoint salvo nas Configurações, e as Configurações o mostram sem deixar ninguém editá-lo. No [modo empresarial](/pt-br/security/), é a única fonte do Jev permitida além de **Desativado**, e vem selecionada por padrão.

Assim que um provedor funciona, o cartão em **Configurações → Provedores** mostra **Pronto**.

## Quando a sua escolha para de funcionar

Se o provedor escolhido estiver indisponível antes do envio, o OpenChamber mantém sua escolha e usa a primeira opção disponível nesta ordem: chave da TypeSafe, seu endpoint personalizado, OpenRouter, Vercel AI Gateway e chave do Zen. Para usar a promoção, o Google Gemini ou o OpenAI Decisions, selecione a opção diretamente. **Desativado** continua desativado. A página mostra o provedor em uso.

Se o Jev estiver lento ou falhar em uma solicitação, nada quebra. Cada função tem uma resposta segura para esse caso:

- A rede de segurança deixa a ação esperando por você.
- O Auto manda o prompt para o seu modelo de reserva.
- A dica "parece concluído" não aparece nas sessões em andamento.
- O resumo e a sugestão são gerados como se o Jev não existisse.

## O que o Jev vê

O Jev recebe sua última mensagem e, como contexto, trechos da conversa recente: até três turnos anteriores, cortados em algumas centenas de caracteres cada, e ao fim de um turno, o começo e o fim da resposta do agente. Para a rede de segurança, ele também recebe a ação para a qual o agente pede permissão, do jeito que o OpenCode a descreve: o comando que o agente quer executar, ou o arquivo e a mudança em uma edição. Quando o agente cria um arquivo, essa mudança é o arquivo inteiro, incluindo imagens escritas como texto, como SVG. Quando o Jev verifica um objetivo, ele recebe o objetivo e a última resposta do agente, até 10.000 caracteres dela.

As solicitações vão do servidor do OpenChamber direto para o OpenCode Zen, o OpenRouter, o Vercel AI Gateway, o Google, a OpenAI, a TypeSafe ou o seu endpoint personalizado, conforme a sua escolha.

## Onde funciona

O Jev roda no servidor do OpenChamber, então funciona no app desktop, no app web e no seu celular conectado a qualquer um dos dois. A extensão do VS Code fala direto com o OpenCode e não tem Jev: lá não há rede de segurança, não há Auto e não há a dica "parece concluído".
