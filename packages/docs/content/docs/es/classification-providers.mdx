# Proveedores de clasificación (Jev)

Algunas funciones de OpenChamber necesitan una decisión rápida antes de actuar: ¿este comando es arriesgado?, ¿qué tipo de tarea es este prompt?, ¿este trabajo parece terminado? Esas preguntas las responde Jev, un pequeño modelo de decisión de TypeSafe. Esta página explica cómo darle a OpenChamber acceso a Jev.

Jev nunca escribe código ni responde en tu chat. Solo devuelve un veredicto, y OpenChamber actúa según él. OpenChamber espera la respuesta como mucho cuatro segundos antes de enviar un mensaje o ejecutar una acción, y hasta quince segundos en las comprobaciones tras un turno, donde nada depende de ella.

## Qué usa Jev

| Función | La pregunta que responde Jev |
| --- | --- |
| [Permisos y red de seguridad](/es/permissions/) | ¿Debe el agente preguntarte antes de ejecutar esta acción? |
| [Enrutamiento automático de modelos](/es/auto-model-routing/) | ¿A cuál de tus categorías pertenece este prompt? |
| [Sesiones en curso](/es/sessions-in-work/) | ¿Este turno parece el final del trabajo? |
| [Resumen y sugerencia del próximo mensaje](/es/sessions-in-work/) | ¿Vale la pena generar un resumen o una sugerencia después de este turno? |

Sin proveedor, la red de seguridad y Auto quedan ocultos, y las sesiones en curso no reciben la pista «parece terminado». Las sesiones siguen pasando a en curso cuando envías un mensaje. Los resúmenes y las sugerencias siguen funcionando, solo que sin el filtro.

## Configuración

Jev está desactivado hasta que lo actives: nada de tus conversaciones va a un proveedor de clasificación a menos que elijas uno. Abre **Configuración → Proveedores → Proveedores de clasificación** y elige a dónde van las solicitudes a Jev. Además de **Desactivado**, hay siete opciones.

### Promoción de OpenCode Zen

Gratis por tiempo limitado, sin clave. Mientras dure la promoción, OpenCode deja que OpenChamber use Jev a través de OpenCode Zen sin costo.

Cuando la promoción termine, la opción desaparece y OpenChamber cambia a una de las claves de abajo, si tienes alguna.

### Clave de OpenCode Zen

Usa la clave API de Zen guardada en OpenCode y se paga con tu saldo de Zen.

1. Abre **Configuración → Proveedores** y añade una clave API al proveedor **OpenCode Zen** (consulta [Proveedores, modelos y agentes](/es/providers/)).
2. Vuelve a **Proveedores de clasificación** y elige **Clave de OpenCode Zen**.

Iniciar sesión con una cuenta de OpenCode no basta. Para Jev, Zen solo acepta una clave API.

### Clave de OpenRouter

Usa la clave API de OpenRouter guardada en OpenCode y se cobra a tu cuenta de OpenRouter. Si ya usas modelos de OpenRouter en OpenCode, no hay nada que configurar. Una clave en la variable de entorno `OPENROUTER_API_KEY` también sirve. Si están las dos, gana la clave guardada en OpenCode.

1. Abre **Configuración → Proveedores** y añade una clave API al proveedor **OpenRouter**.
2. Vuelve a **Proveedores de clasificación** y elige **Clave de OpenRouter**.

### Clave de Vercel AI Gateway

Usa la clave API de AI Gateway guardada en OpenCode y se cobra a tu cuenta de Vercel. Una clave en la variable de entorno `AI_GATEWAY_API_KEY` también sirve. Si están las dos, gana la clave guardada en OpenCode.

1. Abre **Configuración → Proveedores** y añade una clave API al proveedor **Vercel AI Gateway**.
2. Vuelve a **Proveedores de clasificación** y elige **Clave de Vercel AI Gateway**.

### Google Gemini

Usa Gemini Decision 1, el modelo de decisiones de Google, a través de la Decisions API de Google, con cargo a tu cuenta de Google. OpenChamber le hace las mismas preguntas que a Jev. En el nivel gratuito de Google, Google puede usar lo que recibe para mejorar sus productos ([condiciones de la API de Gemini](https://ai.google.dev/gemini-api/terms#data-use-unpaid)).

1. Consigue una clave API en [Google AI Studio](https://aistudio.google.com/apikey).
2. Pégala en el campo **Clave API de Gemini** y pulsa **Guardar**.

Al guardar una clave, también queda seleccionada. La clave se queda en el servidor de OpenChamber, en su propio archivo, y nunca se envía al navegador.

Si el proveedor **Google** de OpenCode ya tiene una clave API, puedes saltarte el campo y elegir **Google Gemini**. Una clave en `GOOGLE_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY` o `GEMINI_API_KEY` también sirve. Una clave guardada en OpenChamber gana a ambas. Guarda la clave en OpenChamber si quieres Gemini solo para decisiones: una clave en el proveedor Google de OpenCode también abre todos los modelos de chat de Gemini en OpenCode, y una clave API de Gemini no se puede limitar a un solo modelo.

### Clave API de TypeSafe

Tu propia clave y tu propia cuota de TypeSafe.

1. Consigue una clave API en [TypeSafe](https://docs.typesafe.ai).
2. Pégala en el campo **Clave API de TypeSafe** y pulsa **Guardar**.

Al guardar una clave, también queda seleccionada. La clave se queda en el servidor de OpenChamber, en su propio archivo, y nunca se envía al navegador.

### Endpoint personalizado

Cualquier servicio que hable la API System One de TypeSafe: un gateway autoalojado, un proxy de empresa o un proveedor que no aparece aquí.

1. En **Endpoint personalizado**, rellena la **URL del endpoint** y el **Modelo** (por ejemplo, `jev-latest`).
2. Añade una **Clave de API** si el servicio la necesita. Se envía como token `Bearer`.
3. Pulsa **Guardar**.

Pega la dirección completa en la que responde el servicio, como `https://api.typesafe.ai/v1/systemone` o `https://proxy.company.internal/v1/decision` en un proxy de empresa. OpenChamber la llama tal como la pegas y no añade nada a la ruta. Solo funcionan `http` y `https`, y la clave va en su propio campo, nunca en la URL.

Al guardar, el endpoint también queda seleccionado. Igual que la clave de TypeSafe, el endpoint y su clave se quedan en el servidor de OpenChamber, en su propio archivo, y la clave nunca se envía al navegador.

Un servidor también puede tomar su endpoint del entorno, algo útil cuando configuras OpenChamber para un equipo:

```bash
OPENCHAMBER_JEV_URL=https://jev.example.com/v1/systemone
OPENCHAMBER_JEV_MODEL=jev-latest        # opcional, este es el valor predeterminado
OPENCHAMBER_JEV_API_KEY=...             # opcional
```

En los portátiles que administras, pon el mismo endpoint bajo `jev` en el [archivo de políticas](/es/security/) de la máquina. Tiene prioridad sobre el entorno.

En ambos casos, reemplaza el endpoint guardado en Configuración, y Configuración lo muestra sin que nadie pueda editarlo. En el [modo empresa](/es/security/) es la única fuente de Jev permitida además de **Desactivado**, y viene seleccionada por defecto.

En cuanto un proveedor funciona, la tarjeta en **Configuración → Proveedores** muestra **Listo**.

## Cuando tu elección deja de funcionar

Si el proveedor que elegiste no se puede usar (terminó la promoción, se quitó una clave), OpenChamber recurre a la primera de tus propias claves que funcione: clave de TypeSafe, luego tu endpoint personalizado, luego OpenRouter, luego Vercel AI Gateway, luego clave de Zen. Nunca recurre a la promoción ni a Google Gemini, y **Desactivado** sigue desactivado. La página te dice cuál está usando ahora.

Si Jev va lento o falla en una solicitud, no se rompe nada. Cada función tiene una respuesta segura para ese caso:

- La red de seguridad deja la acción esperando tu decisión.
- Auto manda el prompt a tu modelo de respaldo.
- No aparece la pista «parece terminado» en las sesiones en curso.
- El resumen y la sugerencia se generan como si Jev no existiera.

## Qué ve Jev

Jev recibe tu último mensaje y, como contexto, fragmentos de la conversación reciente: hasta tres turnos anteriores, recortados a unos cientos de caracteres cada uno, y al terminar un turno, la respuesta del agente recortada a su principio y su final. Para la red de seguridad también recibe la acción para la que el agente pide permiso, tal como la describe OpenCode: el comando que el agente quiere ejecutar, o el archivo y el cambio en una edición. Cuando el agente crea un archivo, ese cambio es el archivo entero, incluidas las imágenes escritas como texto, como SVG. Cuando Jev comprueba un objetivo, recibe el objetivo y la última respuesta del agente, hasta 10.000 caracteres de ella.

Las solicitudes van del servidor de OpenChamber directamente a OpenCode Zen, OpenRouter, Vercel AI Gateway, Google, TypeSafe o tu endpoint personalizado, según tu elección.

## Dónde funciona

Jev funciona en el servidor de OpenChamber, así que está disponible en la app de escritorio, en la app web y en tu teléfono conectado a cualquiera de las dos. La extensión de VS Code habla directamente con OpenCode y no tiene Jev: no hay red de seguridad, ni Auto, ni pista «parece terminado».
