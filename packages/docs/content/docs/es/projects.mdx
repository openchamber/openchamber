# Proyectos

Un proyecto es una carpeta de tu computadora que OpenChamber rastrea, normalmente un único código base. Cambiar de proyecto cambia la carpeta en la que trabaja el agente, junto con las sesiones y los ajustes de ese proyecto.

## Añade un proyecto

Puedes añadir un proyecto desde varios lugares:

- la entrada **Add project** en la paleta de comandos
- el botón **+** en la parte superior de la barra lateral de sesiones
- el explorador de carpetas cuando eliges un directorio

Apúntalo a una carpeta y OpenChamber la recuerda. El nombre viene de la carpeta; puedes cambiarlo más tarde.

## Cambia de proyecto

Elige un proyecto de la barra lateral para activarlo. Todo —sesiones, git, notas— sigue al proyecto que tengas abierto.

## Haz reconocible un proyecto

Abre **Settings → Projects** para darle a un proyecto un nombre, color o icono personalizado. OpenChamber intenta encontrar un icono automáticamente; consulta [Iconos de proyecto](/es/project-icons/).

> En VS Code, OpenChamber siempre usa la carpeta que tienes abierta como único proyecto, así que no hay nada que añadir ni cambiar. La página de ajustes de proyectos está oculta allí.

## Entorno del proyecto

Cuando las herramientas de un proyecto vienen de direnv, devenv o un shell de Nix, los hooks de Git, la terminal y las [acciones de proyecto](/es/project-actions/) no las encuentran por sí solos. Abre **Configuración → Proyectos**, elige el proyecto y, en **Entorno**:

- añade variables que solo necesita este proyecto
- o define un **comando de entorno** que las imprima, por ejemplo `direnv export json` o `devenv print-dev-env --json`

El comando se ejecuta en la carpeta del proyecto y, para un worktree, en la carpeta propia de ese worktree. Se vuelve a ejecutar cuando haces un commit, abres una terminal o ejecutas una acción, si la última ejecución tiene ya unos minutos, y **Ejecutar de nuevo** lo ejecuta en el acto. Tener el proyecto abierto no basta para ejecutarlo. Debajo del campo ves cuántas variables añadió la última ejecución o por qué falló. Una ejecución fallida no añade nada, y Git y la terminal siguen funcionando sin ella.

Estas variables van a Git, a la terminal y a las acciones de proyecto, además de las de **Configuración → General → Variables de entorno** (consulta [Variables de entorno](/es/environment/#variables-para-opencode-git-y-la-terminal)). OpenCode atiende todos los proyectos desde un solo proceso, así que no recibe las variables de proyecto: pon lo que necesite el agente en la lista general.

El comando es solo tuyo. No se lee del repositorio, así que un repositorio clonado no puede hacer que OpenChamber ejecute nada.
