# Hosts Git: issues y pull requests

Conecta una cuenta en el host donde vive tu proyecto y OpenChamber podrá listar sus issues y pull requests, iniciar una sesión desde uno, y abrir, revisar y fusionar pull requests por ti. Hay cinco hosts integrados: GitHub, incluido GitHub Enterprise; GitLab, incluido GitLab autogestionado; Gitea; Forgejo, incluido Codeberg; y Gerrit. Una [extensión](/es/extensions/#una-extensión-como-host-git) puede añadir otro.

El remoto del proyecto decide con qué host habla OpenChamber. Un proyecto cuyo `origin` está en gitlab.com usa tu cuenta de GitLab para el tablero, la insignia de pull request de sus ramas y el panel Git. Un remoto en un alias de host de `~/.ssh/config`, como `github.com-work`, no se asocia a ningún host.

Las palabras siguen al host. GitLab dice merge request, y Gerrit dice cambio.

## Conecta un host

1. Abre **Settings → Integrations**. Cada host tiene su propia tarjeta.
2. Despliega la tarjeta del host de tu proyecto e inicia sesión:
   - **GitHub**: elige **Connect GitHub**, abre el enlace que muestra, introduce el código corto y aprueba. Para GitHub Enterprise, elige **Añadir instancia** en **Otras instancias**, introduce la dirección de tu servidor y pega un token de acceso personal.
   - **GitLab**: en gitlab.com, inicia sesión con un código corto, un token de acceso personal o el login de `glab`. Para un GitLab autogestionado, añade su dirección y pega un token de acceso personal.
   - **Gitea**: añade la dirección de tu servidor y pega un token de acceso personal.
   - **Forgejo**: para Codeberg, pega un token de acceso personal; para otro servidor, añade primero su dirección.
   - **Gerrit**: añade la dirección de tu servidor, y luego tu usuario de Gerrit y una contraseña HTTP.

Cuando esté conectado, tu cuenta aparece en la tarjeta. Puedes conectar más de una cuenta en un host y cambiar entre ellas, o desconectar en cualquier momento. Si la CLI `gh` tiene sesión iniciada en la misma máquina, OpenChamber también puede usarla para GitHub. Los scopes que necesita cada token y las versiones que necesita cada host están en [Integraciones](/es/integrations/#gitlab-gitea-forgejo-y-gerrit).

Una cuenta conectada también puede ser la [identidad de Git](/es/git-identities/) del proyecto, así los commits llevan su nombre y los push por HTTPS usan su token.

## Empieza a trabajar desde una issue o un pull request

Cuando creas una [sesión de worktree](/es/worktrees/), puedes empezarla desde una issue o un pull request del host del proyecto:

- elige una **issue** y OpenChamber nombra la rama según ella
- elige un **pull request** y hace checkout de la rama del pull request; puedes incluir su diff para que el agente tenga el cambio completo
- elige un **cambio de Gerrit** y hace checkout del último patchset en una rama llamada `change-<number>`

La nueva sesión se abre con el elemento ya adjunto en el cuadro de mensaje. No se envía nada por ti: elige el modelo y el agente, di qué quieres que se haga y envía.

El tablero [Issues y PRs](/es/issues-and-prs/) lista los mismos elementos, con filtros, vista previa, comentarios y revisiones, y también inicia sesiones desde ahí.

## Abre y gestiona pull requests

Desde la pestaña **PR** en el [panel Git](/es/git/), puedes crear un pull request, actualizarlo, marcar un borrador como listo o fusionarlo. OpenChamber puede escribir el título y la descripción a partir de tus cambios.

- **GitLab**: la misma pestaña abre merge requests. Al fusionar ofrece merge y squash.
- **Gitea** y **Forgejo**: igual que en GitHub.
- **Gerrit**: creas un cambio haciendo push a revisión, y cada push posterior sube un nuevo patchset. Consulta [Hacer push a revisión en Gerrit](/es/git/#hacer-push-a-revisión-en-gerrit). Fusionar es **Enviar**, y espera a que el cambio cumpla sus requisitos de envío. Las revisiones son votos en las etiquetas del proyecto, como Code-Review y Verified.

## Vincula una issue o un pull request a un mensaje

En el compositor del chat, abre el menú **+** y elige la entrada de vínculo de tu host, como **Vincular issue o PR de GitHub**, **Vincular incidencia o MR de GitLab** o **Vincular cambio de Gerrit**. Elige uno o varios elementos. Cada uno acompaña tu siguiente mensaje como contexto, un pull request puede traer su diff, y el panel de estado de trabajo de la sesión conserva un enlace. Adjuntar solo añade contexto; tu mensaje dice qué hacer con él.

Gerrit no tiene issues, así que ahí solo aparecen cambios.
