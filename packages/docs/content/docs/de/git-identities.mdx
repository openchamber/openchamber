# Git-Identitäten

Eine Git-Identität ist der Name und die E-Mail-Adresse, die deine Commits tragen, und die Art, wie sich ein Repository bei seinem Remote anmeldet. Wenn du zwischen privaten und Arbeits-Repos wechselst, kannst du Identitäten speichern und pro Repository die richtige anwenden. Verwalte sie unter **Einstellungen → Git**.

## Eine Identität hinzufügen

1. Öffne **Einstellungen → Git** und wähle **New**.
2. Gib den **Benutzername** und die **E-Mail-Adresse** ein, mit denen committet werden soll.
3. Wähle unter **Authentifizierung**, wie gepusht und gepullt wird:
   - **Dieser Rechner**: was Git auf diesem Rechner schon nutzt, etwa SSH-Schlüssel, einen Credential Manager oder die `gh`-CLI
   - **Konto**: das gewählte **Versionsverwaltungskonto**, also ein beliebiges Konto, das auf einer Host-Karte unter [Integrationen](/integrations/) verbunden ist, etwa GitHub, GitLab, Gitea, Forgejo oder Gerrit; Pushes laufen über HTTPS mit dem Token dieses Kontos
   - **SSH**: ein Schlüssel, den OpenChamber für diese Identität aufbewahrt
   - **Anonym**: liest öffentliche Repositories über HTTPS ohne Anmeldung und kann nicht pushen
4. Gib ihr optional eine Farbe und ein Symbol, damit sie leicht zu erkennen ist.

Auch deine globale System-Identität wird angezeigt, allerdings nur lesbar.

Bei Gerrit meldet sich eine Konto-Identität bei Git mit deinem Gerrit-Benutzernamen und dem verbundenen HTTP-Passwort an. Ein GitHub-Enterprise-Konto liefert Issues und Pull Requests, Klonen und Pushen laufen dort aber über **Dieser Rechner** oder **SSH**.

## Eine Identität auf ein Repo anwenden

Wähle die Identitäts-Schaltfläche oben im [Git-Panel](/git/) und dort eine Identität. Die Bildschirme zum Hinzufügen und Klonen bieten dieselbe Auswahl. Eine Identität, die das Repository nicht erreichen kann, bleibt deaktiviert in der Liste, mit dem Grund: ein Konto bei einem anderen Host, ein Konto oder **Anonym** bei einem SSH-Remote oder ein SSH-Schlüssel bei einem HTTPS-Remote.

Das Anwenden einer Identität schreibt sie in die **lokale** Git-Konfiguration dieses Repositories. Sie betrifft also nur dieses Repo, und deine globale Einstellung bleibt, wie sie ist. Auch Git im Terminal und die Shell des Agenten nutzen sie. **System-Identität** entfernt, was OpenChamber geschrieben hat, sodass wieder deine eigene Git-Konfiguration gilt.

## Verwandt

- [Git-Workflows](/git/): mit der von dir festgelegten Identität committen
- [Git-Hosts](/github/): ein Konto bei GitHub, GitLab, Gitea, Forgejo oder Gerrit verbinden
