# Worktree-Sitzungen

Eine Worktree-Sitzung läuft in einer eigenen ausgecheckten Kopie deines Repos auf einem eigenen Branch (einem Git-Worktree). So kommen sich parallele Sitzungen nicht in die Quere — die eine kann refaktorieren, während eine andere einen Fehler behebt, ohne ständiges Hin- und Herwechseln.

## Eine erstellen

1. Öffne den Dialog für einen neuen Worktree: Wähle **Neuer Worktree…** im Branch-Menü über dem Eingabefeld, wenn du eine neue Sitzung startest, oder nutze die Worktree-Schaltfläche in einer Projektzeile der Seitenleiste.
2. Wähle unter **Start from** eine Option:
   - **new branch** — benenne den Branch
   - **existing branch** — checke einen bereits vorhandenen Branch aus
   - **PR or issue** — wähle einen Eintrag aus GitHub, GitLab, Gitea, Forgejo, Gerrit, Linear oder einer Erweiterung; der Branch wird danach benannt (ein PR checkt seinen eigenen Branch aus, eine Gerrit-Änderung ihr neuestes Patchset auf `change-<number>`), und der Eintrag wird an deine erste Nachricht angehängt
3. Prüfe **Based on** (der Branch, von dem ein neuer Branch ausgeht, standardmäßig der Standard-Branch des Remotes, etwa `origin/main`) und **Folder name**; ändere sie nur, wenn es nötig ist.
4. Erstelle ihn. Hat das Projekt Setup-Befehle, laufen sie direkt danach.

OpenChamber legt den Branch an, richtet den Ordner ein und öffnet dort eine neue Sitzung, bereit für deine erste Nachricht. Du kannst auch direkt von einer [todo](/notes-todos-plans/) oder einem [Issue oder Pull Request](/github/) aus damit beginnen.

Ohne Rückfragen geht es mit **Schneller Worktree** im selben Branch-Menü: OpenChamber gibt dem Branch einen vorläufigen Namen und richtet die neue Sitzung darauf aus. Sobald der Agent der Aufgabe einen Namen gibt, benennt er auch den Branch danach um, etwa in `fix/login-timeout`, solange der Branch noch nicht gepusht wurde.

## In der Seitenleiste

Ein Worktree ist eine Zeile in der Seitenleiste, darunter alle Sitzungen darin. Die Zeile zeigt den Namen der Aufgabe, sobald der Agent sie benannt hat (bis dahin den Titel der Sitzung, in der du dort zuletzt gearbeitet hast), den Pull Request oder das Issue, dem er folgt, als farbige Markierung, und ob dort eine Sitzung läuft oder Neuigkeiten für dich hat. Ein Worktree, der für einen Pull Request oder ein Issue angelegt wurde, trägt zuerst dessen Titel, bis der Agent einen kürzeren Namen wählt. Fahre mit der Maus darüber, um den Branch zu sehen. Klicke darauf, um die Sitzung zu öffnen, in der du dort zuletzt gearbeitet hast; um die Liste aufzuklappen, fahre über das Branch-Symbol links davon und klicke auf den Pfeil, der an seiner Stelle erscheint. Sein Menü benennt die Aufgabe um, legt den Worktree in einen Ordner des Projekts oder löscht ihn. Wie Arbeiten in den Bereich In Arbeit kommen und ihn verlassen, steht unter [Sitzungen in Arbeit](/de/sessions-in-work/).

## Projekte, die auf einem Ordner des Repositorys geöffnet sind

Öffnest du ein Projekt auf einem Ordner innerhalb eines Repositorys, etwa `repo/ai`, öffnen sich neue Worktrees ebenfalls dort. Eine Sitzung in einem neuen Worktree startet im selben Ordner des Checkouts, sodass OpenCode die Konfiguration findet, die dort liegt. Ein Projekt, das auf dem Repository-Stammverzeichnis geöffnet ist, startet wie bisher im Worktree-Stammverzeichnis. Hat ein Branch diesen Ordner nicht, startet die Sitzung im Worktree-Stammverzeichnis, und OpenChamber weist darauf hin.

## Die Arbeit zurückbringen

Wenn die Arbeit gut ist, verwende **Integrate** in der Git-Ansicht, um die Commits des Worktrees auf einen anderen Branch (etwa `main`) zu übertragen. Wenn ein Konflikt auftritt, kannst du den Konflikt dem Agenten zur Lösung geben.

## Aufräumen

Markiere die Zeile des Worktrees als erledigt, wenn die Aufgabe fertig ist: Geht nichts verloren, werden seine Sitzungen archiviert und der Worktree und sein lokaler Branch entfernt; andernfalls zeigt OpenChamber, was verloren ginge, und lässt dich entscheiden. Du kannst den Worktree auch über sein Menü löschen oder seine Sitzung löschen oder archivieren. Du entscheidest, ob auch der Branch gelöscht werden soll — lokal und, falls vorhanden, remote.

## Wenn etwas seltsam aussieht

Ein Worktree braucht möglicherweise Aufmerksamkeit, wenn sein Ordner fehlt, sein Branch in einem detached-Zustand ist oder ein Merge oder Rebase noch nicht abgeschlossen wurde. OpenChamber markiert das, damit du es beheben kannst — siehe [Worktrees & Git](/troubleshooting/worktrees-git/).
