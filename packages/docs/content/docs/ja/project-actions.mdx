# プロジェクトアクション

プロジェクトアクションは、一度保存してクリックで実行できるシェルコマンドです。開発サーバー、ビルド、テスト実行などに使えます。各プロジェクトが独自の一覧を持ちます。**Settings → Projects → Project Actions** で設定します。

## アクションを追加する

1. **Settings → Projects** を開き、**Project Actions** セクションを見つけます。
2. アクションを追加し、名前を付け、アイコンを選び、実行するコマンドを入力します。
3. 保存します。

コマンドが特定の OS でしか意味を持たない場合は、アクションをその OS に限定できます。

## アクションを実行する

チャットの右側にあるカード、Work Status パネルの **プロジェクト** セクションにアクションの行があります。アクションを押すと実行し、もう一度押すと停止します。横のシェブロンで別のアクションを選べます。そのメニューの **新しいアクションを追加** は **設定 → プロジェクト** を開きます。行には最後に選んだアクションが表示され、アクションの実行中はそのアクションが表示されます。実行にプレビューのアドレスがあるときは、行の横の地球儀ボタンでそのアドレスを開けます。

キーボードからは、macOS で **⌘⌥R**、Windows と Linux で **Ctrl+Alt+R** を押すとプロジェクトアクションのダイアログが開きます。現在のプロジェクトのアクションが状態とともに一覧表示されます。矢印キーで選択を移動し、Enter で停止中のアクションを実行、実行中のアクションを停止します。Esc で閉じます。検索欄で一覧を絞り込めます。最後の **アクションを設定** はプロジェクトのアクション設定を開きます。ダイアログは Work Status の行のアクションが選択された状態で開くので、ショートカットに続けて Enter を押すと前回の実行を繰り返せます。ショートカットは **設定 → ショートカット** の **プロジェクトアクションを開く** で変更できます。

⌘P または Ctrl+P で開くコマンドパレットで「実行」またはアクション名を入力すると、**実行: dev** や **停止: dev** のような項目が見つかります。パレットの **プロジェクトアクション** はダイアログを開きます。

各アクションはセッションのフォルダ内のターミナルで実行されます。セッションが worktree にあればその worktree、メインのチェックアウトで実行するよう設定したアクションはメインのチェックアウトです。出力を見られるようにターミナルが開きます。プロジェクトアクションはデスクトップと Web アプリで使えます。VS Code、スマートフォン、Chats のセッションでは使えません。

## 開発サーバーを自動で開く

サーバーを起動するアクションでは **auto-open URL** をオンにします。OpenChamber は出力からローカルアドレスを監視し、開く候補として表示します。[プレビューと開発サーバー](/preview/) を参照してください。デスクトップでは SSH ポートフォワード経由にすることもできます。

サーバーのアドレスが決まっている場合は、アクションの URL 欄に入力します。`{worktree}` と `{branch}` はアクションを実行するチェックアウトに置き換わるので、1 つのアクションがどの worktree でも使えます。[portless](https://github.com/vercel-labs/portless) を使う場合、`https://{worktree}.myapp.localhost` は `feature/auth` の worktree では `https://auth.myapp.localhost`、メインのチェックアウトでは `https://myapp.localhost` を開きます。この欄が不要なこともあります。portless がアドレスを出力すると、OpenChamber はその裏のポートではなくそのアドレスを開きます。リモートインスタンスに接続したデスクトップでは、トンネルを通るのはループバックのポートだけなので、代わりにポートを開きます。
