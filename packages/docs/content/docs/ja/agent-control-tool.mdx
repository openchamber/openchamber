# エージェント制御ツール

`openchamber` エージェントツールはチャットからアプリ内の作業を直接管理し、`openchamber_schedule` はスケジュールタスクを扱います。OpenChamber が独自のローカル OpenCode サーバーを実行している場合はどちらもデフォルトで有効で、インストールや shell コマンドの実行は必要ありません。

## 頼めること

エージェントには普段の言葉で頼めます。例:

- 「このプロジェクトに新しい OpenChamber セッションを作成し、`openai/gpt-5.6-sol` モデルを使って、次のプロンプトを送って: 認証フローをレビューして。」
- 「このタスク用に別の worktree で新しい OpenChamber セッションを作成し、ログインフローのテストを追加するよう頼んで。」
- 「OpenChamber で最近の 10 セッションを、現在の状態と一緒に一覧表示して。」
- 「平日レビューという名前の OpenChamber スケジュールタスクを作成し、平日の 09:00 に次のプロンプトを送るようにして: 前回の実行以降の変更をレビューして。」
- 「平日レビューという名前の OpenChamber スケジュールタスクを今すぐ実行して。」
- 「認証レビューという名前の OpenChamber セッションを確認して、アシスタントの最新の返答を見せて。」

制御ツールはプロジェクトとモデル設定の一覧表示、モデルカタログの検索、セッションの作成と継続、セッションのフォーク、分離された worktree セッションの作成を行います。スケジュールツールはスケジュールタスクの作成、変更、実行、一時停止、削除を行います。この方法で始めたセッションは他のセッションと同じように OpenChamber に表示されるので、開いて自分で作業を続けられます。

## 注意点

- 新しいセッションへのプロンプトはデフォルトですぐに戻ります。OpenChamber でセッションを追うか、あとで確認するようエージェントに頼んでください。
- 別の worktree は頼んだときだけ作成されます。現在の worktree の未コミットの変更はそこにコピーされません。
- 同じブランチで別のセッションが作業しているなど、チェックアウトが使用中に見えるとき、エージェントは自分のセッションを新しい worktree に移すことを提案する場合があります。同意したあとに移動し、自分が変更したファイルだけを持っていきます。
- これらのツールはセッションや worktree の削除、プロジェクトパスの登録、任意の shell コマンドの実行、任意の URL の呼び出しはできません。

## ツールのオンとオフ

**設定 → 一般 → OpenChamber ツール** を開き、**エージェント制御ツール** または **エージェントのスケジュールツール** を切り替えます。それぞれ個別にオンオフできます。スケジュールが独立したツールになる前に制御ツールをオフにしていた場合、スケジュールツールもオフで始まります。変更は実行中のセッションに次のターンで届き、再起動は不要です。ご自身の環境ですでに `OPENCODE_CONFIG` を設定している場合は、管理対象の OpenCode サーバーが再起動したときに反映されます。

OpenChamber が `OPENCODE_HOST` や skip-start で外部の OpenCode サーバーに接続している場合や、VS Code 拡張機能の中ではこれらのツールは使えません。OpenChamber の管理対象 OpenCode サーバーを使うデスクトップ版とウェブ版では自動的に使えます。
