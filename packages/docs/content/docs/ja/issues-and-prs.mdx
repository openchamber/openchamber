# Issues と PR

**Issues and PRs** ボードは、プロジェクトの GitHub、GitLab、Gitea、Gerrit の Issue とプルリクエスト（GitLab ではマージリクエスト、Gerrit では変更。Gerrit には Issue はありません）、または Linear の Issue を一覧する専用ページです。項目を選ぶと、一覧の横にプレビューが開きます。ここで別のプロジェクトを見ても、アプリのほかの部分のプロジェクトは変わりません。

## ボードを開く

- サイドバーのヘッダーにあるプルリクエストアイコンをクリックします。スケジュールタスクとアーカイブの隣にあります。
- コマンドパレットで **Issues and PRs** を選びます。
- <kbd>⌘K</kbd> に続けて <kbd>B</kbd> を押します（Windows と Linux では <kbd>Ctrl+K</kbd> に続けて <kbd>B</kbd>）。同じキーで閉じます。

スマートフォンでは、セッションメニュー下部のプルリクエストボタンをタップします。VS Code 拡張機能にはボードはありません。

ボードは、前回閉じたときのプロジェクト、タブ、チームで開き直します。

## 項目を探す

操作はツールバーの 1 行にまとまっています。左端はプロジェクトピッカーで、プロジェクトアイコンと検索があります。その隣で **Issues**、**Pull requests**、**Linear** を切り替えます。Issue とプルリクエストは、プロジェクト自身のホストから取得します。GitHub、GitLab、Gitea、Gerrit、または [拡張機能](/ja/extensions/#git-ホストとしての拡張機能) が追加したホストです。**Linear** タブは Linear を接続したときだけ表示されます。これらのどのホストにもないプロジェクトでは、そのタブだけが表示されるか、一覧するものがないと表示されます。`github.com-work` のような `~/.ssh/config` のホストエイリアスにあるリモートは、どのホストにも当たりません。

プロジェクトのフォルダ自体は Git リポジトリではなく、中にリポジトリがある場合は、プロジェクトピッカーの横にある 2 つ目のピッカーで、ボードに一覧するものを選びます。最初にある **すべてのリポジトリ** が既定です。ボードはフォルダ内のすべての GitHub リポジトリの Issue とプルリクエストをまとめて一覧し、各行にリポジトリ名が表示されます。検索は貼り付けたリンクや番号も含めて、すべてのリポジトリを対象にします。一覧の上の注記には、含まれていないリポジトリの数が表示されます。たとえば GitLab、Gitea、Gerrit にあるリポジトリや、接続したどのアカウントでも読めないリポジトリです。注記のメニューで、どれがなぜ含まれていないかを確認できます。1 つのリポジトリを選ぶと、そのリポジトリだけを一覧します。ボードはこの選択をプロジェクトごとに覚えます。Git ビューで選んでいるリポジトリとは別です。

コメント、ラベル、レビュアー、マージは、項目が属するリポジトリに対して行われます。**New session** はこれまでどおりプロジェクトのフォルダで開始します。**Changes** と **Walkthrough** はプルリクエストをそのリポジトリで開き、Git ビューで選んでいるリポジトリはそのまま残します。これらの項目では、worktree で作業を始める操作はまだ使えません。これらのリポジトリの Issue やプルリクエストへのリンクは、そのリポジトリを通して読み込まれ、Tracker で開きます。スマートフォンではボードで開き、見つけるために **すべてのリポジトリ** に切り替わります。VS Code 拡張機能にはボードがないので、ここでは何も変わりません。

**Linear** では、プロジェクトピッカーがチームピッカーに変わります。**All teams** か 1 つのチームを選びます。**Linear** だけのプロジェクトでも、プロジェクトピッカーはチームピッカーの横に残るので、別のプロジェクトに切り替えられます。Linear のワークスペースを複数接続している場合は、同じメニューでワークスペースを切り替えます。Linear の接続方法は [統合機能](/ja/integrations/) にあります。

検索では、タイトル、番号、または貼り付けたリンクを使えます。フィルターメニューは選んでいる間も開いたままなので、フィルターを組み合わせられます。

GitHub、GitLab、Gitea、Gerrit:

- ステータス: **Open**、**Closed**、**All**、プルリクエストでは **Merged** も
- 人: **Anyone**、**Assigned to me**、**Created by me**、プルリクエストでは **Review requested** も

Linear:

- ステータス: **Open**、**All**、**Backlog**、**To Do**、**In Progress**、**In Review**、**Done**、**Canceled**、**Duplicate**
- 人: **Anyone**、**Assigned to me**、**Created by me**
- 優先度: **All priorities**、**Urgent**、**High**、**Medium**、**Low**、**No priority**

## 項目を読む

プレビューには説明、ラベル、コメントが表示されます。Linear の Issue では、ステータスのピルをクリックすると、チームの別のステータスに移せます。

**Labels** の行には鉛筆ボタンがあり、リポジトリのラベルを検索できるリストが開きます。ラベルのチェックを付けたり外したりします。変更はリストを閉じたときに保存されるので、何度クリックしても 1 回の変更になります。開いているプルリクエスト（GitLab ではマージリクエスト）には **Reviewers** の行もあり、同じように使えます。リストに出るのは、そのリポジトリでレビューできる人です。GitHub では、プルリクエストの作成者は候補に出ません。Linear の Issue にはどちらの行もありません。

## コメントとレビュー

Issue やプルリクエストのアクティビティの下にはコメント欄があります。**Comment** を押すと、書いた内容をリポジトリのホストに投稿します。<kbd>⌘</kbd>+<kbd>Enter</kbd>（Windows と Linux では <kbd>Ctrl</kbd>+<kbd>Enter</kbd>）でも同じです。テキストは投稿されるまで欄に残るので、投稿に失敗しても何も失われません。別の項目に切り替えると欄は空になります。Linear の Issue にはコメント欄はありません。

開いているプルリクエスト（GitLab ではマージリクエスト）には **Approve** と **Request changes** もあり、欄の内容はレビューと一緒に送られます。**Request changes** にはテキストが必要なので、何を変えてほしいかを書きます。レビューはプレビューに表示されているコミットに対するものです。その後に誰かがプッシュしていると、レビューは拒否され、プレビューが更新されるので、もう一度確認できます。GitLab では、**Request changes** はマージリクエストのレビュアーであるときに使えます。レビューのテキストは別のコメントとして投稿されます。そのコメントだけが失敗した場合も、レビューは有効で、テキストは欄に残ります。

Gerrit の変更には、Code-Review や Verified といったプロジェクトのラベルごとに行があり、あなたが付けられるスコアが並びます。スコアを選んで **投票する** を選びます。欄のテキストはメッセージとして投票と一緒に送られます。投票は最新のパッチセットに付くので、以前のパッチセットを読んでいる間は投票できません。

## 作業を始める

操作ボタンはプレビューの下部にあります。

- **New session** は、項目をメッセージ欄に添付した状態で、プロジェクトに新しいセッションを開きます。最初のメッセージは自分で書きます。
- Issue の **Start in worktree…**、プルリクエストの **Check out in worktree…** は、項目を選んだ状態で New Worktree ダイアログを開きます。プルリクエストはその PR 自身のブランチをチェックアウトします。[Worktree セッション](/ja/worktrees/) を参照してください。

Linear の Issue では、**Start in** にセッションを開始するプロジェクトが表示されます。これは [統合機能](/ja/integrations/) の Linear カードで Issue のチームに対応付けたプロジェクトです。チームの対応付けがなければ既定のプロジェクト、それもなければボードが最後に表示していたプロジェクトになります。その Issue だけ別のプロジェクトをそこで選ぶこともできます。

## プルリクエスト

プルリクエストのプレビューには、ブランチ、サイズ（追加・削除した行数と変更ファイル数）、チェック、レビューも表示されます。**Activity** フィードは、コメント、レビューの判定、最新のコミットを起きた順に並べます。続けて入ったコミットはまとめて表示されるので、レビューがどのコミットに対するものかがわかります。

サイズの横には 2 つのボタンがあります。**Changes** はプルリクエストの差分をサイドパネルに開き、**Walkthrough** はその [変更のウォークスルー](/ja/walkthrough/) を開きます。アプリが別のプロジェクトを開いている場合は、先に PR のプロジェクトに切り替えます。スマートフォンでは **Changes** がワークスペースパネルの **Git** タブで PR を開きます。**Walkthrough** はデスクトップと Web だけで使えます。

下部の **Merge** は、マージ前に確認し、いつものマージ方法を使います。ドラフトには **Ready for review** もあります。

Gerrit では、プレビューに変更のトピックと、非公開か作業中かも表示されます。パッチセットが複数ある変更では、**Changes** の横のピッカーで、ファイルと差分をどのパッチセットから表示するかを選べます。最初は最新のパッチセットです。**Merge** は **サブミット** になり、変更のサブミット要件を満たすまでオフのままで、満たしていない要件が横に表示されます。**Close** と **Reopen** は **変更を破棄** と **変更を復元** になります。

開いている Issue やプルリクエストの下部には **Close issue** または **Close pull request**（GitLab では **Close merge request**）があり、閉じたものには **Reopen issue** または **Reopen pull request**（**Reopen merge request**）があります。元に戻せる操作なので、確認は出ません。マージ済みのプルリクエストは閉じることも開き直すこともできません。GitHub では、Issue は完了として閉じられます。
