# 統合機能

**設定 → 統合機能** では、OpenChamber が連携するサービスにサインインします。サインイン情報は OpenChamber サーバーに保存されるため、Web、デスクトップ、ペアリングした端末で共有されます。

## 統合機能カタログ

統合機能カタログには、ワンクリックでエージェントに渡せる 150 以上のサービスが並んでいます。Linear、Notion、Sentry、Supabase、Figma のほか、オブザーバビリティツール、CRM、議事録ツールなどがあります。インストールすると、たいていはそのサービスの MCP サーバー（エージェントがそのサービスの情報を読んだり変更したりするための接続）が追加され、付属するスキルやプラグインが入ることもあります。インストールはユーザー単位なので、すべてのプロジェクトで使えます。

1. サイドバーのヘッダーにあるストアアイコンを選びます。
2. サービスを探します。名前で検索するか、**コード** や **品質と運用** などのカテゴリで一覧を絞り込みます。**OpenChamber** には OpenChamber 独自の拡張機能とプラグインが並んでいます。
3. その行の **+** を選ぶか、サービスを開いて **インストール** を選びます。
4. サービスが求める方法でサインインします。
   - **OAuth**：ブラウザーでサービスのサインインページが開きます。そこでアクセスを承認します。
   - **トークン**：**APIトークン** に API トークンを貼り付けます。**トークンを取得** を選ぶと、サービスがトークンを発行するページが開きます。
   - **サインイン不要**：何もする必要はありません。

完了すると、サービスにチェックマークが付き、左側の **インストール済み** に表示されます。そのツールは次のメッセージから使えます。黄色の点や **サインインが必要** が表示されている場合は、サインインが完了していません。サービスを開いてもう一度サインインしてください。

サインインだけでは済まない項目もあります。

- **ローカルサーバー** は OpenCode が動いているマシン上で動作し、Node.js、uv を使う Python、または Docker が必要になる場合があります。初回の起動には時間がかかることがあります。
- **プラグイン** は OpenCode の中で動くコードなので、カタログは先にプラグインのライセンスを表示し、確認を求めます。
- サービスに付属する **スキル** は、サービスと一緒にインストールされます。足りないものがあれば、サービスのページにそのスキル用の **インストール** が表示されます。

サービスを削除するには、サービスを開いて **その他の操作**（**⋯**）を選び、**削除** を選びます。削除されるのはカタログが追加したものだけで、サービス側のアカウントはそのまま残ります。MCP サーバー、プラグイン、スキルはこれまでどおり設定からも管理できます。

カタログは Web アプリとデスクトップアプリで使えます。[エンタープライズモード](/ja/security/#エンタープライズモード)では表示されません。

## GitHub

**GitHub** カードを展開し、**Connect GitHub** を選んで短いデバイスコードでサインインします。接続後は、Issue やプルリクエストからセッションを開始し、メッセージに添付し、PR を作成・更新できます。Git ホストでできることは [Git ホスト](/ja/github/) にまとめています。

## GitLab、Gitea、Forgejo、Gerrit

GitLab、Gitea、Forgejo、Gerrit には、GitHub の隣にそれぞれ専用のカードがあります。接続すると、その Issue とプルリクエスト（GitLab ではマージリクエスト、Gerrit では変更）が、GitHub と同じように [Issues と PR](/ja/issues-and-prs/) ボードとチャットの **+** メニューに表示されます。

- **GitLab**: gitlab.com では、短いデバイスコード、Personal Access Token、またはサーバー上の `glab` のログインでサインインします。セルフマネージドの GitLab では、そのアドレスを追加し、`api` スコープを持つ Personal Access Token を貼り付けます。そこでデバイスコードによるサインインが使えるのは、サーバーが `OPENCHAMBER_GITLAB_CLIENT_ID` にそのインスタンスで登録したアプリケーションを設定している場合だけです。
- **Gitea**: `https://gitea.example.com` のようなインスタンスのアドレスを追加し、`write:repository`、`write:issue`、`read:user` スコープを持つ Personal Access Token を貼り付けます。カードには、インスタンス上でトークンを作成するページへのリンクがあります。Gitea にはデバイスコードや CLI によるサインインはありません。Gitea 1.21 以降が必要で、アドレスのルートで提供されている必要があります。
- **Forgejo**: Codeberg はすでにカードにあるので、接続に必要なのは `write:repository`、`write:issue`、`read:user` スコープを持つ Personal Access Token だけです。カードには、Codeberg 上でトークンを作成するページへのリンクがあります。別の Forgejo サーバーでは、`https://forgejo.example.com` のようなアドレスを追加し、同じスコープを持つトークンを貼り付けます。Forgejo 7.0 以降が必要で、アドレスのルートで提供されている必要があります。Forgejo サーバーはこのカードで、Gitea サーバーは Gitea カードで接続します。
- **Gerrit**: `https://gerrit.example.com` のようなインスタンスのアドレスを追加し、Gerrit のユーザー名と HTTP パスワードを入力します。パスワードは Gerrit の **Settings → HTTP Credentials** で生成します。カードにそこへのリンクがあります。サインイン用のパスワードは使えず、ユーザー名のないアカウントは接続できません。Gerrit 3.8 以降が必要で、アドレスのルートで提供されている必要があります。googlesource.com と `.gitcookies` のように、レビュー用のアドレスと Git のアドレスが異なるサイトには対応していません。

Gerrit では変更をレビューします。変更をアップロードするたびにパッチセットができ、変更のプレビューでは以前のパッチセットを選んで読めます。レビューは Code-Review や Verified といったプロジェクトのラベルへの投票で行い、サブミット要件を満たした変更は **サブミット** で取り込みます。Gerrit には Issue がないので、表示されるのは変更だけです。変更を作成したり、変更に新しいパッチセットをアップロードしたりするには、Git パネルの **レビューへプッシュ** を使います。[Git](/ja/git/#gerrit-でレビューへプッシュする) を参照してください。

OpenChamber がどのカードのアカウントを使うかは、プロジェクトのリモートで決まります。これらのカードのアカウントはどれも、プロジェクトの [Git ID](/ja/git-identities/) にできます。[拡張機能](/ja/extensions/#git-ホストとしての拡張機能) は、専用のカードを持つ別のホストを追加できます。

## Linear

### ワークスペースを接続する

1. **Linear** カードを展開し、**Connect** を選びます。
2. 開いたブラウザータブでアクセスを承認します。承認するまでカードには **Waiting for Linear** と表示されます。

別の Linear 組織は **Add workspace** で接続します。現在のワークスペースは常に 1 つで、**Switch to** で切り替え、**Disconnect** は現在のものだけを外します。プロジェクトの対応付けは残ります。

### Issue を閲覧する

Linear の Issue は **Issues and PRs** ボードにあります。サイドバーのヘッダーにあるプルリクエストアイコンから開くか、<kbd>⌘K</kbd> に続けて <kbd>B</kbd> を押し（Windows と Linux では <kbd>Ctrl+K</kbd> に続けて <kbd>B</kbd>）、上部で **Linear** を選びます。ボードには現在のワークスペースの Issue が一覧され、次の操作ができます。

- 1 つのチームか **All teams** を表示する
- 複数のワークスペースを接続している場合、現在のワークスペースを切り替える
- ステータス、誰の Issue か（**Assigned to me** または **Created by me**）、優先度を組み合わせて絞り込み、タイトルや識別子で検索する
- 一覧の横で Issue の説明、コメント、ラベル、優先度を読む
- **Status** を変更する

### Issue からセッションを開始する

- ボードで Issue を選び、新しいブランチで作業するなら **Start in worktree…**、プロジェクトをそのまま使うなら **New session** を選びます。
- **New Worktree** ダイアログで Linear の Issue を選びます。

どちらの場合も、セッションは Issue がメッセージ欄に添付された状態で開き、最初のメッセージは自分で書きます。ボードは Issue のチームに対応付けられたプロジェクトでセッションを開始します。そのプロジェクトは **Start in** の横に表示され、必要ならそこで別のプロジェクトを選べます。チームの対応付けは Linear カードで行います。**Default project** が全チームに適用され、**Team projects** でチームごとに上書きできます。対応付けがない場合、ボードは最後に表示していたプロジェクトを使います。

### Issue をメッセージに添付する

チャットのコンポーザーで **+** メニューを開き、**Linear** を選びます。Issue は次のメッセージにコンテキストとして添付され、セッションの作業ステータスパネルにリンクが残ります。

### セッションコメント

Linear カードで **Session comments** をオンにすると、Issue から開始したセッション、または最初のメッセージにその Issue を添付したセッションが、開始時、完了時、失敗時にその Issue へコメントを投稿します。各コメントにはセッションを開くリンクが付きます。コメントは、この OpenChamber サーバーが公開アドレスを持つ場合にのみ投稿されます（Issue の関係者全員がリンクを開けるようにするため）。ローカルやプライベートなアドレスでは何も投稿されません。

## 統合機能をインストールする

1. **Settings → Integrations** を開きます。
2. 統合機能を見つけて **Install** を選びます。
3. 求められたら OpenCode を再起動します — 再起動後にプロバイダーが現れます。
4. **Set up** を選んでサインインします。するとチャットのモデル選択にモデルが表示されます。

統合機能はユーザー単位でインストールされるため、すべてのプロジェクトで使えます。同じカードからいつでも更新や削除ができます。

## 拡張機能の通知チャネル

[拡張機能](/ja/extensions/)は、Slack や Matrix、自前のサーバーにあなたの通知を届けられます。**設定 → 拡張機能** で許可すると、このページの **拡張機能のアカウント** にカードが表示されます。そこにアカウントのトークンを入力し、カードが求める場合はサーバーのアドレスも入力して接続します。以後、拡張機能は[通知の設定](/ja/notifications/)に従って、スマートフォンが受け取るものと同じ通知を受け取ります。トークンは OpenChamber に保持されます。拡張機能のサービスは OpenChamber 経由で送信し、トークンを見ることはありません。

後でサーバーがトークンを拒否すると、カードに **アカウントの確認が必要** と表示されます。新しいトークンで再接続してください。拡張機能を削除せずに配信を止めるには、**切断** するか拡張機能を一時停止します。拡張機能を削除するとアカウントも忘れられます。

## Claude Code

Claude Code は、お使いのマシンの Claude Code CLI を通じて Claude Pro または Max プランを使います — API キーは不要です。

1. 統合機能をインストールします（上記）。
2. **Set up** を選んでサインインします。Claude Code CLI がまだない場合は、セットアップがまずインストールを提案し、その後サインインします。

**Claude アカウントが守られる仕組み：** この統合機能は Anthropic の公式 Claude Agent SDK と、インストール済みの Claude Code CLI を使用します。OAuth の乗っ取り、ブラウザートークンの抽出や再生、未対応クライアントへの偽装、Anthropic の認証フローの回避は一切行いません。Anthropic がサポートする正規のアクセス経路を使うため、トークン乗っ取りや不正な認証の回避につきもののアカウント停止リスクはありません。

## 更新と削除

- **Update** はプラグインの最新の公開バージョンをインストールします。
- **Remove** は OpenCode の設定からプラグインを削除します。OpenCode が再読み込みされるとプロバイダーは読み込まれなくなります。

カードに手動での管理が必要だと表示された場合は、**Manage plugins** を選んで重複を整理してください。

## Excalidraw

Excalidraw を使うと、`.excalidraw` ファイルや Obsidian の `.excalidraw.md` 図面を Files の中で直接描けます。OpenChamber 拡張機能で、同じページの **OpenChamber extensions** に表示されます。

1. **Settings → Integrations** を開き、Excalidraw カードで **Install** を選びます。Files で図面を開き、その上に表示される通知で **Install** を選ぶこともできます。
2. 図面をもう一度開きます。ファイルのテキストの代わりにキャンバスが表示され、Cmd/Ctrl+S、自動保存、ソース表示の切り替え、全画面表示はほかのファイルと同じように使えます。

カードからは、新しいバージョンが出たときの拡張機能の更新、一時停止した拡張機能の再有効化、削除ができます。削除しても図面はそのまま残り、テキストとして開かれるだけです。Web とデスクトップのみ対応しています。

## Resource Monitor

Resource Monitor は、マシン全体の CPU とメモリの使用量と、そのうち OpenChamber、OpenCode、それらが起動したすべてのプロセス、その下で動く開発サーバーが使っている量を表示します。OpenChamber 拡張機能で、同じページの **OpenChamber extensions** に表示されます。

1. **Settings → Integrations** を開き、Resource Monitor カードで **Install** を選びます。
2. **Settings → Extensions** でローカルサービスを承認します。数値は OpenChamber がパネルの横で起動する小さなプロセスから届きます。このプロセスは、パネルか **Resources** セクションが画面に表示されている間だけ計測します。
3. 右側のレールから **Resource Monitor** を開きます。Work Status パネルの **Resources** にも短い概要が表示されます。

開発サーバーやジョブの Stop は、そのコマンドと、それが起動したすべてのプロセスを終了します。そのため watcher がサーバーを再起動することはありません。Terminal グループの **Stop all** は、ターミナルと project actions で動いているものをすべて終了し、ターミナルのタブは開いたまま残します。OpenChamber 本体と OpenCode サーバーには Stop はありません。

開発サーバーは、内蔵ターミナルから、または OpenChamber 自身が OpenCode を起動した場合にエージェントから起動されて、OpenChamber の下で動いているときに表示されます。親プロセスから切り離されるサーバーや、`docker compose up -d` で起動したコンテナは表示されません。リモートの OpenChamber に接続している場合は、そのマシンの情報が表示されます。Web とデスクトップのみ対応しています。
