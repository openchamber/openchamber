# Git ホスト: Issue とプルリクエスト

プロジェクトがあるホストのアカウントを接続すると、OpenChamber はその Issue とプルリクエストを一覧し、そこからセッションを開始し、プルリクエストの作成、レビュー、マージを代わりに行えます。組み込みのホストは 4 つです。GitHub（GitHub Enterprise を含む）、GitLab（セルフマネージドの GitLab を含む）、Gitea、Gerrit です。[拡張機能](/ja/extensions/#git-ホストとしての拡張機能) で別のホストを追加することもできます。

OpenChamber がどのホストと通信するかは、プロジェクトのリモートで決まります。`origin` が gitlab.com にあるプロジェクトでは、ボード、ブランチのプルリクエストバッジ、Git パネルに GitLab アカウントが使われます。`github.com-work` のような `~/.ssh/config` のホストエイリアスにあるリモートは、どのホストにも対応付けられません。

用語はホストに合わせて変わります。GitLab ではマージリクエスト、Gerrit では変更と呼びます。

## ホストを接続する

1. **Settings → Integrations** を開きます。ホストごとにカードがあります。
2. プロジェクトのホストのカードを展開してサインインします。
   - **GitHub**: **Connect GitHub** を選び、表示されたリンクを開いて短いコードを入力し、承認します。GitHub Enterprise では、**その他のインスタンス** の下にある **インスタンスを追加** を選び、サーバーのアドレスを入力して Personal Access Token を貼り付けます。
   - **GitLab**: gitlab.com では、短いコード、Personal Access Token、または `glab` のログインでサインインします。セルフマネージドの GitLab では、そのアドレスを追加して Personal Access Token を貼り付けます。
   - **Gitea**: サーバーのアドレスを追加し、Personal Access Token を貼り付けます。
   - **Gerrit**: サーバーのアドレスを追加し、Gerrit のユーザー名と HTTP パスワードを入力します。

接続されると、カードにアカウントが表示されます。1 つのホストに複数のアカウントを接続して切り替えたり、いつでも切断したりできます。同じマシンで `gh` CLI にサインイン済みなら、OpenChamber は GitHub にもそれを使えます。各トークンに必要なスコープと、各ホストに必要なバージョンは [統合機能](/ja/integrations/#gitlabgiteagerrit) にあります。

接続したアカウントはプロジェクトの [Git ID](/ja/git-identities/) にもできます。その場合、コミットにはそのアカウントの名前が入り、HTTPS での push にはそのトークンが使われます。

## Issue またはプルリクエストから作業を始める

[worktree セッション](/ja/worktrees/) を作成するとき、プロジェクトのホストにある Issue またはプルリクエストから開始できます。

- **issue** を選ぶと、OpenChamber はその Issue に基づいてブランチ名を付けます
- **pull request** を選ぶと、そのプルリクエストのブランチをチェックアウトします。差分を含めて、エージェントに変更全体を渡すこともできます
- **Gerrit の変更** を選ぶと、最新のパッチセットを `change-<number>` という名前のブランチにチェックアウトします

新しいセッションは、項目がメッセージ欄に添付された状態で開きます。自動では何も送信されません。モデルとエージェントを選び、やってほしいことを書いて送信してください。

[Issues と PR](/ja/issues-and-prs/) ボードにも同じ項目が並び、フィルター、プレビュー、コメント、レビューがあり、そこからもセッションを開始できます。

## プルリクエストを開いて管理する

[Git パネル](/ja/git/) の **PR** タブから、プルリクエストの作成、更新、draft から ready への変更、マージができます。OpenChamber は変更内容からタイトルと説明を書けます。

- **GitLab**: 同じタブでマージリクエストを開きます。マージでは merge と squash を選べます。
- **Gitea**: GitHub と同じです。
- **Gerrit**: レビューへプッシュすると変更が作られ、その後のプッシュごとに新しいパッチセットがアップロードされます。[Gerrit でレビューへプッシュする](/ja/git/#gerrit-でレビューへプッシュする) を参照してください。マージは **サブミット** で、変更がサブミット要件を満たすまで待ちます。レビューは、Code-Review や Verified といったプロジェクトのラベルへの投票です。

## Issue やプルリクエストをメッセージに添付する

チャットのコンポーザーで **+** メニューを開き、ホストのリンク項目を選びます。たとえば **GitHub の Issue または PR をリンク**、**GitLab の Issue または MR をリンク**、**Gerrit の変更をリンク** です。項目を 1 つ以上選びます。それぞれが次のメッセージにコンテキストとして添付され、プルリクエストは差分も含められます。セッションの作業ステータスパネルにはリンクが残ります。添付で加わるのはコンテキストだけです。何をしてほしいかはメッセージで伝えます。

Gerrit には Issue がないので、表示されるのは変更だけです。
