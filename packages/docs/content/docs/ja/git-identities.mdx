# Git ID

Git ID は、コミットに入る名前とメールアドレス、そしてリポジトリがリモートにサインインする方法です。個人用リポジトリと仕事用リポジトリをまたいで作業する場合、ID を保存し、リポジトリごとに正しいものを適用できます。**Settings → Git** で管理します。

## ID を追加する

1. **Settings → Git** を開き、**New** を選びます。
2. コミットに使う **ユーザー名** と **メールアドレス** を入力します。
3. **認証方法**（push と pull の方法）を選びます。
   - **このマシン**: このマシンの Git がすでに使っているもの。SSH キー、資格情報マネージャー、`gh` CLI など
   - **アカウント**: 選んだ **ソース管理アカウント**。[統合機能](/ja/integrations/) のホストカードで接続したアカウントなら何でも使えます（GitHub、GitLab、Gitea、Forgejo、Gerrit など）。push はそのアカウントのトークンを使って HTTPS で行われます
   - **SSH**: OpenChamber がこの ID 用に保持するキー
   - **匿名**: サインインせずに HTTPS で公開リポジトリを読み取ります。push はできません
4. 必要なら、見分けやすいように色とアイコンを付けます。

システムのグローバル ID も読み取り専用で表示されます。

Gerrit では、アカウントの ID は Gerrit のユーザー名と接続した HTTP パスワードで Git にサインインします。GitHub Enterprise のアカウントは Issue とプルリクエストには使えますが、そこでの clone と push は **このマシン** または **SSH** で行います。

## ID をリポジトリに適用する

[Git パネル](/ja/git/) 上部の ID ボタンを選び、ID を 1 つ選びます。追加画面と clone 画面でも同じ選択ができます。リポジトリに届かない ID は、無効の状態で理由と一緒にリストに残ります。理由は、別のホストのアカウント、SSH リモートに対するアカウントまたは **匿名**、HTTPS リモートに対する SSH キーのいずれかです。

ID を適用すると、そのリポジトリの**ローカル** Git 設定に書き込まれます。影響するのはそのリポジトリだけで、グローバル設定はそのまま残ります。ターミナルの Git とエージェントのシェルもこの ID を使います。**システムのアイデンティティ** を選ぶと OpenChamber が書き込んだ内容が削除され、自分の Git 設定が再び使われます。
