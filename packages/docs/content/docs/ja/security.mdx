# セキュリティ

OpenChamber はあなたのマシンとコードへのアクセスを提供するため、あなた以外が到達できるようにする前に必ず保護してください。このページでは UI パスワード、パスキー、ネットワークに OpenChamber を公開する前に知っておくべきことを説明します。

## UI パスワードを設定する

パスワード付きで OpenChamber を起動すると、ブラウザ UI がそれを要求します。

```bash
openchamber --ui-password be-creative-here
```

コマンドラインに書く代わりに、`OPENCHAMBER_UI_PASSWORD` 環境変数で設定することもできます。サインイン後、OpenChamber はしばらくそのデバイスを記憶するため、毎回求められることはありません。

インスタンスが自分以外から到達可能な場合は、必ずパスワードを設定してください。特に [トンネル](/tunnels/) や public internet 経由の場合は重要です。

## パスキー

パスワードを設定すると、より速くサインインするためにパスキー（Face ID、Touch ID、セキュリティキー）を追加できます。**Settings → OpenChamber → Passkeys** で追加します。

パスキーは現在のパスワードに紐づきます。パスワードを変更または削除すると、保存済みパスキーは消去され、再追加が必要になります。

## デバイストークン

[デバイスを接続する](/connect-devices/) でペアリングしたデバイスは、UI パスワードではなく、デバイスごとの専用トークンで認証します。ペアリングリンクは 1 回限りで、未使用なら期限切れになります。ペアリング済みのデバイスはすべて **Settings → Remote Instances → このサーバーに接続** に一覧表示され、いつでも無効化できます。外出先からの接続は [Private Relay](/private-relay/) を経由します。リレーはエンドツーエンドで暗号化されており、通信内容を読むことはできません。

## 公開する前に

- デフォルトでは、OpenChamber はあなたのマシン上（`127.0.0.1`）でのみ待ち受けます。より広く待ち受けるには明示的な変更が必要で、その前にパスワードを設定するべきです。
- 自分のデバイスなら、[Private Relay](/private-relay/) を使った [ペアリング](/connect-devices/) を推奨します。何も公開されません。
- 公開 URL が必要な場合は、インターネットにポートを開けるより、[トンネル](/tunnels/) または VPN のようなプライベートネットワークを推奨します。
- OpenChamber を自分の HTTPS サーバーの背後に置く場合は、[リバースプロキシ](/reverse-proxy/) を参照してください。

## エンタープライズモード

チームが会話の内容を OpenCode で設定したモデルプロバイダーにしか送れない場合は、エンタープライズモードをオンにします。方法は 2 つあり、どちらか一方で十分です。

### マシン上のポリシーファイル

管理しているノート PC ではこちらを使います。管理者だけが書き込めるフォルダーに `policy.json` という名前のファイルを置きます。

| システム | パス |
|---|---|
| macOS | `/Library/Application Support/OpenChamber/policy.json` |
| Windows | `C:\ProgramData\OpenChamber\policy.json` |
| Linux | `/etc/openchamber/policy.json` |

パスは OpenChamber のインストール方法に関係ありません。デスクトップアプリ、npm から起動した Web サーバー、CLI、VS Code 拡張機能はすべて同じファイルを読みます。配布にはデバイス管理ツール（Jamf、Intune など）を使えます。Docker で動かすサーバーでは、Linux のパスにファイルをマウントしてください。

```json
{
  "enterpriseMode": true,
  "organization": "Acme",
  "relayUrl": "wss://relay.acme.com/ws",
  "allowNetworkAccess": false,
  "jev": {
    "url": "https://llm.acme.com/v1",
    "model": "acme-classifier",
    "apiKey": "..."
  }
}
```

必須なのは `enterpriseMode` だけです。`organization` は設定に「Acme が管理しています。」と表示され、誰が決めたのかがわかります。`relayUrl` と `jev` は自前のリレーと自前の Jev エンドポイントを固定し、`allowNetworkAccess` はほかのデバイスがネットワーク経由で OpenChamber にアクセスできるようにします。3 つとも後述します。

- ユーザーが設定や環境で何を指定しても、ファイルでオンにしたものはオフになりません。
- ファイルでエンタープライズモードをオンにした場合、決めるのはファイルだけです。後述のリレー、Jev、ネットワークアクセス用の環境変数は無視されます。これらはユーザーが自分で設定できるためです。
- ファイルがあるのに読み込めない、または JSON として正しくない場合、エンタープライズモードはオンのままで、何も固定されません。設定には、ポリシーを読み込めなかったことが表示されます。壊れたファイルが知らないうちに保護を外すことはありません。
- 変更は再起動なしで反映されます。
- OpenChamber はユーザーの権限で動くため、ユーザーはこのファイルを読めます。API キーを書き込む前に、この点を考慮してください。

### 環境変数

環境を自分で管理できるサーバーやコンテナーなら、これで十分です。

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

ノート PC ではロックとして弱くなります。デスクトップアプリはこの変数をログインシェルのプロファイル（例：`~/.zshrc`）から読み込みますが、そのファイルはユーザーが編集できます。ノート PC ではポリシーファイルを使ってください。

この変数を使う場合、リレー、Jev、ネットワークアクセスもそれぞれの変数（`OPENCHAMBER_RELAY_URL`、`OPENCHAMBER_JEV_URL`、`OPENCHAMBER_ALLOW_NETWORK_ACCESS=1`）で指定します。Docker ではサーバーがコンテナーの外に向けて待ち受ける必要があるため、最後の変数が必要です。

### 変わること

- モデルプロバイダーは OpenCode の設定からのみ読み込まれます。OpenChamber でプロバイダーを接続する、サインインする、キーを追加する、カスタムプロバイダーを作成する操作はオフになります。すでにあるアカウントの削除や切り替えは引き続きできます。これはアプリ経由の入り口を閉じるだけで、実際のロックは後述の OpenCode ポリシーです。
- [分類プロバイダー（Jev）](/classification-providers/)はオフのままで、誰かが設定で入力したカスタムエンドポイントも同様です。セーフティネットと Auto は表示されず、セッションは手動で移したときだけ作業中になります。自社のインフラ経由で Jev を使うには、ポリシーファイルの `jev`、または `OPENCHAMBER_JEV_URL`（加えて `OPENCHAMBER_JEV_MODEL`、必要なら `OPENCHAMBER_JEV_API_KEY`）でエンドポイントを固定します。それが既定になり、オフにはできますが、ほかのものは選べません。
- OpenAI による読み上げはオフになります。カスタムの音声合成サーバーや文字起こしサーバーは、同じマシン上で動かす必要があります。ローカルの音声とローカルの音声入力モデルはそのまま使えます。
- スマートフォンやブラウザへのプッシュ通知には「Agent response is ready」のような汎用のタイトルだけが入り、メッセージ本文やセッション名は含まれません。デスクトップ通知はあなたのマシンの中にとどまり、全文を表示します。
- 更新の確認は引き続き行われるため、セキュリティ修正は届きます。ただし利用状況は一切報告せず、匿名のインストール ID すら送りません。
- [外部トンネル](/tunnels/)（Cloudflare、ngrok）はオフになります。トンネルのプロバイダーはエッジで通信を復号するため、すべてのリクエストを平文で見られます。
- [Private Relay](/private-relay/) は自前のリレー経由でのみ動作します。[セルフホストのリレー](https://github.com/openchamber/openchamber-relay)を動かし、ポリシーファイルの `relayUrl` または `OPENCHAMBER_RELAY_URL=wss://relay.example.com/ws` で OpenChamber をそこに向けてください。共有リレーもエンドツーエンドで暗号化されているため通信内容は読めませんが、自前のリレーなら接続のメタデータとこのマシンへの入り口をネットワーク内にとどめられます。自前のリレーがなければ、デバイスのペアリングは一切できません。
- OpenChamber は動いているマシン上でしか待ち受けません。ローカルネットワーク上のほかのデバイスからアプリを開けるようにするデスクトップの設定はオフになり、CLI（`--host`、`--lan`）でも環境でも、サーバーはネットワークアドレスでの起動を拒否します。アプリの実行中にポリシーファイルが置かれた場合、ほかのマシンからの接続は次回の起動まで切断されます。ネットワークアクセスを許可するには、ポリシーファイルで `"allowNetworkAccess": true` を指定するか、環境でエンタープライズモードをオンにしている場合は `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1` を設定します。接続は暗号化されていない HTTP なので、共有ネットワークでは誰でも内容を読めることに注意してください。ほかの人がアクセスするサーバーは[自前の HTTPS](/reverse-proxy/) の背後に置いてください。
- VS Code 拡張機能では、プロバイダーの接続がオフになり、更新の確認は利用状況を報告しません。Jev、リレー、トンネル、プッシュ通知、クラウドの音声機能はもともとありません。

小さなモデルのタスク（セッションのタイトル、要約、コミットメッセージ、変更のウォークスルー）に特別なモードは必要ありません。常に、設定で選んだ小さなモデル、作業中のプロバイダーの小さなモデル、または OpenCode の設定にあるデフォルトモデルのいずれかで動きます。たまたま接続している別のプロバイダーに切り替わることはありません。

そもそもどのモデルプロバイダーを使えるかを決めるのは、OpenChamber ではなく OpenCode です。[OpenCode ポリシー](https://opencode.ai/v2/docs/policies/)で固定してください。すべてのプロバイダーを拒否し、そのうえで承認したものを許可します。

```jsonc
{
  "experimental": {
    "policies": [
      { "action": "provider.use", "resource": "*", "effect": "deny" },
      { "action": "provider.use", "resource": "anthropic", "effect": "allow" }
    ]
  }
}
```

拒否されたプロバイダーは、誰かがキーを追加しても表示されません。ポリシーは、プロジェクトから解除できないグローバルの `~/.config/opencode/opencode.jsonc` に置くか、最終的な決定権を持つ OpenCode Console のワークスペースから配布してください。エンタープライズモードが扱うのは、それに加えて OpenChamber 自身が送るものです。

エージェントの Web 検索やページ取得も OpenCode を経由し、検索サービスやページそのものに接続します。これらをネットワークの外に出したくない場合は、同じ種類のポリシーで拒否してください。

```jsonc
{ "action": "permission", "resource": "websearch:*", "effect": "deny" },
{ "action": "permission", "resource": "webfetch:*", "effect": "deny" }
```
