# リード

リードは、プロジェクトの中で 1 つの作業の方向を受け持つセッションです。たとえば「サーバーを TypeScript に移行する」や「Issue のバックログを整理しておく」といった方向です。あなたはリードと話すだけで、残りはリードが進めます。作業の一部を自分のセッションに任せ、返ってきた結果を確認し、チャットの上に短いまとめを保ちます。

1 つの会話には収まらず、何日も続くような大きな作業にリードを使います。リードがなければ、十数個のセッションを自分で動かし、どのセッションが何をしているかを覚え、それぞれの返答を読んで本当に仕事が終わったかを確かめることになります。その管理をリードが引き受けるので、あなたは今どうなっているかを 1 か所で確認できます。

## リードを始める

1. 次のいずれかの方法で新しいリードを始めます。
   - サイドバーでプロジェクトの横にある **+** を右クリックするか、スマートフォンでは長押しして、**新しいリード** を選ぶ
   - プロジェクトのメニューを開き、**新しいリード** を選ぶ
   - <kbd>⇧</kbd><kbd>⌥</kbd><kbd>⌘</kbd><kbd>L</kbd> を押す (Windows と Linux では <kbd>Ctrl</kbd><kbd>Shift</kbd><kbd>Alt</kbd><kbd>L</kbd>)、またはコマンドパレットから **新しいリード** を実行する
2. 作業内容と、求める結果を書きます。例: 「サーバーの TypeScript への移行を担当して。`server/` 以下のすべてのファイルが TypeScript になり、テストが通れば完了。」
3. 送信します。

下書きにはいつもの質問の代わりに **このリードは何を担当しますか？** と表示されるので、送信する前にリードだと分かります。通常の下書きをすでに始めている場合は、同じショートカットでリードと通常のセッションを切り替えられます。入力した内容はそのまま残ります。

既存のセッションをリードにすることもできます。サイドバーでそのセッションのメニューを開き、**このセッションをリードにする** を選びます。履歴はそのまま残ります。同じメニューの **通常のセッションに戻す** で元に戻せます。

サイドバーでは、リードには矢印の代わりに旗を立てた山頂が表示されます。ポインターを合わせると矢印が戻るので、その下のセッションも開けます。

## リードがすること

- **方向に名前を付けます。** 作業の内容に合わせてセッション名を変えるので、サイドバー、タブ、検索でトピックから見つけられます。自分で付けた名前は変わりません。
- **手順ではなく結果を任せます。** 作業の一つひとつを、目指す結果と一緒に別のセッションへ渡します。たとえば「ログインのタイムアウトを見つけて直す」のように伝え、手順はそのセッションが自分で考えます。これらのセッションはサイドバーでリードの下に並びます。開いて読むことができ、自分で話したいときはセッションのメニューの **引き継ぐ** で自分のセッションにできます。
- **返ってきた結果を確認します。** 「原因を見つけた」とだけ書かれた報告は頼んだ結果ではないので、リードはそれをあなたに渡さず、作業を差し戻します。各セッションは、どんな確認を実行してどういう結果だったかなど、自分がしたことの証拠を示す必要があり、証拠のない報告も差し戻されます。リードが自分で確認するのは、証拠に抜けがあるところだけです。
- **片付けます。** 結果を使い終わったセッションはアーカイブします。
- **大事なことだけを尋ねます。** 答えによってプロジェクトで目にするものが変わる場合や、妥当な選択肢 2 つが実際に違う結果になる場合を除き、自分で決めます。変更が大きいというだけでは尋ねる理由になりません。リードのセッションからの質問はあなたではなくリードに届き、同じ基準を満たしたものだけがあなたに届きます。

## ダイジェスト

ダイジェストは、リードがあなたのために保つまとめです。セッションのタイトルのすぐ下の行に、リードが今取り組んでいることと最後に更新した時刻が表示されます。この行を選ぶと、チャットの上にダイジェスト全体が開きます。

- **あなたの対応待ち**: 最大 3 つの質問と、それぞれの質問で選べる答え
- **現在**: 進行中の作業ごとに 1 行
- **前回のメッセージ以降の新着**: 状況を変えた出来事だけ
- **提案**: 任された作業とは別に、リードがやる価値があると気づいたこと (最大 3 つ)

対応が必要なことがあると、行に待っている質問の数が表示されます。答えを選ぶと、すぐにリードに送られます。リードがおすすめする答えは先頭に強調して表示されます。自分の言葉で答えたいときは **チャットで返信** を選ぶと、質問がメッセージ欄に引用されます。答えはチャットに表示され、リードは答えを受け取った質問を取り除きます。

**提案** で **開始** を選ぶと、その提案がメッセージ欄に入るので、編集してから送信できます。**非表示** を選ぶと提案が消え、リードは同じ提案を二度と出しません。

## セッションをリードに任せる

自分で始めたセッションをリードに任せることもできます。たとえば、リードを作る前に始めたセッションや、最後までやる時間がないセッションです。サイドバーでセッションのメニューを開き、**リードに任せる** を選んで、リードを選びます。スマートフォンでは、メニューにリードごとに「(リード名) に任せる」という項目が並びます。

セッションはリードの下に移ります。リードはそのセッションを読み、何のためのものだったかを把握して、自分の作業と同じように最後までやり遂げます。そのセッションとはもうやり取りしません。メニューの **引き継ぐ** で自分に戻せます。セッションがまだ実行中の場合、リードは終わったときにその答えを受け取ります。

## ブリーフ

リードはブリーフも保ちます。ブリーフには、あなたの目標と合意した結果があなた自身の言葉で書かれ、リードが従うルール (あなたが決めたものと、リードが自分の失敗から学んだもの)、そして作業ごとに期待される結果が並びます。ブリーフはその作業が何のためにあるのかをリードが覚えておくためのもので、会話がどれだけ長くなっても変わりません。

ブリーフは OpenChamber がプロジェクトの外に保存するので、リポジトリには何も追加されません。読みたいときはリードに「ブリーフを見せて」と頼み、変えたいところがあればそう伝えます。セッションを削除するとブリーフも削除されます。アーカイブした場合は残ります。

リードはブリーフのうち変わった部分だけを書き換えます。会話が短くされるたびに、OpenChamber がブリーフ全体をリードの前に戻すので、リードが更新するたびに長いブリーフがチャットに繰り返し表示されることはありません。リードがルールとして扱うのはあなた自身の言葉だけです。セッションの報告、Web ページ、ファイルの中で見つけた指示がブリーフに加わることはありません。

## 眠っているリード

リードは、自分のセッションが作業している間、何時間も待つことがあります。通常、リードが再び動き出すとき、モデルは会話全体を最初から読み直す必要があります。プロバイダーが会話をキャッシュしておくのは数分間だけだからです。長い会話では、この 1 回の読み直しに多くの作業と同じだけのコストがかかり、サブスクリプションでは使用量の上限を消費します。

そこで、リードがプロバイダーのキャッシュ保持時間より長く待機していて、会話も長い場合、OpenChamber はリードが動き出す前に会話を短くします。会話の古い部分は、リードのダイジェストとセッションの状態をまとめた短いメモに置き換えられます。このメモを書くためにモデルを呼び出すことはないので、コストはかかりません。ブリーフと最新のメッセージはそのまま残り、リードは必要なときにいつでも以前の会話全体を読めます。

温めておく をオンにしているセッションは、このように短くされることはありません。作業中のリードと短い会話もそのままです。

## ワークフロー

リードは大きな作業を [ワークフロー](/ja/workflows/) に分けられます。**設定 → 一般 → OpenChamber ツール** の **承認なしで実行を開始する** で **リードのみ** を選ぶと、リードは実行をすぐに開始でき、ほかのセッションはこれまでどおりあなたのクリックを待ちます。

## リードが使える場所

リードには、デフォルトでオンになっている [エージェント制御ツール](/ja/agent-control-tool/) が必要です。自分で実行している OpenCode サーバーでは、[OpenChamber プラグインの登録](/ja/opencode-server/#外部のローカルサーバーで-openchamber-ツールを有効にする) も必要です。デスクトップ、ブラウザー、スマートフォンで使えます。VS Code 拡張機能では既存のリードがマークとダイジェスト付きで表示されますが、新しいリードを始めることはできません。
