# 作業中のセッション

サイドバー上部の **作業中** ブロックには、作業しているセッションが完了にするまで残ります。最後に開いたのがどれだけ前でも同じです。プロジェクトにはこれまでのすべてのセッションが残り、作業中にはまだ終わっていないものだけが並びます。

## 場所

**作業中** ブロックはサイドバーの、チャットの下、プロジェクトまたはタイムラインの上にあります。スマートフォンでも、セッション一覧の同じ位置にあります。

作業中のセッションは、プロジェクトとフォルダーにも、タイムラインのプロジェクトの下にも残るので、2 か所に表示されます。サブセッションも一緒についてきます。検索では、作業中ブロックに 1 回だけ表示されます。

ツリー表示では、ブロック内の各セッションは 1 行で表示されます。タイトル、状態、時刻に加えて、プルリクエストや issue があるときは色付きのマークが付きます。行にカーソルを合わせるとプロジェクト、ブランチ、リンクが表示されます。サイドバーの表示メニューで **詳細な行** をオンにすると、タイトルの下に表示されます。リスト表示は常に 2 行です。

ピン留めしたセッションを作業中の上にある専用の **ピン留め** ブロックにまとめるには、同じメニューで **ピン留めセクションを表示** をオンにします。作業中のセッションをピン留めすると、ピン留めにだけ表示されます。

## セッションが入る仕組み

セッションは後述のとおり手動で追跡できます。**設定 → セッション → 作業中のセッション** の **作業中に入れるタイミング** で、自動で入れることもできます。

- **オフ**：既定です。追跡したセッションだけが入ります。
- **すべてのメッセージ**：セッションでメッセージを送ると、そのセッションが入ります。完了にしたセッションは、新しいメッセージを送ると戻ってきます。
- **Jev が判断**：[分類プロバイダー](/ja/classification-providers/)を設定すると、Jev が送信された各メッセージを読み、変更の依頼、バグの報告、これから行う具体的な変更の相談のときにセッションを作業中に入れます。質問、説明、調査は対象外です。エージェントがターンを終えたときにも Jev がもう一度確認するので、返答で初めて分かる作業も拾えます。完了にしたセッションは、その後に送ったメッセージに Jev が新しい作業を見つけたときだけ戻ってきます。分類プロバイダーがない場合、Jev が判断はオフと同じ動作です。

worktree のセッションも含め、どのプロジェクトセッションでも同じです。

この設定が加わる前に **作業中のセッションを表示** を自分でオンにしていた場合は、それまでの動作である **すべてのメッセージ** から始まります。それ以外はオフから始まります。

チャット、アーカイブ済みのセッション、レビューセッション、[スケジュールタスク](/ja/scheduled-tasks/)の実行は入りません。実行をフォークして作業を続けると、そのフォークは入ります。サブセッションは単独では入らず、親セッションと一緒に入ります。

## 手動で追跡して完了にする

- **追跡する：** セッションにカーソルを合わせて目のアイコンを押すか、セッションメニューで **作業中として追跡** を選びます。
- **完了にする：** ブロック内のセッションにカーソルを合わせてチェックを押すか、メニューで **完了にする** を選びます。

スマートフォンでは、セッションの行をスワイプすると同じ操作ができます。セッションメニューも使えます。

チャットには目のアイコンが表示されません。ただの会話だからです。

### 「この作業は完了したようです。」

[分類プロバイダー](/ja/classification-providers/)を設定しておくと、Jev が作業中のセッションのターンを毎回確認します。ターンが作業の終わりに見えるとき（お礼を言った、コミットを頼んだ、動いたと確認した）、Jev は何も閉じずにヒントを残します。

- サイドバーのセッション行に灰色のチェック
- 入力欄の上に帯：**この作業は完了したようです。** と **完了にする** ボタン

Jev の判断が正しければ **完了にする** を押してください。違っていれば、そのまま続けるだけで大丈夫です。ヒントは次のメッセージで消えます。分類プロバイダーがなければヒントは表示されず、セッションは自分で完了にします。

## 要約と次のメッセージの提案

エージェントが作業を終え、セッションが 1 分間静かになると、OpenChamber は小さなモデルを使って 2 つのものを書けます（[プロバイダー、モデル、エージェント](/ja/providers/)を参照）。

- **要約：** 何をしたか、いまどういう状態かを短くまとめたメモ。最後の返答の下と、サイドバーのセッションのツールチップに表示されます
- **提案：** あなたが次に送りそうなメッセージ。入力欄の上部に 1 行で表示され、クリックすると入力欄に入ります。勝手に送信されることはありません

Jev が使える場合、OpenChamber はまずそのターンにこれらが必要かを Jev に確認します。本格的な作業のあとの「ありがとう、以上です」には要約が付きますが、やることが残っていなければ提案は省かれ、どちらも役に立たないときは小さなモデルを呼び出しません。Jev がなければ、これまでどおりターンごとに両方が生成されます。

オン・オフは **設定 → チャット → セッション支援** で切り替えます。

## 設定

**設定 → セッション → 作業中のセッション** を開きます。

- **作業中のセッションを表示**：既定でオンです。オフにすると機能全体がオフになり、ブロックは表示されず、セッションが自動で入ることもありません。
- **作業中に入れるタイミング**：オフ、すべてのメッセージ、Jev が判断から選びます。動作は上記のとおりです。

ブロックだけを隠すには、サイドバーの表示メニューで **作業中セクションを表示** を使います。

## 使える場所

ブロックと手動の追跡・完了は、VS Code を含むどこでも使えます。セッションを自動で作業中に入れる機能、「完了したようです」のヒント、要約の Jev フィルターには OpenChamber サーバーが必要なので、デスクトップアプリ、Web アプリ、スマートフォンでは使えますが、VS Code では使えません。VS Code ではセッションを手動で追跡します。
