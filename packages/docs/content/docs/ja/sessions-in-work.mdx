# 作業中のセッション

メッセージを送ったセッションは、その作業をサイドバー上部の **作業中** ブロックに入れ、作業は完了にするまでそこに残ります。最後に開いたのがどれだけ前でも同じです。プロジェクトにはこれまでに行ったすべてが残り、作業中にはまだ終わっていないものだけが並びます。

## 作業とは

サイドバーには個々のセッションではなく作業が並びます。作業は次のどちらかです。

- **worktree** とその中のすべてのセッション。タスク名の付いた 1 行で表示されます（[Worktree セッション](/ja/worktrees/)を参照）。
- **プロジェクト自体のフォルダーにあるセッション**。そこから生まれたものがその下に入れ子で並びます。サブエージェント、レビュー、残しておいたフォークや脇道の質問、そのエージェントがあなたのために始めたセッションです。

行をクリックすると開き、左側の矢印でその下のセッションを展開します。

## 場所

**作業中** ブロックはサイドバーの、チャットの下、プロジェクトまたはタイムラインの上にあります。ここに入った作業はプロジェクトから外れるので、各作業は 1 回だけ表示されます。プロジェクトの下にも残したい場合は、サイドバーの表示メニューで **作業中の項目もプロジェクトの下に表示** をオンにします。検索では、作業中ブロックに 1 回だけ表示されます。

各作業は 1 行で表示されます。タイトルと状態に加えて、プルリクエストや issue があるときは色付きのマークが付きます。行は最新のアクティビティ順に並ぶので、日付は表示されません。行にカーソルを合わせるとプロジェクト、ブランチ、時刻、リンクが表示されます。表示メニューで **詳細な行** をオンにすると、タイトルの下に表示されます。詳細な行はプロジェクトの下にも適用されます。作業の中のセッションは 1 行のままです。

ピン留めしたセッションは作業中の上にある専用の **ピン留め** ブロックにまとまります。それぞれのプロジェクトの下にだけ置くには、同じメニューで **ピン留めセクションを表示** をオフにします。作業中のセッションをピン留めすると、ピン留めにだけ表示されます。

スマートフォンのセッション一覧も同じで、表示メニューも同じです。**詳細な行** をオフにしない限り行は 2 行で表示され、カーソルを合わせる操作がないので、作業を展開する矢印は常に表示されます。

## セッションが入る仕組み

セッションでメッセージを送ると、そのセッションは作業中に入ります。worktree のセッションも含め、どのプロジェクトセッションでも同じです。新しい worktree は、作成した時点で作業中に入ります。そこで開いた下書きをまだ送信していなくても同じです。

完了にしたセッションは、新しいメッセージを送ると戻ってきます。

チャット、アーカイブ済みのセッション、レビューセッション、[スケジュールタスク](/ja/scheduled-tasks/)の実行は入りません。実行をフォークして作業を続けると、そのフォークは入ります。サブエージェントが親セッションを作業中に入れることはありません。

## タスク名

タスクがはっきりした時点で、エージェントが「ログインのタイムアウト修正」のような短い言葉で各作業にタスク名を付けます。worktree は名前をブランチの説明に保存するので、リポジトリをどこで開いても表示されます。プロジェクトフォルダーのセッションは、その名前をタイトルにします。自分で名前を変えるとその名前が残ります。あなたが名付けたタスクの名前をエージェントが変えることはありません。

## 手動で追跡して完了にする

- **追跡する：** 行にカーソルを合わせて目のアイコンを押すか、セッションメニューで **作業中として追跡** を選びます。
- **完了にする：** ブロック内の行にカーソルを合わせてチェックを押すか、メニューで **完了にする** を選びます。完了にすると作業全体が終わり、その中でまだ作業中だったセッションもすべて完了になります。

worktree を完了にすると、作業中から外れ、その場所に残ります。完了にしたときにアーカイブもするには、**設定 → セッション** で **完了にしたらワークツリーをアーカイブする** をオンにします。するとフォルダーはなくなり、セッション、変更、ブランチはアーカイブページに残って、いつでも復元できます。そこでまだ実行中のセッションがあれば、worktree は残ります。

スマートフォンでは、行を横にスワイプすると同じ操作ができます。

チャットには目のアイコンが表示されません。ただの会話だからです。

### 「この作業は完了したようです。」

[分類プロバイダー](/ja/classification-providers/)を設定しておくと、Jev が作業中のセッションのターンを毎回確認します。ターンが作業の終わりに見えるとき（お礼を言った、コミットを頼んだ、動いたと確認した）、Jev は何も閉じずにヒントを残します。

- サイドバーのセッション行に灰色のチェック
- 入力欄の上に帯：**この作業は完了したようです。** と **完了にする** ボタン

Jev の判断が正しければ **完了にする** を押してください。違っていれば、そのまま続けるだけで大丈夫です。ヒントは次のメッセージで消えます。分類プロバイダーがなければヒントは表示されず、セッションは自分で完了にします。

## 要約と次のメッセージの提案

エージェントが作業を終え、セッションが 1 分間静かになると、OpenChamber は小さなモデルを使って 2 つのものを書けます（[プロバイダー、モデル、エージェント](/ja/providers/)を参照）。

- **要約：** 何をしたか、いまどういう状態かを短くまとめたメモ。最後の返答の下と、サイドバーのセッションのツールチップに表示されます
- **提案：** あなたが次に送りそうなメッセージ。入力欄の上部に 1 行で表示され、クリックすると入力欄に入ります。勝手に送信されることはありません

Jev が使える場合、OpenChamber はまずそのターンにこれらが必要かを Jev に確認します。本格的な作業のあとの「ありがとう、以上です」には要約が付きますが、やることが残っていなければ提案は省かれ、どちらも役に立たないときは小さなモデルを呼び出しません。Jev がなければ、これまでどおりターンごとに両方が生成されます。

オン・オフは **設定 → チャット → セッション支援** で切り替えます。

## 設定

**設定 → セッション → 作業中のセッション** を開きます。設定は **作業中のセッションを表示** の 1 つだけで、既定でオンです。オフにすると機能全体がオフになります。ブロックは表示されず、メッセージを送ってもセッションは作業中に入りません。

ブロックだけを隠すには、サイドバーの表示メニューで **作業中セクションを表示** を使います。

## 使える場所

ブロックと手動の追跡・完了は、VS Code を含むどこでも使えます。メッセージ送信時に作業中に入れる機能、「完了したようです」のヒント、要約の Jev フィルターには OpenChamber サーバーが必要なので、デスクトップアプリ、Web アプリ、スマートフォンでは使えますが、VS Code では使えません。VS Code ではセッションを手動で追跡します。
