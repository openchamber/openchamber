# Git ワークフロー

OpenChamber には組み込みの Git ビューがあり、ターミナルに切り替えずに変更の確認、コミット、ブランチ管理ができます。右サイドバーの **Git** タブから開きます。

## 確認してコミットする

Git ビューは変更を **staged** と **unstaged** に分けて表示します。

- ファイルの **+** をクリックしてステージ、**−** をクリックしてアンステージします
- グループ内のすべてをまとめてステージまたはアンステージできます
- ファイルをクリックすると差分を確認できます

その後、コミットメッセージを書いてコミットします。OpenChamber に staged 変更から**コミットメッセージを生成**させることもできます。現在のセッションのモデルを使うため、セッションを開いておく必要があります。

## ブランチと履歴

Git ビューは日常的な Git 操作も扱います。

- ブランチの作成、切り替え、名前変更、削除
- push、pull、fetch
- 履歴とコミットごとの差分の閲覧
- 変更の stash と復元

## プルリクエスト

プロジェクトのホストでアカウントを接続すると、**PR** タブからプルリクエストを開く、更新する、ready にする、またはマージできます。OpenChamber はタイトルと説明もコミットメッセージと同じように書けます。GitHub、Gitea、Forgejo、GitLab で使え、GitLab ではこのタブでマージリクエストを開きます。Gerrit には専用のフォーム **レビューへプッシュ** があります。ホストの接続方法は [Git ホスト](/github/) にあります。

## Gerrit でレビューへプッシュする

Gerrit のプロジェクトでは、プルリクエストのフォームが **レビューへプッシュ** になります。コミットを `refs/for/<branch>` にプッシュし、変更を作成するか、すでにプッシュした変更の新しいパッチセットを作ります。コミットメッセージが変更の説明になるので、フォームにはタイトルと本文の代わりに最新コミットの件名が表示されます。ターゲットブランチを選び、必要ならトピック、ハッシュタグ、**作業中**、**非公開** を指定します。ターゲットブランチそのものの上でも使えます。これが Gerrit での一般的な作業方法です。

Gerrit は、commit-msg フックが各メッセージに追加する `Change-Id` 行でコミットと変更を対応付けます。最新のコミットだけに Change-Id がない場合は、**Change-Id を追加** が確認のうえでそのコミットを amend します。プッシュするまでは何も送られません。それより前のコミットに Change-Id がない場合は、フックをインストールしてそれぞれに Change-Id を付けるまでプッシュは待ちます。

最初のプッシュの後は、ローカルのコミットがまだ変更に載っていないときに、パネルが **パッチセットをアップロード** を表示します。変更のチェーンに含まれる変更には、バッジの横にチェーン内の位置（**3 件中 2** など）が表示されます。

## コンフリクトを取り込む

merge、rebase、integrate でコンフリクトが起きると、OpenChamber は詰まっている箇所を表示し、解決できるようにします。エージェントに渡して解決させることもできます。
