# ワークフロー

ワークフローは大きなタスクを多数の小さな作業に分け、それぞれに専用のエージェントを割り当てます。セッションのエージェントが、どのエージェントを起動し、それぞれに何を頼むかを書いた短いスクリプトを作成します。OpenChamber はこのスクリプトをバックグラウンドで実行するので、エージェントが作業している間もセッションは自由に使えます。実行が終わると、そのレポートがセッションに戻ってきます。

ワークフローが向いているのは、似たような独立した作業が多数ある場合です。たとえば変更されたファイルごとのレビュー、API ルートごとの監査、多数のファイルにまたがる移行、情報源ごとに個別に確認する調査などです。単一の機能や数ステップの作業なら、1 つのセッションで進めたほうが速く終わります。

## オンにする

ワークフローツールはデフォルトでオフです。**設定 → 一般 → OpenChamber ツール** を開き、**ワークフローツール** をオンにします。実行中のセッションには次のターンで反映されます。再びオフにすると、ツールとその説明がすべてのセッションから取り除かれ、ワークフローパネルも非表示になります。再びオンにすると、既存の実行が戻ります。

ワークフローには OpenChamber 自身の OpenCode サーバーが必要です。OpenChamber が `OPENCODE_HOST` や skip-start で外部の OpenCode サーバーに接続している場合や、VS Code 拡張機能の中では使えません。

## ワークフローを実行する

1. 普段の言葉で頼みます。例: 「このブランチで変更されたファイルをすべてレビューして、見つかったバグを一覧にするワークフローを実行して。」
2. エージェントが計画と、フェーズごとのモデルを提案します。実行を始める前にモデルを決めておきます。[モデルとコスト](#モデルとコスト) を参照してください。
3. 計画を載せたカードがチャットに表示されます。**ワークフローを実行** を選ぶと開始し、**実行しない** を選ぶと取りやめます。どちらかを選ぶまで何も実行されません。
4. 実行中、カードには各フェーズとエージェントが表示されます。サイドバーのセッション行には **ワークフロー実行中** と表示され、作業状況パネルの **ワークフロー** セクションに実行が一覧表示されます。途中で終わらせるには **停止** を選びます。
5. 実行が終わると、そのレポートがメッセージとしてセッションに届きます。完了または失敗した実行はエージェントを起こし、エージェントが結果に応じて動けるようにします。停止した実行や実行しなかったものはエージェントを起こしません。

停止または失敗した実行は **再開** で続けられます。すでに回答したエージェントはその回答をそのまま使い、残りのエージェントだけが再び実行されます。

実行中のワークフローのエージェントは、自分でワークフローを開始できません。

## モデルとコスト

スクリプトで別のモデルを指定しない限り、ワークフローのすべてのエージェントはセッションのモデルで動きます。数十のエージェントを最上位のモデルで動かすと、同じ作業を小さなモデルで行う場合の何倍ものコストがかかります。そのためエージェントはフェーズごとにモデルを提案します。読み取りや決まったリストとの照合には安価なモデルを、判断が必要なフェーズやプロジェクトに入る内容を書くフェーズにはより強力なモデルを使います。合わない場合は、実行を承認する前に選択を変更します。

同時に動くエージェントは最大 8 つで、1 回の実行で起動するエージェントはすべての試行を合わせて最大 200 です。

## ワークフローパネル

右のレールにある **ワークフロー** パネルには、プロジェクトの実行が表示されます。エージェント、ログ、結果、スクリプトに加えて、各エージェントのモデルとトークン使用量も確認できます。パネルまたはチャットのカードから任意のエージェントのセッションを開くと、会話全体を読めます。アイコンは、プロジェクトに実行または保存済みワークフローができた時点で表示されます。

1 回の実行で 100 ものエージェントが起動することがあるため、ワークフローのエージェントはセッションのサイドバーに表示されません。実行のカードとワークフローパネルからいつでも開けます。

**実行を削除** は完了した実行をパネルから取り除きます。エージェントのセッションは残ります。

## 保存済みワークフロー

もう一度実行したいワークフローは、エージェントに保存を頼みます。プロジェクト内に `.openchamber/workflows/<name>.js` として保存されるので、リポジトリのほかのファイルと一緒にコミットできます。

保存済みワークフローは、パネルの実行ピッカーにある **保存済みワークフロー** から実行します。開いているセッションか新しいセッションですぐに開始し、レポートはそのセッションに戻ってきます。名前を指定してエージェントに実行を頼むこともできます。
