# OpenCode サーバー

OpenChamber は OpenCode サーバーの上で動作します。デフォルトでは OpenChamber がサーバーを起動するため、何もする必要はありません。このページが必要なのは、すでに実行しているサーバーに OpenChamber を向けたい場合、または OpenChamber が起動するサーバーを管理したい場合だけです。

## OpenChamber がサーバーを見つける順序

OpenChamber の起動時、次の順序でサーバーを探します。

1. すでに起動済みのサーバーを再利用する
2. 外部サーバーを設定している場合は、そのサーバーに接続する
3. それ以外の場合は、自分のサーバーを起動して管理する

デフォルトでは、OpenChamber は割り当てられたポートで自分のサーバーを管理します。再起動後にポートが変わることがあります。OpenChamber はポート `4096` の別の OpenCode サーバーに自動接続しません。

## すでに実行しているサーバーに接続する

OpenChamber を起動する前に次を設定します。

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true openchamber
```

- `OPENCODE_HOST` — ポートを含む OpenCode サーバーの完全なアドレスです（`http://localhost:4096` のような値）。末尾にパスを付けてはいけません。
- `OPENCODE_SKIP_START=true` — OpenChamber に自分のサーバーを起動しないよう伝えます。

ポートだけを変えたい場合は、`OPENCODE_HOST` ではなく `OPENCODE_PORT` を設定します。

`OPENCODE_HOST` にポートがない、またはパスが含まれている場合、OpenChamber はそれを無視し、自分のサーバー起動にフォールバックします。期待した接続が行われなかった場合は、起動ログの `[config]` 警告を確認してください。

## VS Code と 1 つのサーバーを共有する

デスクトップアプリと VS Code 拡張機能は、通常それぞれ別の OpenCode サーバーを起動します。Windows では、`opencode-mem` などの一部のプラグインが、同じデータベースを 2 つのプロセスで開けません。この競合を避けるには、両方のアプリを 1 つのサーバーに接続します。

共有サーバーには OpenCode 2.2.4 以降が必要です。古いバージョンでは、両方のアプリが「OpenCode を更新」画面で止まります。

1. OpenChamber Desktop と VS Code を終了し、それぞれが管理するサーバーを停止します。ターミナルで動いているものなど、同じプラグインデータを使うほかの OpenCode サーバーも停止します。OpenCode の TUI もバックグラウンドサーバーを起動し、TUI を閉じても動き続けます。`opencode service status` で確認し、`opencode service stop` で停止します。
2. OpenCode サーバーを 1 つ起動し、そのまま動かしておきます:

   ```bash
   opencode serve --port 4096
   ```

   OpenCode は待ち受けているアドレスを `server listening on` の行に表示します。以下の手順で `http://localhost:4096` と書かれている箇所には、そのアドレスを使います。

   `OPENCODE_PASSWORD` と `OPENCODE_SERVER_PASSWORD` のどちらも設定されていない場合、OpenCode は生成した `server password` も表示します。どちらかが設定されている場合はパスワードを表示せず、設定したパスワードをサーバーが使います。パスワードは他人に見せず、次の手順で使います。

3. `OPENCODE_HOST=http://localhost:4096`、`OPENCODE_SKIP_START=true`、サーバーのパスワードを入れた `OPENCODE_PASSWORD` を設定して OpenChamber Desktop を起動します。Windows では PowerShell ウィンドウから起動します:

   ```powershell
   $env:OPENCODE_HOST = 'http://localhost:4096'
   $env:OPENCODE_SKIP_START = 'true'
   $password = Read-Host 'OpenCode server password' -AsSecureString
   $env:OPENCODE_PASSWORD = [System.Net.NetworkCredential]::new('', $password).Password
   & "$env:LOCALAPPDATA\Programs\@openchamberelectron\OpenChamber.exe"
   ```

   Desktop を別の場所にインストールした場合は、お使いの `OpenChamber.exe` のパスを指定します。

4. 同じ PowerShell ウィンドウから `code` で VS Code を起動します。VS Code の設定で `openchamber.apiUrl` を `http://localhost:4096` にし、**Developer: Reload Window** を実行します。

これで両方のアプリがそのアドレスのサーバーを使います。どちらかのアプリを使っている間は、サーバーを動かしたままにしてください。両方のアプリは毎回、手順 3 と 4 のように PowerShell から起動してください。スタートメニューから開くと、Desktop は再び自分のサーバーを起動し、VS Code は共有サーバーのパスワードを持ちません。パスワードを設定せずにサーバーを再起動すると新しいパスワードが表示されるので、そちらを使います。`OPENCODE_PASSWORD` が設定されていない場合は、古い名前の `OPENCODE_SERVER_PASSWORD` も使えます。信頼できないネットワークにサーバーを公開しないでください。Desktop が自動で管理するサーバーではポートとパスワードが変わるため、この方法は使えません。

外部サーバーには OpenChamber が管理するプラグインは入りません。どちらかのアプリが接続できない場合は、[OpenCode 接続](/ja/troubleshooting/opencode-connection/) を参照してください。

## CLI からサーバーを管理する

```bash
openchamber status
openchamber logs
openchamber restart
openchamber stop
```

`openchamber` だけを実行すると、サーバーはバックグラウンドで起動します。ターミナルに接続したままにするには `--foreground` を追加します。

## ログイン時に OpenChamber を起動する

`startup enable` を使うと、ネイティブのユーザーサービスをインストールできます。OpenChamber は macOS では `launchd`、Linux では `systemd --user`、Windows では Task Scheduler を使います。

```bash
openchamber startup enable
openchamber startup status
openchamber startup disable
```

UI を保護するには、サービスを有効化するときにパスワードを設定します。

```bash
OPENCHAMBER_UI_PASSWORD='secret' openchamber startup enable
```

ログイン時に起動し、デスクトップまたはモバイルクライアント向けに使うヘッドレスサーバーでは、`--api-only` と到達可能な host を含めます。

```bash
openchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` は現在の環境をサービスにスナップショットするため、同じシェルから `openchamber` を起動した場合に近い動作になります。これにより、プロバイダートークン、`PATH`、SSH agent 設定、その他の CLI 認証/設定変数が利用できます。最小限のサービス環境にしたい場合は `--no-env-snapshot` を使ってください。

スタートアップサービスは `--port`、`--host`、`--ui-password`、`--api-only` を記憶します。CLI の restart と update restart は保存済み設定を再利用します。

別の OpenChamber アプリ向けに接続リンクを作成するには、次を使います。

```bash
openchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

`openchamber connect-url --help` を実行すると、`--name`、`--lan`、`--server`、`--api-only`、`--ui-password`、`--qr` など、すべてのリンクオプションを確認できます。

その実行中サービスに対して、トンネルは独立して管理できます。

```bash
openchamber tunnel start --port 3000
openchamber tunnel stop --port 3000
```

トンネルを停止しても、サービスやアプリは再起動されません。

## "OpenCode is restarting"

サーバーの起動中または再起動中、OpenChamber は "OpenCode is restarting" 状態を表示し、準備が整うまでリクエストを一時停止します。これは起動直後や再起動直後には正常です。いつまでも消えない場合は、[OpenCode 接続](/ja/troubleshooting/opencode-connection/) を参照してください。
