# 进行中的会话

你发过消息的每个会话都会进入侧边栏顶部的 **进行中** 区块，并一直留在那里，直到你把它标记为完成，不管你上次打开它是多久以前。项目里保存着你所有的会话；进行中只收纳你还没做完的事。

## 在哪里

**进行中** 区块位于侧边栏中，在聊天下方、你的项目或时间线上方。在手机上，它在会话列表中的同一位置。

进行中的会话也会留在所属项目和文件夹中，在时间线里也仍在所属项目下，所以你会在两个地方看到它。它的子会话会跟着它一起。搜索只列出它一次，在进行中区块里。

## 会话如何进入

在会话中发送一条消息，它就会进入进行中。任何项目会话都是如此，包括 worktree 里的会话。

你标记为完成的会话，在你再发送一条新消息时会回来。

聊天、已归档的会话、审查会话以及[定时任务](/zh-cn/scheduled-tasks/)的运行永远不会进入；如果你分叉某次运行来继续处理，分叉出的会话会进入。子会话不会单独进入，而是跟随父会话一起。

## 手动跟踪和完成会话

- **跟踪：** 把鼠标悬停在会话上，点眼睛图标，或在会话菜单中选择 **作为进行中跟踪**。
- **完成：** 把鼠标悬停在区块里的会话上，点对勾，或在菜单中选择 **标记为完成**。

在手机上，滑动会话行就能找到同样的操作，也可以用会话菜单。

聊天没有眼睛图标：它们只是普通对话。

### "这项工作看起来已完成。"

设置好[分类提供方](/zh-cn/classification-providers/)后，Jev 会检查进行中会话的每一轮。当某一轮看起来像是工作的收尾（你道了谢、让它提交、确认一切正常），Jev 不会关闭任何东西，而是留下提示：

- 侧边栏的会话行上出现一个灰色对勾
- 输入框上方出现一条横栏：**这项工作看起来已完成。** 以及 **标记为完成** 按钮

如果 Jev 判断得对，就点 **标记为完成**。如果不对，继续工作就好：你发出下一条消息时提示就会消失。没有分类提供方时不会出现提示，由你自己把会话标记为完成。

## 摘要和下一条消息建议

智能体完成工作、会话安静一分钟后，OpenChamber 可以用你的小模型写两样东西（参见[提供商、模型与智能体](/zh-cn/providers/)）：

- **摘要：** 简短提醒做了什么、目前进展到哪一步，显示在最后一条回复下方，以及侧边栏中该会话的悬停提示里
- **建议：** 你接下来很可能发送的消息，以一行的形式出现在输入框顶部；点击会把文字放进输入框，它永远不会自己发送

有 Jev 时，OpenChamber 会先问它这一轮是否需要这两样东西。真正的工作之后，一句简单的"谢谢，就这样"仍然会得到摘要；但没什么可做时会跳过建议，两者都没用时根本不会调用小模型。没有 Jev 时，两者照旧在每一轮之后生成。

在 **设置 → 聊天 → 会话辅助** 中开启或关闭它们。

## 设置

打开 **设置 → 会话 → 进行中的会话**。这里只有一项设置 **显示进行中的会话**，默认开启。关闭后整个功能都会关闭：没有区块，发送消息也不再把会话放入进行中。

如果只想隐藏区块，请使用侧边栏显示菜单中的 **显示进行中部分**。

## 在哪里可用

区块以及手动跟踪和完成在任何地方都能用，包括 VS Code。发送消息时自动放入进行中、"看起来已完成"的提示和摘要的 Jev 过滤需要 OpenChamber 服务器，因此在桌面应用、网页应用和手机上可用，在 VS Code 中不可用。在 VS Code 中，会话只能手动跟踪。
