# 进行中的会话

提问、调研和随手的试验很快就会堆积起来，你真正在修东西的那个会话就被埋在里面了。**进行中** 区块把这些会话集中放在侧边栏的一个地方。会话会一直留在那里，直到你说它完成了。

这就是它和"最近"的区别。"最近"显示过去两天里有变化的所有内容，而且会自己更替：你今天早上随手点开的会话在里面，周一暂停的那个修复却已经不见了。"进行中"是你还没做完的事情的清单，不管你上次打开它是多久以前。

## 在哪里

**进行中** 区块位于侧边栏中，在聊天下方、"最近"（Timeline 模式下是时间线）上方。在手机上，它在会话列表中的同一位置。

进行中的会话会连同它的子会话一起移过去。它不会在"最近"、时间线、所属项目或文件夹中重复出现。标记为完成后，它会回到原来的位置。

## 手动跟踪和完成会话

- **跟踪：** 把鼠标悬停在会话上，点眼睛图标，或在会话菜单中选择 **作为进行中跟踪**。
- **完成：** 把鼠标悬停在区块里的会话上，点对勾，或在菜单中选择 **标记为完成**。

在手机上，滑动会话行就能找到同样的操作，也可以用会话菜单。

任何项目会话都可以进入进行中，包括 worktree 里的会话。子会话跟随父会话一起移动。聊天永远不会进入：它们只是普通对话，所以没有眼睛图标。

## 让 Jev 替你移动会话

设置好[分类提供方](/zh-cn/classification-providers/)后，你就不必自己跟踪会话了。Jev 会阅读你发送的每条消息，并在以下情况把会话移入进行中：

- 你要求做一项修改
- 你报告了一个 bug
- 你在讨论一项马上要做的具体修改

提问、解释和调研不算。智能体结束一轮后，Jev 会再看一次，这样那些要看到回复才明确的工作也能被发现。

Jev 只会把会话 **移入** 进行中。你把会话标记为完成后，只有之后发出的新请求才能把它带回来。

### "这项工作看起来已完成。"

当某一轮看起来像是工作的收尾（你道了谢、让它提交、确认一切正常），Jev 不会关闭任何东西，而是留下提示：

- 侧边栏的会话行上出现一个灰色对勾
- 输入框上方出现一条横栏：**这项工作看起来已完成。** 以及 **标记为完成** 按钮

如果 Jev 判断得对，就点 **标记为完成**。如果不对，继续工作就好：你发出下一条消息时提示就会消失。

## 摘要和下一条消息建议

智能体完成工作、会话安静一分钟后，OpenChamber 可以用你的小模型写两样东西（参见[提供商、模型与智能体](/zh-cn/providers/)）：

- **摘要：** 简短提醒做了什么、目前进展到哪一步，显示在最后一条回复下方，以及侧边栏中该会话的悬停提示里
- **建议：** 你接下来很可能发送的消息，以一行的形式出现在输入框顶部；点击会把文字放进输入框，它永远不会自己发送

有 Jev 时，OpenChamber 会先问它这一轮是否需要这两样东西。真正的工作之后，一句简单的"谢谢，就这样"仍然会得到摘要；但没什么可做时会跳过建议，两者都没用时根本不会调用小模型。没有 Jev 时，两者照旧在每一轮之后生成。

在 **设置 → 聊天 → 会话辅助** 中开启或关闭它们。

## 设置

打开 **设置 → 会话 → 进行中的会话**：

- **显示进行中的会话：** 区块本身；关闭后，会话留在它们一直在的位置
- **自动将会话移入进行中：** Jev 负责的部分；关闭后只能手动跟踪

两项默认都开启。

## 在哪里可用

区块以及手动跟踪和完成在任何地方都能用，包括 VS Code。自动移入、"看起来已完成"的提示和摘要的 Jev 过滤需要 OpenChamber 服务器，因此在桌面应用、网页应用和手机上可用，在 VS Code 中不可用。
