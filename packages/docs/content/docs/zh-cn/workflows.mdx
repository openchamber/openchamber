# 工作流

工作流把一个大任务拆成许多小块，并为每一块分配一个独立的智能体。会话中的智能体会编写一个简短的脚本，说明要启动哪些智能体以及分别向它们提出什么请求。OpenChamber 在后台运行这个脚本，因此智能体工作期间你的会话仍可继续使用。运行结束后，报告会回到会话中。

工作流适合由许多相似且彼此独立的部分组成的工作：审查每个改动过的文件、审计每个 API 路由、跨多个文件的迁移，或者需要逐一核对每个来源的调研。单个功能或少数几个步骤在一个会话中完成会更快。

## 开启工具

工作流工具默认关闭。打开 **设置 → 通用 → OpenChamber 工具**，开启 **工作流工具**。运行中的会话会在下一轮获得该工具；再次关闭后，所有会话中的该工具及其相关说明都会被移除，工作流面板也会隐藏。重新开启后，已有的运行会重新出现。

工作流需要 OpenChamber 自己的 OpenCode 服务器。当 OpenChamber 通过 `OPENCODE_HOST` 或 skip-start 连接外部 OpenCode 服务器时，以及在 VS Code 扩展中，工作流不可用。

## 运行工作流

1. 用平常的话提出请求，例如“运行一个工作流，审查这个分支上改动的每个文件，并列出发现的 bug。”
2. 智能体会提出一个计划，并为每个阶段建议一个模型。请在运行开始前确定模型，参见 [模型与费用](#模型与费用)。
3. 聊天中会出现一张带有计划的卡片。选择 **运行工作流** 开始运行，或选择 **不运行** 放弃。在你做出选择之前，什么都不会运行。
4. 运行期间，卡片会显示每个阶段和每个智能体。侧边栏中该会话的那一行会显示 **工作流运行中**，工作状态面板的 **工作流** 部分会列出这次运行。选择 **停止** 可以提前结束。
5. 运行结束后，报告会作为一条消息出现在会话中。运行完成或失败时会唤醒智能体，让它根据结果继续处理；被你停止或拒绝的运行则不会。

已停止或失败的运行可以用 **继续** 接着运行。已经给出回答的智能体会保留回答，只有其余的智能体会重新运行。

正在运行的工作流中的智能体不能自己再启动工作流。

## 模型与费用

除非脚本指定了其他模型，工作流中的每个智能体都使用你会话的模型。几十个智能体使用顶级模型，费用会是同样工作使用小模型时的许多倍。因此智能体会为每个阶段建议一个模型：阅读内容和对照固定清单检查时用便宜的模型，需要判断或编写会落到项目中的内容时用更强的模型。如果不合适，请在确认运行之前修改。

同一时间最多有 8 个智能体在工作，一次运行在所有尝试中最多启动 200 个智能体。

## 工作流面板

右侧栏中的 **工作流** 面板显示项目的运行：智能体、日志、结果和脚本，以及每个智能体使用的模型和 token 用量。可以从这里或聊天中的卡片打开任意智能体的会话，查看完整对话。项目有了运行或已保存的工作流后，图标才会出现。

工作流的智能体不会出现在会话侧边栏中，因为一次运行可能启动上百个智能体。它们仍可以从运行的卡片和工作流面板中打开。

**删除运行** 会把已结束的运行从面板中移除。智能体的会话会保留。

## 已保存的工作流

想再次运行某个工作流时，让智能体把它保存下来。它会以 `.openchamber/workflows/<name>.js` 的形式保存在项目中，因此可以和仓库的其他内容一起提交。

在面板的运行选择器中，从 **已保存的工作流** 运行已保存的工作流。它会立即在当前打开的会话或一个新会话中启动，报告会回到该会话。也可以让智能体按名称运行它。
