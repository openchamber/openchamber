# OpenCode Server

OpenChamber 运行在 OpenCode 服务器之上。默认情况下，它会为你启动一个，所以你无需做任何事。只有当你想让 OpenChamber 指向一个你已经运行的服务器，或者管理它所启动的服务器时，才需要本页内容。

## OpenChamber 如何查找服务器

OpenChamber 启动时，会按以下顺序查找服务器：

1. 复用它已经启动的服务器
2. 如果你已配置外部服务器，则连接到该服务器
3. 否则，启动并管理自己的服务器

默认情况下，OpenChamber 会在分配的端口上管理自己的服务器。重启后，端口可能会改变。OpenChamber 不会自动连接到使用端口 `4096` 的其他 OpenCode 服务器。

## 连接到你已经运行的服务器

在启动 OpenChamber 之前设置这些变量：

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true openchamber
```

- `OPENCODE_HOST` — 你的 OpenCode 服务器的完整地址，包括端口（类似 `http://localhost:4096` 这样的值）。末尾不能带路径。
- `OPENCODE_SKIP_START=true` — 告诉 OpenChamber 不要启动它自己的服务器。

如果你只需要更改端口，请设置 `OPENCODE_PORT` 而不是 `OPENCODE_HOST`。

如果 `OPENCODE_HOST` 缺少端口或带有路径，OpenChamber 会忽略它并回退到启动自己的服务器。如果你期望的连接没有发生，请留意启动日志中的 `[config]` 警告。

## 与 VS Code 共用一个服务器

桌面应用和 VS Code 扩展通常各自启动一个 OpenCode 服务器。在 Windows 上，部分插件（包括 `opencode-mem`）无法在两个进程中打开同一个数据库。让两个应用连接同一个服务器即可避免这个冲突。

共用的服务器需要 OpenCode 2.2.4 或更新版本。版本更旧时，两个应用都会停在“更新 OpenCode”界面。

1. 退出 OpenChamber Desktop 和 VS Code，让它们管理的服务器停止。同时停止其他使用相同插件数据的 OpenCode 服务器，例如在终端中运行的服务器。OpenCode TUI 也会启动一个后台服务器，关闭 TUI 后它仍会继续运行。用 `opencode service status` 查看它，用 `opencode service stop` 停止它。
2. 启动一个 OpenCode 服务器并保持运行：

   ```bash
   opencode serve --port 4096
   ```

   OpenCode 会在 `server listening on` 这一行中打印它监听的地址。下面步骤中出现 `http://localhost:4096` 的地方，都改用这个地址。

   如果 `OPENCODE_PASSWORD` 和 `OPENCODE_SERVER_PASSWORD` 都没有设置，OpenCode 还会打印一个生成的 `server password`。如果设置了其中一个，它不会打印密码，服务器会使用你设置的密码。请妥善保管密码，并在后续步骤中使用。

3. 使用 `OPENCODE_HOST=http://localhost:4096`、`OPENCODE_SKIP_START=true`，以及设为服务器密码的 `OPENCODE_PASSWORD` 启动 OpenChamber Desktop。在 Windows 上，从 PowerShell 窗口启动：

   ```powershell
   $env:OPENCODE_HOST = 'http://localhost:4096'
   $env:OPENCODE_SKIP_START = 'true'
   $password = Read-Host 'OpenCode server password' -AsSecureString
   $env:OPENCODE_PASSWORD = [System.Net.NetworkCredential]::new('', $password).Password
   & "$env:LOCALAPPDATA\Programs\@openchamberelectron\OpenChamber.exe"
   ```

   如果你把 Desktop 安装在其他位置，请使用你的 `OpenChamber.exe` 路径。

4. 在同一个 PowerShell 窗口中用 `code` 启动 VS Code。在 VS Code 设置中把 `openchamber.apiUrl` 设为 `http://localhost:4096`，然后运行 **Developer: Reload Window**。

现在两个应用都使用该地址上的服务器。使用任一应用期间，请保持服务器运行。每次都要像第 3、4 步那样从 PowerShell 启动两个应用：从开始菜单打开时，Desktop 会再次启动自己的服务器，VS Code 也没有共享服务器的密码。如果在未设置密码的情况下重启服务器，它会打印新密码，请改用新密码。未设置 `OPENCODE_PASSWORD` 时，旧名称 `OPENCODE_SERVER_PASSWORD` 也可以使用。不要把服务器暴露在不受信任的网络中。这种方式不适用于 Desktop 自动管理的服务器，因为它的端口和密码会变化。

外部服务器不会获得 OpenChamber 管理的插件。如果任一应用无法连接，请参阅 [OpenCode 连接](/zh-cn/troubleshooting/opencode-connection/)。

## 从 CLI 管理服务器

```bash
openchamber status
openchamber logs
openchamber restart
openchamber stop
```

单独运行 `openchamber` 会在后台启动服务器。添加 `--foreground` 可以让它保持附加在你的终端上。

## 登录时启动 OpenChamber

使用 `startup enable` 安装原生用户服务。OpenChamber 在 macOS 上使用 `launchd`，在 Linux 上使用 `systemd --user`，在 Windows 上使用 Task Scheduler。

```bash
openchamber startup enable
openchamber startup status
openchamber startup disable
```

要保护 UI，请在启用服务时设置密码：

```bash
OPENCHAMBER_UI_PASSWORD='secret' openchamber startup enable
```

如果要在登录时启动一个供桌面或移动应用使用的 headless 服务器，请加上 `--api-only` 和可访问的 host：

```bash
openchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` 会把当前环境快照保存到服务中，让启动行为更接近你在同一个 shell 中手动运行 `openchamber`。这会保留提供商 token、`PATH`、SSH agent 设置以及其他 CLI auth/config 环境变量。如果你想要最小化的服务环境，请使用 `--no-env-snapshot`。

启动服务会记住 `--port`、`--host`、`--ui-password` 和 `--api-only`。CLI restart 和更新期间的 restart 会复用这些已保存设置。

要为另一个 OpenChamber 应用创建连接链接，请使用：

```bash
openchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

运行 `openchamber connect-url --help` 可查看所有链接选项，包括 `--name`、`--lan`、`--server`、`--api-only`、`--ui-password` 和 `--qr`。

你仍然可以独立管理这个运行中服务的隧道：

```bash
openchamber tunnel start --port 3000
openchamber tunnel stop --port 3000
```

停止隧道不会重启服务或应用。

## “OpenCode is restarting”

当服务器正在启动或重启时，OpenChamber 会显示 “OpenCode is restarting” 状态，并暂停请求直到服务器就绪。这在启动或重启后立即出现是正常的。如果它一直无法消失，请参阅 [OpenCode 连接](/zh-cn/troubleshooting/opencode-connection/)。
