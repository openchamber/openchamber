# Worktree 会话

worktree 会话运行在你仓库自己独立检出的副本中，位于它自己的分支上（一个 git worktree）。这能防止并行会话相互干扰彼此的文件 — 一个会话可以做重构，另一个可以修复 bug，无需来回切换。

## 创建一个

1. 打开新建 worktree 对话框：开始新会话时，在输入框上方的分支菜单中选择 **新建工作树…**，或使用侧边栏项目行上的 worktree 按钮。
2. 在 **Start from** 下选择一项：
   - **new branch** — 命名分支
   - **existing branch** — 检出一个你已经拥有的分支
   - **PR or issue** — 从 GitHub、GitLab、Gitea、Forgejo、Gerrit、Linear 或扩展中选一个；分支会以它命名（PR 会检出它自己的分支，Gerrit 变更会把最新补丁集检出到 `change-<number>`），该条目也会附加到你的第一条消息中
3. 检查 **Based on**（新分支的起始分支，默认是远程仓库的默认分支，例如 `origin/main`）和 **Folder name**；只在需要时修改。
4. 创建它。如果项目配置了初始化命令，创建后会立即运行。

OpenChamber 会创建分支、设置文件夹，并在其中打开一个新会话，等你发送第一条消息。你也可以直接从一个 [待办](/zh-cn/notes-todos-plans/) 或一个 [issue 或拉取请求](/zh-cn/github/) 发起一个。

如果不想回答这些问题，在同一个分支菜单中选择 **快速工作树**：OpenChamber 会先给分支一个临时名称，并让新会话指向它。智能体为任务命名后，也会按任务重命名分支，例如 `fix/login-timeout`，前提是该分支还没有推送。

## 在侧边栏中

一个 worktree 在侧边栏中是一行，其中的所有会话都在它下面。在所属项目下，它和项目的其他会话一起按最近活动排列，所以你刚刚使用过的 worktree 会排在靠前的位置。智能体命名任务后，这一行显示任务名称（在此之前显示你在那里最后使用的会话的标题）、以彩色标记显示它关联的拉取请求或 issue，以及其中是否有会话正在运行或有新动态等你查看。为拉取请求或 issue 创建的 worktree 起初显示该项的标题，直到智能体起一个更短的名称。将鼠标悬停在这一行上可查看分支。点击它会打开你在那里最后使用的会话；将鼠标悬停在左侧的分支图标上，再点击取而代之出现的箭头，即可展开列表。它的菜单可以重命名任务、把 worktree 归入项目的某个文件夹、归档它，或删除它。在手机上，点击这一行上的箭头可展开列表，把这一行向一侧滑动可将它标记为完成、重命名任务、归档 worktree 或删除它。工作如何进入和离开进行中区块，参见[进行中的会话](/zh-cn/sessions-in-work/)。

## 在仓库内文件夹中打开的项目

如果你在仓库内的某个文件夹中打开项目，比如 `repo/ai`，新的 worktree 也会在同样的位置打开。新 worktree 中的会话会在检出内的同一文件夹启动，因此 OpenCode 能找到放在其中的配置。在仓库根目录打开的项目仍像以前一样在 worktree 根目录启动。如果某个分支没有这个文件夹，会话会在 worktree 根目录启动，OpenChamber 会提示你。

## 把工作带回来

当工作完成得不错时，在 Git 视图中使用 **Integrate** 将 worktree 的提交带到另一个分支（比如 `main`）上。如果某个变更产生冲突，你可以把冲突交给智能体来解决。

## 清理

任务完成后，在这一行的菜单中选择 **归档工作树**，或按住 Shift 并点击行上取代新建会话按钮出现的归档按钮。OpenChamber 会归档它：文件夹会被移除，它的会话、未提交的更改和分支会留在归档页面中。如果其中还有会话在运行，worktree 会保留。

把这一行标记为完成只会让它离开进行中。要在每次标记完成时归档 worktree，或在它的 PR 合并后归档，请在 **设置 → 会话 → 已完成的工作树** 中开启。

在归档页面中，已归档的 worktree 列在各自的项目下。**还原** 会连同分支一起找回 worktree，运行项目的初始化命令，并放回它的更改和会话；还原它的某个会话效果相同。git 忽略的文件，比如 `node_modules` 或 `.env`，不会保留，所以要靠初始化命令把它们重新生成。项目的工作树页面也会列出已归档的 worktree。

要彻底移除一个 worktree，可以从它的菜单中删除，或在归档页面中删除已归档的 worktree。从菜单删除时，你可以选择是否同时删除分支 — 本地的，以及远程的（如果有）。

## 如果有什么看起来不对劲

如果 worktree 的文件夹丢失、分支处于游离状态，或一次合并或变基处于半完成状态，它可能需要关注。OpenChamber 会标记这些情况，以便你修复它们 — 参阅 [Worktree 与 Git](/zh-cn/troubleshooting/worktrees-git/)。
