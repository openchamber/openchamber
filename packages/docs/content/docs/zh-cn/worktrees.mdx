# Worktree 会话

worktree 会话运行在你仓库自己独立检出的副本中，位于它自己的分支上（一个 git worktree）。这能防止并行会话相互干扰彼此的文件 — 一个会话可以做重构，另一个可以修复 bug，无需来回切换。

## 创建一个

1. 打开新建 worktree 对话框：开始新会话时，在输入框上方的分支菜单中选择 **新建工作树…**，或使用侧边栏项目行上的 worktree 按钮。
2. 在 **Start from** 下选择一项：
   - **new branch** — 命名分支
   - **existing branch** — 检出一个你已经拥有的分支
   - **PR or issue** — 从 GitHub、Linear 或扩展中选一个；分支会以它命名（PR 会检出它自己的分支），该条目也会附加到你的第一条消息中
3. 检查 **Based on**（新分支的起始分支，默认是项目当前所在的分支）和 **Folder name**；只在需要时修改。
4. 创建它。如果项目配置了初始化命令，创建后会立即运行。

OpenChamber 会创建分支、设置文件夹，并在其中打开一个新会话，等你发送第一条消息。你也可以直接从一个 [待办](/zh-cn/notes-todos-plans/) 或一个 [GitHub issue 或 PR](/zh-cn/github/) 发起一个。

如果不想回答这些问题，在同一个分支菜单中选择 **快速工作树**：OpenChamber 会自动命名分支，并让新会话指向它。

## 把工作带回来

当工作完成得不错时，在 Git 视图中使用 **Integrate** 将 worktree 的提交带到另一个分支（比如 `main`）上。如果某个变更产生冲突，你可以把冲突交给智能体来解决。

## 清理

删除或归档会话可以移除 worktree。你可以选择是否同时删除分支 — 本地的，以及远程的（如果有）。没有你的请求，不会删除任何东西。

## 如果有什么看起来不对劲

如果 worktree 的文件夹丢失、分支处于游离状态，或一次合并或变基处于半完成状态，它可能需要关注。OpenChamber 会标记这些情况，以便你修复它们 — 参阅 [Worktree 与 Git](/zh-cn/troubleshooting/worktrees-git/)。
