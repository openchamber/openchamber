# 负责人

负责人是在项目中负责一个工作方向的会话，例如“把服务器迁移到 TypeScript”或“保持 issue 积压整洁”。你只需要和负责人对话，其余的事由它来做：它把一块块工作交给自己的会话，检查返回的结果，并在聊天上方为你维护一份简短的摘要。

当一项工作大到一次对话装不下、而且要持续好几天时，就适合用负责人。没有负责人，你得自己同时运行十几个会话，记住每个会话在做什么，再逐个阅读它们的回答，确认活是否真的干完了。负责人替你做这些记录工作，你只需回到一个地方，就能看到事情进展到哪一步。

## 创建负责人

1. 用以下任一方式新建负责人：
   - 在侧边栏中右键点击项目旁边的 **+**，或在手机上长按它，然后选择 **新建负责人**
   - 打开项目菜单，选择 **新建负责人**
   - 按 <kbd>⇧</kbd><kbd>⌥</kbd><kbd>⌘</kbd><kbd>L</kbd>（在 Windows 和 Linux 上按 <kbd>Ctrl</kbd><kbd>Shift</kbd><kbd>Alt</kbd><kbd>L</kbd>），或在命令面板中运行 **新建负责人**
2. 描述这项工作和你想要的结果，例如“负责把服务器迁移到 TypeScript。完成的标准是 `server/` 下的每个文件都是 TypeScript，并且测试通过。”
3. 发送。

草稿会显示 **这个负责人要负责什么？**，而不是平常的问题，这样发送前你就能看出这是一个负责人。如果你已经开始写一个普通草稿，同一个快捷键可以在负责人和普通会话之间来回切换，已输入的内容会保留。

已有的会话也可以变成负责人：在侧边栏中打开它的菜单，选择 **将此会话设为负责人**。它会保留历史记录。同一菜单中的 **改回普通会话** 可以把它改回来。

负责人在侧边栏中显示一座插着旗帜的山峰，而不是箭头；鼠标悬停时箭头会重新出现，所以你仍然可以展开它下面的会话。

## 负责人会做什么

- **为方向命名。** 它会按工作内容重命名会话，方便你在侧边栏、标签页和搜索中按主题找到它。你自己起的名字不会被改掉。
- **交付的是结果，而不是步骤。** 每一块工作都会连同它应达到的结果交给一个单独的会话，例如“找到并修复登录超时”，具体步骤由那个会话自己决定。这些会话在侧边栏中位于负责人下方。你可以打开阅读它们；如果想直接和其中一个对话，可以在会话菜单中选择 **接管**，把它变成你自己的会话。
- **检查返回的结果。** 一份只写着“我找到了原因”的报告并不是它要的结果，所以负责人会把工作打回去，而不是转交给你。每个会话都必须拿出它做了什么的证据，比如运行了哪些检查、结果如何；没有证据的报告也会被打回。只有证据有缺口的地方，负责人才会自己去检查。
- **清理。** 会话在工作树里完成的工作合入之后，它会移除那个工作树。会话本身保留，方便你查看。
- **只问真正重要的事。** 除非答案会改变你在项目中看到的东西，或者两个合理的选项确实结果不同，否则它会自己做决定。仅仅因为改动很大，并不构成提问的理由。它的会话提出的问题会先交给负责人，而不是你；只有通过同样标准的问题才会转到你这里。

## 摘要

摘要是负责人为你整理的概况。它显示在会话标题正下方的一行中，列出负责人当前在做什么，以及上次更新的时间。选择这一行，就会在聊天上方打开完整摘要：

- **等你处理**：最多三个问题，每个都附有可供选择的答案
- **当前**：每块进行中的工作各占一行
- **自你上条消息以来的新进展**：只列出改变了整体情况的内容
- **建议**：最多三件负责人注意到、在你交代的工作之外值得做的事

有事等你处理时，这一行会显示有几个问题在等待。选择一个答案，它会立即发送给负责人；负责人推荐的答案排在最前面并突出显示。想用自己的话回答，就选择 **在聊天中回复**，问题会被引用到消息框中。你的答复会显示在聊天中，负责人收到后会把这个问题移除。

在 **建议** 中，**开始** 会把这条建议放进消息框，你可以修改后再发送。**忽略** 会隐藏它，负责人不会再提出同样的建议。

## 把会话交给负责人

你可以把自己开始的会话交给负责人，比如在有负责人之前就开始的会话，或者你没时间做完的会话。在侧边栏中打开会话的菜单，选择 **交给负责人**，然后选择负责人。在手机上，菜单会为每个负责人列出一项“交给”加上它的名字。

会话会移到负责人下方。负责人会阅读它，弄清它的用途，并像对待自己的工作一样把它做完。你不再与这个会话对话；在它的菜单中选择 **接管** 可以把它交还给你。如果会话还在运行，负责人会在它结束时收到它的回答。

## 简报

负责人还会维护一份简报：用你自己的话写下的目标和你们商定的结果、它遵循的规则（你定的规则，以及它从自己的错误中学到的规则），以及每块工作预期达到的结果。简报是负责人记住这项工作目的的方式，所以无论对话变得多长，它都保持不变。

OpenChamber 把简报保存在你的项目之外，所以不会有任何内容写进你的仓库。想看简报，就对负责人说“给我看看你的简报”；想修改，直接告诉它改什么。删除会话会同时删除它的简报；归档则会保留。

负责人只修改简报中有变化的部分。每次对话被缩短时，OpenChamber 都会把完整的简报重新放到它面前，所以负责人每次更新简报时，长长的简报不会在聊天中反复出现。负责人只把你自己的话当作规则：它在会话的报告、网页或文件中看到的指令，永远不会写进简报。

## 休眠的负责人

负责人可能会在它的会话工作期间等上几个小时。它被唤醒时，模型通常需要从头重新读一遍整个对话，因为提供商只会把对话缓存有限的一段时间，通常是几分钟到一小时。对于很长的对话，这一次重读的花费相当于做很多工作；如果你用的是订阅，它会消耗你的用量额度。

因此，当负责人空闲的时间超过提供商保留缓存的时间，而且对话也很长时，OpenChamber 会在唤醒它之前先缩短对话。对话中较早的部分会被替换成一条简短的说明：负责人的摘要和它的会话状态。写这条说明不需要调用模型，所以不产生任何费用。简报和最新的消息保持原样，负责人在需要时仍然可以随时读取之前的完整对话。

开启了 保持预热 的会话不会被这样缩短。正在工作的负责人和较短的对话也不受影响。

## 工作流

负责人可以把一项大任务拆成一个[工作流](/zh-cn/workflows/)。在 **设置 → 通用 → OpenChamber 工具** 的 **无需我批准即开始运行** 中选择 **仅负责人**，负责人就可以立即启动它的运行，而其他会话仍然等你点击确认。

## 负责人在哪里可用

负责人需要默认开启的[智能体控制工具](/zh-cn/agent-control-tool/)。在你自己运行的 OpenCode 服务器上，还需要[登记 OpenChamber 插件](/zh-cn/opencode-server/#在外部本地服务器上启用-openchamber-工具)。它们可以在桌面端、浏览器和手机上使用。VS Code 扩展会显示已有负责人的标记和摘要，但不能创建新的负责人。
