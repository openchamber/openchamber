# 分类提供方（Jev）

OpenChamber 的一些功能在行动前需要先快速做个判断：这条命令有风险吗？这个提示属于哪类任务？用户是不是刚开始一项真正的工作？回答这些问题的是 Jev，一个来自 TypeSafe 的小型决策模型。本页介绍如何让 OpenChamber 使用 Jev。

Jev 从不写代码，也不会在你的聊天里回复。它只返回一个判定，OpenChamber 据此行动。OpenChamber 最多等待四秒。

## 哪些功能用到 Jev

| 功能 | Jev 回答的问题 |
| --- | --- |
| [权限与安全网](/zh-cn/permissions/) | 执行这个操作前，智能体是否应该先问你？ |
| [自动模型路由](/zh-cn/auto-model-routing/) | 这个提示属于你的哪个类别？ |
| [进行中的会话](/zh-cn/sessions-in-work/) | 你是不是刚提出了真正的工作？这一轮看起来是不是工作的结尾？ |
| [摘要和下一条消息建议](/zh-cn/sessions-in-work/) | 这一轮结束后，值得生成摘要或建议吗？ |

没有提供方时，安全网和 Auto 会隐藏，会话只有在你手动移动时才会进入进行中。摘要和建议照常工作，只是没有这层过滤。

## 设置

打开 **设置 → 提供商 → 分类提供方**，选择 Jev 请求发往哪里。共有五个选项。

### OpenCode Zen 促销

限时免费，不需要密钥。促销期间，OpenCode 允许 OpenChamber 通过 OpenCode Zen 免费使用 Jev。如果你从没动过这个页面，现在用的就是它。

促销结束后，这个选项会消失；如果你有下面的某个密钥，OpenChamber 会切换过去。

### OpenCode Zen 密钥

使用保存在 OpenCode 里的 Zen API 密钥，费用从你的 Zen 余额中扣除。

1. 打开 **设置 → 提供商**，给 **OpenCode Zen** 提供商添加一个 API 密钥（参见[提供商、模型与智能体](/zh-cn/providers/)）。
2. 回到 **分类提供方**，选择 **OpenCode Zen 密钥**。

只用 OpenCode 账号登录是不够的。对于 Jev，Zen 只接受 API 密钥。

### OpenRouter 密钥

使用保存在 OpenCode 里的 OpenRouter API 密钥，费用记在你的 OpenRouter 账户上。如果你已经在 OpenCode 里用 OpenRouter 的模型，就不用再做任何设置。 环境变量 `OPENROUTER_API_KEY` 里的密钥也可以用。两者都有时，以保存在 OpenCode 里的密钥为准。

1. 打开 **设置 → 提供商**，给 **OpenRouter** 提供商添加一个 API 密钥。
2. 回到 **分类提供方**，选择 **OpenRouter 密钥**。

### Vercel AI Gateway 密钥

使用保存在 OpenCode 里的 AI Gateway API 密钥，费用记在你的 Vercel 账户上。 环境变量 `AI_GATEWAY_API_KEY` 里的密钥也可以用。两者都有时，以保存在 OpenCode 里的密钥为准。

1. 打开 **设置 → 提供商**，给 **Vercel AI Gateway** 提供商添加一个 API 密钥。
2. 回到 **分类提供方**，选择 **Vercel AI Gateway 密钥**。

### TypeSafe API 密钥

使用你自己的 TypeSafe 密钥和额度。

1. 在 [TypeSafe](https://docs.typesafe.ai) 获取一个 API 密钥。
2. 把它粘贴到 **TypeSafe API 密钥** 输入框，然后点 **保存**。

保存密钥的同时也会选中它。密钥单独存放在 OpenChamber 服务器上的一个文件里，从不发送到浏览器。

提供方可用后，**设置 → 提供商** 里的卡片会显示 **就绪**。

## 当你选的提供方不能用时

如果你选的提供方无法使用（促销结束了、密钥被删了），OpenChamber 会改用第一个可用的，优先使用你自己的密钥：先 TypeSafe 密钥，再 OpenRouter，再 Vercel AI Gateway，再 Zen 密钥，最后是促销。页面会显示当前用的是哪一个。

即使 Jev 在某次请求中响应慢或出错，也不会有东西坏掉。每个功能都为这种情况准备了安全的处理方式：

- 安全网会让操作继续等你决定。
- Auto 会把提示交给你的备用模型。
- 进行中的会话保持不变。
- 摘要和建议照常生成，就像没有 Jev 一样。

## Jev 能看到什么

Jev 只拿到对话的简短摘录：你最新的一条消息，以及作为上下文的最多前三轮，每段都截取开头的几百个字符。对于安全网，它还会拿到被检查的操作，也就是 OpenCode 描述的样子：智能体想运行的命令，或者编辑时的文件和改动。它永远拿不到完整文件或图片。

请求会根据你的选择，从 OpenChamber 服务器直接发往 OpenCode Zen、OpenRouter、Vercel AI Gateway 或 TypeSafe。

## 在哪里可用

Jev 运行在 OpenChamber 服务器上，所以在桌面应用、网页应用，以及连接到它们的手机上都能用。VS Code 扩展直接和 OpenCode 通信，没有 Jev：那里没有安全网，没有 Auto，会话也只能手动移入进行中。
