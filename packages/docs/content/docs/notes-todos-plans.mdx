# Project Notes, Todos & Plans

Each project has its own scratch space for notes, a todo list, and saved plans. They belong to the project, not to any one session, so they stick around as you move between sessions. Find them in the **Context** tab of the right sidebar (a dedicated tab on mobile).

## Notes

A free-form notes box for anything you want to remember about the project. It saves on its own as you type.

If another client changes a note before your edit saves, the save reports an
error and keeps your draft. The other client's saved text stays unchanged.

## Todos

A simple checklist. Add items, check them off, reorder them by dragging, and clear the finished ones.

Each todo has a **send** menu so you can hand it to the agent:

- send it to the current session
- start a new session with it
- start a new [worktree session](/worktrees/) with it (only when the project is a git repo)

## Plans

A place to keep longer plans as saved files. You can:

- import a plan from a Markdown or text file
- open a plan to read it in the side panel
- delete plans you no longer need

You should land back in the Context tab with your note saved, your todo checked,
or your plan listed.

An open saved plan updates when an agent or another client changes it. Unsaved
edits stay in the editor. If the saved document changes before your edit saves,
the save reports an error and keeps your draft. Deleting a plan makes an open
draft read-only and does not recreate the plan.

## Agent actions

On a managed OpenCode runtime, the existing `openchamber` tool can list, read,
create, update and delete project notes and plans. It can list, create, update
and delete todos, including completing or reopening an item. Changes appear in
the open project panel through the existing event stream.

Actions use the calling session's project by default. An agent can supply a
configured `projectId` or a `directory`, but cannot supply both. Worktrees use
their project owner. Managed Chats share their Chats owner.

For a plan update, read the plan first and send its returned `raw` as
`expectedRaw` with the new `raw`. If the plan has changed, the update fails with
a conflict. Read it again before preparing another update. Without this optional
precondition, a plan update replaces the saved document.

For a note update, read the note first and send its returned `body` as
`expectedBody` with the new `body`. A changed note rejects the update with a
conflict. Without this optional precondition, an agent update replaces the body.

Todo item changes preserve other items. Reordering or clearing completed items
from the UI checks the last confirmed list. A concurrent change rejects that
bulk save. Existing note and plan attachments remain specific to each session.
