# Guest panels

## Purpose

OpenChamber-owned install and static serve for iframe guests. This is not the OpenCode plugin manager (`plugin-routes.js` / Settings → Plugins).

## Routes

- `GET /api/guests` — installed guests. `attach` is `"panel"` or `"dialog"` on the row when the manifest set it, and `attachEntry` is the dialog page when the manifest's object form declared one. `version` is the package.json semver when present. `integration` is the public slice only: name, description, `auth`, setting field defs. OAuth URLs and token origins stay on the server. `service` is the public slice when the package declared one: `runtime`, optional `permissions` (socket ids + exec names), optional `socketBindings` (resolved paths for this host), and `granted`. `capabilities` is `{ requested, granted }`: `requested` is derived from the manifest (`contributes.capabilities` — `prompt`, `sessions`, `files` — plus `conversation` for a session action with `payload: ["messages"]`, `service` for a declared service, `network` for a declared integration, and `filesystem` for a declared `contributes.filesystem`), `granted` is what the user approved. `actions` and `commands` are the parsed `contributes.actions` / `contributes.commands` entries as declared (present only when the package has them); the UI decides what to show from `enabled` and the grant, and owns command-name collisions. `filesystem` is the declared pattern list when the package has one, so the approval dialog can show it. A guest whose `granted` does not cover `requested` is installed but inactive: the rail, the + menu, Integrations, and every proxy treat it like a paused one until Settings → Extensions records the approval. `enabled` is false when the user paused the extension. Failure is 500, not an empty list.
- `GET /api/guests/:id/oauth/status` — `{ connected, account, hasClient, settings, redirectUri }`. No secrets. Host Linear merges first-party Linear status. `redirectUri` is empty unless `auth` is `oauth`.
- `PUT /api/guests/:id/oauth/client` — client id and optional secret from the Integrations form. OAuth guests only.
- `PUT /api/guests/:id/token` — pasted API token. Token guests only. The host probes the declared account path. The token never goes to the iframe.
- `PUT /api/guests/:id/settings` — declared keys only. The Integrations card calls it when a declared field loses focus with a changed value; there is no Save button. Connect saves the token (and username for `basic`) or the OAuth client id and then the declared fields.
- `POST /api/guests/:id/oauth/start` — PKCE S256 for OAuth guests. Host Linear starts the first-party Linear authorize URL. Token guests get `NO_INTEGRATION`.
- `GET /api/guests/:id/oauth/callback` — public HTML page. The provider redirects here with no UI bearer. State and verifier stay on the server. A callback without a matching `state` is refused; nothing is inferred from a pending exchange. Host Linear uses the first-party Linear callback, not this URL.
- `DELETE /api/guests/:id/oauth` — drops tokens for that guest. Client and settings stay. Host Linear disconnects the first-party Linear workspace.
- `POST /api/guests/:id/request` — authenticated UI session. Attaches Authorization. Path must stay on that guest's `apiOrigin`. Token guests send the pasted token as is, `Bearer <token>` when the manifest sets `token.scheme: "bearer"`, or `Basic <pair>` for `"basic"`, where `PUT /api/guests/:id/token` took `{ token, username }` and stored `base64(username:token)` as the access token (`USERNAME_MISSING` without a username). Host Linear sends the Linear bearer to `https://api.linear.app` only. Linear issue file URLs stay on `GET /api/linear/issues/get`. The guest proxy does not add Linear headers. A paused extension (`enabled: false`) is 400 `DISABLED`; tokens stay. A guest without the `network` capability granted is 400 `NOT_GRANTED`.
- `POST /api/guests/:id/service/request` — authenticated UI session. Proxies to that guest's host-spawned service on `127.0.0.1`. Spawns on first use after the grant; every service needs one. Missing grant, missing service, or bad path is 400 with `NO_SERVICE` / `BAD_PATH`. Paused extension is 400 `DISABLED` (service stopped). Ready failure is 502 `SERVICE_FAILED`.
- `POST /api/guests/:id/files` — authenticated UI session. `{ op: 'read' | 'write' | 'list' | 'stat', path, content? }` (`content` required for `write`, at most `GUEST_FILE_CONTENT_MAX` characters; `path` at most `GUEST_FILE_PATH_MAX`). The open project comes from `resolveOptionalProjectDirectory(req)` (`x-opencode-directory` header or `directory` query). `files.js` resolves the path: relative → joined to the project's realpath, and the deepest existing ancestor is realpath'd so a symlink out of the project is `BAD_PATH`; a relative path with no project is `NO_DIRECTORY`. `/…` or `~/…` → home expanded, normalized, canonicalized the same way, then matched against the package's `contributes.filesystem` globs whose literal prefixes were canonicalized too (`/tmp` → `/private/tmp` on macOS); no match is `BAD_PATH`. Any `..` segment, NUL, or backslash is `BAD_PATH`. Then the grant: project scope needs `files`, outside needs `filesystem`, else `NOT_GRANTED`. Then the operation: read is UTF-8 and refuses a file over the cap with `FILE_TOO_LARGE`; write makes parent directories and lands through a temp file plus rename (a reader never sees a truncated file); list returns `{ name, kind }` sorted by name and capped at `GUEST_FILE_LIST_MAX`, with symlinks as `other`; stat answers `kind: 'missing'` for nothing there. Answers are `{ ok: true, result }`, or `{ error: code, message }` with 400 (404 for `NOT_FOUND`). Paused extension is 400 `DISABLED`. `ENOENT` is `NOT_FOUND`, `EACCES` / `EPERM` is `DENIED`, `EISDIR` / `ENOTDIR` is `BAD_PATH`. Neither the path nor the content is ever logged.
- `GET /api/guests/:id/service/status` — `{ status }` for that guest's service runtime (`stopped` / `starting` / `ready` / `failed`).
- `PUT /api/guests/:id/capabilities` — `{ granted: GuestCapability[] }`. The list must equal the package's requested list, or be empty to withdraw approval (which also stops a running service). Anything else is 400 `invalid-request`. `service.granted` mirrors whether `service` is in the granted list.
- `PUT /api/guests/:id/service/sockets` — `{ id, path }` for a declared socket binding. Empty or null `path` clears the override. Stops a running service for that guest. Catalog `service.socketBindings` shows `resolved` and `override` for this host.
- `PUT /api/guests/:id/enabled` — `{ enabled }`. False is a full pause: catalog `enabled: false`, rail/attach/Integrations hide the guest, open panels close, cloud `request` and `service/request` return `DISABLED`, and a running service stops. Tokens and grants stay until Remove.
- `POST /api/guests` — `{ path }` or `{ url }`, exactly one. Optional `replace: true` uninstalls the same panel id first, then installs. `path` is an absolute folder or a local `.zip`. `url` is https git or an https `.zip`. Folder persist is the realpath in this instance's `{openchamberDataDir}/extensions.json`, 201 (200 after replace). Zip and git copy into `{openchamberDataDir}/extensions/{id}`. Missing, invalid, or relative path is 400 `invalid-path`. A bad URL is 400 `invalid-url`. Clone uses the host's resolved git binary (`resolveGitBinaryForSpawn`), so Windows and the packaged desktop app find git without PATH. Clone fail is 400 `clone-failed`. A copy left under `extensions/{id}` by an install that died before persisting is replaced on the next install of that id instead of blocking it. Extract fail is 400 `extract-failed`. A panel whose HTML loads a relative `.js` that is not on disk is 400 `missing-build`. A service whose entry file is missing is also 400 `missing-build`. Missing or non-semver `package.json` `version` is 400 `invalid-manifest`. A package whose `engines.openchamber` is newer than this host is 400 `host-too-old` (body may include `required`). Duplicate id or folder without `replace` is 409 (`id-taken` / `already-installed`, body may include `id`). Two OpenChamber processes with different `OPENCHAMBER_DATA_DIR` do not share this list.
- `DELETE /api/guests/:id` — drops the store row, any service grant, and socket overrides; stops a running service. Path-install does not delete the user's folder. Zip and git copies under `{openchamberDataDir}/extensions/` are deleted. Unknown id is 404.
- `GET /api/guests/:id/{*filePath}` — a file inside that guest's package root. Unknown id, escape, missing file, or unknown type is 404. Guest HTML gets the request's `oc_url_token` copied onto relative `script` / `link` / `img` URLs so the iframe can load its own files. That token is minted with `scope=guest:<id>` (`POST /auth/url-token?scope=guest:<id>`) and is accepted only under `GET /api/guests/<id>/`; a guest that reads it from its own URL cannot reach `/api/fs/raw` or the event stream. Every response carries `Content-Security-Policy: sandbox allow-scripts`, so a guest document opened outside the rail iframe is still sandboxed and never runs with the user's session on the app origin. Files are served as they sit on disk; the host never compiles guest sources.

## Install

Guests do not ship inside the app. Add a folder, a local `.zip`, or an https git / zip URL from Settings → Extensions. Connect on Settings → Integrations. A guest must ship `panel/main.js` as a classic IIFE, for example from `bunx openchamber-guest-bundle panel/main.ts panel/main.js` (any bundler with an IIFE output works). `package.json` needs a semver `version` (`1.0.0`); Settings → Extensions shows it on the card. `panel.icon` is a Remixicon name or a package `.svg` path; a missing SVG fails install as `invalid-manifest`. Optional `engines.openchamber` (`1.22.0` or `>=1.22.0`) is checked at install against this OpenChamber version. No runtime compiles TypeScript: `oc-dev`, packaged Electron, and `openchamber serve` all serve the built file. The iframe has no `allow-same-origin`, so ESM imports do not run.

Folder install stores the realpath with `source: "path"`. Zip and git extract or clone into `{openchamberDataDir}/extensions/{id}` (`source: "zip"` / `"git"`). Zip limits: 20MB archive, store/deflate only, no zip64 or encryption, no `..` paths, 500 files / 40MB uncompressed. A single wrapper folder around `package.json` is unwrapped. Uninstall deletes zip/git copies and leaves path-install folders alone.

OAuth and pasted tokens live in `{openchamberDataDir}/guest-auth.json`. Host Linear tokens stay in `linear-auth.json`. Writes are atomic and `0o600`. The file is per OpenChamber instance, same as `extensions.json`. Web and desktop share it. VS Code and mobile set the guest catalog to `unsupported`. That is not an empty ready list. Those cards stay hidden.

A missing folder is omitted from the list. Other guests stay. A corrupt `extensions.json` is 500, not an empty catalog. A missing or blank `guest-auth.json` is an empty store. Corrupt JSON there is 500, not a disconnected card. This is not Settings → Plugins.

## Invariants

- Paths stay inside the package root (`realpath`). `..`, absolute paths, and URLs do not serve.
- Only an allowlisted content type is served.
- Host and guest speak `@openchamber/sdk`. Do not copy those types into `packages/ui`.
- `contributes.actions` and `contributes.commands` are validated by the SDK parse at install (`invalid-actions` / `invalid-commands` surface as `invalid-manifest`) and copied to the catalog row unchanged. No server route runs an action or a command: the message or session item is built in the UI from the same records Export as Markdown uses, and a slash command is answered by the guest frame over `postMessage`. The rail badge is UI memory only.
- `contributes.attach` is copied as `"panel"` or `"dialog"`. The composer + menu and New Worktree read that field. Omitted guests stay off those menus. The object form's `entry` (dialog only) is checked at install like `panel.entry`: missing HTML is `invalid-manifest`, an unbuilt script it loads is `missing-build`; the catalog exposes it as `attachEntry` and the attach window loads that page instead of `panel.entry`. The optional attach `data` payload lives only in the UI's chip, queued context part, and session metadata snapshot; no server route parses it.
- `request` never leaves the declared `apiOrigin`. A 401 refreshes once. If that fails, tokens for that guest are dropped. Host Linear does not drop Linear auth on a failed GraphQL query. A paused guest never proxies `request` or `serviceRequest`.
- `serviceRequest` never leaves that guest's loopback port. Auth to the service is `Authorization: Bearer` with a host-minted token. The service env is an allowlist (PATH, HOME, temp, locale, Windows system variables) plus `OPENCHAMBER_SERVICE_*`; host secrets are not inherited. There is no sandbox: an allowed service has the user's full access, and the grant card says so. Ready is `GET /health` → 200. Parallel first requests share one spawn; they must not kill each other mid-start. Host quit stops every service. Disabling a guest stops its service without clearing OAuth or grants.
- File access is decided in `files.js` on canonical paths, never on the string the guest sent. `matchesFilesystemPattern`, `expandHome`, and `globToRegExp` are pure; `resolveGuestFilePath` and `runGuestFileOperation` take `fsPromises` / `nodePath` so tests can stub the OS. The project directory is whatever `resolveOptionalProjectDirectory` validated for this request, so a guest cannot name a project the UI did not open.
- The OAuth callback skips UI auth. Everything else under `/api/guests` stays behind the usual session.
