# 每个音效通道独立选择音效，而非全局单一音效

OpenChamber 引入通知音效时，需要决定是提供每个事件类型（agent 完成、权限请求、会话错误）独立选择音效，还是使用一个全局音效。我们选择了按通道独立选择。

选择 per-channel 独立音效的原因：

- 不同事件类型使用不同音效帮助用户在不看屏幕的情况下区分通知类型（agent 完成 = 积极短促音效，error = 警示音效），这是 opencode 用户研究中验证过的模式。
- 默认音效已体现这一区分：staplebops-01/02（积极短促）、nope-03（警告感）。
- 可降级——用户可以选择所有三个通道使用相同音效，但系统不限制能区分不同事件的用户。

数据结构为每个通道两个字段（启用开关 + 音效 ID），对应 `useUIStore` 中六个 `sounds*` 字段，与 opencode 的 `SoundSettings` 形状一致。选择 "None" 会关闭该通道（设置 `enabled=false`），而不是保留一个空音效 ID。

**Consequences**: 设置 UI 需要为每个通道渲染一个独立的选择器行；新增事件类型（如目标完成）时需要扩展 `useUIStore` 字段和设置 UI，但服务端无需变更。
